## 结论

根因已定位并修复：`frontend/src/components/ChatPanel.vue` 里 `watch(() => props.topic, ...)` 按**对象引用**监听话题切换。父组件 `WorkspaceView.vue` 的 `handleTurnDone()`（每轮 agent 回复结束都会触发）会调用 `refreshTopics()`，把 `topics.value` 整体替换成接口返回的新数组——即使话题内容没变，`selectedTopic`（`topics.value.find(...)` 计算属性）每次都是全新对象引用。ChatPanel 把这当成"切换到了新话题"，于是每轮结束都完整走一遍 `loadTopic()`：关闭 WebSocket → 清空/重拉 `listBlocks` → 重开 WebSocket。输入框的 `disabled` 绑定 `!connected`，重连瞬间 `connected` 变 false，浏览器对 disabled 元素自动失焦——这就是"发一条消息、输入框失焦/被禁用、聊天记录整体重载"的完整链路。

## 修复

`frontend/src/components/ChatPanel.vue:812-830`：watch 的 source 从 `() => props.topic`（对象）改成 `() => props.topic?.id`（字符串）。真正切换话题（id 变化）时行为不变（重连、重拉历史都是必要的）；同一话题被父组件换了个新对象引用时不再触发重载。改动约 15 行，无新增抽象。
