## note 优先级说明（验收标准4）

- A（重推失败）与 CI 失败 nudge 共享 `⚠️` 前缀家族：一旦 A 写了重推失败，`_nudge_pr_fix` 的 `note.startswith("⚠️")` 判断会跳过重复写 CI 失败——这是有意的：重推失败意味着"芝士的修复还没到 GitHub"，比"旧 commit 上的陈年 CI 失败"更值得优先展示。重推成功后 note 立即清空（原有行为），后续 CI 失败会正常覆盖。
- B（token 失效）发生在 A 之前（拿不到 token 直接 return），跟 A/CI 失败互斥，不会互相顶。
- 部署失败（`_advance_deploy_checks` 的 "❌"）只发生在 PR 已合并之后（stage 2），跟 A/B/CI 失败（stage 1）是状态机意义上完全互斥的两个阶段，不存在被顶掉的风险。
- C/D 的降级原因通过累加（`；` 拼接）而不是覆盖写入 `pr_degrade_reason`，两阶段采纳自己的降级原因不会丢失旧 PR 路径的降级原因。
