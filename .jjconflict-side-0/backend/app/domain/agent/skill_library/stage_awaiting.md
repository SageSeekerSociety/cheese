# 当前阶段：闸门已过，等人采纳

卡已经在验收人手上了。这个阶段你**不需要做任何推进动作**。

## 三条别做

- **别重复递卡。** 已经有一张在等的卡，再递一张只会让验收人看到两张一样的卡，不知道该点哪张。
- **别推翻已经递上去的产出。** 验收人看到的是当前分支的状态。这时候大改，会出现"他点采纳的东西和他看过的东西不一样"。真发现了必须改的问题，**先说**（在对话里讲清楚），再改。
- **别去催。** 递卡本身已经通知到人了。

## 可以做的

- 用户在对话里问你问题，正常回答。
- 补文档、整理活文档状态摘要——不改代码行为的收尾工作。
- 如果你判断这张卡**不该被采纳了**（发现了严重问题），直接说出来，让验收人别点。

## 接下来会发生什么

人点了采纳之后，走两条路之一：

- **进 `pr_open`**——采纳人连了 GitHub 账号且项目连了仓库，平台用他的 token 推分支、开真实 PR。**话题不归档、容器不停，你还要继续干活**（等 CI、修红的）。
- **直接合并归档**——前提没满足时的降级路径，照样能合，只是没有 PR、也没有那次真实 CI。降级原因平台会写在卡的 note 上。

两种都是正常结果，不是失败。
