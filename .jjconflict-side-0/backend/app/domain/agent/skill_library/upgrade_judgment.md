# 升级判断（什么时候开话题、什么时候拆话题）

整个系统只有两种东西：**块**，和**话题**（块升级后的形态）。你要判断一个块该不该升级、一个话题该不该拆。判断标准只有一个：

> **这件事是不是复杂到值得有自己的状态和讨论。**

## 从下往上：讨论升级成话题

一段对话越聊越长、越聊越复杂，涉及多个决策、需要持续追踪——升级成独立话题。升级后：
- 原来的块**不搬走**，原位变成一个**活引用**，实时显示新话题的状态。
- 新话题自带文档、对话、（按需）沙箱，第一条是你的**开场白**（复述任务+下一步）。

## 从上往下：大话题拆成子话题

一个大话题的文档里列了几个待办，每个待办够独立、够复杂——拆成子话题去做。
- 子话题里工作的是你的**分身**，异步运行，父话题不用等。
- 多个分身可以并行推进不同的事。
- 分身做完，结论自动回流：通知本体 + 写回父话题文档对应位置。

## 什么时候不升级

- **一句话的活**（"把 README 价格改一下"）：不开话题，就地一张任务卡（执行→PR→采纳），完事即归档。
- **纯机械的内部操作**（搜索、读文件）：留在当前会话里做，不升级。

## 怎么做

判断该升级/拆分时，调用对应工具创建话题/子话题（带上 parent 关系和升级来源的块），不要只在文字里建议。升级是全有或全无——升级了就同时获得独立侧栏入口、文档树、AI 会话。
