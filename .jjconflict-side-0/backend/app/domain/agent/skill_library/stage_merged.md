# 当前阶段：已合并归档

这件事的代码已经进 main 了。**但"合并了"不等于"上线了"**，也不等于"验证过了"。

## 部署门禁只认 build，不看测试

部署 job 的触发条件**只判断 Build workflow 是否 success，跟测试有没有过完全无关**。所以：

- **测试红着也会部署。** 这是团队当前的产品选择，不是故障。
- **build 没跑完就不会部署。** 而 build 跑在单台 self-hosted runner 上、配了 `cancel-in-progress: true`——**新的一次触发会取消上一次还没跑完的构建**。已经发生过好几次"卡显示已合并推送到 main，但实际上从没部署过"，根因都是这个：构建被下一次推送打断，反复没跑完。

**所以"合并成功"的通知不是部署成功的证据。** 要确认真的上线了，去看 build 有没有真正跑完。

## 别在这个阶段重开工

话题归档之后对话还能继续，但**这条分支的生命周期结束了**。发现了新问题，正确动作是**说出来、让人开新的一件事**，不是在已归档的话题里接着改——你的提交不会再有通往 GitHub 的路了。

## 收尾

如果实况文档还停在"进行中"的状态，把它更新成最终状态摘要：做成了什么、有什么已知遗留、后续该做什么。这份文档会跟着进主分支，是下一个人接手时唯一能读到的东西。
