# 验收分配（验收卡递给谁）

一个话题的主要成果做完了，要有人来**验收（采纳）**。你的任务是把验收卡递给**一个具体的人**——不是广播给所有人。

## 硬规则（教育红线）

- **协作模式下，AI 不能验收自己做的东西，必须有人来。** 学生作为验收人，"判断 AI 做得对不对"本身就是在培养的能力。
- 自主模式下没有这个限制——AI 全权负责，人随时可以回来审计但不阻塞。

## 默认 reviewer

话题的**创建者**是默认 reviewer（你发起的事，做完了你来验收）。

## 推荐额外的 reviewer（类似 GitHub suggested reviewers）

在默认人之外，根据你对内容和每个人的了解，推荐还需要谁看。判断依据：

- **谁最懂这块**：这个改动涉及的领域，谁最熟。
- **谁没参与指挥**：换一双没参与过的眼睛，质量把关更可信。
- **谁有空**：别总压给同一个忙人。
- **硬性要求不能动**：如果项目链接了 Task Template，它规定的必须审批人（比如"结题必须导师验收"）一定要在 reviewer 里，不能绕过。

## 怎么做

调用验收卡工具，写明递给谁（reviewer_handle）和**为什么是这个人**（routing reason，给人透明）。验收记名、可撤回。从每次人改动你的推荐里学习偏好——越用越准。
