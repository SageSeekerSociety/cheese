说明文件收口

把散落的 agent 说明统一成 AGENTS.md；文件级描述换成「机器生成」而不是手写 schema；索引只从结构生成、按需展开一层。

最要紧的一件事不是新做法：根目录叫 CLAUDE.md、两个子目录叫 AGENTS.md，混着写的结果是那两份子目录说明目前没有任何 agent 读得到。至于「每个文件手写一段 schema 描述」，外部调研把它否了一半——各语言没有统一的文件级 schema 标准，而「逐文件强制注释」这条线已经被 Go 和 ESLint 官方先后放弃，理由是产出填充、且描述会静默过期。可行的是：结构索引零人工生成，需要用途说明时由模型从代码生成。

背景

仓库里关于「agent 该怎么在这儿干活」的说明文件有三份：根目录 CLAUDE.md（81 行，写的是没有工具能自动拦住的原则），backend/AGENTS.md（49 行），frontend/AGENTS.md（206 行）。另有 .claude/rules/ 下 6 份按路径触发的规则，合计约 780 行。

名字混着用不是风格问题，是功能问题。Claude Code 的默认设置叫 claude-md-or-agents-md：从工作目录往上数，只要存在一个 CLAUDE.md（或 .claude/CLAUDE.md、CLAUDE.local.md），所有 AGENTS.md 一律不读，包括子目录里的。根上有 CLAUDE.md，所以那 255 行现在是死文件。

平台这边还有一层：芝士的会话由三个 harness 之一驱动，三者对说明文件的取法各不相同。这一层决定了改名到底修好谁。

claude-code 这一行不是遗漏：会话启动时带的是 --setting-sources user，代码注释写明是刻意排除宿主的上层说明（harness/claude_code/remote_execution/client.py）。pi 这一行是平台自己走树的实现（harness/pi/repository.py）：根目录读 AGENTS.md、CLAUDE.md、CLAUDE.local.md，全树读 .claude/rules/** 和任意层级的 CLAUDE.md，但嵌套清单里没有 AGENTS.md。

在平台的会话里，三份文件只有根 CLAUDE.md 被读到一次（由 pi），两份子目录 AGENTS.md 谁都不读。两个 harness 对同一个仓库给出不同说法，正是 pi/repository.py 开头那段注释说要避免的事。

别人怎么做

六路外部调研（外部方案、加载机制实测、注释工具链、标准清单、反面实证、学术与结构工具）扫下来，设想里的三块各有各的成熟度。

文件头写描述、脚本生成索引——机制老，但 schema 和手写这两环站不住

「人写注释、工具聚成索引、只给一级、按需展开」不是新东西：TypeDoc、Sphinx、pdoc、Doxygen 都在这条路上，最贴近的是 Doxygen 的 \file + \brief——brief 文本官方说明就是「used in lists and at the start of the documentation page」。各语言也都有文件/模块级描述的一等公民机制：

语言机制硬到什么程度
Rust//!语言参考里有正式语法定义，最硬
Python模块 docstring（PEP 257）官方 PEP，但明文自称 conventions, not laws or syntax
JavaScriptJSDoc @fileoverview官方标签，只有一句描述，无结构化字段
TypeScriptTSDoc @packageDocumentation正式规范，且必须放进口 .d.ts 文件
Go / Javapackage comment / package-info.java官方，但是「包」级不是「文件」级

关键结论是统一的 schema 不存在：JSDoc 与 TSDoc 同属 JS/TS 一脉却用不同标签名，跨语言更无一致字段。唯一稳定的只有「一段自由文本」。所以「schema 化 description」等于自造一套约定，再用 linter 强制——而「逐文件强制注释」这条线，Go 的 golint（2021 弃用）和 ESLint 的 require-jsdoc（v9 移除）官方都放弃了，理由一致：不能按项目关掉、产出无信息量的填充。

更硬的问题是描述会静默过期。注释与代码不一致的改动，引入 bug 的概率约为一致改动的 1.5 倍；Linux 内核 v6.18-rc1 上自动查出 869 处引用已消失函数的陈旧注释。而现有检查（jsdoc/require-file-overview、ruff D100）只判断描述存在，不判断正确——一段过期多年的 @fileoverview 照过全部检查。

逐级 AGENTS.md 按需加载——规范有，实现不稳

agents.md 规范写着「离被编辑文件最近的那份优先」，OpenAI 主仓有 88 份 AGENTS.md。但加载时机是各家自己实现的，实测都在翻车：Claude Code 子目录的加载只认 Read/Edit/Write 三个工具，用 cat/grep 或 Grep 工具读文件不触发（issue 93403，仍开着），auto 模式下会静默漏加载；Cursor 反向出过把整仓嵌套文件当 Always 规则全量加载、撑爆上下文的问题。所以它适合当「人和团队的约定」，不适合当「按需解析」的唯一实现载体。

纯结构索引——零人工，推荐做主干

不要求任何注释，索引完全从语法结构生成：ctags 出符号表、tree-sitter 抽 AST、SCIP 做跨文件符号关系，aider 的 repo map 用引用关系跑 PageRank、裁到 token 预算（默认 1024）。零人工、可脚本化、没有注释腐烂问题，而且天然支持「只给一级、按需深挖」。代价是它只会指路，不会讲用途：产出全是「文件在哪、有哪些符号、谁引用谁」，没有一个结构工具给出「这个文件是干什么的」。大仓上还会失灵——aider 的 issue #2405 里，80 万行的 monorepo 中纯引用频率被高频 import 淹掉，连直接 import 的文件都挤不进图。

要用途说明，就让模型生成回填

想让索引带上「这个模块是干什么的」，可行路线是结构工具切单元、LLM 逐单元生成、再聚合到文件级（arXiv 2501.07857 有完整流水线）。它解决的是「谁写」和「腐烂」：生成时点与代码同步，不靠人记得改。要注意验收不能拿 BLEU/ROUGE 这类 n-gram 重叠当数，它们和人的判断相关性差。

方案

整体走仓库已经用过很多遍的路子：只对新改动生效，存量冻结。check-file-sizes.py、catalog-ratchet.py、scene-ratchet.py 都是这个形状——一次全量迁移在这个仓库里从来不划算，也没人做过。

一、命名收口到 AGENTS.md

根目录 CLAUDE.md 改成 AGENTS.md，子目录两份已经是这个名。改完 Claude Code 会在启动时读根文件，并在用 Read 打开子目录里的文件时带进那一层的 AGENTS.md。

但只改名是半个修复。必须一起动的还有四处：

  • pi/repository.py 的嵌套清单（第 82 行）加上 AGENTS.md，否则 pi 那边照旧看不见那两份。
  • check-claude-md-review.py 的 GUARDED = "CLAUDE.md"。它保证这份文件只有人批准才能合；改名会让这道护栏静默失效。
  • check-repo-rules.sh 第 312 行盯住根 CLAUDE.md 的那条规则（不许出现平台 CLI 用法）。
  • 三处把旧名字写死的引用：claude-review.yml 第 52 行让自动 reviewer 照着 CLAUDE.md 走；ratchet-snapshot.py 第 585 行把 CLAUDE.md 登记成 palette 那条 ratchet 的判据文件；check-repo-rules.sh 的规则与报错文案（第 312、333 行）。

注意承接面比想的小：子目录 AGENTS.md 只在 Read 那个目录的文件时进来，cat/grep 不算。所以不能把它当「按需解析」的唯一手段，下面那条索引命令是要一起有的。

二、文件级描述：不手写、不自造 schema

原设想是「每个文件手写一段 schema 注释」，调研否掉了它的两半。schema 各语言没有统一标准，等于自造一套再用 linter 强制，而这条线被两个官方放弃过；手写还躲不过静默过期，检查只验存在不验正确。

所以分两步，都不手写：先不做意图字段，索引只指路（结构索引本来就不带用途）；如果实测下来 agent 找不到目标文件、非要点用途说明，再走「LLM 从代码生成一句、回填」——生成时点和代码同步，不靠人。两条路都不引入「人写描述然后烂掉」这一环。

三、索引：按需生成，只给一级

建议不落盘，按需生成：加一条命令，打印当前目录下一级的文件和子目录，每个带一句描述（先只有名字和符号，之后可选加 LLM 生成的一句），并提示「要看更深就跑它带子目录名」。根 AGENTS.md 里写一行怎么用。

检查进仓库的索引有两个躲不掉的问题：每动一个文件就要重新生成（PR 噪音加 CI 负担），或者它会过期。按需生成两个都没有。结构抽取用成熟的现成件（ctags / tree-sitter），不自造。这样「就近一级、更深按需」落在生成器的输出格式上，不落在文件布局上——比按目录切一堆索引文件好维护。

验证

每一步都要有能当场核对的动作，不是「确认没问题」。

  • 命名：改名前后的会话各截一次上下文，比对子目录 AGENTS.md 在不在里面。
  • pi：给 test_pi_repository.py 加一个临时仓库，断言嵌套 AGENTS.md 被读到——今天这个断言会失败，这正是要修的东西。
  • 护栏：拿一个只改 AGENTS.md 的测试 PR 跑 check-claude-md-review.py，它必须报「需要人批准」。
  • 索引命令：在 backend/app/domain 下跑一次，输出行数与该目录下一级条目数对得上。
  • 若做意图描述：验收看人能不能认，不看 BLEU/ROUGE——那些和人的判断相关性差。

风险

嵌套 AGENTS.md 的加载面比想的窄。只在 Read 子目录文件时触发，cat/grep 不算，auto 模式还会静默漏。对策就是别把它当唯一手段，配上那条索引命令。

CLAUDE.local.md 会静默关掉整套机制。默认设置下它算数，一个人在自己机器上建了这个文件，AGENTS.md 就全不读了。对策：把项目设置钉成 claude-md-and-agents-md——但这个值只在 user 设置、--settings 和管理设置里生效，写进项目设置无效，所以得进每个人的 user 配置或平台的启动参数。

读 AGENTS.md 有版本门槛。要 Claude Code ≥ 2.1.277；Amazon Bedrock 或关掉遥测的会话读不到，只能靠 CLAUDE.md 里 @AGENTS.md 导入。改名之前先确认团队的版本。

结构索引在大仓会失灵。纯引用频率排名被高频 import 淹没（aider #2405）。本仓 6706 个受控文件、2828 个 py 加 1450 个 ts/tsx，是否已到失灵区间，要跑一次才知道。
