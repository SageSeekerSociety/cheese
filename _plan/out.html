说明文件收口

统一到 AGENTS.md；给文件夹和文件加 description；索引由代码生成，只展开当前一级，更深按需。

结论先说：这些做法在 AI 时代已经有官方文档和论文背书，而且背书落在「找对文件」上，不落在「写对代码」上。已经出问题的是命名混乱——根目录叫 CLAUDE.md、两个子目录叫 AGENTS.md，混着写的结果是那两份子目录说明现在没有任何 agent 读得到。另外两件是新增做法，值不值得做由「agent 能不能更快找到正确的文件」来判，不由「有没有现成的语言规范」来判。手搓的成本不高，这轮不用等标准背书。

背景

仓库里关于「agent 该怎么在这儿干活」的说明文件有三份：根目录 CLAUDE.md（81 行，写的是没有工具能自动拦住的原则），backend/AGENTS.md（49 行），frontend/AGENTS.md（206 行）。另有 .claude/rules/ 下 6 份按路径触发的规则。

名字混着用不是风格问题，是功能问题。Claude Code 的默认设置叫 claude-md-or-agents-md：从工作目录往上数，只要存在一个 CLAUDE.md（或 .claude/CLAUDE.md、CLAUDE.local.md），所有 AGENTS.md 一律不读，包括子目录里的。根上有 CLAUDE.md，所以那 255 行现在是死文件——这一点在官方 memory 文档里写得很直白。

平台这边还有一层：芝士的会话由三个 harness 之一驱动，三者对说明文件的取法各不相同。这一层决定了改名到底修好谁。

左右滑动看全部列

claude-code 这一行不是遗漏：会话启动时带的是 --setting-sources user，代码注释写明是刻意排除宿主的上层说明（harness/claude_code/remote_execution/client.py）。pi 这一行是平台自己走树的实现（harness/pi/repository.py）：根目录读 AGENTS.md、CLAUDE.md、CLAUDE.local.md，全树读 .claude/rules/** 和任意层级的 CLAUDE.md，但嵌套清单里没有 AGENTS.md。

在平台的会话里，三份文件只有根 CLAUDE.md 被读到一次（由 pi），两份子目录 AGENTS.md 谁都不读。两个 harness 对同一个仓库给出不同说法，正是 pi/repository.py 开头那段注释说要避免的事。

别人怎么做

这一节只收 AI 时代的材料——官方 agent 文档、直接的仓库先例、和 2026 年的实测论文。上一轮拿 JSDoc、Sphinx、golint 那一套来判，问的是人类文档规范，答的不是这个问题，整段作废。

官方就是这么推荐的

Anthropic 给大仓库/单仓多包写了一份专页（code.claude.com/docs/en/monorepo），推荐的做法正是这件事：按目录分层放说明文件，从根启动时只在启动读根文件，子目录的文件「按需加载」——具体是 Claude 用 Read 打开该目录下的文件时才带上那一层。它同时给了几件配套：claudeMdExcludes 排掉不碰的包、Read 拒绝规则挡住生成物和 vendored 代码、用代码智能插件（语言服务器）跳定义找引用而不是满仓扫、以及把约定继续按目录切成 skills。换句话说，「就近一级可见、更深按需」不是我们独有，官方文档就是这么教的。

配套的细节在 memory 文档里：子目录的 AGENTS.md 同样按需加载，触发条件是「用 Read 打开该目录下的文件」，且只认 Read/Edit/Write（Bash 的 cat/grep 不算）；该目录自己若有一份 CLAUDE.md，那一层的 AGENTS.md 会被压掉。这条路还有个版本门槛：直接读 AGENTS.md 要 Claude Code ≥ 2.1.277。

真的有人整仓迁过

最大的先例是 vercel/next.js，分两步：2026-01-05 的 #88105 把 CLAUDE.md 改名成 AGENTS.md 并留一个软链，2026-09-22 的 #99043 直接改用 AGENTS.md。一次性的仓库也不少：apache/airflow 有 14 份 AGENTS.md、grafana/grafana 13 份、microsoft/vscode 8 份（vscode 的根文件正文只有一句指针）。两个坑要避开：路径上任何位置残留一份 CLAUDE.local.md，AGENTS.md 会被静默忽略、无警告（issue #96117，5/5 复现，仍 open）；改名别用软链——git 在有 core.symlinks=false 的机器（Windows）会把软链检出成「内容是目标路径」的纯文本，加载即乱码。要兼容读不了 AGENTS.md 的旧版本，官方给的办法是在 CLAUDE.md 里放一行 @AGENTS.md 导入。

效果如何——分两半，得说实话

实测把「写说明文件」这件事拆成了两半，结论不一样：

说明文件本身，对「做对」没有可测效果。一篇双 agent 消融（arXiv 2607.27250，Claude Code + Codex，3 个真实仓库 17 个任务 288 次运行）发现：换上下文注入策略，两个 agent 的正确定变化都被夹在 ≤10–15 个百分点内，等于没动。它的解释是 agent 输在实现能力——功能设计、方案选择、接线——不是缺一份说明文件能给的仓库知识。

但「文件/实体的描述」，对「找对文件」有实测效果。arXiv 2607.11046 把「角色感知摘要」和「文件路径」比，摘要高出最多 40% Hit@5，占用却小 10.4–20.9 倍，是各项里性价比最好的。arXiv 2609.31176 的 Semantic Cards（每个实体一句源信息的角色说明）把 File Hit@10 从 68.33% 拉到 82.67%，工作上下文少 48.2%，下游解决率 44.00%→52.33%。arXiv 2606.30963 端到端确认：文件级定位是一个稳定的修复杠杆，定位从 44.7% 提升到 49.1%（模型定位）、52.4%（金标定位）。结构索引也有同样方向的证据：arXiv 2606.22417 在固定 harness 里加一个结构索引，定位大涨、解决率统计显著上升、且不额外花钱，每解决一个任务的成本更低。

把两半合起来，正确的说法不是「写了描述 agent 就更聪明」，而是描述是给 agent 指路用的，不是替 agent 读代码用的。arXiv 2607.09691 把这一点钉死了：把文件剩下部分渲染成 UML 骨架和签名，跟直接删掉它，解决的 issue 数量一样多（N=70，p=0.75）——摘要替代不了代码。描述回答「改哪个文件」，代码回答「这里怎么改」。

一条要记住的成本教训：token 少不等于花得少。arXiv 2607.12161 里，最大压缩配置把工具输出 token 砍掉 38.4%，账单反而贵 6.8%（token 削减和成本削减的相关只有 r=0.15）。别把这套东西的卖点写成「省 token」。

方案

整体走仓库已经用过很多遍的路子：新做法只对新改动生效，存量冻结。check-file-sizes.py、catalog-ratchet.py、scene-ratchet.py 都是这个形状。

一、命名收口到 AGENTS.md

根目录 CLAUDE.md 改成 AGENTS.md，子目录两份已经是这个名。改完 Claude Code 会在启动时读根文件，并在用 Read 打开子目录里的文件时带进那一层的 AGENTS.md——正好是「就近一级、更深按需」，不用自己造机制。

预期收益要说准：这一步的价值是让那 255 行重新可达、让两个 harness 说法一致，不是提升 agent 合格率——按上面的消融，说明文件对正确率没有可测影响。它是修 bug，不是提性能。

只改名是半个修复。必须一起动的还有四处：

  • pi/repository.py 的嵌套清单（第 82 行）加上 AGENTS.md，否则 pi 那边照旧看不见那两份。
  • check-claude-md-review.py 的 GUARDED = "CLAUDE.md"。它保证这份文件只有人批准才能合；改名会让这道护栏静默失效。
  • check-repo-rules.sh 第 312 行盯住根 CLAUDE.md 的那条规则（不许出现平台 CLI 用法）。
  • 三处把旧名字写死的引用：claude-review.yml 第 52 行让自动 reviewer 照着 CLAUDE.md 走；ratchet-snapshot.py 第 585 行把 CLAUDE.md 登记成 palette 那条 ratchet 的判据文件；check-repo-rules.sh 的规则与报错文案（第 312、333 行）。

再补一道防呆：把 Project instructions 钉成 claude-md-and-agents-md，避开某个人的 CLAUDE.local.md 把整套机制关掉。这个值只在 user 设置、--settings 和管理设置里生效，写进项目设置无效，所以进每个人的 user 配置或平台的启动参数。

二、文件夹和文件的 description

做。判据换成「对找文件有没有用」之后，这一段是有实测支持的（见上节 2607.11046 / 2609.31176）。要定的只是形状：

  • 形状：文件头一段 schema 化的注释，description 必填（一句「这个文件负责什么角色」），其余字段可选。文件夹用同构的一段说明，和「就近一级」对齐。
  • 谁写：由代码生成或模型回填，不靠人长期手写。实测里起作用的正是「角色感知摘要」和「源信息卡片」，两者都是生成出来的；手写这一环会静默腐烂（上一轮的证据：注释与代码不一致使引入 bug 的概率约 1.5 倍，Linux 内核单版查出 869 处指向已消失函数的陈旧注释）。所以描述的产出要么由脚本从代码生成，要么在 CI 里校（描述提到的符号、导出、路径还在不在）。
  • 边界：描述只负责指路，不承担「讲清这个文件怎么改」。别为了让描述更全而把它写成代码的复述——2607.09691 说这没有回报，而且会过期。

三、索引

按需生成，不落盘：一条命令打印当前目录下一级的文件和子目录，每个带一句 description，并提示「要看更深就跑它带子目录名」。根 AGENTS.md 里写一行怎么用。机制上正好接上官方那套按需加载——一级由命令给，更深的交给 Claude 的 Read 触发。

不落盘是因为检查进仓库的索引躲不掉两个问题：每动一个文件就要重新生成（PR 噪音加 CI 负担），或者它会过期。按需生成两个都没有。「就近一级、更深按需」落在生成器的输出格式上，不落在文件布局上——比按目录切一堆索引文件好维护。

成本上有一处要先定：前后端都有文件贴着行数上限，而后端 1500 行、前端 src/ 1000 行、src/api/ 400 行这些上限把注释算进行数。测得贴到 90% 上限的有 31 个文件（后端 14、前端 src 16、src/api 1 个已豁免的生成文件），给它们加描述头会挂 CI。三条出路：抬上限、给描述头开例外、或这些文件等它们自己缩下去。

验证

每一步都要有能当场核对的动作，不是「确认没问题」。

  • 命名：改名前后的会话各截一次上下文，比对子目录 AGENTS.md 在不在里面。
  • pi：给 test_pi_repository.py 加一个临时仓库，断言嵌套 AGENTS.md 被读到——今天这个断言会失败，这正是要修的东西。
  • 护栏：拿一个只改 AGENTS.md 的测试 PR 跑 check-claude-md-review.py，它必须报「需要人批准」。
  • 索引命令：在 backend/app/domain 下跑一次，输出行数与该目录下一级条目数对得上。
  • 描述不过期：改一个域的描述提到的符号名，CI 的校验要能报出来。
  • 有效性：按实测的口径量定位（目标文件进没进 top-k）和 $/solved，不量 token 数——2607.12161 证明 token 少不代表花得少。

风险

别把说明文件当提性能的手段。消融显示它对正确率没有可测影响（2607.27250）。这一步的正当收益是可达性和一致性，别对外承诺「agent 会做得更好」。

嵌套 AGENTS.md 的加载面比想的窄。只在用 Read 打开子目录文件时触发，用户 @-mention 不算，cat/grep 也不算，auto 模式还会静默漏。所以别把它当「按需解析」的唯一手段，配上那条索引命令。

描述会静默过期。一段写对了的描述半年后指向一个不存在的符号，agent 会照着错的地图走，而且看不出来。对策是让它可机检（描述里的符号/路径能对上代码），不是靠人记得改。

读 AGENTS.md 有版本门槛。要 Claude Code ≥ 2.1.277；Amazon Bedrock 或关掉遥测的会话读不到，只能靠 CLAUDE.md 里 @AGENTS.md 导入。改名之前先确认团队的版本。

结构索引在大仓会失灵。纯引用频率排名被高频 import 淹没（aider #2405）。本仓 6706 个受控文件、2828 个 py 加 1450 个 ts/tsx，是否已到失灵区间，要跑一次才知道。
