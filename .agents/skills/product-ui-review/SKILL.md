# Product interface review

Every delivery of product interface changes includes one review artifact in the user's language that shows the affected screens before and after and explains the change from the product user's perspective. Pick the form that fits the change; a PR link, a test report or loose screenshots do not replace it.

Explain what users see, what they can do, and any changed limits or unavailable actions. Label sample data and distinguish previews from deployed screens. Describe settings by their effect on users; keep code, database and command details in the engineering report.

Keep it proportional to the change. Give it, with the pull request link, to whoever asked for the change alongside the delivery report, and regenerate it when the interface revision changes.
