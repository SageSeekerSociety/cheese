# 现场内容改为 raw

## 目标
现场（施工记录）里的工具卡片改为保留**原始内容**，不再是加工过的摘要。

## 现状定位（为什么现在不是 raw）
现场卡片在**入库那一刻就被加工了**，原始信息直接丢掉，事后想看也看不到：

- 后端 `backend/app/domain/agent/chat.py` 的 `_format_tool_event()`：把每次工具调用压成「中文动词 + 参数预览」两行存进事件块——
  - 工具名被映射成中文（`Bash`→「执行命令」、`Read`→「读文件」…）；
  - 只挑**一个**参数字段做预览，且压掉换行、**截断到 120 字**；
  - 其余参数全部丢弃。
- 前端 `DocPanel.vue` 的现场时间线就按「● 动词 / ⎿ 预览」渲染这两行，没有原始数据可展开。
- 补充：**工具的输出/结果目前完全没有采集**（`service.py` 只捕获了调用，没有捕获返回结果），所以现在的现场只有"调了什么"，没有"返回了什么"。

## 对标：Claude Code 现在怎么展示（调研结论）
Claude Code 的原则是「**存储永远 raw，压缩只在展示层**」：

1. **按时间交错**：助手的每段叙述文字和工具调用按实际顺序穿插展示（说一段 → Ran 1 shell command → 再说一段 → Read 1 file…），不是把话都攒到最后。
2. **默认折叠成一行**：每次调用一行（`● Bash(命令预览)`），下面 `⎿ 输出预览 (+N lines, ctrl+o to expand)`——**工具的输出结果也采集并展示**，只是默认折叠。
3. **ctrl+o 进 transcript 模式**：展开看全部 raw——完整命令、完整输出、thinking、时间戳、用的模型。
4. **底层 session 文件（JSONL）从不截断**：完整 tool_use 参数 + 完整 tool_result 输出全存，折叠/摘要纯粹是显示层的事。

对照下来我们现在有 **3 个差距**：入库就截断加工（↑现状定位）；输出完全没采集；工具调用之间的叙述文字也没落库（只存了最后一段话）。

## 方案（对齐 Claude Code）
1. **落库 raw**：事件块存完整工具名 + 完整参数 JSON + **完整输出结果**，不截断、不做中文映射。采集输出要在 SDK 流里多接一种消息（工具返回）。
2. **叙述穿插**：工具调用之间的中间叙述也按顺序落库，现场时间线还原真实过程。
3. **前端**：默认折叠一行（中文动词做标签没问题），点开看完整 raw 参数+输出（等宽字体）——相当于网页版的 ctrl+o。
4. 旧数据（已按"动词+预览"存的块）保持原样兼容渲染。
