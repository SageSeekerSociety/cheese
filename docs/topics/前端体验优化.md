# 前端体验优化

## 目标

打磨前端两块体验：① 消息通知的未读数字角标做到类似飞书的水平；② 归档后的话题有明确去处，不再和活跃话题混在一起。

## 现状

**通知**：顶栏铃铛已有未读数字角标，通知列表能标已读、能一键拍板。但：
- 未读数是前端拿全量列表自己数的，后端没有专门的未读数接口；
- 话题侧边栏、聊天区**完全没有**按话题的未读红点/计数——看不出哪个话题有新消息；
- 通知只在切项目/点开铃铛时才刷新，没有实时推送，"全部标记已读"也没有。

**归档**：目前归档只是"采纳"的副作用（采纳 = 合并 + 自动归档，可撤回），没有手动归档按钮。归档后的话题**原地留在侧边栏树里**，只加个"已归档"小徽标，没法隐藏，也没有专门的归档列表。

## 改进方案（建议按此顺序）

### A. 话题级未读红点（对标飞书）
1. 后端：给话题增加未读消息数（按人记已读位），提供未读数接口；
2. 侧边栏话题树：每个话题名后挂未读数字角标，点进话题即清零；
3. 顶栏铃铛角标改用后端未读数接口，加"全部标记已读"。

### B. 归档去向
1. 侧边栏把已归档话题收进底部可折叠的「已归档」分组，默认折叠；
2. 增加手动归档/取消归档入口（后端补接口）；
3. （可选）按归档时间排的归档列表页。

### C. 实时性（可后置）
- 通知/未读数改为推送或轮询刷新，不用等用户手动点开。
