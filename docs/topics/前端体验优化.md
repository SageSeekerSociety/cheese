## 进展：已全部实现，待验收 ✅

### A. 话题级未读角标（对标飞书）

- **后端**：新表 `topic_read_states` 按人记已读位（游标式，进话题即上报）；一条 SQL 聚合出全项目 `{话题: 未读数}`。未读只数**别人发的消息**，自己发的不算；别人的私聊不算。接口：
  - `GET /api/projects/{id}/topic-unread?handle=` 未读数map
  - `POST /api/topics/{id}/read` 上报已读
  - `GET .../notifications/unread-count`、`POST .../notifications/read-all`（通知未读数由后端算，silent 级不计入）
- **前端**：侧边栏每个话题名右侧挂红色数字角标（99+ 封顶），本体栏也有；点进话题即清零（乐观更新 + 服务端游标）。顶栏铃铛角标改用后端未读数，通知面板新增「全部已读」按钮。

### B. 归档去向

- 侧边栏新增底部**「已归档」折叠分组**（默认折叠，显示数量；有未读时折叠头显示红点）：已归档话题移出活跃树、按归档时间倒序收进该组，样式置灰。
- 每行新增**手动归档**按钮（📥），归档组里有**取消归档**按钮（📤）；后端补了 `POST /api/topics/{id}/archive` / `unarchive` 接口（幂等，本体不可归档，会在话题里落一条系统事件）。原「采纳=归档」逻辑不变。

### C. 实时性（MVP：轮询）

- 话题未读角标和铃铛未读数每 30 秒自动刷新；芝士回完话也会即时刷新。真·推送（WebSocket 广播）留待后续。

### 验证

- 前端 vue-tsc 类型检查 + 构建通过，单测通过。
- 数据库有一个新迁移（`topic_read_states` 表），部署时随 Alembic 自动应用。
