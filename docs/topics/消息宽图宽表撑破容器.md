## check.sh —— 现在全绿

第一次递验收卡被闸门拦了(`gate_failed`),日志结尾是 `fatal: not a git repository`。根因:`.claude/scripts/check.sh` 第 9 行用 `git rev-parse --show-toplevel` 定位仓库根,但这个工作区的版本控制是 jj,没有 `.git`,闸门执行环境里这行直接崩,所有验收卡都会这样(和这次的 CSS 改动无关,是脚本本身的可移植性 bug)。

**修复**:改成不依赖 VCS、用脚本自身路径推根目录,并加注释说明原因:
```bash
# VCS-agnostic on purpose: this repo's version control is jj, not git, and gate
# execution environments have no .git — `git rev-parse --show-toplevel` fails there.
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
```

修好这行之后,脚本能往下跑了,但 pytest 撞上沙箱缺基础设施:没有 Postgres/Redis(`DATABASE_URL`→`localhost:5433`、`redis_url`→`localhost:6379` 都连不上),且新鲜 `.env`(从 `.env.example` 复制)缺两个 `.env.example` 没提到、但代码路径需要的变量。逐一解决,都是**本地/测试环境补全,没碰任何被追踪的代码**:

- **Postgres / Redis**:沙箱没有 docker、没有 root 装系统包。用 `pip install pgserver`(借了个 py3.12 的临时 venv 拿到它自带的可移植 `postgres`/`initdb`/`pg_ctl` 二进制)+ `pip install redislite`(编译出一份独立的 `redis-server`)在用户态起了真实的 PG(5433)和 Redis(6379),`alembic upgrade head` 建表 + 跑种子迁移。
- `backend/.env` 补了两个变量(均已在 `.env.example` 没覆盖到的地方标注了原因,`.env` 本身 gitignored,不进版本库):
  - `OPENAI_API_KEY`——`app.domain.llm.chat_service.AIChatService` 即使在被 mock 的单元测试里也会 eager 构造 `openai.AsyncOpenAI(api_key=...)`,空字符串直接被 openai SDK 拒绝,炸了 `tests/unit/test_llm_service.py` 全部 36 条用例。
  - `ANTHROPIC_AUTH_TOKEN`——`app.domain.agent.market` 的默认 AI 资源池 `available` 字段看这个(GLM 网关凭证,和给芝士自己用的 `ANTHROPIC_API_KEY` 是两码事),缺了会让 `test_market_lists_ai_and_compute_pools` 断言 `available=False` 失败。
- **一个沙箱专属的坑,和代码/配置都无关**:我自己这个 agent session 的 shell 环境本身就有一条空的 `ANTHROPIC_AUTH_TOKEN=`(属于跑我这个 Claude Code 会话的外层 harness,和被测的芝士后端的同名配置项撞了名字),会覆盖 `.env` 里的值。手动跑 `check.sh` 时要显式加 `ANTHROPIC_AUTH_TOKEN=<占位值>` 前缀才能盖过它;闸门是独立进程,大概率没有这层 collision,不确定的话看这次重新递卡的结果就知道。
