## check.sh 结果(backend,与本次改动无直接关系——本次未碰后端代码)

- `bash .claude/scripts/check.sh` 本身在此沙箱跑不起来:脚本用 `git rev-parse --show-toplevel` 定位仓库根,而这个工作区不是 git 仓库(cheese 平台自己管版本),直接报 `fatal: not a git repository`。改为手动在 `backend/` 下逐项跑脚本里的三步:
  - **ruff check + format**:✅ PASS——`All checks passed!`,`573 files already formatted`。
  - **pyright**:✅ PASS——`0 errors, 0 warnings, 0 informations`。
  - **pytest**:❌ 跑不了,环境限制,非本次改动引入。沙箱里没有 Postgres,`DATABASE_URL` 指向的 `localhost:5433` 连不上。抽了一条最简单的纯单元测试单独跑,0.37s 内直接报错坐实:
    ```
    OSError: Multiple exceptions: [Errno 111] Connect call failed ('::1', 5433, 0, 0),
    [Errno 111] Connect call failed ('127.0.0.1', 5433)
    ```
    可见连 `tests/unit/` 下最基础的用例也在 fixture 里依赖真实 PG 连接,并非只有集成测试受影响。2234 条用例会等量复现同一个连接失败,没有跑完整套(跑了会在同一个原因上重复超时/报错,没有额外信息量)。这一项需要能起 Postgres 的环境才能验证。
