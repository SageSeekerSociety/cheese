## 目标

同一个房间（母话题 + 它派出的所有 task）**共用一个沙箱容器**。
这不是省钱优化，而是 <@wangchangxin> 2026-08-17「容器不回收」那条决定的**必要前提**：
不回收 × 每话题一个 × 2GB，先崩的是内存。共用之后容器数跟着**房间数**走。

## 做完了什么

**① 容器按房间分配。** 容器名从 `cheesex-tmux-<话题>` 变成 `cheesex-tmux-<房间>`。
话题→房间由 provider 查库解析（task 往上走到 root/topic 那一层），
再把答案落成一个 marker 文件，供 workspace 层那些同步、无 DB 的路径（`docker port` 查询）读。
解析失败一律退回「话题就是自己的房间」——也就是改动前的行为，不会指到别人的容器上。

**② 一容器多会话，per-topic 的东西全部走 tmux 会话环境。**
话题 id、回调令牌、`CLAUDE_CONFIG_DIR`、工作目录、预览端口，一律用
`tmux new-session -e` 逐键写进会话环境。**这条不是洁癖**：tmux 新会话是从
**tmux server 的全局环境**（第一个会话启动时冻结的那份）继承的，不用 `-e` 的话，
房间里第二个话题的 claude 会顶着第一个话题的身份跑、把事件报成那个话题——
device 后端在共享机器上实测过这个事故（`device_launch.py` 里有记录）。

**③ 「后端一重启存量容器全聋」修在根上。** 根因是签名密钥
（`sandbox_auth.SANDBOX_TOKEN`）在没钉 `SANDBOX_TOKEN` 时 fallback 到
**每进程随机**。改成从 `jwt_secret` 派生（带域分隔），重启之间稳定，不需要改部署。
原来那条「发现聋了就重建容器」现在只重建**会话**，不动容器——同房间其他话题不受影响。

**④ 配额提到房间预算**：6GB / 4 CPU / pids 2048（可配）。

**⑤ 顺带修掉两个不修就会立刻炸的东西**（不是附赠，是这次改动的必要条件）：
- `CLAUDE_CONFIG_DIR` 一设，claude 就**不再读** `$HOME/.claude.json`——
  而镜像里烤的首启动门禁正在那儿。不补的话会话会卡在 onboarding 对话框、
  永远等不到 `❯`，每一轮都在 45 秒就绪握手上超时死掉。现在每个话题的 config dir
  里都写一份门禁，并且信任的是**它自己的** cwd（镜像里烤的信任路径是 `/work`，早就不存在了）。
- `docker run -w` 会**创建**不存在的工作目录，而它落在 bind mount 里。
  容器 `-w` 原来指向房间话题的工作区目录——房间没跑过轮次时那目录不存在，
  于是会在宿主机上凭空造一个空目录，正好挡住以后 `jj workspace add` 的位置。
  改成指向 `/topics`（树本身），每个会话用 `new-session -c` 定自己的 cwd。

**⑥ reaper 改成按房间算活跃度。** 容器以房间命名，闲置判断必须取
「房间 + 它所有 task」的最大活跃时间。只看房间的话，一个把活拆出去、
自己安静下来的房间（**这是常态不是边缘情况**）会被连着正在干活的 task 一起回收。

**⑦ 逃生开关** `SANDBOX_SHARE_ROOM_CONTAINER=false`：一键退回每话题一个容器。
共用把房间的故障域合并了（一个话题 OOM 掉容器，同房间全死），
运维撞上时需要一条不用改代码的退路。
