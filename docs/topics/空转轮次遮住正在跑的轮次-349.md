# 空转轮次会遮住正在跑的那一轮（#349）

## 目标

芝士正在干活时，房间里有人说一句**不 @ 芝士**的普通话，这个话题在状态接口上就变成「停了」。
要修的性质：`GET /topics/{id}/status` 的 `turn` 字段回答的是「这个话题现在在不在跑」，
那它就该返回**正在跑的那一轮**，而不是「最近建的那条记录」。

## 核实（动手前）

- issue #349 仍然 open，正文 + 评论都读了（评论那条是主菜）。
- `main` 上没有相关提交；当前只有两个 open PR（#200、#158），都不相干；issue 上没有关联 PR。
- 结论：**这活还没被做掉，要做。**

## 病根

一条不 @ 芝士的消息，走的是**和一次真轮次完全相同的机制**：
`runner.submit(summon=False)` → `_run` → 准入闸 `_admit` → `_execute`（写轮次记录、写在飞注册表、
跑 `converse`、收尾）。它只是在 `converse` 里提前 return 了而已，
外面那一整套「我是一轮」的账照记不误。

于是这条 0.1 秒的空转记录成了这个话题**最近的一条轮次记录**，而下面这些读者全都按
「最近一条 = 现在的状态」来理解它：

| 读者 | 后果 |
|---|---|
| `topic_turn()` → `/status` | 报「已停」，而 `/health` 说还有一轮在跑（**issue 主菜**） |
| `running_topic_ids()` → 话题列表 | 侧边栏「还在说话」指示灯灭掉 |
| `running_topic_ids()` → `awaited_tasks` | 后台任务以为没人在跑，直接发起新轮次 |
| `continuation_for()` | 返回 None → 正在跑的那一轮，它的 cheese 写操作丢掉幂等命名空间 |

顺着同一条路还查出三条 issue 里没提的（都在同一个病根上）：

1. **结论卡被静默采信**：每轮收尾都会跑 `settle_turn_cards`（机制①「轮次结束=默认采信」）。
   空转轮次也跑——于是**在房间里说一句闲话，就把子话题回流上来的结论卡全部默认采信了**，
   而真正该读这些卡的那一轮还在跑。这条是数据后果，不只是显示后果。
2. **实时流被打断**：空转轮次末尾发的 `done` 帧会清掉 broker 的重放缓冲，
   `in_flight` 变 false；前端收到 `done` 会把「正在看…」指示器关掉——
   **所有**在看这个房间的人的浏览器上都关掉，不只是说话那个人。
3. **准入闸误伤**：一条纯人类消息要排项目并发队列，还会因此收到
   「⏳ 项目同时进行的轮次已满」；额度用完时收到「算力额度已用完」。
   而代码自己写着「speaking is free — only the AI turn is metered」。

外加一条罕见但真实的：空转轮次也会写在飞注册表，进程在那 0.1 秒里死掉的话，
重启后的孤儿清扫可能把这条**没 @ 芝士的消息当成人类 prompt 原样重发一次**（还是 summon 的）。

## 决策

配菜（原帖问「这种记录该不该存在」）选 **(a) 根本不建这条记录**，同时保留一层
查询侧兜底：

- **(a)**：纯发言（`summon=false`、非续跑、非平台事件）不再当作一轮——不走准入闸、
  不写轮次记录、不写在飞注册表、不做轮次收尾。消息照发、实时帧照广播。
  依据：grep 过全部轮次记录的读者（`/debug/turns`、上表四个方法、孤儿清扫），
  **没有一个需要「每条消息都有轮次记录」**——消息本身的 turn_id 存在 block 上，不受影响。
- **查询侧兜底**：`topic_turn` / `running_topic_ids` / `continuation_for` 改成
  「有正在跑的那一轮就返回它」，而不是「返回最近建的那条」。
  只做 (a) 不够：一轮 summon=true 但**秒失败**的轮次（额度拒绝、崩溃）同样会成为
  「最近一条」把正在跑的那轮遮住，病根是那个**取最近**的实现选择，不是空转记录本身。
