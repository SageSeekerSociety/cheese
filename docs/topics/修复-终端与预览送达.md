## 摸底结论（已读代码确认）

链路上的断点比简报里列的还多一处：

1. **终端缺凭据** — `terminal.py:_may_view_topic` 要求 `?token=`（iframe 设不了请求头，`tests/integration/test_terminal_auth.py` 钉着这个约定），但 `DocPanel.vue:634` 把后端返回的裸 url 直接塞进 iframe。`api.ts:authToken()` 现成可用（`getDeviceScreenWs`、`getUploadUrl` 都是这么拼 `?token=` 的）。
2. **生产 nginx 会把这条路吃掉（新发现，简报里没有）** — `frontend/nginx.conf` 的 `location /api/ { proxy_pass http://backend:8081/; }` 固定剥掉一层 `/api`，而 `vite.config.ts` 专门给 `/api/topics/*/terminal` 开了「不剥」的例外，nginx 没跟上。也就是说**即使补上 token，生产环境仍然 404**（后端收到的是 `/topics/…/terminal/live/`，不匹配 `/api/topics` 前缀）。ttyd 的 `/ws`、`/token` 是按 `location.pathname` 相对推的，所以这条路径必须原样透传。
3. **available 是假的** — `terminal_status` 只看 `docker port` 解析得出端口就报 `available:true`，既不探活也不看调用者有没有凭据；前端于是不退回时间线，只剩白框。
4. **预览查错容器** — `workspace/service.py:1432 app_preview_url` 只查 `container_name()`（`cheesex-sbx-`），而 3000 端口由 `tmux_container_name()`（`cheesex-tmux-`）发布。
5. **预览地址进不了浏览器** — 就算查对，返回的是 `http://127.0.0.1:<宿主端口>`，绑的是**宿主** loopback。`docs/spec.md:451` 自己写了这是已知边界（「远程算力节点接入时升级为经后端的反向代理」）——现在就是升级它的时候。
6. **空态吞故障** — `DocPanel.vue:664` 与 `:676` 两处 `.catch(() => null)`，把「后端报错」「文件读不到」都塌成「芝士还没有指定预览」。
