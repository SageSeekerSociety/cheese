## 摸底结论（已读代码确认）

链路上的断点比简报里列的还多一处：

1. **终端缺凭据** — `terminal.py` 的鉴权要求 `?token=`（iframe 设不了请求头），但 `DocPanel.vue` 把后端返回的裸 url 直接塞进 iframe。
2. **生产 nginx 会把这条路吃掉（新发现，简报里没有）** — `frontend/nginx.conf` 的 `location /api/ { proxy_pass http://backend:8081/; }` 固定剥掉一层 `/api`，而 `vite.config.ts` 专门给 terminal 开了「不剥」的例外，nginx 没跟上。即使补上 token，生产环境仍然 404。ttyd 的 `/ws`、`/token` 是按 `location.pathname` 相对推的，所以这条路径必须原样透传。
3. **available 是假的** — `terminal_status` 只看 `docker port` 解析得出端口就报 `available:true`，既不探活也不看调用者有没有凭据；前端于是不退回时间线，只剩白框。
4. **预览查错容器** — `app_preview_url` 只查 `cheesex-sbx-`，而 3000 端口由 `cheesex-tmux-` 发布。
5. **预览地址进不了浏览器** — 就算查对，返回的是 `http://127.0.0.1:<宿主端口>`，绑的是**宿主** loopback。`docs/spec.md` 自己写了这是已知边界（「远程算力节点接入时升级为经后端的反向代理」）。
6. **空态吞故障** — `DocPanel.vue` 两处 `.catch(() => null)`，把「后端报错」「文件读不到」都塌成「芝士还没有指定预览」。

## 一处安全取舍

预览 iframe **故意不带 `?token=`**。终端里跑的是 ttyd——我们自己的固定包；而预览框里渲染的是芝士自己写的页面，查询串能被那个页面的 JS 直接读到（`location.search`，即使 sandbox 也读得到），等于把访问者的 session token 交给 agent 生成的代码。所以预览多走一次 `app-session` 握手：用 Authorization 头换一枚 HttpOnly、path-scoped 的 cookie，iframe 的同源子请求自己带上。

## 已知边界（写进了 spec §9.1）

应用挂在 `/api/topics/{id}/app/` 子路径下。代理会把 HTML 里的**根绝对**资源 URL（`src="/x"`）改写到这个前缀，覆盖静态服务器和普通 dev server 首页；但运行时用 JS 拼根绝对 URL 的应用仍需按注入的 `$CHEESE_APP_BASE` 启动（`vite --base=$CHEESE_APP_BASE`）。

### 一次判断失误，记下来

第二轮之前我下过一个错误结论：「base 是 head 的祖先，不可能有冲突，`mergeable: false` 是 GitHub 的过期值」。错在前提——我拿本地的 `main@upstream`（停在 `4f580bd`）当成了 GitHub 的 main，而那个引用本身是陈旧的。

戳破它的办法：只读 token 虽然对 PR / refs / compare 全是 403，但 `commits/{sha}/check-runs` 的 `pull_requests` 字段会漏出 base——

```
base_ref = main   base_sha = 2afcb0cf     # 本地仓库里根本不存在这个提交
head_ref = cheesex/c4a9ad69   head_sha = 594d70df
```

再用 `actions/runs?branch=main` 列出 main 的近期提交，就能看到主干实际已经走到 `b8bc26db`。**修复只需要 `jj git import`**——对象早就被宿主同步进共享 git store 了，是我这个 jj 工作区没把引用导进来。`upstream/sync` 没有坏。

教训：在沙箱里判断「与远端的关系」之前，先 `jj git import`；只有一个本地远端跟踪引用时，不要下「不可能」这种结论。
