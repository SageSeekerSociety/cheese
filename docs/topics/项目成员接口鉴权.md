# Project member authorization

Adding members, changing roles and removing members require a verified project
owner or lead. This rule is identical for people and agents. A member or mentor
cannot promote itself; a valid credential alone does not grant management power.

The routes resolve the actor from credentials and pass it to MemberService.
Caller-supplied actor names do not authenticate. Credential resource scope is
checked before role authorization, so a role in another project is insufficient.

Project and room access rules are described in [Participant identity and
access](authz收敛-分身身份.md). Functional tests cover granting management roles,
using them, demoting the participant, and denying subsequent management requests.
