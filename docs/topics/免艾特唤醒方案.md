# 免艾特唤醒方案

## 目标

在多人房间里叫芝士干活，现在必须在正文里 @ 它一下。池若彤反馈：每次都要打这五个字很麻烦，而且**容易忘**——忘了之后消息石沉大海，房间里没有任何东西说明为什么没人接。这个话题解决这两件事。

私聊芝士（成员列表里点它进去）本来就免 @，问题只出在多人房间。

## 已定的原则（这条决定了方案长什么样）

**召唤与否的唯一真相是「这条消息正文里有没有 @ 它」，入口可以有好几个。**

背景：房间输入框以前有一个独立的「@芝士」开关，后来被删掉了。当时的理由是「同一个意图有两条并列的说法，而只有开关那条是通的」——你在正文里 @ 了它，它读得到，却不会动。那一版把 @ 修通成了唯一依据，同时把开关删了。

池若彤质疑了这个理由：路不通应该修通，不是把入口删掉。核对下来一半成立：路当时确实修通了（今天正文 @ 它就会动），但**「两条并列的说法」本身不构成删的理由**——只有当两条**能互相矛盾**时才必须砍掉一条（开关关着、正文里却 @ 了，这条到底算不算叫了它？没人答得上来）。一个跟着正文走的按钮不产生这种状态，它不是第二个事实来源，只是同一个事实的第二个入口。那一刀把入口和歧义一起砍了。

所以现在的做法是：真相仍然只有正文一条，入口加到三个，每个入口都只做一件事——**把那个 @ 写进正文**，写完你看得见、也能自己删掉。

## 已经做完的（分支 topic/1dde843b）

1. **「交给芝士」按钮**（输入框右下，挨着发送）。点一下把 `@芝士 ` 写进正文；你手打 @ 它就自动亮；再点一下取消。它不存任何自己的状态。
2. **⌘/Ctrl+Enter = 发送并交给它**。同样是先把 @ 写进正文再发，时间线上那条消息自己说明它叫了谁。
3. **忘了 @ 的补救**：房间里最后一句是没 @ 的人类消息、且芝士没在干活时，那条消息下面出现一行「这条没叫芝士，它不会现在动 · 让它现在就看」。点一下走新接口 `POST /api/topics/{id}/summon`——它只开一轮、让待读窗口把那条消息捎上，**不补发一条重复消息**。房间已经在干活、或者没有待读内容时它什么都不做，并说明是哪一种（不白花钱）。
4. **名册没到时按钮是关着的**（没人要求，但绕不开）：「叫没叫它」是浏览器把你打的名字解析成 handle 算出来的，名册没到就解析不出来，那时候替你写进去的 @ 只是一行字——消息照发、它照样不动，而你以为自己叫了它。

文案上有一条特意没写错：提示语不能说「它还没看到」。没 @ 的消息不会丢，它在待读窗口里等着下一轮捎上，只是**不会现在动**。

### 被否掉的方案

- **输入框默认预填 `@芝士 `**：房间里人对人说话每次都要删那五个字，比现在打五个字更烦（它是每次都出现的噪音，不是你主动的动作）；而且误发一次就是白开一轮，要花钱。
- **按上下文自动判断**（上一条是芝士说的就默认唤醒之类）：唤醒是花钱且会打断它当前工作的动作，一个你猜不准什么时候触发的规则，比每次打五个字更让人不安。
