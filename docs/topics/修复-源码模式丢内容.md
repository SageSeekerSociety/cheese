## 结论

P0-6 三条已修完，检查跑绿。核心改动：**文档编辑链路里所有"两份内容对不上"的地方，一律不再靠悄悄扔掉一边来收敛——留住两边，把选择权交给人。**

## 修了什么

### 1. 引导按钮删内容（最刺眼那条）

「确认覆盖保存？」对话框里推荐按钮「用源码模式」调 `enterSourceMode`，旧实现在 lossy + dirty 时把 `sourceDraft` 置成磁盘原文并 `dirty = false`——用户点的是保护内容的按钮，未保存的改动当场蒸发，只留一行 errorMsg。同一个函数也是 lossy 横幅上「源码模式」按钮的入口，两条路都在删。

**现在**：改动进**暂存区**，编辑器上方挂一条提示条「有未保存的改动没有带入…」+ 「恢复我的改动」/「丢弃」。一个字都不会消失，要丢也是人自己按的。

### 2. 自动保存暂停后不重排、UI 还谎报

`queueAutosave` 命中 `lossy && !sourceMode` 直接 `return`，改动永久搁浅，头部却一直显示「编辑中…」——人以为在存。

**现在**：头部新增 `paused` 态，显示「**已暂停 · 改动未保存**」（橙色，带 tooltip 说明怎么救）。同时补上真正会漏存的路径：进/出源码模式时若仍 dirty 会主动排一次自动保存（源码模式的保存本来就是安全的），改动不再干等下一次敲键。只读态下遗留的未保存改动也归入 paused——它同样永远不会被自动保存，以前也被伪装成「编辑中…」。

### 3. dirty 期间外部更新被静默丢弃

`reloadFromActivity` 开头 `if (dirty) return`，芝士写进磁盘的更新根本不取，面板与磁盘从此永久分叉，两边都不知情。

**现在**：照常取，按 `planExternalUpdate` 分三种——磁盘没变就忽略、本地干净就载入、**两边都动了就挂冲突条**：「芝士更新了磁盘上的这篇文档，而你有未保存的改动」+「查看磁盘版本」/「用我的版本覆盖」。两份都在内存里，谁也不会静默胜出。

## 关键取舍

**lossy 文档进源码模式是个真两难**：源码视图必须显示**磁盘原文**（显示降级后的序列化 = 逃生口自己把不支持的语法毁了），但用户的未保存改动**只存在于**那份降级序列化里。两者都不能丢，所以做成「展示一份、交回另一份」。

暂存区是**栈**而不是槽，且「恢复」是**交换**（屏幕上那份自动回到暂存区）——否则第二次暂存会顶掉第一次、恢复动作本身又会丢掉屏幕上的内容，等于把同一个 bug 换个地方复发。同一套机制复用在冲突条的「查看磁盘版本」上。

顺带修掉一个自己引入的坑：保存在途时的活动刷新会误报冲突（服务端快照可能已含我们的 PUT，而 `rawDoc` 还没更新），已加 `saving` 守卫。
