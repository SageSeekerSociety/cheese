# 返回键：现状与改造方案

## 目标

@池若彤 提的问题：**从小队点进一个项目，按 ← 应该回小队。** 现在做不到。

## 现状（核查过的）

顶栏那颗 ← **不是浏览器后退**，是一个普通跳转链接：每条路由在自己的定义里写死「我的上一层是谁」（`meta.backTo`），按钮读这个值跳过去。

- 声明在 <&frontend/src/router/workspaceRoutes.ts>、<&frontend/src/router/teams.ts> 等路由文件的 `meta` 上。
- 按钮是 <&frontend/src/components/common/Navigation/ParentBackButton.vue>，把 `meta.backTo` 用 `router.resolve()` 变成真实路径。手机和桌面共用它。
- **没写 `backTo` 的路由，这颗按钮直接不渲染。**

**问题的根**：`backTo` 描述的是一棵**树**，但实际的应用是一张**图**。同一个项目页可以从小队进、从空间进、从左边项目栏进、从别人贴的链接进——一个写死的父级不可能对所有入口都是对的。

**而且项目主页 `/projects/:id` 压根没写 `backTo`**（<&frontend/src/router/workspaceRoutes.ts> 里 `workspace-project` 的 meta 只有 `barSlot`），所以从小队点进去之后**连 ← 都没有**，只能靠底栏/左栏绕回去。这就是「返回只在同一个界面里打转」的实感来源。

## 分享一个项目链接，对方会看见什么（本轮逐条 curl 实测）

**决定能不能看内容的只有一件事：你是不是「项目成员」。** 判定在 <&backend/app/api/auth.py:434>，三条路任选其一——在项目名册上 / 是项目创建者 / **是项目所属小队的成员**。

所以「项目属不属于小队」这一维**只影响一件事**：它决定第三条路存不存在。项目没有小队，就只有名册上的人和创建者进得来。

| 项目 | 打开的人 | 算不算项目成员 | 界面上看见什么 |
|---|---|---|---|
| 属于小队 X | 没登录 | 否 | 空壳 + 红条「Login required to access a project」，4 秒后消失 |
| 属于小队 X | 登录，是 X 的队员 | **是**（第三条路） | 全部内容 |
| 属于小队 X | 登录，非 X 队员，但在项目名册上 | **是**（第一条路） | 全部内容 |
| 属于小队 X | 登录，两条都不沾 | 否 | 空壳 + 红条「你不是这个项目的成员，无权查看」，4 秒后消失 |
| 不属于任何小队 | 没登录 | 否 | 同上（401） |
| 不属于任何小队 | 登录，在名册上 / 是创建者 | 是 | 全部内容 |
| 不属于任何小队 | 登录，都不沾 | 否 | 空壳 + 红条 403，4 秒后消失 |

**「看不见」具体长什么样**——这是本轮最该改的东西：

- 红条弹 4 秒就没了，之后页面上**没有任何解释**。
- 话题列表一片空白，**连一句空态文案都没有**（<&frontend/src/components/TopicSidebar.vue:629> 那一段只处理「有话题但都与你无关」，没处理「一条都没有」）。
- 项目名也不显示（名字取自「我的项目」列表，非成员那个列表里没有它）。
- **但成员头像照常显示**（那个接口没有守卫，见下）。

结果：**非成员看到的界面，跟「一个刚建好、还什么都没有的项目」长得一模一样。** 错过那 4 秒就再无线索。

前端 401 不跳登录页：<&frontend/src/api.ts:257> 的 `request()` 只在 401 时刷一次 token，刷不出新的就把 `ApiError` 抛给调用方，workspace store 的 `reportError` 把它变成那条 4 秒红条。

### 小队页那一侧

`GET /teams/{id}`（<&backend/app/api/routes/teams.py:463>）**只要求登录、不要求是队员**，所以「← 回小队」对任何能打开这个项目的人都点得开，不会 403。

但 `GET /teams/{id}/members` 挂的是 `require_permission(READ, TEAM_MEMBERSHIP)`，要 MEMBER 及以上，非队员 403；前端 <&frontend/src/views/teams/Detail.vue:58> 把这个 403 `catch` 掉只打了一行 console，所以**页面照常渲染、成员名单静默留空**，看起来像这个小队一个人都没有。

线上数据（36 个项目）：**3 个项目 `team_id` 为空**（历史遗留行，新建项目一律会落到个人小队）；名册上有 1 个人不在项目所属小队里。

## 顺带撞见的权限洞（不在本次改动范围，已记入项目记忆）

**不带任何凭据**（连登录都不用）就能读到：

| 接口 | 返回 |
|---|---|
| `GET /projects/{id}` | 项目名、创建者 handle、所属小队 id |
| `GET /projects/{id}/members` | **完整名册**（handle + 显示名 + 头像） |
| `GET /projects/{id}/decisions` | **159 条决策记录全文** —— 这是货真价实的项目内容 |
| `GET /projects/{id}/usage` | token 用量与花费 |

整片里**只有 `GET /topics?project_id=` 是守着的**。另外 `GET /projects?team_id=<id>` 带 `team_id` 时也不校验调用方是不是这个小队的人（<&backend/app/api/routes/projects.py:178>）——同一条路由不带 `team_id` 时反而是严的。

## 方案：记住来路，写死的父级降级成兜底

### 一条规则

> **← 指向「你进入当前这一层时所在的地方」。在同一层里横向移动，不改变它。**

「层」有两个粒度，两个都要，但这次只做第一个：

**① 项目这个框**（本次要做）。从项目**外面**走进来的那一跳，记下来当这个项目的「入口」。在项目里怎么翻都不覆盖它——包括从话题按 ← 回到话题列表，那是框内移动。话题列表这一层的 ← 就指向那个入口。

**② 框内的层**（**已拍板：本次不做**，见下）。看板 / 私聊 / 侧栏都能点进一条话题，但话题页写死了 `backTo: 'workspace-project'`，所以从看板进去、← 出来落在话题列表。这是同一类问题矮一级的复制品。

### ← 取值的优先级

1. **本层记下的入口** —— 有就用它，并且**带名字**：「← 小队 · XX组」。
2. **归属兜底** —— 只有框根用得上：`ProjectOut`（<&backend/app/domain/project/schemas.py>）本来就带 `team_id`，← 指向所属小队。不用动后端。
3. **写死的父级** —— 框内那些真层级（话题 → 话题列表、私聊 → 名册）继续用现在的 `meta.backTo`，一个字不改。
4. 都没有 → 不显示（`team_id` 为空的历史项目就落在这儿，36 个项目里 3 个）。

### 三个实现要点

- **名字要在离开那一页的时候就抓下来**，跟路由名和参数一起存。等按 ← 的时候再去请求，那一刻页面上根本没有小队的数据，只能显示一个光秃秃的箭头。
- **入口按项目分别存**（`sessionStorage`，一个标签页一份）。不然从小队进了 A 项目、再从左栏切到 B 项目，B 也会挂着「回小队」。
- **桌面端同样要**。左边的 rail 上只有项目、没有小队，所以桌面一样出不去——不是只有手机的问题。

### 为什么不直接用浏览器后退

- **贴链接直接进来的，历史里没有上一层**，`history.back()` 会把人踢出整个应用。这正是当初改成写死父级的原因，代码注释里写着。
- **在项目里翻了二十下，后退要按二十次才出得去**；「回上一层」应该是一下的事。
- 浏览器后退 / 手势后退**保持原样**。它管「撤销上一步」，顶栏这颗 ← 管「回上一层」，两件事，不合并。

### 为什么框内那一层这次先不做

看板 / 私聊 / 话题之间互跳，一共四个入口（<&frontend/src/views/workspace/RunningWorkView.vue:235>、<&frontend/src/views/workspace/DmView.vue:79>、<&frontend/src/views/workspace/ProjectSidebar.vue:32>、<&frontend/src/views/workspace/TopicView.vue:88>）。机制跟框那一层是同一套，但它会**改变一个现在稳定地错着的行为**——今天从看板进话题，← 一定落在话题列表，用的人已经形成肌肉记忆。值得单独看一次，不混在这次里。

还有一个坑要一起想：话题 → 话题的横跳**不能**算「重新进入话题层」，否则 ← 就退化成浏览器后退，一步一步往回倒。

## 要注意的坑

- **记下来的入口可能已经失效**（小队被删）。存路由名 + 参数，跳之前 `router.resolve` 校验。
- 漏写不会报错，只会表现为「进去出不来」。<&frontend/src/router/workspaceRoutes.spec.ts> 已有一条测试逐条检查每一层都声明了 `backTo`；框根的 ← 不来自 `backTo`，要另加测试，否则这条新机制没人守。

## ← 不出现时要不要给提示（@池若彤 提出，待定）

诉求是对的：**不能让人干瞪眼**。但核实下来，「看不到」发生的位置和原先设想的不是同一处。

- **← 不出现的唯一一档，是「这个项目不属于任何小队」**（`team_id` 为空的历史项目），不是「你没加入小队」。非队员照样进得了小队页，所以对他们 ← 是正常出现的。
- **真正会撞上「看不到」的地方在小队页里面**：非队员点 ← 回到小队，成员名单是空的，而且一个字都不解释（上面那条 403 被静默 catch）。

所以提示该放在小队页的成员那一块，写「你不是这个小队的成员，看不到成员名单」；而 ← 不出现的那一档，用户没有任何可操作的事，加一句「这个项目不属于任何小队」只会让人更困惑。
