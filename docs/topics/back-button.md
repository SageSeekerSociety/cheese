# 返回键

## 顶栏那颗 ← 是什么

一个按钮，两种形态：

- **有应用内来路** —— 按浏览器的语义退一格（`router.back()`）。「回到我刚才看的那一页」。
- **没有来路**（刷新后第一次打开、贴链接直接进来，`history.state.back` 是 null）—— 退到路由声明的上一层 `meta.backTo`。「回到逻辑上的上一层」。

判断在 <&frontend/src/components/common/Navigation/ParentBackButton.vue>。两种形态都是一颗普通按钮（直开时那一支是链接），手机和桌面共用。

`meta.backTo` 声明在 <&frontend/src/router/workspaceRoutes.ts>、<&frontend/src/router/teams.ts> 等路由文件的 `meta` 上。**没写 `backTo`、身后又没有来路的路由，这颗按钮不渲染。**

### 为什么声明还留着

**`backTo` 描述的是一棵「树」，实际的应用是一张「图」。** 同一个项目页可以从小队进、从空间进、从左边项目栏进、从别人贴的链接进——一个写死的父级不可能对所有入口都是对的。所以来路优先。

但直开一页时**没有来路可用**，而 `history.back()` 会把人踢出整个应用（前一个历史条目是别的站点）。这时只有声明能给一个答案。

### 两个例外

- **最外层那一页不画 ←**：桌面上是待办（`inbox`），手机上是首页（`HomeHub`）。它俩是侧栏 / 底栏的落点，是终点，退一格只会在别的页面之间来回弹。
- **身后那一页的 ← 正落在这一页上时，不吃这条历史**，改去最外层那一页。两页互指时（首页 ↔ 团队页、项目根 ↔ 频道页）照来路走就会在两页之间死弹。判据是「**它自己的 ← 会落在哪**」而不是它声明的父级：项目根上的 ← 是「所属小队」，只比 `meta.backTo` 会漏掉「小队页 ← 回项目根、项目根 ← 回小队页」这一对。

### 项目这个框的根

桌面的根是项目总览（`workspace-overview`），手机的根是频道列表（`workspace-project`）——两端的根不是同一条路由，不是漂移：`/projects/:projectId` 在桌面上一帧都不停，WorkspaceEntry 当场 `router.replace` 去总览。

根上没有可声明的上一层（总览声明 `backTo: 'workspace-project'`，在桌面上解出来就是总览自己，一颗按了没反应的 ←）。**没有来路时**，根退到项目所属的小队：`ProjectOut`（<&backend/app/domain/project/schemas.py>）里带 `team_id`，小队页只要求登录、不要求是队员，所以对任何能打开这个项目的人都点得开。`team_id` 为空的历史项目没有这一层，← 就不显示。

## 要注意的坑

- 漏写不会报错，只会表现为「进去出不来」。<&frontend/src/router/workspaceRoutes.spec.ts> 逐条检查每一层都声明了 `backTo`；框根的 ← 不来自 `backTo`，由 <&frontend/src/components/common/Navigation/ParentBackButton.spec.ts> 守。
- 来路这一支在单测里只能用 `createWebHistory` 演：内存历史（`createMemoryHistory`）不写 `state.back`，每一页都长得像直开的。jsdom 的 `history.back()` 是空操作，所以断言落在「会调用 `history.go(-1)`」和 `history state` 里的来处地址上。

## ← 不出现时要不要给提示（@池若彤 提出，待定）

诉求是对的：**不能让人干瞪眼**。但核实下来，「看不到」发生的位置和原先设想的不是同一处。

- **← 不出现的唯一一档，是「这个项目不属于任何小队」**（`team_id` 为空的历史项目），不是「你没加入小队」。非队员照样进得了小队页，所以对他们 ← 是正常出现的。
- **真正会撞上「看不到」的地方在小队页里面**：非队员点 ← 回到小队，成员名单是空的，而且一个字都不解释。

所以提示该放在小队页的成员那一块，写「你不是这个小队的成员，看不到成员名单」；而 ← 不出现的那一档，用户没有任何可操作的事，加一句「这个项目不属于任何小队」只会让人更困惑。

`GET /teams/{id}/members` 挂的是 `require_permission(READ, TEAM_MEMBERSHIP)`，要 MEMBER 及以上，非队员 403；前端 <&frontend/src/views/teams/Detail.vue:58> 把这个 403 `catch` 掉只打了一行 console，所以页面照常渲染、成员名单静默留空。`GET /teams/{id}`（<&backend/app/api/routes/teams.py:463>）则只要求登录，所以上面那颗 ← 本身不会 403。

## 没权限的人看到什么（已拆成单独一条活 `2f77c41a`，本话题不碰）

**决定能不能看内容的只有一件事：你是不是「项目成员」。** 判定在 <&backend/app/api/auth.py:434>，三条路任选其一——在项目名册上 / 是项目创建者 / **是项目所属小队的成员**。所以「项目属不属于小队」只影响第三条路存不存在。

非成员看到的是**空壳 + 一条 4 秒就消失的红条**，之后页面上没有任何解释：话题列表一片空白（连空态文案都没有）、项目名不显示，但**成员头像照常显示**。看起来跟「一个刚建好、还什么都没有的项目」一模一样。前端 401 不跳登录页：<&frontend/src/api.ts:257> 的 `request()` 只在 401 时刷一次 token，刷不出新的就把 `ApiError` 抛给调用方，workspace store 的 `reportError` 把它变成那条红条。

顺带撞见的权限洞（不带任何凭据就能读）：`GET /projects/{id}`（项目名、创建者、所属小队 id）、`GET /projects/{id}/members`（**完整名册**）、`GET /projects/{id}/decisions`（决策记录全文）、`GET /projects/{id}/usage`（token 用量与花费）；`GET /projects?team_id=<id>` 带 `team_id` 时也不校验调用方是不是这个小队的人（<&backend/app/api/routes/projects.py:178>）。整片里只有 `GET /topics?project_id=` 是守着的。
