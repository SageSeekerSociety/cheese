### 第二处是我自己的回归

我把「读这一轮的提交基线」放在了轮次开头**同步等待**的位置：

```python
known_commits = await self._known_commits(project_id, topic_id)   # ← 挡在 provider 前面
```

`git_log` 里第一件事是 `ensure_repo()`——项目是冷的就要 `git init` + 建基础提交 +
**jj colocate**，几百毫秒起跳。而 `test_turn_exit_paths` 的「取消」用例只给轮次 0.5 秒
就发 cancel：这段延迟把窗口吃光，芝士还没来得及报出 session id 就被取消，会话指针
自然落不了库。本地它是绿的，CI 机器负载重才炸——典型的我在关键路径上加了活。

修法：**发起读取但不等它**，轮末再取。基线只要在 checkpoint（把这轮编辑变成提交的
那一步）之前读完就有效，所以这既正确又不花时间：

```python
known_commits = asyncio.ensure_future(self._known_commits(project_id, topic_id))
...
changeset = await self._turn_changeset(project_id, topic_id, await known_commits)
```

配了一条会红的防回归测试
（<&backend/tests/integration/test_room_sees_the_work.py>::`test_the_baseline_read_never_delays_the_turns_start`）：
让 `git_log` 阻塞到 agent 真正启动为止——旧写法下必然死锁超时，实测已验证它在旧代码上是红的。

### 2. 这一轮的改动汇总

一轮结束、**checkpoint 之后**落一条：`这一轮改了 3 个文件（+128 -7）` + 路径列表。
