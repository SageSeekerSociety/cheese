## 已落地

### 1. 脚本 <&.claude/scripts/dev-db.sh>

```bash
eval "$(bash .claude/scripts/dev-db.sh start)"   # 起 PG+Redis，导出 TEST_PG_BASE / REDIS_URL
cd backend && uv run pytest tests/ -n 4 -q
bash .claude/scripts/dev-db.sh stop --purge      # 停掉并删数据目录，不留残留
```

子命令 `start | stop [--purge] | status | env`。只有 `export ...` 走 stdout（这才让 `eval` 安全），
其余全走 stderr。数据目录 `${TMPDIR:-/tmp}/cheesex-dev-db`（可用 `CHEESEX_DEV_DB_DIR` 覆盖），
端口默认 5433 / 6379，正好对上 conftest 与 settings 的默认值。

- PG 16.2 来自 `pgserver` wheel，Redis 6.2 来自 `redislite` wheel，两个都由 `uv` 拉、之后走缓存；
  解析出的路径缓存在数据目录的 `bins.env`，重复 start 完全不碰 uv。
- `initdb -U cheesex --auth=trust`，socket 用 `-k $PGDATA` 关在数据目录里，`--purge` 才真删得干净。

### 2. 依赖：**故意不进 backend 依赖组**

`pgserver` 只发 cp39–cp312 wheel，本项目 `requires-python >=3.13`——声明进去 `uv` 直接解析失败
（*no wheels with a matching Python ABI tag*）。所以改为在脚本里钉版本
（`pgserver==0.1.4`、`redislite==6.2.912183`），跑在一个独立的 3.12 解释器上**只用来起服务**，
测试仍在项目的 3.13 上跑。

这比"只进 dev group"保证更强，两条独立证据：
- 两个包在 `backend/pyproject.toml`、`backend/uv.lock` 里**一次都没出现**（`uv.lock` 未改动）；
- 生产构建本来就是 `uv sync --frozen --no-dev`（<&backend/Dockerfile> 第 62 行、
  `deploy/deploy-blue-green.sh` 第 60 行），dev 组根本不进镜像。

## 两个自己查出来的结论

**Redis 是必需的，不是顺手。** 2FA / 登录 / 会话状态存在 Redis 里（`app/api/routes/users.py`
几十处 `AsyncRedis.from_url`）。实测：停掉 Redis 跑 `tests/integration/test_2fa.py` → 8 个全 error；
起着 Redis → 8 passed。所以脚本必须管 Redis。

**沙箱镜像缺 procps。** 没有 `ps` / `pgrep` / `kill` 二进制（bash 只有内建 `kill`），
导致 `test_machine_service.py`、`test_tmux_control.py` 共 22 个单测报
`FileNotFoundError: 'kill'`。与 DB、与本次改动都无关，是镜像缺件。

## 第二部分：已做

<&backend/tests/conftest.py>：`_pg_schema` 从 `scope="session", autouse=True` 改为
非 autouse 的 session fixture，另加一个函数级 autouse 的 `_pg_schema_gate` 按需触发它。
判定条件两条（`_needs_db`）：不在 `tests/unit/` 下 → 一律当 DB 测试（集成 harness 直接绑
`settings.database_url`，光看 fixture 名认不出来）；在 `tests/unit/` 下则看 fixture 闭包里有没有
`_pg_schema`（`request.fixturenames` 是传递闭包，所有 DB fixture 都挂到它上面）。

改动量：单文件、约 30 行。DB 测试行为不变（schema 仍是每 session 建一次）。

**实测（PG 和 Redis 全部停掉）**：`uv run pytest tests/unit -q` →
**2501 passed, 1 skipped, 22 failed, 3 errors**。改之前这条命令是 0 个测试能跑
（session 级 autouse fixture 在 setup 阶段就把整轮带崩）。
22 failed 是上面那条 procps 缺件；3 errors 是 `tests/unit/` 下两个其实需要 DB 的文件
（`test_idle_reap.py`、`test_task_ai_advice_routes.py`，用了 `client` / `python_client`）——
它们报错正确，而且现在只错自己，不再连坐其余 132 个文件。

没有加"PG 不可达就自动 skip"：那会让 CI 的 PG 抽风变成静默绿灯。
