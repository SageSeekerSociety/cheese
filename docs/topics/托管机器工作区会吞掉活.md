## 一、根因（都当场验证过，不是推测）

### `refs/heads/.invalid` 是 git 在 clone 期间的**占位符**

轮询一次真实 clone 的 `.git/HEAD`：

```
[1]    ref: refs/heads/.invalid
[2136] ref: refs/heads/topic/2d5ce09c
```

git 在 clone 一开始就把 HEAD 写成 `refs/heads/.invalid`，**最后一步**才写真正的分支名。所以**一次被打断的 clone**（容器被拆、机器重启）留下的就是这个 HEAD。

它有三个要命的性质：
- `.git` 目录存在 → `[ -d "$CHEESE_WORK/.git" ]` 为真；
- `git status` **退出码 0、显示干净**；
- `git log` 才会说 `fatal: your current branch appears to be broken`。

旧代码的判据正是 `[ ! -d "$CHEESE_WORK/.git" ]`——**它把一个半成品仓库当成好仓库，此后每一轮都直接跨过去**。这一条同时是问题二和问题三的成因。

### `2>/dev/null || true` 吞掉的不只是错误

`git clone` **拒绝 clone 进一个非空目录**。所以「工作区还在、只是 `.git` 没了」的时候，旧代码让 git 往里 clone → git 报错 → 错误被丢掉 → 分身拿到一堆文件和**一个根本不存在的仓库**，而且没有任何地方说了这件事。

### 快照移动 HEAD，把「还原」变成「钉死」

旧 `cheese-sync` 每轮末尾跑 `git add -A && git commit && git push`。commit **移动了 HEAD**。分身做「先回退文件、证明测试是红的」时，下一句 `git checkout HEAD -- <文件>` 读到的 HEAD 已经是快照——于是**撤销临时改动变成了固化临时改动**，33 行生产代码就这样进了共享分支，`git status` 干净、测试全绿（`bb39bca21` / `97948678f`）。

二分查找、A/B 对照、临时加 print，全都踩在「HEAD 不会动」这个假设上。

## 二、改成了什么

**bring-up**（`CHEESE_WORKSPACE_BRINGUP`，从 launcher 的 f-string 里拆成独立常量，测试能直接跑这段原文）：

- 健康判据换成「**git 读不读得懂 HEAD**」：`rev-parse --verify HEAD` 和 `symbolic-ref HEAD` **两个都失败**才算坏。这样**分离头指针**（分身在二分查找）和**未出生分支**都被正确放过，只有 `.invalid` 会被抓住。
- 坏了先**就地修**（把 HEAD 指回分支，对象一个不动）；修不好才把 `.git` **挪到 `.git.broken.<pid>`——从不删除**。
- 缺 `.git` 时**在隔壁 clone 再把 `.git` 搬进来**，绕开「非空目录不能 clone」，工作区里的文件一个不丢。
- 收养动作**永不移动已经存在的分支**，也**永不覆盖已经存在的文件**——两者都可能是某个东西的唯一副本。
- 每一条非正常路径都通过 `cheese-hook` 发一个 `CheeseWorkspace` 事件，`hook_events.py` 把它变成房间里看得见的消息。
- 位置挪到 cheese-hook 装好之后——**它出问题时能说话，才是这一步的全部意义**。

**快照**（`CHEESE_SYNC_SCRIPT`）：把两件事分开。

- **发布**：把分身**自己提交**的 HEAD push 到分支。分支只会前进到分身自己做的提交。
- **备份**：没提交的内容用**临时索引**（`GIT_INDEX_FILE` 指向 `.git` 里一个临时文件）+ `commit-tree` 做成一个提交**对象**，push 到 `refs/cheese/snapshots/<分支>`。
- **HEAD、分支、真索引、工作区，一个都不动。**

> ⚠️ **这是一个交付语义的改变**：分身如果全程不自己 `git commit`，它写的文件会被备份、但不进 PR。已用 `cheese ask` 问房间要不要这么定，**还没收到答复**。真要改回去，改的是同一段脚本里的两行。

**SKILL.md**：用 Edit 加了一节「另一种工作区:git 的那种」（原来整份文档只讲 jj 沙箱，而托管机器上是普通 git clone——**上一节几乎条条相反**）。核心三条：自己 commit、只有 push 出去的才算存在、**还原临时改动记 sha 别用 `HEAD`**。
