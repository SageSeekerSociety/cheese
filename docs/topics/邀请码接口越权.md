## 目标

`/api/users/invite-codes` 这三个接口在 OpenAPI 摘要里写着「(admin)」，实际只挂了 `require_auth_user`——**任何一个登录用户**都能：

- 读到平台全部邀请码的**明文**（这直接废掉了「邀请制注册」这道门）
- 无限量签发新邀请码
- 停用别人签发的邀请码

要做的是：把这三个接口真正锁成管理员专属，并留下回归测试。

## 现状：改完了，在验证

改动全在工作区（<&backend/app/api/routes/users.py> 等 6 个文件，+347/−86）。

### 定下来的几个关键点

**1. 管理员身份从配置来，不从 token 来。**
本来想直接查 `SystemRole.ADMIN`，但查代码发现这条路是死的：`get_auth_user` 给每个登录请求盖的都是 `{SystemRole.USER}`，代码库里**没有任何地方**会把人提成 ADMIN，`user` 表也没有角色列（加一列要写迁移）。所以直接判 ADMIN 等于把所有人都挡在外面。

最后走配置：新增 `settings.admin_handles`（<&backend/app/core/config.py>），一串 handle（就是 `User.username`），新依赖 `require_admin_user`（<&backend/app/auth/checker.py>）做 handle→id 的匹配。

**2. 空名单 = 没有管理员，不是「所有人都是管理员」。**
名单没配时，这三个接口对所有人 403。反过来的写法（空名单放行）会让洞看起来补了、其实还开着。

**3. 顺手修了一个「一直没人发现接口是坏的」的问题。**
原来这三个路由写在 `GET /{userId}` **后面**。FastAPI 按声明顺序匹配，`/invite-codes` 是单段路径，声明在 `/{userId}` 之后就永远匹配不上——列表接口实际对谁都返回 400「userId must be an integer」。现在整块挪到了 `/{userId}` 上面（跟 `/me`、`/registration-config` 一样）。

**4. 环境变量能写 `ADMIN_HANDLES=alice,bob`。**
pydantic-settings 对裸 `list[str]` 会按 JSON 解，逗号形式会让后端**起不来**。所以这个字段带了 `NoDecode` + 自己的分隔逻辑，逗号和 JSON 两种写法都收。

### 测试

- <&backend/tests/unit/test_admin_handles_config.py>：逗号 / 带空格 / JSON / 未设置四种写法。
- <&backend/tests/integration/test_invite_codes_admin.py>：每个接口三种身份（匿名 401 / 普通登录用户 **403**（这条就是本次回归）/ 名单内管理员 2xx），外加空名单全拒、handle 必须全等不能是子串前缀。
