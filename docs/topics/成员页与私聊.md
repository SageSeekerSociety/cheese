# 成员页与私聊

## 目标
@符露夀 提的：在侧栏话题之上加一个「成员」入口，点进去能管理项目成员（升职 / 降职 / 踢出 / 邀请），并且把私聊收进这里。这一轮直接做成**能看的效果**：真代码 + 真截图。

预览在右侧（<&docs/topics/成员页与私聊-预览.html>），七张图：成员页 / 改角色菜单 / 邀请 / 移出确认 / 点私聊 / 侧栏私聊的 + / 深色主题。

## 现状（已核实）
- 后端那几条接口早就齐全且已鉴权：`GET/POST /projects/{id}/members`、`PUT/DELETE .../{handle}`，服务层只让 owner 或 lead 写（<&backend/app/domain/membership/services.py>），并且**不认**请求体里自称的 handle。角色只有三种：`lead` 组长 / `member` 成员 / `mentor` 导师。
- 前端此前**没有任何界面调得到它们**：`listProjectMembers` 只被「改验收人」菜单和分支保护读，名册只作为别的功能的下拉框存在。
- 私聊已经有了：`/projects/:id/dm/:peer`（<&frontend/src/views/workspace/DmView.vue>），侧栏底部常驻「有事的人」。
- 单人主页也有：`/projects/:id/members/:handle`（<&frontend/src/views/MemberView.vue>），但没有入口列出全部成员。

## 这一版做了什么
- 新页面 <&frontend/src/views/workspace/ProjectMembersView.vue>，地址 `/projects/:id/members`。侧栏「AI 队友」下面多一行「成员」。
- 一行 = 一个人 = 两件事：**找到他**（点行进主页，点对话图标进私聊）和**管理他**（⋯ 里升职 / 降职 / 移出）。
- 人按角色分三段；AI 队友单独一段（它没有可升降的角色，右边是「设置」，通到 AI 队友页）。
- 名册读的是 `store.members` 那一份——在这里改完角色，侧栏和 @ 补全同一刻跟着变。

## 定下来的几条（可以推翻，说一声就改）
1. **管理动作只对项目所有者和组长出现。** 后端本来就只让这两种人写，给别人一个按钮等于给一个必定失败的按钮。
2. **所有者那一行和自己那一行不带管理动作。** 把所有者降职会让项目没人管得了；自己要不要走由本人决定——那条路是右上角的「退出项目」加一次确认（第五轮），不在 ⋯ 菜单里点一下就出去。
3. **邀请填 handle，不是搜人。** 后端就是按 handle 加的；做「搜全站用户」得另开一条接口。
4. **侧栏私聊那一栏的 + 改成通到成员页**（原来是一个自己的小名册下拉：没搜索、没角色、没头像）。名册只该有一份。底部常驻的仍然只有「有事的人」。

## 顺手修的一个平台 bug：预览是白板
@符露夀 打开预览看到的是一块白板。原因不在这一版界面，在预览面板本身：

- 后端的**文本**读取有 1MB 上限（<&backend/app/domain/workspace/textfile.py> 的 `MAX_TEXT_BYTES`）。这条上限的本意是保护**文件面板里那个能编辑能保存的编辑器**——注释写着来由：以前不限大小，一个 52MB 的可执行文件转成 JSON body 变成 127MB，浏览器当场卡死。
- 但**预览面板借了同一个读法**。预览不是编辑器：不需要保存、不需要版本号，而一个把图片内嵌进去的 HTML 天生就是几 MB。
- 更要命的是第二层：超限时后端返回 `content: null`，而面板把它当空字符串塞进 iframe（`:srcdoc="previewFile.content ?? ''"`），**不报错、不提示**——渲染出来和「芝士还没指定预览」一模一样。没人能把这个报成 bug，因为它没有任何一处说自己坏了。

预览 iframe 从独立内容域名读取原始文件字节，不受编辑器的 1 MiB 文本上限限制。文本读取仍用于文件错误提示与类型检查；全屏保留同一页面，新窗口先在主站取得授权。

## 第二轮：@符露夀 提的三条改法（查完了，等拍板）

**① 侧栏左下角私聊整块删掉 —— 建议不删。** 那一栏有两个身份：名册（+ 号下拉）和未读。名册那一半这一版已经拆了；剩下的是**私聊唯一会在界面上亮的地方**，而且固定在底部不随话题滚（就是为了未读不被话题挤出屏幕）。整块删了之后「有人找你」在主界面没有任何提示。折中：没有未读时整栏隐藏（现在芝士那行是常驻的）。

**② 私聊加返回键回成员页 —— 同意，但桌面和手机不同。** 桌面上私聊在内容区、侧栏常驻，返回键多余；手机上私聊是页面栈的一层，现在的 ← 回话题列表。做成**从哪来回哪去**：从成员页进来回成员页，从未读进来回原处。

**③ 私聊包含所有 AI 队友 + 默认不起云机器 —— 方向对，但都不是开关。**
- 今天**没有「跟某个 AI 队友私聊」这回事**：后端只有一间「本人 ↔ 芝士」（`peer_handle` 为空），不记是哪个队友（<&backend/app/domain/topic/services.py> 的 `get_or_create_private`）；侧栏的私聊列表还专门把 `agent` 过滤掉了。要做得先给私聊记上队友。
Private chats use a central Claude Code session and a separate container for temporary shell and file work. Published content remains in platform storage. See [execution placement](../where-a-turn-runs.md) for configuration and lifecycle.

## 第四轮：@符露夀 又提的四条（都做完了）

**① 邀请改成按 uid，两个框拉开间距。** uid 是个人主页地址里那个数字，抄得准；handle 得对方告诉你，打错一个字母的后果是「查无此人」还是「加错了人」全看运气。

**② 查 uid 存不存在。** 边打边查（防抖 350ms，只认最后一次请求的结果），查到了把**这个人是谁**摆出来给人确认（头像 + 昵称 + @handle）。查不到、或者已经在项目里，当场说，按钮按不下去。

**③ 邀请变成待办，对方接受才算加入。**
- 新表 `project_invitations` + 迁移 `c1f4a9b73d20`（HEAD 哨兵已挪，单头检查通过）
- 邀请方在成员页看到「等待接受」，可撤回；答复过的行**留着不删**——它是「谁在什么时候把谁拉进来的」唯一记录
- 被邀请的人在 **首页 → 小队 → 待定** 那一页看到（@符露夀 指定的位置；我一开始放在左侧栏上，已撤干净，App.vue 和导航文件现在零改动）
- 通知用 `decision_request`：这种在**被答复之前**不会从收件箱消失，答复/撤回时我把它结掉
- 13 条后端用例

**④ 建项目时把小队成员拉进来。**
- 只拉**队里的其他人**。第一版我把所有者也写进成员表，**炸了 18 条用例**——这个仓里「谁是所有者」记在 `Project.owner_handle` 上，成员表存的是其他人，别处「把所有者加进名册」的调用会撞唯一约束。
- 所有者「在自己的成员页上看不见自己」这个真问题，改成**名册接口读的时候**补那一行（他本来就在项目上，不需要一行数据来证明）。一开始只补在成员页那一个界面上，漏掉了同样读名册的聊天面板和 @ 解析——所有者在自己项目里于是显示成一串 handle、@ 他也通知不到；补在读的那一处，这些一起好了。
- 跨域调用按仓库规矩走 service 不走 repository（`test_domain_import_guard` 抓到过一次）。

## 第五轮：成员自助退出项目（@蔡松洋 拍板了两条）

从前只有 owner / lead 能把人移出项目，成员自己想走只能去求人。现在多了一条本人可用的路：
`DELETE /projects/{id}/membership`（<&backend/app/api/routes/members.py>）。身份只从 token
解析，**没有代退的入口**；路径用 `/membership` 而不是 `/members/me`——`/members/{handle}`
那条路由先注册，`me` 到了那里就是一个人的名字。

- 「退出」是项目级的退场，所以**席位跟着一起走**：删成员行的同时也撤掉他在本项目各话题里的
  席位（`TopicMemberService.revoke_project_seats`）。被 owner / lead 移出项目走的是同一份
  撤销——从前只删名册那一行，人从名册上消失了却还是每个房间都进得来，同一处顺带修掉。
- 三种退不了，各自说得出下一步：所有者（先把项目转让给别人）、访问来自所属小队的人（在小队里
  退）、某个话题唯一的 owner（先把那间房交出去，报错点名是哪一间）。
- **「名册上没有成员行」不等于「不是成员」**：所有者从来不落成员行，项目转让之后他手上只剩
  话题席位，而他确实还进得来那些房间。用「不是成员」答复他既不是事实、又把他那份残留留在库
  里——他走得掉，席位跟着一起清。
- 界面在成员页右上角，带一次确认；所有者看不到这颗按钮（后端也会拒他，界面上先不给一个必定
  失败的动作）。
