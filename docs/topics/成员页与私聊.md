# 成员页与私聊

## 目标
@符露夀 提的：在侧栏话题之上加一个「成员」入口，点进去能管理项目成员（升职 / 降职 / 踢出 / 邀请），并且把私聊收进这里。这一轮直接做成**能看的效果**：真代码 + 真截图。

预览在右侧（<&docs/topics/成员页与私聊-预览.html>），七张图：成员页 / 改角色菜单 / 邀请 / 移出确认 / 点私聊 / 侧栏私聊的 + / 深色主题。

## 现状（已核实）
- 后端四条接口早就齐全且已鉴权：`GET/POST /projects/{id}/members`、`PUT/DELETE .../{handle}`，服务层只让 owner 或 lead 写（<&backend/app/domain/membership/services.py>），并且**不认**请求体里自称的 handle。角色只有三种：`lead` 组长 / `member` 成员 / `mentor` 导师。
- 前端此前**没有任何界面调得到它们**：`listProjectMembers` 只被「改验收人」菜单和分支保护读，名册只作为别的功能的下拉框存在。
- 私聊已经有了：`/projects/:id/dm/:peer`（<&frontend/src/views/workspace/DmView.vue>），侧栏底部常驻「有事的人」。
- 单人主页也有：`/projects/:id/members/:handle`（<&frontend/src/views/MemberView.vue>），但没有入口列出全部成员。

## 这一版做了什么
- 新页面 <&frontend/src/views/workspace/ProjectMembersView.vue>，地址 `/projects/:id/members`。侧栏「AI 队友」下面多一行「成员」。
- 一行 = 一个人 = 两件事：**找到他**（点行进主页，点对话图标进私聊）和**管理他**（⋯ 里升职 / 降职 / 移出）。
- 人按角色分三段；AI 队友单独一段（它没有可升降的角色，右边是「设置」，通到 AI 队友页）。
- 名册读的是 `store.members` 那一份——在这里改完角色，侧栏和 @ 补全同一刻跟着变。

## 定下来的几条（可以推翻，说一声就改）
1. **管理动作只对项目所有者和组长出现。** 后端本来就只让这两种人写，给别人一个按钮等于给一个必定失败的按钮。
2. **所有者那一行和自己那一行不带管理动作。** 把所有者降职会让项目没人管得了；把自己踢出去点一下就回不来。
3. **邀请填 handle，不是搜人。** 后端就是按 handle 加的；做「搜全站用户」得另开一条接口。
4. **侧栏私聊那一栏的 + 改成通到成员页**（原来是一个自己的小名册下拉：没搜索、没角色、没头像）。名册只该有一份。底部常驻的仍然只有「有事的人」。

## 顺手修的一个平台 bug：预览是白板
@符露夀 打开预览看到的是一块白板。原因不在这一版界面，在预览面板本身：

- 后端的**文本**读取有 1MB 上限（<&backend/app/domain/workspace/textfile.py> 的 `MAX_TEXT_BYTES`）。这条上限的本意是保护**文件面板里那个能编辑能保存的编辑器**——注释写着来由：以前不限大小，一个 52MB 的可执行文件转成 JSON body 变成 127MB，浏览器当场卡死。
- 但**预览面板借了同一个读法**。预览不是编辑器：不需要保存、不需要版本号，而一个把图片内嵌进去的 HTML 天生就是几 MB。
- 更要命的是第二层：超限时后端返回 `content: null`，而面板把它当空字符串塞进 iframe（`:srcdoc="previewFile.content ?? ''"`），**不报错、不提示**——渲染出来和「芝士还没指定预览」一模一样。没人能把这个报成 bug，因为它没有任何一处说自己坏了。

已修（提交 a98d0b3）：把 null 的两种含义分开说（太大 / 不是文本）、印出实际大小、把「在新窗口打开」留着——原始字节那条路（`preview/raw` → `read_file_bytes`）**没有上限**，是内容读不回来时唯一还能看到东西的路。新增 2 条用例，在旧代码上是红的。

**还没做的那一步（要你拍板）**：真正的修法是预览面板**根本不该走文本读取**——把 iframe 从 `srcdoc` 换成 `src=".../preview/raw"`，走字节、没有上限、CSP 已经是 sandbox。那是一次更大的改动（缓存失效、错误态、全屏都要跟着走），不在这条线的范围里，所以先只把「不吭声」补上。

## 第二轮：@符露夀 提的三条改法（查完了，等拍板）

**① 侧栏左下角私聊整块删掉 —— 建议不删。** 那一栏有两个身份：名册（+ 号下拉）和未读。名册那一半这一版已经拆了；剩下的是**私聊唯一会在界面上亮的地方**，而且固定在底部不随话题滚（就是为了未读不被话题挤出屏幕）。整块删了之后「有人找你」在主界面没有任何提示。折中：没有未读时整栏隐藏（现在芝士那行是常驻的）。

**② 私聊加返回键回成员页 —— 同意，但桌面和手机不同。** 桌面上私聊在内容区、侧栏常驻，返回键多余；手机上私聊是页面栈的一层，现在的 ← 回话题列表。做成**从哪来回哪去**：从成员页进来回成员页，从未读进来回原处。

**③ 私聊包含所有 AI 队友 + 默认不起云机器 —— 方向对，但都不是开关。**
- 今天**没有「跟某个 AI 队友私聊」这回事**：后端只有一间「本人 ↔ 芝士」（`peer_handle` 为空），不记是哪个队友（<&backend/app/domain/topic/services.py> 的 `get_or_create_private`）；侧栏的私聊列表还专门把 `agent` 过滤掉了。要做得先给私聊记上队友。
- **打开私聊不起机器，说一句话才起**，但一起就是完整一轮：私聊是一个话题，机器按话题分配（<&docs/where-a-turn-runs.md>，`chat.py` 的 `_resolve_compute_id` 不因 `is_private` 短路）。所以每个人的芝士私聊各占一台/一个容器。
- 「不起机器」做不成开关：芝士就是机器上的一个 Claude Code 进程。要么给私聊单独一条轻执行路（纯模型对话、**没有任何工具**），要么让同一个人的所有私聊共用一台而不是一间一台。

已发选项卡问 @符露夀：私聊里的芝士要不要保留干活能力。
