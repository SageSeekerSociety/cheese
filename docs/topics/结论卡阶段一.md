## 目标（一句话）

`conclude` 之后，父话题手上多出一张**有状态、可结算**的结论卡；不结算它也会**默认采信**（父话题那一轮结束时自动 accepted，另加 30 分钟绝对超时），子话题随之归档，不再停在 active。**现有三个副作用（往父话题插消息 / 织进父活文档 / 发 change_alert）一字不改**——本阶段是纯加法。

范围之外，明确不做：结构化栏位（`--card ./conclusion.json`，阶段二）、把父活文档的全文追加改成引用（阶段三）。

## 设计要点（已定，实现按这个来）

- **独立建表 `conclusion_cards`**，收方是新字段 `receiver_topic_id`（父话题）。**不复用 `AcceptCard`**。
- **状态机**：`open` → `accepted` / `returned`（补证据，唯一能回到 open 的分支）/ `escalated` / `superseded`。同一子话题任何时刻最多一张 open 卡。
- **默认采信的四条机制**：
  1. 父话题一轮结束时，**该轮开始前就已存在**的 open 卡自动 accepted（用「轮开始时间」卡一刀，避免把本轮跑到一半才产生、根本没被这一轮看见的卡也吞掉）；另加 30 分钟绝对超时兜底。
  2. 打回必须锚定卡面 uncertainties 里某条 blocking 项 —— 阶段一没有结构化栏位，校验代码写好但对「无结构化栏位的卡」放行，代码里注明这是阶段二才生效。
  3. 每张卡最多打回 1 次（硬上限 2）。
  4. 采信零成本（不唤醒任何人）；打回要付一整轮（唤醒子话题）。
- **打回叫「补证据 need-evidence」**，不叫驳回/rejected。
- **归档语义**：采信即归档子话题；归档前先结算下级未结算的结论卡（否则级联会把孙子连人带卡冻住）；写入顺序先父后子（归档后活文档定格，`edit_doc` 会 400）。
- **路由挂在父话题下**：`POST /api/topics/{parent_id}/conclusion-cards/{card_id}/{accept|need-evidence|escalate}`（per-turn token 按 URL 里的 topic 校验作用域）。三条写路由**必须**进 <&backend/app/main.py> 的 `_CHEESE_WRITE_PATHS`；授权类路由绝不进白名单。
