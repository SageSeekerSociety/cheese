# 卡面要分清等待和回退

## 目标

验收卡上有两句话在说谎，都改掉：

1. **等待 vs 回退分不开**。平台等一项 required 检查时，「这项检查该出现而还没出现」和「平台没能判断这次改动碰了哪些文件、于是保守地仍然要求它」在卡面上一个字都不差。人只能靠后端日志区分，而那份日志的保留期只有「距上次部署多久」。
2. **人工放行的留痕自相矛盾**。卡上写「明知检查未全绿仍合并」，括号里却同时写着「全部 5 项检查通过」——2026-08-17 的 PR #520 真的留下了这么一条历史。

范围只在 `<&backend/app/domain/review/services.py>`。**不碰** `/pr-checks` 路由和 `github_pr.py` 的 `_as_pr_error`（父话题 PR #522 正在采纳）、**不碰** `_parse_required_checks` / `_diff_touches`（已验证判定逻辑正确）、**不碰** copilot 那条（@fulu 单开卡修）。

## 改法

**回退要自陈是回退。** `_required_and_absent` 原来返回一个名字列表，两条保守回退（认不出 base 分支 / GitHub 没给文件清单）的「为什么」只落在 `logger.warning` 里。现在它返回 `_AbsentRequired(names, fallback)`：`fallback is None` = 真的算过范围，非空 = 没算出来，那句就是原因（异常摘要 / 「GitHub 没给出文件清单」）。卡面文案由两个纯函数决定：

- `_absent_required_tail()` —— 等待提示。真等待的措辞**一字未改**（`required 检查还没出现：test`）；回退变成 `平台没能判断这次改动碰了哪些文件（<原因>），保守起见仍然要求：test`。
- `_absent_required_timeout()` —— 等过头交给人（✋）时的理由。回退状态下不再照搬「多半是 workflow 没被触发、被改名或被禁用」——平台连这次改动碰没碰后端都不知道，那是个它没验证过的判断。

两条新文案都走原来的 `_note_waiting_on_checks`，所以优先级规则（不盖 ⚠️/🚫/✋/❌/🌿/🚪）和 5 分钟分档防抖原样生效，各有测试钉住。

**人工放行按当时读到的状态措辞。** `_force_merge_verdict(state)`：`failure` → 「明知检查未全绿仍合并」（原文保留），`success` → 「当时检查其实已经全绿」，`pending` → 「没等检查跑完」，`no_checks` → 「当时没有任何 CI 跑过这次改动」，读不到 → 「当时读不到检查状态」。原始状态串照旧留痕在括号里。
