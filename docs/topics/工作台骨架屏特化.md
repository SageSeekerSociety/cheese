## 目标

符露夀提出「工作台上面的 skeleton 是不是没有特化？感觉和实际加载出来的东西差距有点大」。把工作台每一处骨架屏跟它替代的真内容逐处对齐，让内容到达那一刻区域不再挪位置。

## 结论：不是没做特化，是一种形态被三处共用

`<&frontend/src/components/common/LoadingSkeleton.vue>` 里本来就按我们自己的行写了 5 种形态，侧栏、聊天、名册三处是对着真行量过的。问题出在 `entry` 这一种：它当初照着「支线进度」那种 55px 的行量的，后来看板和「现场」也拿去用了，而那两处的真内容根本不是这个形状。

骨架只存在一瞬间、不会报错，所以共用形态赌输了没人会发现。**判据已写进组件顶部：一种形态只对一样东西负责，宁可多一个 variant，也不要共用。**

## 实测到的差距（改之前）

尺寸不是读 CSS 推的，是把应用在沙箱里真跑起来、用无头浏览器量的。

| 位置 | 骨架 | 真内容 | 后果 |
|---|---|---|---|
| 看板的卡 | 54px，两条灰线，无边框 | 101px 的带框块，间距 109 | 两条骨架换来一张卡，整列重排 |
| 现场的一条动作 | 54px | 带参数的一条 38.6px，间距 52.6 | 骨架比真内容高一半，还多缩进 8px |

| 文档 | 没有骨架 | — | 见下 |

## 顺带修的一处「说假话」

「文档」那一格原来没有骨架，正文区空着。而空编辑器会亮出占位句「芝士会在这里维护文档，你也可以直接编辑」——**那句话的意思是「这篇文档是空的」**，于是每一篇有内容的文档，在到达之前都被界面说成空的。现在加载期间摆骨架、编辑器让位（`v-show`，不卸载，否则每换一个话题都要重建编辑器）。

## 改法与验证结果

拆成 `card` / `site` / `brief` / `doc` 四种新形态，`entry` 留给支线进度并补上分组小标。每一处的尺寸都写着它抄自哪一条真规则。

看板那处现在**逐像素重合**：骨架第一张卡 y=165 高 101、第二张 y=274；真卡 y=165 高 101、y=274。

沙箱里真跑过的检查：vitest 147 文件 1177 条全过（含新增 2 条）、vue-tsc 0 error（基线 0）、eslint 0 error、stylelint 63 未超基线 63、`<&.claude/scripts/check-repo-rules.sh>` PASS。深色主题另外截图确认过。后端一行未动。

`<&frontend/src/components/panels/PanelDoc.skeleton.spec.ts>` 是新加的回归测试，把修复撤掉跑过一次确认会红。
