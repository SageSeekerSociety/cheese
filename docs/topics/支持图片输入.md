# Chat attachments

The chat composer accepts files, including PDF, Word, spreadsheets, archives, and
images. Users can select or drop files, or paste screenshots. Each file is limited
to 10 MiB, with up to nine attachments per message.

Uploads retain their basename under a unique directory in the topic worktree.
Each attachment becomes a block whose content is the relative path and whose MIME
type describes the file. Documents appear as download buttons in chat. The file
panel also offers a download action for the selected file.

`POST /api/topics/{id}/attachments` requires a verified caller.
`GET /api/topics/{id}/attachments/raw?path=...&download=true` also requires a
verified caller and returns an attachment disposition. Inline reads accept only
PNG, JPEG, GIF, and WebP extensions. Downloads include the original basename and
headers that prevent executable content from running in the app origin.

The existing device transfer stages document bytes before prompt delivery.
Document prompts name the file and ask the agent to use an appropriate reader;
failed transfers are reported as missing attachments.
