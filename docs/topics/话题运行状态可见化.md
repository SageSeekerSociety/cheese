## 采纳时的合并冲突（已解决）

采纳合并时和另一个并行子话题「话题列表排序」撞了——它给 `list_topics`/`TopicService.list_for_project` 加了 `sort`/`order` 参数。冲突只在 `backend/app/api/routes/topics.py`：`list_topics` 的签名和 import 各改了一半。语义化合并成一份：`sort`/`order` 和 `runner`（算 `running`）两组参数都保留，`_topic_out()` 建在排序后的结果上。改完 `ruff`/`pyright` 全绿，`app.main:app` 能正常 import+建路由（60 条），排序功能自己的集成测试（`test_topic_sort.py`）只断言 `titles`/`parent_id`，不会因为响应里多一个 `running` 字段而破。

## 目标（已按 maxiaoyu 确认的方向实现）

芝士这一轮对话说没说完，前端看不出来——话题列表/侧边栏没法区分"活跃但空闲"和"活跃且正在跑一轮"，人不知道什么时候该派下一个任务。

方向已确认：**不新增 `Topic.status` 枚举值，不碰人工采纳/归档逻辑**，把已有的、只在内存里的 turn 运行状态（`TurnRunner`）批量送到话题列表接口，前端在话题行的图标上加一个轻量呼吸点。
