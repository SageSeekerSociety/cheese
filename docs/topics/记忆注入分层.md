# 记忆注入分层：core 每轮常驻，其余按当轮上下文检索

收编 issue #187。前置于「把每话题的记忆池归并到 agent 名下」——不先改注入方式，
池子一合并大半就进不来。

## 为什么

记忆池的粒度今天是话题，归并到 agent 之后是一个池。本项目实测（2026-08-17）
**180 条 / 50056 字符**，而注入预算是 20000 字符——合并当天大半进不来。
更要命的不是"进不来"，是**按什么标准进不来**：原来的规则是 `created_at DESC` 取前 50，
于是座位归了"最后写的那批"，跟这一轮在干什么毫无关系。

## 现在是什么样

记忆条目有了 `layer` 字段（`app/domain/memory/models.py` 的 `MemoryLayer`）：

- **`core`** —— 这个 agent 是谁、它的长期规则和目标。**每轮全量注入，不参与相关性筛选。**
  预算 4000 字符，独立且比另一层小一个数量级——"永远在场"只有在它足够小的时候才付得起。
- **`fact`**（默认）—— 其余学到的东西。**按当轮上下文排序后填 20000 字符预算**，
  没进来的照旧明说，一条 `cheese recall` 就能取回。

**当轮上下文**是：本轮还没读过的人类消息（最新的在前）＋ 话题标题 ＋ 实况文档，
截到 2000 字符。打分器复用 `keywords.py` 现成的关键词覆盖度（无新增依赖、无模型调用），
只是把词条上限从 24 放宽到 96——一轮的上下文不是一个问句，24 个关键词只留得下最长的几个中文短语。

**无信号的一轮**（用户只打了「继续」）退化成时间倒序填预算——和改之前一模一样，不会更差。

## 实测（本项目真实记忆池，46 个池合并成一个）

| | 老规则（时间倒序前 50） | 现在 |
|---|---|---|
| 注入 | 50 条 / 14655 字符 | core 3 条恒在 ＋ 65–71 条 / ≈19900 字符 |
| 没进来的 | 130 条（72%），是**最旧的** | 109–115 条（≈61%），是**与本轮最不相关的** |
| 与本轮最相关的 10 条命中 | **0–2 / 10** | **10 / 10** |

四个真实 query（本话题的任务简报、「沙箱里怎么跑测试」、「递验收卡要确认什么」、
以及无信号的「继续」）都跑过，core 四次都是 3/3 在场。

**缺席比例没有降到 0，也降不到**：50056 字符的池子配 20000 字符的预算，
装不下一半以上是预算的定义决定的。真正变了的是**没进来的是哪些**——
以及"缺席比例"在检索之后已经不是该看的指标了，该看的是"本轮要用的在不在场"。

## 写入侧

`cheese remember "<事实>"` 默认写 `fact`；`cheese remember --core "<事实>"` 写 `core`。
API 是 `POST /projects/{id}/memory` 的 `layer` 字段，非法值直接 422——
静默降级会把写的人以为常驻的东西丢进按需检索的那一层。
记忆页（`GET /memory`）每条都带 `layer`，因为每轮花座位的正是这批，最该被人修剪。

## 两个后端

- **db（线上默认）**：`layer` 是一列，`recall_core` 是一次带层过滤的查询，
  `rank_facts` 取该池非 core 的行在 Python 里打分（池子是百条量级）。
- **openviking**：core 单独占一个 scope space（uid 加 `-core` 后缀）。
  不在卡片里写标记，是因为放置和措辞由它的 extractor 决定、写进去的标记事后信不过；
  "在哪个 space"是我们说了算的。`rank_facts` 走它的语义检索——这是两个后端唯一
  真正不同性质的地方。

## 明确没做

存量记忆池的归并/迁移、dreaming、自动摘要、向量检索、`(project, handle)` 这个池 key
和 handle 派生、前端。
