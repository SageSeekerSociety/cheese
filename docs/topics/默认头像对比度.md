## 目标

默认头像（没上传头像时显示的彩色首字母）的底色是按 handle 哈希算出来的，白字压在上面，**大部分色相根本读不清**。把底色算法改成"白字在任何色相下都达到 WCAG AA (4.5:1)"，同时保持每个人原来的色系不变。

只动两个文件：`frontend/src/utils/avatar.ts` + 新建的 `frontend/src/utils/avatar.spec.ts`。6 个调用点一行都不用改。

## 问题是什么（改之前的实测）

老公式是 `hsl(色相, 55%, 55%)`，色相来自 handle 哈希、遍布 0–359 全域。HSL 的"亮度"不是感知亮度——同样写 55%，黄色的实际光度比蓝色高得多，于是白字的对比度随色相剧烈摇摆：

- 最差 **1.72:1**（色相 60，黄），最好 **6.47:1**（色相 240，蓝）
- 360 个色相里 **297 个（83%）达不到 AA 的 4.5:1**，其中 **175 个（49%）连 3:1 都不到**
- 不达标的集中在色相 27–201 一整段（橙→黄→绿→青）
- 空种子的回退灰 `hsl(0,0%,62%)` 是 **2.68:1**

**这不是深色模式的问题**——`hsl()` 在两套主题下是同一个值，浅色下一样糟。

## 怎么改的

保留色相哈希（`hueFromString` 一个字没动），把**感知亮度**钉死，而不是钉 HSL 的亮度：用 OKLCH 的 L 轴（这条轴是感知均匀的），取 `L = 0.54 / C = 0.12`。

不直接输出 `oklch()` 字符串、而是在 JS 里算成 `#rrggbb`，原因有两条：

1. C=0.12 时约三分之一的色相落在 sRGB 色域外，浏览器怎么把它映射回来是各家自己的事，**测不了也钉不住**。自己做色度回退，测试校验的字节就等于浏览器画出来的字节。
2. 顺带把兼容性问题清零——十六进制颜色哪儿都能用。（仓库 `.browserslistrc` 是 `>1% / last 2 versions / not dead`，且 `color-mix()` 已经在 ChatPanel/DocPanel 用了 30 处，oklch 本来也在基线内；但既然算出来更可测，就没必要赌。）

改完的实测结果：

| | 老 | 新 |
|---|---|---|
| 360 色相对比度范围 | 1.72 – 6.47 : 1 | **4.75 – 5.43 : 1** |
| 达不到 AA 的色相数 | 297 / 360 | **0 / 360** |
| 空种子回退色 | 2.68 : 1 | **5.03 : 1** |

对比度跨色相只有 1.14 倍的浮动（老的是 3.8 倍），也就是"谁的头像都不会比谁明显亮一截"。
