## 目标

把 checklist 从"每轮的 working log"变成**跨轮、跨机器可读的话题状态**。

父话题 #187 的诊断：记忆 / 进度 / 上下文三层里，缺的是**进度层**——"这个任务做到哪了"只活在对话记录里，随机器一起死。这就是"换了机器不知道自己做到哪"最直接的原因，也是六项问题里**唯一不依赖任何未决项**的缺口（第 2 项虽也不阻塞，但必须和切 memory backend 同时上，而后者卡在智谱 key 上）。

## 约束

- **进度层 ≠ 记忆层。** 记忆是要注入 prompt 的稳定事实，越长越互相挤；把"做到哪了"塞进去，记忆会退化成流水账，真正重要的几条被挤出去。所以进度是独立一张表，不是一条记忆。
- **必须在轮次死掉时也留得下。** 这一层存在的全部理由就是"turn 没跑完"，攒到 turn 末尾再写等于专门漏掉要救的那一种情况。
- **#186 在前，#187 在后**（换不了身体时记不记得无所谓）——但第 1 项不依赖 #186，可以独立上。

### 两个容易做错的地方，已经处理

- **不能拿旧清单去 seed 这一轮的 live 列表。** `_apply_task_event` 按位置编号，而 agent 新 session 的 Task 编号从 1 重开——seed 了的话，这一轮第一次 `TaskUpdate("1")` 会打到上一轮残留的那一条上。所以 live 列表照旧从空开始，旧清单只走 prompt 和那一帧 restored。
- **存的那行会被下一轮第一次 `TaskCreate` 覆盖。** 所以 prompt 里明写"重新建清单时把已完成的也列进去并标成 completed，只列剩下的等于把做过的抹掉"，并有测试盯着这句话还在。

### 后端全量测试的跑法（08-12 踩坑记录）

上一轮 `pytest tests/ -n 4` 退出码 137，是 OOM 不是测试失败。根因有数：**沙箱 cgroup 上限 2 GiB**（`/sys/fs/cgroup/memory.max` = 2147483648），起了 PG+Redis 之后基线已占 ~1.35 GiB，只剩 800 MB —— 4 个 xdist worker 各带一套连接池，必被 kill。

现在的跑法：`dev-db.sh stop --purge` 清干净 → 分段（unit / integration / contract）→ 并发降到 `-n 2`。`-n 2` 实测不 OOM，integration 1171 个跑完 9 分 28 秒。

**同一个 2 GiB 也管着前端**：`vue-tsc` 报 "failed without reporting any diagnostic" + exit 2 就是被 OOM 杀了（`memory.events` 的 `oom_kill` 会涨，08-11 那个 1.1 GiB 的 `frontend/core.7491` 就是它崩出来的，已删）。**别加 `--max-old-space-size=3072`**——那比 cgroup 上限还大，等于放任 V8 涨到必死；要给个装得下的堆，并且别和后端测试同时跑。

已跑完的段：**`tests/unit` 2698 passed**，失败 22 个全部落在已知的无-procps 名单里。另有 3 个 ERROR 一度可疑（`test_idle_reap.py`、`test_task_ai_advice_routes.py`），查明只是「PG 没起」——它们是要 DB 的 unit 测试，起库后 4 个全过。
