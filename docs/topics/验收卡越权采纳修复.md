## 问题

反馈：验收卡（acceptance card）指定了验收人，但 accept 端点从不校验"当前操作人 == 卡片上指定的验收人"，且该端点疑似无鉴权、操作人由请求体自报。若属实，任何能访问 API 的一方都能采纳任何一张卡——安全漏洞。

## 目标

1. 定位 accept 端点的路由 / service / repository 实现，核实反馈是否属实。
2. 若属实：
   - 路由加 `Depends(require_auth_user)`（或等价鉴权依赖）。
   - service 层校验认证用户 handle == 卡片记录的验收人 handle，不匹配用 `app.core.errors` 里的错误类型拒绝（不用裸 `HTTPException`）。
3. 补充测试：非指定验收人被拒 / 指定验收人成功 / 未认证被拒。
4. `task check` 全绿。

## 约束

- 遵循项目分层约定（route 无业务逻辑，校验放 service）。
- 错误处理走 `app.core.errors`，不要裸 `HTTPException`。
- 测试用真实行为测试，不检查源码实现细节。
