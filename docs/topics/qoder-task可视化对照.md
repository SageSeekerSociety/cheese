本话题产出：**对照我们刚落地的现状，逐条判断哪些值得抄、哪些不该抄、哪一条要人拍板**。
还没动代码，目前是一份判断。

# 二、我们现在有什么（`dc86a0237` / #614，2026-08-24 已进 main）

- **侧栏树**：房间 → 它派出去的活；每行有「任务」标、PR 号 `#614`、卡状态（待验收／等 CI／已采纳／被打回）、已完成。
- **工作面板「任务」tab**（<&frontend/src/components/panels/PanelTasks.vue>）：一条活一行 —— 标题 + 状态标 + `owner_handle` + 最后活动相对时间。

# 三、判断

## 值得抄，而且很便宜（3 条）

1. **行里写「它最近干了什么」，而不是状态词 + 相对时间。**
   这是两边差距最大的一处。我们那行第二排是 `cheese-1cf0 · 3小时前`，回答不了「要不要现在点进去」；
   Qoder 那行是 `选定路线 A：…，生成 8 张门卡图`，一眼就知道。
   **而且我们的数据早就取到手了** —— PanelTasks 已经在拉每条支线最新那一块（`listRoomTasks(roomId, {limit:1})`），
   却只用了它的 `created_at` 做时间戳，正文丢掉了。把那句话显示出来几乎是零成本。

2. **常驻一条折叠细条，而不是藏在一个 tab 里。**
   派活发生在对话里，回执也该在对话视野内。Qoder 把进度卡放对话区顶部、能收成图2 那一行，
   我们放在右侧工作面板一个 tab 里，不点开就完全看不见。
   建议：房间时间线顶部常驻一条 `N 件在跑 / 共 M 件`，点开展成现在的任务 tab。

3. **把「要审多少」提前说出来（`Review +8348 -850`）。**
   我们目前在验收卡递上来之前，人完全不知道这件活攒了多大的 diff。
   一条活的分支相对 base 的 `+X -Y` 是现成的，值得放进行里。

## 不该抄（2 条）

4. **角色化人名（Full-Stack Engineer Tom/Ryan/Bill）不要学。**
   那是同一个模型扮的角色，名字是装饰。我们的 `owner_handle` 指向**真的人**或真的分身；
   给分身起人名会让人误以为它们能力不同。名册是真的，别掺假名。

5. **Expert Canvas（并排卡片墙）对我们是负价值。**
   它解决的是「一次并行 8 个 agent 看不过来」，靠给每个 agent 一列。
   我们的模型是「房间＝地方，活＝房间里的事」，人是**进房间读上下文**，不是俯瞰卡片墙；
   而且本项目已经 169 个房间，画布会立刻烂掉。
   真要鸟瞰，我们缺的是**项目级一张表**（`GET /projects/{id}/tasks` 数据已经有了，界面上还没有全项目视角），不是画布。

## 存疑 / 要拍板（2 条）

6. **`Blocked by Task 10` 这种活与活之间的依赖，我们要不要有？**
   倾向不要：`cheese split` 是单向的，派出去就断线，房间没法表达「这件等那件」。
   我们真实的阻塞是「等 CI」「等人采纳」，#614 已经画在行上了。硬上一个 DAG 编辑器不解决我们的痛点。

7. **`12 /21` 的分母我们没有。**
   Qoder 有分母是因为它先出一份计划再派活；我们的活是随时 split 出来的，没有「计划里一共 21 件」这个总数。
   要分母就得先有「计划」这个对象 —— 这是个真设计决策，不是 UI 细节。

## 一句不好听的（比可视化更该先看）

采纳流程的**实际覆盖率只有 37%**：168 个已归档话题里 78 个零验收卡、直接调 `/archive` 关掉。
看板画得再漂亮，如果活的收尾根本不走这条流程，上面的「已完成」就是假的。
所以我倾向先做上面 1、2 两条便宜的，同时把「做完的活怎么收尾」这件事单独拎出来看。
