成员页与邀请 · 效果预览

按 uid 邀请、先查人再发、发出去之后要对方接受才算加入。

跑在真代码上的截图，只有数据是编的——预览不该碰任何一个真人的名册。「首页 → 小队 → 待定」那一页（被邀请的人接受/拒绝的地方）没有截进来：那一页的数据来自 1.0 那层的小队接口，这套假后端不覆盖它。

成员页

侧栏「AI 队友」下面一行「成员」。人按角色分三段，AI 队友单独一段。私聊的未读挂在「成员」那一行上（总数），进来之后精确到每个人的私聊按钮。

邀请：填 uid，先查出这个人是谁

输入框是 uid（个人主页地址里那个数字），不是 handle——uid 抄得准，handle 得对方告诉你，打错一个字母的后果是「查无此人」还是「加错了人」全看运气。边打边查，查到了把头像 + 昵称 + @handle 摆出来给你确认；图里这个人已经在项目里，所以直接说出来并且按钮按不下去。两个输入框之间的间距也拉开了。

查无此人

uid 不存在就当场说，按钮按不下去——不让你发出一个必定失败的请求。

等待接受

邀请发出去之后不会直接进名册，单独一段「等待接受」，邀请方可以撤回。被邀请的人在「首页 → 小队 → 待定」那一页看到它，接受了才算加入。
