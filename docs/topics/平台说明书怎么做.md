# 平台说明书怎么做

## 目标

给知是做一份**给使用者看的**说明书：Quick Start 型的官方文档站，配合"用户在房间里问芝士，芝士答完给出对应网址"。符露夀提的需求，明确要求**整份重写、给人看而不是给 agent 看**。

## 为什么不是把现有文档整理一下

`docs/` 下 30 多篇加 `docs/topics/` 149 篇全部是写给改这个仓库的人看的（分层约定、迁移坑、部署）。读者是另一拨，搬过来两边都不好用。所以说明书从零写，新目录 `docs/manual/`，一个字不从旧文档搬。

同时核实到：**产品自己现在一句解释都不说**——前端没有帮助中心、没有新手引导、任何 onboarding 入口都搜不到。所以缺的不只是文档。这一层（界面里的空态和就地解释）暂时没做，见"没做的"。

## 定下来的设计

**三层，寿命不同**：界面里就地说话（不会过期，最没做）／一条端到端上手路径（会过期，要有人重走）／概念参考站。当前交付的是后两层。

**放 `docs/manual/`，站点发到 `okcheese.com/docs`。** 放 repo 里的理由：改行为的那个 PR 才有机会顺手改说明书；放飞书就永远是"另一件事"。（现有约定是产品方向住飞书、跟代码同步改的住 repo。）

**"问 AI 给网址"这件事分两半，成本差很远。** 已经有的那一半：房间里的芝士本来就在，给它一份说明书即可。新的那一半：还没注册的访客在文档站上提问——独立的面，要限流防滥用，**先不做**。

**不上向量检索。** 几万字整份进上下文最准，也不会有检索错段落导致答错。

**正文全是人话，不为 AI 另写一套。** 芝士拿到的只是自动生成的索引（网址 + 标题 + 每节第一句话），正文一个字没为机器改过。

**防 AI 编网址靠机器，不靠人记得**（这是本话题最值得留下的一条）：
1. 每个标题自己声明 slug（`## 连上你已有的仓库 {#connect-repo}`）。让站点从中文标题自动生成锚点的话，有人改一个字，所有发出去过的链接同时失效，而且**不会有任何构建报错**——唯一的症状是读者落在页顶。
2. 给芝士的锚点清单 `anchors.json` 只能生成，不能手改。清单一旦落后，模型不会说"我这儿没有"，它会答最接近的东西配一个打不开的网址。
3. 守卫 <&.claude/scripts/check-manual-anchors.py> 拦这四件事，已接进 pre-commit 和 CI。

## 验证

`uvx pre-commit run --all-files` 九项全绿（ruff / ruff-format / pyright / alembic / eslint / stylelint / repo-rules / action-pins / manual-anchors）。守卫的 `--self-test` 覆盖缺 slug、大写 slug、同页重复、无摘要句、死链、陈旧清单、空目录七种情形。站点已构建并作为本话题预览在跑。

顺带一个证据：这个守卫在第一版草稿上就抓到两处——「走不通的时候」和「接下来」都用列表开头，没有能当摘要的第一句话。

## 没做的 / 等拍板

- **常见问题**：想等有真实提问再写。凭空编的 FAQ 通常没人问。可以从历史话题里捞用户真卡住过的问题当数据源。
- **发布到 `okcheese.com/docs`**：需要在 <&frontend/nginx.conf> 加一条静态目录规则 + CI 构建步骤。这算改线上部署，等符露夀点头。
- **界面里就地说话（L1）**：空态文案、首次进房间的引导、关键动作前的一句解释。这一层最不会过期，但它是改前端代码，不是写文档，范围另算。
- 等符露夀看完预览给内容反馈：语气、颗粒度、有没有该讲没讲的。
