# 平台说明书怎么做

## 目标

给知是做一份**给使用者看的**说明书：Quick Start 型的官方文档站，配合"用户在房间里问芝士，芝士答完给出对应网址"。符露夀提的需求，明确要求**整份重写、给人看而不是给 agent 看**。

## 为什么不是把现有文档整理一下

`docs/` 下 30 多篇加 `docs/topics/` 149 篇全部是写给改这个仓库的人看的（分层约定、迁移坑、部署）。读者是另一拨，搬过来两边都不好用。所以说明书从零写，新目录 `docs/manual/`，一个字不从旧文档搬。

同时核实到：**产品自己现在一句解释都不说**——前端没有帮助中心、没有新手引导、任何 onboarding 入口都搜不到。所以缺的不只是文档。这一层（界面里的空态和就地解释）暂时没做，见"没做的"。

## 定下来的设计

**三层，寿命不同**：界面里就地说话（不会过期，最没做）／一条端到端上手路径（会过期，要有人重走）／概念参考站。当前交付的是后两层。

**放 `docs/manual/`，站点发到 `okcheese.com/docs`。** 放 repo 里的理由：改行为的那个 PR 才有机会顺手改说明书；放飞书就永远是"另一件事"。（现有约定是产品方向住飞书、跟代码同步改的住 repo。）

**"问 AI 给网址"这件事分两半，成本差很远。** 已经有的那一半：房间里的芝士本来就在，给它一份说明书即可。新的那一半：还没注册的访客在文档站上提问——独立的面，要限流防滥用，**先不做**。

**不上向量检索。** 几万字整份进上下文最准，也不会有检索错段落导致答错。

**正文全是人话，不为 AI 另写一套。** 芝士拿到的只是自动生成的索引（网址 + 标题 + 每节第一句话），正文一个字没为机器改过。

**防 AI 编网址靠机器，不靠人记得**（这是本话题最值得留下的一条）：
1. 每个标题自己声明 slug（`## 连上你已有的仓库 {#connect-repo}`）。让站点从中文标题自动生成锚点的话，有人改一个字，所有发出去过的链接同时失效，而且**不会有任何构建报错**——唯一的症状是读者落在页顶。
2. 给芝士的锚点清单 `anchors.json` 只能生成，不能手改。清单一旦落后，模型不会说"我这儿没有"，它会答最接近的东西配一个打不开的网址。
3. 守卫 <&.claude/scripts/check-manual-anchors.py> 拦这四件事，已接进 pre-commit 和 CI。

## 定下来的形态（2026-09-09 更新）

符露夀要的是**一个像 `platform.claude.com/docs` 那样的官方文档站，方便大家用；内容他自己写**。所以我的活是骨架，不是文字。

站用 **VitePress**（Vue + Vite，和前端同栈；实测装 37 秒、构建 5 秒、原生支持 `{#slug}`、内置本地搜索）。原先那个 130 行的自造生成器已删除——它接下来要补的是搜索、移动端、暗色切换，等于在重写一个文档框架。

**给模型的那一半仍然是我们自己做**：`llms.txt` + 每页 `.md` 双胞胎，由 <&scripts/emit_llms.py> 在构建后产出。这是抄那五家的（Anthropic / OpenAI / Stripe / Vercel / Linear 全部如此，2026-09-09 逐个实测），也是 VitePress 不管的部分。原先自造的 `anchors.json` 已删。

## 已上线（2026-09-09）

**https://okcheese.com/docs/ 是活的。** 实测：`/docs/` 200、`/docs/quickstart`（无 `.html`）200、`/docs/quickstart.md` 返回 `text/markdown; charset=utf-8`、`/docs/llms.txt` 200。

**「芝士能不能真去查、能不能给链接」这个问题已经答完了**：用 WebFetch（芝士真正抓网页的那个工具）实测——拉 `llms.txt` 拿到分组目录 → 挑中「验收与采纳」→ 读 `accept.md` → 答出内容并**自己报出 `#accept` / `#is-merge` 两个锚点**，也就是能给到精确到小节的链接。

三张卡都已采纳合并：**#905**（说明书骨架 + .docx 修复）、**#908**（发布到 /docs + 按功能重排 + 教会芝士去查）、**#915**（聊天里的链接新标签页打开）。

## 交付内容

| 文件 | 是什么 |
|---|---|
| <&docs/manual/.vitepress/config.mts> | 站的配置。侧边栏是扫目录扫出来的——加一页就是新建一个 `.md`，写内容的人不用开配置 |
| <&docs/manual/index.md> | 首页（hero + 三张卡） |
| <&docs/manual/quickstart.md> | 快速开始：建项目 → 连仓库（可跳过）→ 开房间说一句人话 → 看它干活 → 采纳合并 → 三个常见卡住 |
| <&docs/manual/concepts.md> | 项目 / 房间 / 芝士 / 活 / 看板 / 实况文档 / 验收卡与采纳 / 结论卡 / 算力 |
| <&docs/manual/working-with-cheese.md> | 怎么把活交给 AI 队友——说要什么不说怎么做、第一句回复是纠偏窗口不是审批、它问你时才是真需要你定、反馈对着产出说 |
| <&docs/manual/README.md> | 这本说明书自己的四条规矩 |
| <&.claude/scripts/check-manual-anchors.py> | 锚点守卫，带 `--self-test` |
| <&scripts/emit_llms.py> | 构建后产出 `llms.txt`、每页 `.md`、打包下载的 zip |

内容是照着真实界面核的，不是照设计文档编的：项目创建对话框的字段、进项目落在看板而不是聊天、新建话题先弹队友选择、采纳按钮变灰的三种原因，都在前端代码和 e2e 用例里对过。过程中改掉了一处自己写错的——房间的 AI 队友**是能换的**（房间顶部名册里芝士那一行），只是换掉会丢会话。

## 验证

`uvx pre-commit run --all-files` 九项全绿（ruff / ruff-format / pyright / alembic / eslint / stylelint / repo-rules / action-pins / manual-anchors）。守卫的 `--self-test` 覆盖缺 slug、大写 slug、同页重复、无摘要句、死链、陈旧清单、空目录七种情形。站点已构建并作为本话题预览在跑。

顺带一个证据：这个守卫在第一版草稿上就抓到两处——「走不通的时候」和「接下来」都用列表开头，没有能当摘要的第一句话。

## 写内容的人要知道的三件事

1. 加一页 = 新建一个 `.md`，侧边栏自动出现。
2. frontmatter 三行：`title` / `slug` / `order`。
3. 每个标题带 `{#锚点}`、每节第一句话能当摘要——守卫拦着，忘了 CI 会红。前者保证改标题措辞不打断已发出的链接，后者那句会写进 `llms.txt`。

本地：`task docs:dev` 边写边看，`task docs:build` 出成品。

## 踩过并解决的坑

- VitePress 的 `base` 是 `/docs/`，站内链接写 `/concepts#task`，**不带** `/docs` 前缀；写两遍会变成 `/docs/docs/…`（它的死链检查当场拦下 5 处）。给模型的 `.md` 里由 emit_llms.py 改写成绝对地址。
- **站的根必须就是内容目录**。`srcDir` 指到外面时，Vite 从 `.md` 所在目录往上找 node_modules，解析不到 `vue/server-renderer`，构建直接失败。
- `cheese serve` 报的端口被别人占着时平台探活照样成功，预览会指向不相干的应用——起服务后要核对返回内容里有自己的标记，不能只看状态码。

## 分工已定

**框架我搭，内容和截图符露夀亲手写。** 结构按**功能**分（他的要求）：开始 / 基础 / 干活 / 产出 / 资源。加一页 = 新建一个 `.md` + frontmatter（title / slug / group / order），侧边栏自动扫出来，写内容的人不用开配置。

## 待定：快速开始要不要配图（2026-09-09 提出，等符露夀回）

我的结论是**要，但只要三四张，而且必须自动生成**。

- **为什么要**：知是是 GUI 产品，不是 API 产品。那五家的 quickstart 几乎没有截图，因为每一步都是一段代码；而这里写的是「左边竖栏底部的 ➕」这种句子，读者得在屏幕上找。判据：**「东西在界面哪儿」图强于字；「这件事意味着什么」字强于图。**
- **为什么少**：截图是文档里最易腐烂的东西，而且**读者信图胜过信字**——一张对不上的图比没有图更糟。只放在"找不到入口"的三四处：竖栏的 ➕、打开项目第一屏是看板不是聊天、房间四个面的全景、验收卡长什么样。
- **怎么不腐烂**：接到 e2e 上，作为构建产物。仓库里已有三套现成工具——<&e2e/shot.mjs>（带登录态截任意页）、<&scripts/shots.py>（设计走查全量截图）、<&e2e/preview.mjs>（真组件+编好的假数据，最适合文档，不会截到真人名册）。设想是 `task docs:shots` 输出到 `docs/manual/public/`，CI 里跟 e2e 一起跑，图变了在 PR diff 里看得见；入口被挪走时 e2e 先红。
- **建议的时机**：**等内容定稿再做**。符露夀要重写内容，图配在最终文字旁边才不白做。

## 没做的 / 等拍板

- **常见问题**：想等有真实提问再写。凭空编的 FAQ 通常没人问。可以从历史话题里捞用户真卡住过的问题当数据源。
- **发布到 `okcheese.com/docs`**：三处改动已查清并写在 <&docs/manual/README.md>，等符露夀点头。①文档产物放进 `frontend/public/docs/`（Vite 原样搬运，不用改 Dockerfile）；②<&frontend/nginx.conf> 的 `try_files` 补 `$uri.html`（VitePress 开了 cleanUrls，不补则 `/docs/quickstart` 掉进 SPA 兜底）；③给 `.md` 声明 `text/markdown`（nginx 默认不认，且 Claude Code 有「content-type 是 text/markdown 就直读原文」的快路）。**第①处会静默失败**——镜像照样构建成功、只是 /docs 变 404，要在 <&frontend/scripts/check-static-assets.sh> 加一条断言。
- **Ask AI（站内问答框）**：那五家都有。后端本来就有 OpenAI 兼容的 LLM 通道，文档量小到整份进上下文、不需要检索。**唯一障碍是 `OPENAI_API_KEY` 是空的**——只有符露夀能给。给了之后估半天到一天。
- **界面里就地说话（L1）**：空态文案、首次进房间的引导、关键动作前的一句解释。这一层最不会过期，但它是改前端代码，不是写文档，范围另算。
- **内容由符露夀自己写**。他看过现有三页后的评价是"写得不太好"；问过留着当草稿改 / 全删只留骨架 / 先不管，未回复。骨架和内容分开，不挡事。
- **平台缺口（顺带查出，值得单开 issue）**：平台没有"整份带走"的入口——单文件能下载，打包导出没有，git clone 只认沙箱令牌。写代码的项目还能靠合进 GitHub 取回产出，写文档/做方案的项目完全说不通。临时绕法是文档站自己带了一个 zip 下载。

## 同一批里修掉的一个真 bug（PR #905）

符露夀发 `快速开始.docx` 进房间失败。根因：`blocks.mime_type` 是 `String(64)`，而 Office 的 MIME 是 docx 71 / pptx 73 / xlsx 65，插入报 `value too long for type character varying(64)`，**连同正文整条回滚**；上传那步已经返回 200，所以看起来像发出去了。pdf(15) 和图片没事，所以活了很久。

修法：迁移 `f31c07a9b45e` 把该列放宽到 255（RFC 6838 上限 127+127）。**为什么测试没抓住**：<&backend/tests/integration/test_attachments.py> 里本来就有 docx 用例，但只覆盖上传和下载（都不写 blocks 表），唯一走 `blocks.add` 的用例用的是 pdf。新增 `test_office_document_lands_in_the_room` 覆盖三种类型，并断言时间线上真有那条 attachment。红→绿都验证过。

**未修的相关问题**：<&backend/app/api/routes/chat.py:193> 对任何未知异常一律回「消息未能保存，请重新发送」——这类 schema 错误重发多少次都不会成，建议是错的。属于 issue #450。
