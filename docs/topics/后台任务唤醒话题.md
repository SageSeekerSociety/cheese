## 目标

让"等后台长任务"不再等于"话题冻死"。做一条 **后台任务跑完 → 唤醒本话题** 的通路：agent 可以放心把几十分钟的全量检查丢到后台、结束本轮，任务退出时平台自动起一轮新的，并把**退出码 + 输出尾巴**一起递到它面前。

## 核实结论（先查后做）

两条关键证据都核实过：

- **`post_with_retries` 确实不 summon**（<&backend/app/domain/webhook/service.py>）：它只 `BlockRepository.add` 一个 `kind=event` 的 block 就返回。简报无误。
- **方案 B（接 Claude Code hook）不成立**。`/sandbox/hooks/{topic_id}`（<&backend/app/api/routes/sandbox.py>）收的只有 Claude Code 的**会话生命周期钩子**——`SessionStart` / `PreToolUse` / `MessageDisplay` / `Stop` / `CheeseSync`（映射表见 <&backend/app/domain/agent/hook_events.py>）。它们被 `HookRouter` 投给**当前那一轮**的队列；**没有轮次在听时，事件被 park 进 spool**，下一轮开始时作为历史补记——**从设计上就不 summon**。而且更根本：detached shell 进程退出，Claude Code 压根不发任何 hook，所以 B 没有可接的事件源。

## 方案（已定）：A — `cheese await "<命令>"`

**沙箱侧执行 + 平台侧唤醒端点**，两半：

1. `cheese await "<命令>"` 立刻返回。它先向平台**登记**这个任务，拿到 `task_id` 和一个寿命覆盖整个任务的 `wake_token`，然后 fork 一个 detached 子进程去跑命令（跑在 agent 自己的沙箱里，venv/PATH 都是热的）。
2. 命令退出时，子进程把 `{exit_code, tail, duration}` POST 回平台新端点 → 平台**落一个 block（结果永不丢失）**，再按四道闸决定是否 `runner.submit(..., summon=True)`。

**为什么不让后端自己跑命令**：`ws.run_check_command` 跑在一次性、无网络的 gate 容器里——那正是"全量检查要 40 分钟"的成因（样样是冷的）；而 `docker exec` 进话题容器又会把这个能力焊死在 tmux/docker 后端上。跑在 agent 自己的沙箱里，环境是热的，也与后端形态解耦。

**为什么要登记这一步**：容器注入的 `CHEESE_TOKEN` 只有 1 小时寿命（`_SCOPED_TTL_S`），而本卡针对的就是几十分钟起步的任务——登记时按 `timeout + 1h` 现铸一个 wake token，才不会跑完了却 401。登记同时也是并发上限和"归档不受理"的第一道闸。

## 四道防护

| 要求 | 实现 |
|---|---|
| 不造成唤醒风暴 | 每话题滚动 1 小时内**最多 6 次**自动唤醒 + 同时最多 3 个在跑的 await 任务（登记时就挡）。超限时**仍落 block**、只是不 summon，并在 block 里写明"已达上限"，人能看见 |
| 话题在跑时不重复唤醒 | 用 `runner.running_topic_ids()`；在跑就**延后**（轮询到空闲再 summon，有上限），而不是丢弃 |
| 唤醒要带上下文 | 抄 `gate.py` 的做法：命令、退出码、耗时、完整日志路径，加**输出尾巴**（截断到 1500 字符）一起进 summon 正文 |
| 归档/结算不唤醒 | 登记与回报两处都查 `topic.status == archived` 和终态验收卡（accepted/rejected/revoked）；命中则只落 block |

## 验证结果

- **本卡的 41 个测试：全部通过。** 四道闸每条都有跑出来的证据，不只是代码意图。
- **全量后端套件：3610 passed / 23 failed / 31 skipped，0 errors。** 23 个失败全在 `test_machine_service.py`(20)、`test_market_api.py`(1)、`test_tmux_control.py`(1)——原因是这台机器缺 `ssh-keygen` / `kill` / tmux 等系统二进制（`FileNotFoundError`），与本卡无关，也不碰本卡改动的任何文件。
- **ruff 全绿；pyright 0 errors；alembic 单一 head。**

### 怎么在没有 docker 的机器上跑通（这次踩的坑，值得留下）

1. `check.sh` 在这类机器上会**假绿**：它探到继承来的 `.venv` 控制台脚本执行不了（shebang 里烤死的是另一台机器的绝对路径），就去同步一个 scratch venv，来不及就把 pyright 和 pytest 双双记成 SKIP —— 而**退出码仍是 0**。别信它的 0，要看 `Result:` 行里 skip 了几项。绕开办法：直接 `uv run pytest` / `uv run pyright`。
2. 缺的服务端自己补，不用 docker：PG 用 `pgserver` wheel（只有 cp39–cp312 轮子，装在一个 `uv venv --python 3.12` 里，取它的 `pginstall/bin` 即可，测试仍跑在项目的 3.13 venv 里），Redis 用 `redislite` wheel 里的 `redis-server`。PG 起在 5433（`TEST_PG_BASE` 默认值），Redis 起在 6379。
3. PG 记得调大 `max_locks_per_transaction`（如 512）——`conftest.py` 里说的 "out of shared memory" 就是这个旋钮，xdist 多 worker 各自迁移 ~90 张表时会撞上。
4. **只起 PG 不起 Redis 会看到 581 个 error**，全是 `redis.exceptions.ConnectionError`，很容易误判成代码坏了。

## 已知限制

容器或子进程被杀（沙箱回收、机器重启）时没人回报，话题不会被唤醒。这一步靠子进程自带 `--timeout`（超时也算一次回报，退出码 124）兜住"命令自己挂住"的情况；"容器整个没了"无解——那时会话上下文本来也没了。
