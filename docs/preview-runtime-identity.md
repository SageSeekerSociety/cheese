# Resource-bound preview runtime

The formal right-hand preview uses independent resource origins, signed resource grants and displayed identity. The live/latest content host remains available for existing callers. A retained DOM is not a snapshot.

## Resource and instance contract

A selected file grant binds its room path, MIME and entry SHA-256 prefix. Every subsequent request uses that directory rather than the latest artifact. Reading changed entry bytes returns 409; sibling assets are still mutable. There is no resource-closure snapshot, immutable archive, offline copy or complete reproducibility claim.

An app grant binds artifact, teammate and actual Linux IPv4 listening socket identity. The helper hashes kernel boot ID, locally declared port and listening socket inode. Reconnecting the helper leaves the listener identity unchanged. Changing the listener or declared port invalidates old fixed requests. The helper captures the declared port once, then checks that same target before dial and after native connect, before HTTP headers or WS handshake bytes. Ports are never selected by the wire. An already connected stream stays bound to its native socket; it is not migrated. Linux hosts without readable socket identity and non-Linux helpers expose only live routing, explicitly labeled as not fixed. Socket-inode reuse is not a cryptographic process-incarnation guarantee.

The resource hash is part of one 63-character DNS label under the existing content-domain wildcard. Grants and host-only cookies bind their exact origin. Authorizing a new resource cannot replace an old resource's session cookie. Every content request still checks current topic membership. The fixed host never falls back to latest. A new-tab live link still opens latest, as its label says.

## Navigation, runtime and reconnection

Navigation load promotes the iframe but does not assert application readiness. The content host injects the keyboard runtime into every HTML document it serves: room files and static artifact/resource entries whose media type is `text/html` or `application/xhtml+xml` get `<script src="/_cheese/runtime.js"></script>` inserted at the head of the document. The insertion point is found by reading only the document's opening: BOM, whitespace, comments, doctype and `<?xml ?>`, then an optional `<html ...>` tag, then an optional `<head ...>` tag. The script goes wherever that walk stops. `<head` written later in the page (inside a script string, a template, a style or an attribute value) is never matched, so the injected tag can never cut a page's own script short. A tag-less HTML5 document still keeps its doctype first and stays in standards mode. An unterminated leading comment means nothing is injected. Tag matching is case-insensitive and quote-aware, and a document that already references the script is left untouched. Injection is byte level and confined to ASCII-compatible encodings — an ASCII-incompatible BOM (UTF-16/32) or a non-ASCII-compatible `meta charset` is served unchanged — and it happens after the entry's 409 version check, which still hashes the original bytes. `Content-Length` reports the injected length, including on HEAD. Proxied apps are not injected: their response is streamed and may be compressed or chunked, so there is no clean, well-tested rewrite, and they stay opt-in.

The injected script never calls `ready()`, so an injected page is still readiness-unconfirmed — injection installs the keyboard bridge, not a readiness claim. A cooperating page may also include the script itself; after its own initialization it calls `window.CheesePreviewRuntime.ready()` or `.error(message)`. The bridge caches the result until the parent hello arrives. On installation it also requests the current handshake, so a script loaded after navigation does not lose the first hello. This request cannot confirm readiness or renew the navigation session. It validates parent window and configured platform origin. The parent validates exact content origin, current iframe WindowProxy and protocol/version before replying; readiness and errors additionally require the random navigation session ID. CSP, forms and scripts themselves are not rewritten.

On `Escape` (capture phase, repeat ignored, and only when the page's own handlers left it unhandled) the bridge posts `{type:'escape'}` on the same session channel, unless the page has its own modal open — an open `<dialog>`, or a visible `aria-modal="true"` element — and coalesces to at most one forwarded ESC per 500 ms. The host answers in order: close the preview's locator bar, else exit fullscreen, else move focus out of the iframe back to the panel so host shortcuts work again.

Plain keys (no mod, no alt) are not forwarded while the event target, or the frame document's `activeElement`, is editable, so a plain-letter shortcut never steals typing. Editable means a text-like `input` (no type, text, search, email, url, tel, password, number and the date/time types), a `textarea`, a `select`, a `contenteditable` element, or a document in `designMode`. Buttons, checkboxes, ranges, colour and file pickers are not editable. Chords with mod still forward, and `Escape` follows its own rule above, editable or not. No key is forwarded while an input method is composing (`isComposing`, or keyCode 229): Escape there cancels the composition and must not also close the locator or leave fullscreen.

Metadata polling observes disconnection, same-listener recovery and replacement. While the displayed app frame is not online the panel polls faster (2 s, backing off to the normal 20 s over about a minute) and only while visible. A missing instance fingerprint in the metadata (the probe failed, so `instance` is null) is not a replacement: following on that would sign an unbound grant. On replacement the panel follows automatically — it signs a fresh grant for the currently online instance and loads it into the incoming frame, so the old page stays visible until the new one loads and a notice explains the swap; the displayed frame reads as gone meanwhile. A follow that fails (a 404 during a rapid restart, a session signed before the app answers) is retried on later polls for up to a minute while the server keeps reporting an online instance that differs from the displayed one, after which the panel gives up to the manual refresh path with a hint. Same-instance recovery does not POST or remount, preserving focus and form state, unless the displayed frame's navigation actually failed. Application WS reconnection remains the application's responsibility; the host does not pretend a transport probe restores app state. Hidden panels do not poll. Transport cancellation, streaming and authorization contracts are retained.

## Verification scope

Initial backend targeted run: 49 passed, including native listening socket identity/replacement, before-app-byte guards, existing message/hub/relay boundaries and real database content-host file isolation. Final incremental run: 8 passed, including same-port listener replacement, execution of the actual bridge in Node's JS VM, authorized bridge GET/HEAD and method rejection, and production app grant/host/hub routing with a controlled wire peer. The latter checks latest changes, helper loss, same-instance reconnect, replaced instance and missing capability. It is not a native end-to-end app test.

Frontend final run: 11 passed, including origin/source/session negatives, same-frame connection recovery and readiness session renewal on displayed-document reload. The later API/type extraction run passed 22 selected cases and the size gate without growing frozen barrels. The actual bridge script was executed in a controlled JS VM, not a browser navigation. Selected backend pyright and full frontend type ratchet both reported zero errors. Changed-file Ruff and ESLint exited zero (ESLint retains pre-existing warnings); i18n passed without baseline changes. Original logs and exit records accompany the source handoff.

The captured-port increment has a controlled native Linux HTTP/WS A-to-B-to-A reproduction: the old fixed requests reached listener B and failed two behavioral assertions, while the live controls passed. The same assertions and same-port listener replacement pass after the fix (10 selected cases, exit 0), before any application headers or handshake bytes are sent to an unauthorized target. This is controlled interleaving, not a WAN or load-test claim.

Review must still consider listener inode reuse, SO_REUSEPORT, IPv6 and connect/check races; the implementation is not a cryptographic server-incarnation guarantee. HTTP error pages can produce iframe load; the host reports navigation observed and readiness unconfirmed, not application success. Runtime-ready has no universal deadline. Authorization tests for existing live hosts are retained, but the full negative authorization suite has not been rerun against new resource hosts. Full CI, formal browser deployment observation and immutable resource closure remain unverified.
