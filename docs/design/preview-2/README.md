# 预览 2.0 交互原型

`prototype.html` 是 2026-10-26 产品负责人认可的预览 2.0 可点击原型（单文件，浏览器直接打开）。它是实现的**最低标准**，不是要照抄的模板：每个界面状态至少做到原型的水准，想到更好的做法可以超出，但要在 PR 里写明哪里有意不同、为什么更好。

## 怎么验收一条预览改动

1. 在原型里找到这次改动对应的状态（列表见 `gaps.md` 的各节标题），用同样的操作把原型和真产品走到同一个状态。
2. 两边都在真浏览器里截图，左原型、右产品拼成一张，附在 PR 正文里。量得到的数（位置、尺寸、出现时机、步骤数）两边各量一次写进正文。
3. 产品在任何一处比原型差（流程多一步、该有的元素缺了、遮住了选区、质感更粗），先改再交。

真产品可以在沙箱里这样跑：从任务目录的 `frontend` 起本地 vite，把 `/api`、`/connector`、`/collab` 反代到 `https://okcheese.com`（`ws: true`），用开发号登录后把令牌写进 `localStorage`，并 stub 掉 token refresh。

## 差异清单

`gaps.md` 是 2026-10-27 原型与生产逐状态对照的结果（19 个状态），每条写「原型：…／产品：…」并标结构、样式、文案。已修掉的条目在对应 PR 合入后从清单里删掉。
