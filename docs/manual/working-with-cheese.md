# 与芝士协作 {#working-with-cheese}

与芝士协作时，先说明目标和判断完成的标准，再根据执行过程补充要求、检查结果。

## 描述目标 {#describe-goal}

任务要求应说明预期成果、已有材料和完成标准。例如，整理一份说明时，可以明确读者、需要覆盖的内容和格式要求。对操作步骤有具体要求时，也一并说明。

## 发起处理 {#start-work}

准备好要求后，在话题中使用 `@芝士` 或 `Ctrl/Cmd+Enter` 发起处理。空闲时直接发送的普通消息不会自动触发执行。完整触发方式见[AI 队友](/agents#summon)。

## 执行中补充要求 {#add-context}

芝士执行时，可以在话题中补充条件或调整要求。直接写明需要改变的内容；消息在执行期间正常送达时，会进入当前一轮。

如果出现「消息没能送进正在进行的会话，已转入队列」，说明消息已排队。先查看后续运行状态，再判断是否需要重新发送，避免重复提交同一要求。

## 查看进度并回答问题 {#follow-progress}

执行进度和补充信息请求可以在话题中查看。执行期间，话题会显示「芝士正在处理…」。右侧的「总览」「现场」「改动」提供任务、运行现场和文件改动的查看入口。

芝士需要补充信息时，可能直接在对话中提问。看到这类消息时，按问题回复，再用 `@芝士` 或「交给芝士」继续。

## 检查结果 {#review-result}

检查结果时，应同时核对结果说明和实际文件内容。一轮结束后，先阅读话题中的结果说明，再通过「查看改动」或右侧「改动」检查文件。收到验收卡时，查看差异并决定采纳或退回。详见[验收与采纳](/accept#accept)。
