# 与芝士协作 {#working-with-cheese}

这一页讲怎么和芝士一起把一件事做完：开始说清目标，执行中补充要求，结束后检查结果。

## 描述目标 {#describe-goal}

一条能直接开工的要求包含三件事：

- 要什么：成果是什么，给谁用，比如「给新同学看的一页报名说明」。
- 有什么：已有的材料、链接、文件，直接上传或贴进来。
- 怎样算完：格式、篇幅、必须覆盖的点，比如「不超过一页，结尾列出报名截止时间」。

对做法有要求时也一并写上，比如用什么工具、不要动哪些文件。

## 发起处理 {#start-work}

写好要求后，用下面任意一种方式交给芝士：

- 在消息里 `@` 芝士，然后发送。
- 按 `Ctrl/Cmd+Enter`。
- 点输入框旁的「交给〈队友名字〉」。

直接按回车发出的普通消息只留在频道里，芝士不会开工。`@` 和「交给」的完整说明见[让 AI 队友处理消息](/agents#summon)。

## 执行中补充要求 {#add-context}

执行中随时可以在频道里补一句，比如「标题改短一点」。执行中发的消息并进正在进行的这一轮，不用重新 `@` 它。

对话里出现「消息未送达」时，见[提示消息未送达](/agents#undelivered)。

## 查看进度并回答问题 {#follow-progress}

芝士执行时会在对话里说明它在做什么，更细的内容在任务页右侧的页签里：

| 右侧页签 | 看什么 |
|---|---|
| 概览 | 任务文档、芝士这一轮的清单、它做出来的文件和这件任务的原讨论 |
| 现场 | 芝士每一步做了什么：读了什么、改了什么、跑了什么命令 |
| 改动 | 目前改了哪些文件 |
| 预览 | 做出来的网页或文件的预览 |

芝士需要你拍板时，会在对话里发一条问题，下面带几个快捷回复。点一个选项，或者不点、直接在输入框里回一句，都算回答，它会接着做；输入框一直能用。它只在普通消息里用文字提问时，回复后再 `@` 它一下。

## 检查结果 {#review-result}

一轮结束后，读它的结果说明，再核对它实际改的文件：

- 点本轮摘要的「查看改动」，或打开右侧「改动」。
- 收到验收卡时，点「审阅」看完差异，再决定采纳还是退回，见[验收与采纳](/accept#accept)。

芝士的结果说明和它实际改的文件都要看。
