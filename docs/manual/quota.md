# 额度 {#quota}

额度是知是给 AI 用量记账的点数。在团队「B 树小组」的项目里，芝士每调用一次模型、云端环境每运行一分钟，都从这个团队的额度里扣除。

## 由谁的额度支付 {#payer}

团队下的项目用团队的额度，你名下的项目用你的个人额度。别人在你名下项目的频道里 `@芝士`，扣除的也是你的个人额度。

额度以「点」计，1 点等于 0.01 美元。同样长的一段对话，单价高的模型扣除得多。

团队的额度由所有成员共用。额度由平台或发放方发放和调整；项目所有者和管理员可以设置项目总预算，以及每个成员在项目里的任务用量上限。

## 云端环境怎么计算 {#compute}

AI 队友在平台的沙箱里运行时，沙箱准备好之后到释放为止按分钟计费，不足一分钟按一分钟计算。标准沙箱每小时的价格固定，与实际用了多少 CPU 和内存无关。虚拟机沙箱按虚拟机的规格定价。额度用完时，平台的沙箱不再启动，换成某人的设备或指定的电脑照常能用。

标准沙箱的准备时间不计费。虚拟机沙箱从创建到释放计费，包含准备时间。环境一段时间没有活动就会释放。下一条消息会准备新的环境，每轮结束时推送和备份的改动会带到新环境里。

AI 队友运行在你接入的自有设备上时，不计算力费用，芝士调用模型照常扣额度。自有设备见[自有设备](/devices#devices)。

## 团队的「额度」页 {#team-quota}

在首页左侧栏点团队那一行的「⋯」，选「设置」，再点「额度」。团队的每个成员都能查看这一页：

- 本月用量：标题是当月月份，例如「十月已用」。下方是已用和总数（如「120 / 2000 点」）、剩余点数和重置日期，「协作」（项目里的芝士）和「算力」（云端环境）用两种颜色区分。
- 「使用上限」：方案按时间窗口限额时，它代替本月用量，每个窗口一行，写明用掉的比例和重置时间。
- 「其他额度」：「奖励」「管理员发放」「购买」和题目给项目的额度，各写明剩余点数、到期日和使用顺序（「最先使用」或「方案额度用完后使用」）。没有时不显示。
- 「每天用量」：本月每天用了多少点，两类叠在一起。
- 「按项目」：本月各项目用了多少点。

方案是平台给团队定的额度规则。点页面上的方案名，查看方案包含的内容：每月多少点或「使用上限」，以及「可用模型」。

## 频道和项目的用量 {#project-usage}

点频道顶部右侧的「⋯」（「更多」），菜单里的「用量」分「本频道」和「全项目」两行。每行的格式是「N 次运行 · N token · 费用」，费用以美元计。在电脑上把鼠标停在一行上，显示输入和输出 token 分别是多少。

项目的额度在「项目设置 → 环境」的「额度」区域。这个数字包含团队共享的额度和题目给本项目的额度，先用题目给的那部分。没有上限时显示「未设置额度上限」。

## 项目和成员预算 {#budgets}

在「项目设置 → 环境 → 项目和成员预算」里，项目所有者和管理员可以填写项目总预算，以及各成员的任务额度上限。其他成员可以查看。留空表示不另外设置上限，填 0 表示没有可用预算。预算不会增加团队的额度。

项目总预算包含这个项目的全部开销。任务执行时，费用同时计入项目用量和任务归属人的用量；频道里直接 `@芝士` 的对话，以及共享环境的算力，计为项目公共开销，不占个人上限。每笔费用只扣一次。

任务每次开始执行时记录当时的费用归属。人类负责的任务归负责人；AI 负责的任务归创建它的人。没有人类创建者时，归项目所有者；项目没有个人所有者时归团队所有者。转交任务只影响之后新开始的执行；已经发生的费用和延迟到账的费用仍归原来的人。删除任务或频道不会恢复已花掉的预算。旧记录没有可靠人员归属的，只计入项目总预算。

这两种上限都按项目创建以来的累计用量计算，不随团队月度额度重置。调低上限不会清空已用量。项目预算用完后拒绝新的付费调用；某人的任务上限用完后，拒绝归给他的任务调用，频道公共对话仍可使用剩余的项目额度。

费用结算后才判断上限，正在进行的调用和延迟到账的费用可能使累计用量超过上限。

## 额度快用完时 {#quota-warning}

三层上限各自用到八成时，会提醒一次：

- **团队额度**用到八成：团队里每个人收到一条，额度页顶部也出现一行。方案按月发放的写「几月几日重置」，按时间窗口的写「本周」「本月」或「N 小时」并写明几点恢复。
- **项目总预算**用到八成：这个项目里的每个人收到一条，项目设置的预算区域出现一行。
- **成员任务上限**用到八成：只提醒这个人本人。

提醒只说明还剩多少、什么时候恢复或要谁调整，不改任何调用：低于八成之后到用完之前，芝士照常工作。每越过一次提醒一次；重置（新月、新窗口）或者上限被调高之后重新算。

芝士在执行任务时也会知道付钱的那一层还剩多少。每条对话只念一次：越过之后的第一次开工，之后不再重复，直到下一次越过。

这些提醒走「通知设置 → 额度与计费提醒」那一行，默认进收件箱、按你的邮件设置收信，不弹系统通知。

额度真正用完时的提示见下一节。

## 额度用完时 {#quota-exhausted}

额度用完后，芝士不再开始处理新的消息。你发的消息照常留在频道里，下方出现一条平台提示：

```demo-panel
title: 额度用完时频道里的提示
caption: 芝士没有处理这条消息；提示写明哪天重置，以及需要谁补充额度。
head: 综合
parts:
  - kind: bars
    lines: 2
  - kind: msg
    who: 你
    to: 芝士
    say: 把这周的周报改一版，结尾加上下周待办。
  - kind: line
    text: 本月额度已用完，11月1日重置。这次没有运行。
    at: 1
  - kind: line
    text: 下一步
    value: 联系团队管理员或额度发放方补充额度。
    at: 1
```

团队的方案按下面两种方式之一发放额度：

- 按月发放：每月一份额度，每月 1 日重置，没用完的不留到下个月。
- 按时间窗口限额：每个时间窗口内有用量上限，例如每 5 小时、每周或每月。
  - 按小时的窗口从团队第一次使用时开始计时。
  - 每周的窗口在周一 0 点重置，每月的窗口在 1 日 0 点重置。
  - 窗口用满时，提示写明几点恢复，例如「本周的用量已达上限，10月12日 00:00 恢复。」

窗口用满时，团队还有「管理员发放」「购买」或题目给的额度，就先用这些额度，芝士照常处理消息。

芝士正在执行时，在下一次调用模型时停止，频道里出现同样的提示。额度用完后不再启动新的云端环境。已有的环境在芝士停下后释放，频道里出现「额度已用完，环境已释放」。

额度补充后，重新 `@芝士` 发一条消息，芝士从这条消息继续。

## 个人额度 {#personal}

个人额度用于下面几处：

- 你名下项目里的芝士；
- 文档站的「问芝士」和题目页的「问芝士」；
- 发布页和改题页上的芝士。

个人额度每月 1 日发放 500 点，当月没用完的不留到下个月。用完后提示「本月额度已用完」并写明重置日期；文档站「问芝士」的提示旁有「查看用量」。

点最左侧一列底部的头像，选「设置」，再点「额度」，查看你自己的额度。用量分四种颜色：

- 「协作」：你名下项目里的芝士；
- 「问答」：两处「问芝士」；
- 「写作」：发布页和改题页上的芝士；
- 「算力」：你名下项目的云端环境。

内测期间，领取内测体验额度、反馈被采纳和邀请好友都能得到额度奖励，见[额度奖励](/rewards#rewards)。个人额度页上有「内测体验额度」一栏和「奖励记录」；每份额度奖励在「其他额度」里单独一行，当月的方案额度用完后才使用。

页面下方的「我的项目」列出你名下各项目本月的用量。「我所在的团队」列出每个团队的方案和剩余额度，点一个团队打开它的「额度」页。

## 其他写着「额度」的提示 {#other-limits}

下面几种提示与团队额度、个人额度无关，补充额度不能解决：

| 提示 | 意思 | 处理 |
|---|---|---|
| 这次没做完：你们接入的 … 余额用完了 | 团队或你自己接入的模型服务、API key 余额用完了 | 给那个账户充值后点「重试」，或者点「去 AI 队友设置」换一份连接 |
| 当前方案不能使用模型「…」 | 团队的方案不包含这个模型 | 换一个方案包含的模型；点方案名可以看「可用模型」 |
