# 自有设备 {#devices}

自有设备是你接入知是的电脑或服务器，例如实验室里那台存着数据的 Linux 服务器：接入后，频道可以把它作为[环境](/environment#environment)，芝士在上面读写文件、运行命令。

## 接入 Mac 或 Windows 电脑 {#desktop}

Mac 和 Windows 电脑通过安装桌面端接入。桌面端在「设置 → 设备 → 添加设备」的「Mac 或 Windows 设备」中下载，登录后在「接入这台设备」中点「接入」。完整步骤见[让芝士在你自己的电脑上工作](/use-your-computer#connect)。

接入后，在桌面端的「设置 → 这台设备」中修改设备名称、提供给哪些团队、Claude Code 的登录，或断开这台设备。桌面端启动时和之后每 6 小时检查一次新版本，下载完成后点「重启以完成更新」安装。

### 接入服务器或其他机器 {#add-device}

服务器、Linux 机器，或不装桌面端的电脑，用命令行接入：

1. 在「设置 → 设备」点「添加设备」，在「服务器或未安装桌面端的设备」下复制对应系统的安装命令。
2. 在要接入的机器上运行这条命令，安装连接程序 `cheesehost`。
3. 运行安装命令最后一行给出的命令，形如 `cheesehost link connect <站点地址>/connector`。命令输出一个链接。
4. 在浏览器中打开这个链接，进入「批准这台设备」页面，核对「设备名称」，点「批准并绑定到我」。

```demo-panel

caption: 「设备名称」可以在批准前修改；批准后设备归你所有。
parts:
  - kind: head
    title: 批准这台设备
    plain: true
  - kind: line
    text: 这台机器请求接入芝士，成为归你所有的设备。批准后，芝士就可以把任务派到它上面运行。
  - kind: field

  - kind: buttons

  - kind: line
    text: 设备已连接
    sub: 设备「lab-server」已绑定到你
    at: 1
```

批准后，命令行里的同一条命令接着完成接入并保持连接。设备出现在「设置 → 设备」中，显示「在线」。

在命令行运行 `cheesehost status` 查看登录和连接状态。「设置 → 设备」中设备那一行有「重命名」和「解绑」。

## 把设备提供给团队 {#team-device}

自有设备提供给团队后，团队的项目才能使用它。在团队的「设备」页点「添加自有设备」，选一台已接入的设备；页面上方写着「N 台设备 · N 台在线」。你名下的项目要使用这台设备时，在首页左侧栏你的昵称下打开「设备」，同样点「添加自有设备」。

只提供给某个项目的设备也列在团队的设备列表中，写明「仅供某项目使用」。

AI 队友开始在你的设备上工作时，你收到一条通知「〈AI 队友〉 开始在「〈设备〉」上工作」。通知写明项目和频道；它不在沙箱里、能访问整台电脑时也写明。每个 AI 队友只通知一次；你是那个频道的成员时不通知。团队设备列表里，你自己的设备下写着「正在用：项目 · 频道 · AI 队友」，只有你看得到。

## 自有设备上 AI 队友能看到什么 {#machine-access}

AI 队友的环境是「某人的设备」这种沙箱时，它在那个人的一台设备上的沙箱里工作：

- 看得到、能修改：它自己的工作目录，以及本项目的包缓存。
- 看得到、不能修改：系统里安装的程序，例如 `/usr/bin` 下的 `git`、`python3`、`node`。
- 看不到：设备主人用户目录里的内容（`~/.ssh`、各种凭据、文档）、别的 AI 队友，以及 `/mnt`、`/media` 下挂载的磁盘。
- 不能用：安装在用户目录里的工具，例如 nvm 安装的 Node、`~/.cargo/bin` 和 `~/.local/bin` 下的命令。这类工具要安装到系统里，或写进项目的「安装工具（初始化脚本）」。

设备主人可以给一位 AI 队友选「指定我的电脑」：它直接在这台电脑上以主人的身份运行，不隔离。在名册里那位 AI 队友一行点「改」，选「指定我的电脑」和哪台。只有设备主人登录后能这样选，AI 队友自己不能。

> [!WARNING]
> 选「指定我的电脑」后，那位 AI 队友能看到、修改这台电脑上的一切。频道里的每个成员都能通过它读写这些文件，包括 `~/.ssh` 和其他 AI 队友的内容。

沙箱对设备的要求：

- Linux：不需要安装软件，连接器自带 bubblewrap；但要允许普通用户创建用户命名空间，不允许时设备页写明原因，这台设备不放沙箱。Ubuntu 23.10 起，系统的安全模块 AppArmor 默认禁止普通用户创建用户命名空间：设备主人运行一次 `sudo ~/.local/bin/cheesehost sandbox allow`，之后沙箱照常以普通用户运行。
- macOS：不需要安装软件，沙箱使用系统自带的 `sandbox-exec`。沙箱里的程序只能写自己的目录，`/tmp` 换成它自己的临时目录。这些程序连不上这台 Mac 上其他程序打开的本地连接，例如你自己运行的 tmux。
- Windows：还没有沙箱，Windows 设备上不放沙箱。可以在 Windows 上安装 WSL（Windows 自带的 Linux 子系统），把其中的 Linux 按[接入服务器或其他机器](#add-device)接入；或由设备主人给 AI 队友选「指定我的电脑」。

## 用自己的 Claude Code {#own-claude-code}

Claude Code 能用你自己的模型连接运行：在接入的电脑上登录的 Claude 账号，或保存在你账号里的 Anthropic API key、自定义模型服务。Claude Code 加上你的一份模型连接，就是一位你个人的 AI 队友，名字后面带着这份连接的区分：Claude 订阅写套餐，自定义模型服务写模型名称，Anthropic API key 写「API」，给连接起了名字时写这个名字，例如「〈你的昵称〉的 Claude Code（Max）」「〈你的昵称〉的 Claude Code（kimi-k2）」「〈你的昵称〉的 Claude Code（实验室的 Kimi）」。同一个项目里两份连接的区分相同时，后加入的那位带上序号，例如「（Max 2）」。费用由这份连接的账号承担，不扣项目额度。

Claude Code 本身在哪里运行，取决于这份连接存放在哪里。在电脑上登录的连接，Claude Code 在那台电脑上运行，因为登录只留在那台电脑上，不换到你的其他电脑；Claude 订阅只能这样使用，平台不保管订阅的登录。保存在账号里的 API key 和自定义模型服务，Claude Code 在平台上运行，和项目的芝士一样，不需要你的电脑在线。无论哪一种，它读写文件、运行命令都和其他 AI 队友一样在它在这个频道里的[环境](/environment#environment)中进行，默认是沙箱，不一定在你的电脑上。只有环境指定的就是你的电脑时，它才在你的电脑上操作。

在电脑上登录：在桌面端打开「设置 → 这台设备」，点「登录 Claude Code」；使用 Anthropic Console 账号时点「使用 API key」。在打开的浏览器页面中登录，完成后自动回到桌面端。

登录后，「设置 → 这台设备」写着「已登录」和账号的套餐。没有安装桌面端的电脑，在终端运行 `~/.local/bin/cheesehost claude login`（Windows 上是 `cheesehost claude login`）。

不用电脑时，把 API key 或自定义模型服务保存在账号里，见[保存在账号里](#own-claude-code-account)。

登录后它还不在任何项目里。在允许成员接入的项目里，打开「项目设置 → AI 队友」，在「加入我的 Claude Code」下找到这份连接，点「加入」；你有几份连接，就可以加入几位。加入后，频道里输入 `@`，候选中出现它。不再用时，在它那一行点「移出」：成员列表、频道名册和 `@` 候选里都不再有它；以后用同一份连接再加入，它记得的内容还在。只有你能加入和移出自己的 Claude Code。

谁可以叫你的 Claude Code 由你决定：在「项目设置 → AI 队友」里，你那一行的「谁可以叫它」选「只有我」或「项目成员」，默认是「只有我」。选「项目成员」后，项目里的人都能 `@` 它、把任务交给它、和它私聊，用的是你的这份模型连接，费用和账号条款由你自己负责。只有你能叫它时，别人 `@` 它，频道里写着「这是〈你〉的 Claude Code，只有〈你〉能叫它」。AI 队友不能叫它。用的是电脑上登录的连接、而那台电脑不在线时，频道里写着「Claude Code 所在的电脑不在线，电脑上线后自动继续」；账号用量到上限时，写明大约多少分钟后恢复，恢复后自动继续。

项目内容会经由你自己的账号发给模型，所以项目默认不允许成员接入。项目管理员在「项目设置 → AI 队友」中打开「允许成员接入自己的 Claude Code」后，成员才能把自己的 Claude Code 加入这个项目。管理员还可以在「允许的连接类型」里只勾选其中几类：Claude 订阅、Anthropic API key、自定义模型服务。不在其中的连接不能加入；已经加入的一位用的连接不在其中时，叫它不会开始工作，频道里写明是哪类连接不被允许。

管理员还可以在「允许的服务商」里限定自定义模型服务能用哪几家：填服务地址里的主机名，例如 `api.moonshot.cn`，不带 `https://` 和路径。不填表示不限。填了以后，服务地址的主机名不在其中的自定义模型服务不能加入，无论保存在电脑上还是账号里；已经加入的一位用的服务不在其中时，叫它不会开始工作，频道里写明是哪个服务地址不被允许。Claude 订阅和 Anthropic API key 不受这一项限制。

关闭这个开关后，所有成员的 Claude Code 都退出这个项目：成员列表、频道名册和 `@` 候选里都不再有它们。重新打开后，主人加入过的回到成员列表，在频道里第一次被 `@` 时重新加入那个频道。

「项目设置 → AI 队友」列出每位成员加入的 Claude Code、它的主人和连接类型，订阅写明套餐，自定义模型服务写明模型名称；项目不允许的写着「项目不允许」或「项目不允许这家服务商」。用的是哪台电脑、电脑是否在线，只在你自己的那几行显示；用账号里的连接的那几行写着「在平台上运行」。

### 在「模型连接」里查看和解除 {#own-claude-code-connections}

「设置 → 模型连接」列出你的 Claude Code 的每一份连接。在设备上登录的，写着 Claude 订阅和套餐、Anthropic API key，或自定义模型服务的模型和服务地址，以及存放在哪台设备、设备是否在线、上次检查和上次使用的时间，这些密钥只保存在设备上。保存在账号里的，写着 API key 或自定义模型服务的模型和服务地址、密钥的后四位、上次检查的时间和结果。这一页不显示任何密钥，在浏览器和桌面端里都能打开。

设备上的连接：点「重新检查」，在线的设备会重新报告登录状态。点「改名」给它起个名字，用它加入项目的 Claude Code 的名字随之改变，设备离线时也能改；设备之后再报告登录状态，名字不变。点「解除」并确认，名字一并去掉，这份连接立即停止使用，用它加入项目的 Claude Code 不会再开始工作，叫它时频道里写着这份连接已解除；设备在线时当场退出登录，不在线时写着「解除中」，设备上线后自动退出。你在这台设备上自己使用的 Claude Code 不受影响。

账号里的连接：点「测试」，平台用这份连接再调用一次服务，结果写在那一行上，没通过时写着服务返回的原因。点「改名」给它起个名字，用它加入项目的 Claude Code 的名字随之改变。点「解除」并确认，密钥立即从平台删除，用它加入项目的 Claude Code 不会再开始工作，叫它时频道里写着这份连接已解除。

### 保存在账号里 {#own-claude-code-account}

Anthropic API key 和兼容 Anthropic 接口的自定义模型服务（例如 GLM、Kimi、DeepSeek）可以保存在账号里，不需要电脑：

1. 打开「设置 → 模型连接」，点「添加 API key」或「添加模型服务」。
2. 填写 key；添加模型服务时还要填写服务地址（以 `https://` 开头）和模型名称。可以填一个名称，用来区分几份连接。
3. 点「保存」。平台先用这份连接调用一次服务：API key 向 Anthropic 查询一次模型列表，不产生费用；模型服务用这个模型发一条最短的消息。服务拒绝时不保存，并写明服务返回的原因。

保存后，密钥加密保存在平台上，只显示后四位，不再返回给任何人。用它加入项目的 Claude Code 在平台上运行，只有这位 Claude Code 的会话用这份密钥调用模型，费用记在这份连接的账号上，不用平台的模型服务，也不扣项目额度。它运行命令的环境拿不到这份密钥。Claude 订阅不能保存在账号里，只能在电脑上登录。

### 改用其他模型服务 {#own-claude-code-model-service}

电脑上的 Claude Code 能改用兼容 Anthropic 接口的其他模型服务，例如 GLM、Kimi、DeepSeek。在桌面端「设置 → 这台设备」点「使用自定义模型服务」，填写服务地址、密钥和模型名称，点「保存」。在任何浏览器里，也可以在「设置 → 模型连接」点「在设备上使用自定义模型服务」，选一台在线的设备再填写；密钥直接发送到那台设备，平台不保存。

保存后这一栏写着「使用自定义模型服务（模型名称）」，Claude Code 的调用都改用这个模型，密钥只保存在这台电脑上。改回 Claude 账号时，点「退出登录」，再点「登录 Claude Code」。

没有安装桌面端的电脑，运行 `~/.local/bin/cheesehost claude login --base-url <服务地址> --model <模型名称>`，再按提示输入密钥。

## 提示电脑没有连上平台 {#device-offline}

频道里出现「「〈电脑〉」没有连上平台」或「这个规格的电脑现在都不在线，或者都给不了沙箱」，表示 AI 队友的环境要用的自有设备现在不在线。

1. 点左下角的头像，打开「设置 → 设备」，看这台设备是否「在线」。不在线时，在那台电脑上打开桌面端，或重新运行 `cheesehost link connect`。
2. 设备是团队的设备时，在团队的「设备」页确认它在列表中。
3. 设备在线但仍然出现提示时，打开频道名册，在那位 AI 队友一行点「改」，换一个环境。

提示「选定的那台电脑已经解绑，需要重新选执行环境」时，直接在名册里那位 AI 队友一行点「改」另选。
