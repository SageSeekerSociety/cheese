# 自有设备 {#devices}

自有设备是你接入知是的电脑或服务器，例如实验室里那台存着数据的 Linux 服务器：接入后，频道可以把它作为[环境](/environment#environment)，芝士在上面读写文件、运行命令。

## 接入 Mac 或 Windows 电脑 {#desktop}

Mac 和 Windows 电脑通过安装桌面端接入。从团队的「设备」页点「接入设备」，再点「下载桌面端」。登录桌面端后，还没接入过的电脑自己接入你的个人团队；要用在别的团队上，去那个团队的「设备」页点「接入这台电脑」，选团队、点「接入」。完整步骤见[让芝士在你自己的电脑上工作](/use-your-computer#connect)。

接入后，桌面端的「设置 → 这台设备」列出这台电脑的各次接入、所属团队和在线状态。点团队名进入团队的「设备」页，由管理员修改设备名称或移除接入。桌面端启动时和之后每 6 小时检查一次新版本，下载完成后点「重启以完成更新」安装。

### 接入服务器或其他机器 {#add-device}

服务器、Linux 机器，或不装桌面端的电脑，用命令行接入。需要是目标团队的管理员：

1. 打开团队的「设备」页，点「接入设备」。
2. 在要接入的机器上运行对应系统的安装命令。
3. 运行页面给出的接入命令。命令输出一个批准链接。
4. 在浏览器打开链接，核对「设备名称」和「接入团队」，点「批准接入」。


批准后，命令行接着完成接入并保持连接。设备出现在所选团队的「设备」页，显示「在线」。

## 设备所属团队 {#team-device}

每次接入只属于一个团队，团队下所有项目都能使用。未另选团队时，接入自己的个人团队。同一台电脑接入另一个团队时，创建独立的接入；两次接入的凭据和工作目录分开。

「设备」页每台设备一行，写明在线或离线；离线的设备注明上次在线时间。团队管理员在设备行点「重命名」修改设备名称，点「移除」并确认后这次接入失效；管理员也负责允许 AI 队友访问整台机器和批准 MCP 命令。接入设备的人退出团队后，不再拥有这些权限，设备继续属于团队。设备行只显示设备信息；模型连接在团队的「模型」页管理，并注明登录存放在哪台设备上。

AI 队友开始在设备上工作时，不在那个频道里的团队管理员收到通知，写明项目、频道和是否访问整台机器。桌面端的「这台设备」列出本机正在工作的 AI 队友。

## 自有设备上 AI 队友能看到什么 {#machine-access}

AI 队友的环境是「团队设备」时，它在这个团队的一台设备上的沙箱里工作：

- 看得到、能修改：它自己的工作目录，以及本项目的包缓存。
- 看得到、不能修改：系统里安装的程序，例如 `/usr/bin` 下的 `git`、`python3`、`node`。
- 看不到：设备主人用户目录里的内容（`~/.ssh`、各种凭据、文档）、别的 AI 队友，以及 `/mnt`、`/media` 下挂载的磁盘。
- 不能用：安装在用户目录里的工具，例如 nvm 安装的 Node、`~/.cargo/bin` 和 `~/.local/bin` 下的命令。这类工具要安装到系统里，或写进项目的「安装工具（初始化脚本）」。

团队管理员可以给一位 AI 队友选「指定我的电脑」：它直接在这台电脑上以主人的身份运行，不隔离。在名册里那位 AI 队友一行点「改」，选「指定我的电脑」和哪台。只有团队管理员登录后能这样选，AI 队友自己不能。

> [!WARNING]
> 选「指定我的电脑」后，那位 AI 队友能看到、修改这台电脑上的一切。频道里的每个成员都能通过它读写这些文件，包括 `~/.ssh` 和其他 AI 队友的内容。

沙箱对设备的要求：

- Linux：不需要安装软件，连接器自带 bubblewrap；但要允许普通用户创建用户命名空间，不允许时设备页写明原因，这台设备不放沙箱。Ubuntu 23.10 起，系统的安全模块 AppArmor 默认禁止普通用户创建用户命名空间：设备主人运行一次 `sudo ~/.local/bin/cheesehost sandbox allow`，之后沙箱照常以普通用户运行。
- macOS：不需要安装软件，沙箱使用系统自带的 `sandbox-exec`。沙箱里的程序只能写自己的目录，`/tmp` 换成它自己的临时目录。这些程序连不上这台 Mac 上其他程序打开的本地连接，例如你自己运行的 tmux。
- Windows：还没有沙箱，Windows 设备上不放沙箱。可以在 Windows 上安装 WSL（Windows 自带的 Linux 子系统），把其中的 Linux 按[接入服务器或其他机器](#add-device)接入；或由团队管理员给 AI 队友选「指定我的电脑」。

## 团队的模型连接 {#own-claude-code}

模型连接是一份模型账号或服务，例如实验室的 Claude 订阅或 API key。团队管理员添加的连接用于团队的各个项目，由管理员管理。成员也能把自己的连接加入团队，只用于本人的助理。平台模型使用团队额度，自有连接的费用记在对应模型账号上。

Claude 订阅的凭据留在完成登录的电脑上，需要这台电脑在线。电脑不需要接入团队的设备列表。API key 和兼容 Anthropic 接口的模型服务加密保存在平台上。AI 队友读写文件、运行命令所用的执行设备需要另行选择。

添加 Claude 订阅需要团队管理员权限：

1. 打开团队的「模型」页，点「添加 Claude 订阅」。
2. 在桌面端打开的浏览器中完成登录。使用网页时，在要保存登录的电脑上运行页面给出的命令。
3. 登录完成后，点页头的「重新检查」，连接出现在「订阅与电脑上的登录」中。

同一个 Claude 账号或 API key 可以在两个团队分别添加，两份连接各自管理。订阅每次添加使用独立的登录目录，解除一份不会退出其他登录。

把已有的个人连接加入共享团队：

1. 打开共享团队的「模型」页，点页头的「添加我的连接」。
2. 在「模型连接」中选择本人已有的连接。
3. 点「添加我的连接」，列表显示这份连接和所属成员。

同一份个人连接可以加入多个团队，使用的是同一份凭据。本人管理连接；团队管理员可以将它「移出团队」，原连接仍然保留。修改连接会影响所有使用它的团队。

在「项目设置 → AI 队友」添加队友：

1. 选择团队的「模型连接」。
2. 从这份连接允许的模型中选择「模型」。
3. 选择「执行设备」，点「添加 AI 队友」。新队友出现在 AI 队友列表和 `@` 候选中。

使用团队连接添加队友需要项目的 AI 队友配置权限。成员可以使用自己的个人连接添加和停用本人的助理，不需要这项配置权限。

成员的私人助手仍可以在提示词中写明归属和征求同意的要求。其他项目成员和 AI 仍能点名、私聊和分配任务，平台不按这份成员归属拦截调用；提示词约定不构成访问隔离。私密频道里例外：只有频道成员自己的助手出现在 `@` 候选中，点名也不会把频道外成员的助手拉进频道。

### 查看和解除连接 {#own-claude-code-connections}

团队的「模型」页列出平台模型、电脑上的登录，以及「API key 与模型服务」。每份连接写明可用模型；个人连接还显示所属成员；订阅登录显示它登录的 Claude 账号邮箱，同一台电脑上的几份登录靠它区分，电脑在线时每次检查都会更新；团队连接的账号团队成员都能看到，个人连接的账号只有所属成员本人看得到。订阅所在电脑是团队设备时显示名称，否则其他成员只看到电脑 id；电脑离线时，这份订阅显示「离线」，不能使用。平台保存的密钥只显示后四位。

点连接所在行展开详情，查看登录账号及其组织、存放位置、上次检查和使用时间。管理这份连接的成员可以在「可用模型」中修改后点「保存模型」，也可以重新检查、改名、解除连接。使用这份连接的队友名称随连接名称更新。

解除设备上的登录后，这份连接立即停止用于新工作。在线设备当场退出登录；离线设备显示「解除中」，上线后自动退出。解除平台保存的连接后，密钥立即删除，已经运行的模型进程在结束前仍持有这份密钥。

### 在平台上保存 API key 或模型服务 {#own-claude-code-account}

团队管理员可以添加 Anthropic API key，或兼容 Anthropic 接口的模型服务：

1. 打开团队的「模型」页，在「API key 与模型服务」中点「添加 API key」或「添加模型服务」。
2. 填写密钥。添加模型服务时，再填写以 `https://` 开头的服务地址和模型名称。
3. 点「保存」。平台先检查服务，检查通过后连接出现在列表中；未通过时显示原因，并保留表单内容。

密钥加密保存在平台上，不再显示完整值。模型进程使用这份密钥调用服务，执行设备拿不到密钥。Claude 订阅的登录凭据保存在设备上。

### 使用其他模型服务 {#own-claude-code-model-service}

兼容 Anthropic 接口的服务通过「添加模型服务」接入，见[在平台上保存 API key 或模型服务](#own-claude-code-account)。添加后，展开连接，在「可用模型」中设置项目可以选择的模型。

## 提示电脑没有连上平台 {#device-offline}

频道里出现「「〈电脑〉」没有连上平台」或「这个规格的电脑现在都不在线，或者都给不了沙箱」，表示 AI 队友的环境要用的自有设备现在不在线。

1. 打开所属团队的「设备」页，看这台设备是否「在线」。不在线时，在那台电脑上打开桌面端，或重新运行 `cheesehost link connect`。
2. 在桌面端打开「设置 → 这台设备」，核对这次接入的所属团队。
3. 设备在线但仍然出现提示时，打开频道名册，在那位 AI 队友一行点「改」，换一个环境。

提示「选定的那台电脑已经解绑，需要重新选执行环境」时，直接在名册里那位 AI 队友一行点「改」另选。
