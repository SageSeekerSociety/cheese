# 连接与集成 {#connections}

连接让 AI 队友使用知是以外的服务，例如你的邮箱和飞书、项目的 GitHub 仓库，以及 Notion 这类服务。项目连接 Notion 之后，芝士可以读取团队在 Notion 里的组会安排。

## 个人连接与项目连接 {#kinds}

连接分两种，区别在于用谁的账号、由谁管理。

| | 个人连接 | 项目连接 |
|---|---|---|
| 包括 | 邮箱、飞书 | GitHub、Notion |
| 管理入口 | 个人设置 | 项目设置 |
| 账号 | 你自己的 | 授权人的 |
| 用于 | 你勾选的项目 | 这个项目 |

## 邮箱与飞书 {#mail-feishu}

点左下角的头像，选「设置」，再点「连接」。在这里接入自己的邮箱或飞书，并选择允许哪些项目的 AI 队友使用。AI 队友以你的账号读邮件、写草稿、读写飞书文档。这些账号只有你自己能管理。

- 「接入邮箱」：选「邮箱服务」，填「邮箱地址」和「密码或授权码」，点「测试并保存」。
- 「连接飞书」：跳到飞书的授权页，用你的飞书账号授权。平台还没配置飞书应用时，这个按钮是灰色的，下方写着「管理员还没配置飞书应用」。

QQ、163 等邮箱要先在邮箱的设置里开启 IMAP/SMTP，即允许其他程序收发这个邮箱的邮件，再生成授权码填进来。Gmail 填应用专用密码。

接入后，每个账号是「已接入的账号」中的一行，右侧是状态：「正常」「授权已失效」「无法连接」或「异常」。在这一行的「允许这些项目的 AI 队友使用」中勾选项目。只有勾选的项目里，AI 队友能使用这个账号。

### 芝士写的邮件由你发送 {#mail-drafts}

芝士写的邮件只放进你邮箱的草稿箱，同时列在「连接」页的「待发送的邮件」里。每封写明收件人、主题、正文、附件和来自哪个项目。点「发送」并确认后才发出，发出后无法撤回；不发送时点「丢弃」。

邮件的附件只能是频道里的文件。起草之后附件有改动时，平台拒绝发送这封邮件。

## GitHub {#github}

新建项目时「代码仓库」选「连接 GitHub」的项目，要在「项目设置 → 仓库与署名」中连接一个 GitHub 仓库。连接之后，芝士的提交和 PR（请求把改动合入仓库的申请）都在这个仓库里。连接由项目所有者或团队管理员完成，步骤见[连接 GitHub 仓库](/projects#upstream)。

用 GitHub 登录知是，或在知是里连接 GitHub 后，「个人设置 → 安全 → 已关联账号」会显示这个 GitHub 账号。已经用别的方式登录了知是的，在项目设置的「仓库与署名」中点「连接 GitHub」（提交署名给任务负责人时显示），GitHub 就连接到当前账号，不需要密码。授权在浏览器中完成，这个浏览器要登录着同一个知是账号；从桌面 app 发起时，结果会回到 app。授权失效时，点「重新授权 GitHub」。

在登录页用 GitHub 登录时，如果要关联的已有知是账号尚未设置密码，先用原来的方式登录知是，再按上面的办法连接 GitHub；也可以先在「个人设置 → 安全」中设置密码，再用 GitHub 登录。从知是发起授权时，如果这个 GitHub 账号已关联其他知是账号，或者当前账号已连接的是另一个 GitHub 账号，授权会被拒绝：先在 GitHub 切换到正确的账号，再从知是重新发起。

项目的「提交署名」给任务负责人时，你负责的任务用登录所用的 GitHub 账号创建 PR：提交作者是你，芝士列为共同作者。未连接 GitHub、授权失效或这个账号对仓库没有写权限时，PR 由芝士创建，你列为共同作者，任务里 PR 的下方会写明。连接仓库时，平台也用这个账号确认你对仓库有写权限。

## MCP 服务器 {#mcp}

MCP 是一种让 AI 调用外部服务的通用接口。项目接入 MCP 服务器之后，AI 队友就能使用这些服务的功能，例如搜索和读取 Notion 页面。

### 两种服务器 {#mcp-kinds}

「项目设置 → MCP 服务器」把项目的服务器分成两组：

| 分组 | 是什么 | 从哪来 |
| --- | --- | --- |
| 「远程」 | 服务提供的一个地址，例如 Notion 的 `https://mcp.notion.com/mcp`。平台以项目连接的账号调用它 | 在这一页添加，或写在项目的 `.mcp.json` 里 |
| 「在项目机器上运行」 | 一条命令，例如 `npx -y @playwright/mcp@latest`。它在项目的机器上运行 | 在这一页添加，或写在项目的 `.mcp.json` 里 |

AI 队友类型也可以自带服务器，这一行标着「由 … 类型声明」。

### 声明：项目里的 .mcp.json {#mcp-json}

项目要用哪些 MCP 服务器，可以写在项目文件最外层的 `.mcp.json` 里。这个文件一般交给芝士添加，例如：

```json
{
  "mcpServers": {
    "notion": { "type": "http", "url": "https://mcp.notion.com/mcp" },
    "playwright": { "command": "npx", "args": ["-y", "@playwright/mcp@latest"] }
  }
}
```

芝士添加之后，采纳这次交付，服务器才会出现在「项目设置 → MCP 服务器」中：平台只读取项目已采纳的版本。带 `url` 的条目在「远程」一组，带 `command` 的在「在项目机器上运行」一组。

### 在设置里添加服务器 {#mcp-add}

:::before
需要「配置 AI 队友」权限。
:::

添加远程服务器：

1. 在「项目设置 → MCP 服务器」中点「添加服务器」。
2. 「类型」选「远程」，填「名称」和「地址」。地址以 `https://` 开头。
3. 选「登录方式」：「用账号登录」，或「填写请求头」并填上请求头的名称和值（例如 API 密钥）。
4. 点「添加」。这一行出现在「远程」一组，写着「… 添加」。

添加在项目机器上运行的命令：

1. 在「项目设置 → MCP 服务器」中点「添加服务器」。
2. 「类型」选「在项目机器上运行」，填「名称」和「命令」，例如 `npx -y @playwright/mcp@latest`。
3. 命令要用到密钥时，在命令或「环境变量」里写成 `${API_KEY}` 这样的变量，不写密钥本身。
4. 点「添加」。这一行出现在「在项目机器上运行」一组；用到变量的，点「填写」填上变量的值。

在设置里添加的服务器可以「编辑」和「删除」。改了远程服务器的地址，已有的连接和请求头会被清除，要重新连接或重新填值。改了命令，项目机器是成员自己的设备时，要设备所属团队的管理员重新允许。名字和 `.mcp.json` 里的重了，以 `.mcp.json` 里的为准，设置里这一条显示「不生效：仓库里有同名服务器」。

### 连接 {#mcp-connect}

「远程」一组上方写着「项目里所有人通过芝士共用同一个账号连接这些服务器」。

```demo-panel
title: 连接 notion
caption: 在 Notion 的授权页上授权后回到这一页，这一行写明由谁授权。
parts:
  - kind: head
    title: MCP 服务器
    plain: true
  - kind: row
    title: notion
    sub: mcp.notion.com
    status: 未连接
    button: 连接
    press: 1
    until: 1
  - kind: row
    title: notion
    sub: mcp.notion.com
    status: 已连接
    at: 1
```

- 「未连接」：点「连接」，确认框里点「去授权」，跳到服务自己的授权页，授权后回到这一页。
- 「已连接」：可以使用，下面写着由谁授权。右侧的「断开」取消连接。
- 「需要重新连接」：授权过期或被拒绝，或者地址改了。点「重新连接」。
- 「需要填写 …」：这个服务器用访问密钥授权，不走授权页。点「填写」，在输入框里填入服务提供的密钥，点「保存」，状态变为「已就绪」。

有「配置 AI 队友」权限的成员能连接、断开和填写密钥。连接属于整个项目：之后这个项目里的 AI 队友都以授权人的账号使用这个服务，所以建议用机器人或服务账号授权。机器人或服务账号是专为程序使用开设的账号，可以只开放项目需要的内容。填过的密钥不再显示，点「修改值」时输入框里只写「已填写」。

### 在项目机器上运行的服务器 {#mcp-local}

这一组的服务器是一条命令，平台在项目的机器上运行它。每一行写着命令和状态：

- 「运行中」：已经启动，AI 队友可以使用。
- 「未启动」：还没有 AI 队友用到它。第一次用到时才启动。
- 「启动失败」：点「查看日志」，看它最后输出的几行。
- 「等 … 允许」：项目的机器是团队的自有设备。命令第一次在这台电脑上运行之前，要团队管理员在「待办 → 等你处理」里点「允许运行」。允许过的同一条命令不再询问；命令改了会再问。

命令里写的 `${变量}` 可以在这一行填值：点「填写」，填好后点「保存」。这些值会交给在项目机器上运行的命令，AI 队友能读到它们，所以只填这个命令需要的值。

平台在项目机器上提供 Node 24（`node`、`npm`、`npx`）和 uv（`uv`、`uvx`），所以 `npx` 和 `uvx` 启动的服务器直接可用。机器上已经装了 Node 的，用机器自己的。Docker、Deno、Bun 不提供；需要它们的服务器，放在自己的电脑上运行，或者改用服务提供的远程地址。第一次启动要从 npm 或 PyPI 下载，可能要等一会儿。

## 连接之后芝士能做什么 {#after-connect}

MCP 服务器连接后，项目里每个频道和任务的 AI 队友都能使用它，不需要再设置。还没连接时，芝士回复的支线顶部出现一行灰色提示，例如「notion 需要在项目设置里连接」，芝士也会说明它用不了这个服务。

邮箱和飞书只在你勾选的项目里可用。芝士在那里以你的账号读取和起草，邮件由你发送。

## 断开与删除 {#disconnect}

- MCP 服务器：在「项目设置 → MCP 服务器」中点「断开」。之后 AI 队友不能使用这个服务，直到有人重新连接。在设置里添加的服务器点「删除」，它的连接和请求头一并清除。
- 邮箱和飞书：在「个人设置 → 连接」中点这个账号的「删除」。删除后 AI 队友不能再使用这个账号，保存的密码或密钥同时删除。只想停用某个项目时，在「允许这些项目的 AI 队友使用」中去掉这个项目。
- GitHub 账号：在「个人设置 → 安全」中点 GitHub 那一行的「解除关联」。解除后不能再用 GitHub 登录，你负责的任务改由芝士创建 PR。
