# 项目 {#projects}

项目是一件事的工作空间，例如一份大作业「B 树大作业」：做这件事的成员、对话和文件都放在这个项目里。

## 新建项目 {#create-project}

点最左侧一列项目图标下方的「＋」（「新建项目」）新建项目。在团队的「项目」页点「新建项目」也可以。新建时要做两个决定：

- 「归属」：选你自己（「你名下，可以另外邀请人」）时，项目只有你一个人，之后可以逐个[邀请成员](#invite-project-member)。选一个团队（「团队的 N 位成员会自动加入」）时，团队成员都成为项目成员。
- 「代码仓库」：保持「平台托管（默认）」时，项目文件由平台保存。选「连接 GitHub」时，建好后在「项目设置 → 仓库与署名」连接一个 GitHub 仓库，见[连接 GitHub 仓库](#upstream)。这一项建好后不能再修改。

「你打算做什么（可选）」写一句项目的目标，例如「帮我把这学期的课程材料整理成一份大纲」。下一步给项目的 AI 队友起名字，名字已随机填好，可以修改。点「创建项目」后进入频道「综合」。

第一次登录时的新手引导见[快速开始](/quickstart#project)，在团队下建项目见[和同学一起做一个项目](/team-project#project)。

## 项目里的页面 {#project-navigation}

项目左侧栏最上面是项目名，下面是「总览」和「资料库」，再往下是「频道」分组。分组的第一行是「综合」，最后一行是「浏览频道」。[资料库](/files#library)存放项目的文档和文件，频道的用法见[频道](/rooms#rooms)。

点项目名打开项目菜单。菜单上半部分是「项目文档」「成员」「例行事务」「技能」和「全部任务」，下半部分是「项目设置」，以及「转让项目」或「退出项目」。

在手机上，「总览」和「资料库」也在这个菜单里，频道列表最上面另有一行「总览」。

## 总览 {#project-home}

「总览」是项目的首页。最上面是「现状」，下面左侧是「项目目标」和「最近进展」，右侧是「谁在做什么」和「做出了什么」：

![项目「总览」页：顶部芝士整理的现状，项目目标里的分工和约定，最近进展，林晓手上的两个任务，以及暂无产物的成果区](/images/overview.jpg)

- 「现状」：页面最上面的一段，第一句说项目整体处在什么阶段，下面分几块列出项目要做出来的东西，每块标「可用」「进行中」或「未开始」。它由项目自己的模型写成，材料是项目目标、近两周做完和还在做的任务，以及各公开频道近两周的讨论；私聊和私密频道不算在内。写了项目目标时，它对照目标说还差什么；没写时只讲现状。
- 现状在有人打开「总览」时按需重写，打开页面不用等它：先显示上一次写的，写好后自动换上。任务新建、关闭、有交付被采纳，或者项目目标改了，离上次重写满 5 分钟就重写；只是频道里有新的讨论，满 1 小时才重写。近两周项目里什么都没发生时，这一段不显示。
- 「项目目标」：这个项目要做成什么、什么时候做成、这阶段不做什么，是一份所有成员都能改的文档，AI 队友在每段对话里都会读它。点「编辑项目目标」修改；还没写时显示「暂无项目目标」和要写什么。
- 「最近进展」：最近两周的事，按天排列，例如任务的新建、采纳、退回，以及成果的新版本。点一条打开对应的任务或成果。
- 「谁在做什么」：进行中的任务按负责人分组，你的排在最前面。每件只写状态，例如「在做」「待审阅」「待回答」，等你处理的那几件状态加粗；「全部任务」打开项目的[全部任务](/tasks#board)。
- 「做出了什么」：采纳后的成果和发布的网站。成果的「⋯」里可以「重命名」「合并到…」和「删除」；网站见[发布网站](/sites#publish)。

## 成员从哪里来 {#project-members}

项目属于团队时，团队成员自动出现在项目的「成员」页，他们的加入和退出在[团队](/teams#teams)里管理。团队以外的人要单独邀请，接受后成为外部成员。外部成员只参与这一个项目；在项目里能做什么，和团队成员一样只看角色。

每个人在项目里有一个角色。「成员」页是一张名单：所有者在最前，然后是管理员，再往下是其他人，每一行写着这个人的角色；名单下面是「等待接受」和「AI 队友」。成员超过 8 人或项目有自己的角色时，名单上方有搜索框和「全部角色」筛选。

| 角色 | 是谁 |
|---|---|
| 所有者 | 默认是创建项目的人，拥有全部权限。团队的所有者在团队的每个项目里也是所有者 |
| 管理员 | 管理成员、角色和项目设置。团队的管理员在团队的每个项目里都是管理员 |
| 成员 | 参与项目里的工作。团队成员进项目时是这个角色 |
| 项目自己的角色 | 项目在「角色和权限」里新增的角色，名字和权限由项目定，例如只能发言和评论的「内测用户」 |

导师是一种项目自己的角色，照导师模板建出：查看项目，发言和评论，在文档里只能提修改建议，看不到私聊和没有拉导师进去的私密频道。项目用不到导师时，角色里没有它。

每个角色具体能做什么，在「项目设置 → 角色和权限」里，见[角色和权限](#roles)。

### 邀请成员和导师 {#invite-project-member}

在「成员」页右上角点「邀请」，在「角色」里选一个管理员以外的角色，再按完整的用户名或邮箱邀请。「角色」的最后一项总是「导师」：项目还没有导师角色时，发出邀请会照导师模板建出来。能邀请和移出成员的默认是管理员和所有者。对方接受之前，邀请列在「等待接受」下，点「撤回」收回。完整过程见[邀请一个人加入你的项目](/invite-to-project#invite-to-project)。

比你角色低的人那一行，角色是一个下拉，选一个就换成那个角色；「⋯」里是「移出项目」。管理员能给除管理员以外的人换角色；只有所有者能把人设为管理员，也只有所有者能把管理员换成别的角色。团队成员被移出后仍在团队里。团队所有者和团队管理员的身份来自团队，在[团队](/teams#teams)里修改。

### 转让和退出 {#transfer}

所有者以外的人在项目菜单或「成员」页右上角点「退出项目」。所有者不能退出，要先「转让项目」：

1. 在「成员」页右上角点「转让项目」。
2. 选一位项目里能编辑文档和文件的人，点「发出转让」。
3. 「所有者」下面出现「等待某人接受转让」；对方在「等你处理」里点「接受」之前，项目不变。

对方接受后，项目归对方所有，你变成管理员。你名下的项目转让后会移到对方名下。转让发出后，点「撤回转让」收回。

你名下的项目也可以「移到团队」：在「成员」页右上角点「移到团队」，选一个你管理的团队。项目里的人和角色保持不变，团队里的人都能看到这个项目。

## 项目设置 {#settings}

点项目名，在菜单中点「项目设置」。左侧按组列出各项：

- 「协作」：「角色和权限」「频道」「项目地址」。
- 「AI」：「AI 队友」（见 [AI 队友](/agents#agents)）、「任务命名」。
- 「运行」：「环境」，包括新 AI 队友默认使用的环境和项目的额度，见[项目的环境](/environment#project-environment)。
- 「代码」：「合并规则」「仓库与署名」「MCP 服务器」。
- 「数据」：「导出项目」，把代码仓库、资料库文件、各频道的文件与产物和每份文档打包下载。
- 「归档项目」：只有所有者看得到。

「项目主模型」「默认分身模型」「任务命名」「新 AI 队友默认使用」和「提交署名」这几项，有「修改项目设置」权限的人能改，默认是管理员和所有者；AI 队友不能改。每次改动都在「综合」里留下一行，写明谁把哪一项从什么改成了什么。模型仍受团队方案的限制。

### 角色和权限 {#roles}

「项目设置 → 角色和权限」列出项目的角色，每行写着有几个人。管理员和成员排在最上面，名字固定，不能删除；项目自己的角色排在下面。点一个角色，打开它自己那一页，页上按组列出每项权限的开关。项目里的人都能打开看，只有管理员能拨。所有者拥有全部权限，不算角色。

「邀请和移出成员」「修改角色」两项带锁，不能修改：管理员始终有，别的角色始终没有。管理员或成员的权限改过以后，那一页右上角「⋯」里出现「恢复默认」。

新增一个角色：

1. 在「角色和权限」右上角点「新增角色」。
2. 填「角色名称」。
3. 在「权限复制自」里选一个现有角色，新角色先拿到和它一样的权限。项目还没有导师角色时，这里最后一项是带「模板」标记的「导师」，选它可以不填名称。
4. 点「新增」。新角色那一页打开，在页上逐项调整权限。

项目自己的角色那一页右上角「⋯」里有「重命名」和「删除角色」。还有人是这个角色时，删除前先在「这个角色的 N 人改为」里选一个角色，这些人和发给这个角色的邀请都换成它。

## 连接 GitHub 仓库 {#upstream}

新建时「代码仓库」选了「连接 GitHub」的项目，在「项目设置 → 仓库与署名」中填写「GitHub 仓库地址」，点「保存」，再点「连接 GitHub 仓库」，按提示授权。

连接要由有「修改项目设置」权限的人完成，默认是管理员和所有者。完成的人需要先连接 GitHub（用 GitHub 登录知是，或在「仓库与署名」中点「连接 GitHub」），并对这个仓库有写权限。GitHub 授权失效时，重新授权 GitHub 后再连接仓库。

一个 GitHub 仓库只能连接一个项目。仓库已经连接在别的项目上时，连接失败，提示里写明是哪个项目（你是那个项目的成员时）。

平台托管的项目没有这一步；在频道里使用芝士也不需要 GitHub。

## 归档项目 {#archive-project}

不再使用的项目可以归档，内容全部保留，随时可以取消归档。只有所有者能归档和取消归档；平台没有删除项目的入口。

在「项目设置」最下面点「归档项目」，输入项目名称确认，再点「归档」。归档之后：

- 项目从所有成员的项目列表和团队的「项目」页中消失。打开项目链接，看到的是「项目已归档」。
- 项目不能再修改：发消息、建频道、改设置、邀请成员都会被拒绝。
- 正在运行的任务停止，平台回收频道的环境。定时任务不再运行，平台不再跟进项目在 GitHub 上的合并请求（PR）。
- 尚未接受的邀请被撤回。
- 频道、文件、审阅记录、额度用量和仓库连接都保留；已发布的网站仍然打得开。

取消归档：点左下角的头像，打开「已归档的项目」，在那一行点「取消归档」。也可以打开项目链接，在「项目已归档」页点「取消归档」。随项目归档的频道随之恢复，被撤回的邀请不会恢复。
