# 发布网站 {#sites}

芝士在项目里做出的网页，可以发布成一个项目网站，发一个链接给别人看。

## 能发布什么 {#what}

能发布的是项目**已采纳版本**里的网页：一个包含 `index.html` 的目录，以及它引用的文件。没有采纳的改动、没有提交的文件不会被发布。

- 只托管静态文件，不运行构建脚本，也不运行后端程序。React、Vite 这类项目要先构建出静态文件、采纳后再发布。
- 所有资源都要在所选目录里。上限是 2000 个文件、总计 100MB，入口 HTML 不超过 1MB。

## 发布 {#publish}

1. 点击侧栏顶部的项目名，打开项目首页。「做出了什么」一栏的最上面是网站那一行，没发布过时显示「暂无已发布的网站」。
2. 点这一行右侧的「发布」，弹出「发布网站」。
3. 确认「网站入口」（项目里有多个网页目录时是一个下拉框，只有一个时直接显示，比如 `index.html`），点弹窗里的「发布」。

完成后：这一行显示网站地址，点开就是线上的那一版。

项目负责人和团队管理员可以发布。话题右侧预览里的「发布网站」按钮，也会把你带到这里。

## 更新 {#update}

网站发布后，再采纳新的改动**不会**自动更新网站。要更新时，回到同一行点「发布更新」。

- 线上已经是最新采纳的那一版时，「发布更新」是灰的，弹窗里写着「线上的就是已采纳的这一版」。
- 发布过程中项目又采纳了新版本，会提示「项目已采纳的版本变了，确认之后再发布」，确认后重新发布即可。
- 发布失败时，线上仍是上一版。

已经打开网站的人，刷新后才会看到新版。

## 谁能打开 {#access}

网站的地址是 `/sites/<项目编号>`。打开时会先登录，只有这个项目和所属团队的成员能访问；发布不会让网站变成公开的。打开网站不需要开发机器在线。

## 和话题里的预览有什么区别 {#preview}

话题右侧的预览展示的是工作区里当前的文件或正在运行的应用，随时在变；项目网站展示的是你发布的那一版，发布后固定不变。在话题里预览不会发布网站。
