# 技能 {#skills}

技能是项目保存下来的一套做法，AI 队友遇到同类的事时按它执行。例如项目保存了一项「组会周报」，之后让芝士写周报，它都按这项技能里的格式和步骤写周报。

## 一项技能 {#skill}

一项技能由下面几部分组成，和新建技能时填写的字段一一对应：

- 「名称」：给人看的名字，例如「组会周报」。
- 「调用名」：技能在芝士那里的名字，由小写字母、数字和连字符组成，例如 `weekly-report`，项目里不能重复。新建时预填一个，例如 `skill-1`，建议改成看得出用途的名字；保存之后不能再修改。
- 「用途」：一两句话，说明什么时候用这项技能。芝士根据这一句判断当前这件事是否适用这项技能。
- 「正文」：具体做法。新建时预填了「需要的输入」「步骤与规则」「输出要求」三个小标题。
- 「配套文件」：可选，例如一份模板或一个检查脚本。最多 30 个文本文件，每个不超过 200 KB。

## 芝士怎么用技能 {#use}

项目保存的技能，对之后每个频道和任务里的芝士都有效。芝士平时只看每项技能的名称和用途；判断这件事适用某项技能时，才读正文并按它执行。消息里点名技能时，芝士直接使用它，例如：

```prompt
用项目技能“组会周报”写一份本周周报。
```

芝士每次都以这一次给的材料为准，不沿用上一次的内容。缺少技能要求的输入时，芝士先提问。你纠正芝士按技能做出的结果时，芝士会提议修改这项技能。

## 平台自带的技能 {#built-in}

除了项目自己的技能，平台还为所有项目提供几项通用技能，例如处理 Word、PPT、Excel 文件，制作网页和报告页，数值计算。它们不在技能页上列出，项目技能也不能和它们重名。

## 技能从哪来 {#sources}

技能页在项目菜单的「技能」里（点左侧栏顶部的项目名打开项目菜单）。列表中「本项目」下是正在用的技能，每一行右侧写着来源和版本，例如「手写」「第 2 版 · 10月10日」。

- 手写：点右上角的「新建」，填写各项后点「保存」。
- 芝士整理：芝士把你在项目里多次交代的同一类做法整理成一项技能，提议新增，见下一节。
- 导入：点「导入」，上传 `SKILL.md` 或技能文件夹的 `.zip`，或者填 GitHub 上技能文件夹的地址，点「读取」。确认内容后点「添加」。

只有项目管理员能导入。导入的技能可能带有脚本，芝士会在频道的环境里运行它们，读取后的弹窗会写明「含 N 个脚本，会在环境里运行。添加前先看一遍」。

### 芝士提议的技能 {#proposals}

芝士提议新增一项技能时，它那次回复的最后附一张卡片，写着技能的名称、「提议新增技能」和「待确认」。点这张卡片，右侧打开这项提议：技能的用途，以及「依据」「本次结果」「与现有技能的区别」。在支线、私聊和手机上，点卡片打开技能页里的这一项。

点「展开全文」查看正文；点「保存」接受提议，点「不保存」拒绝提议。提议同时列在技能页最上面的「待确认」中，例如「@芝士 提议新增」；修改已有技能的提议写着「@芝士 提议修改」，详情里有「修改原因」。在详情里也能先「修改」再「保存」。

保存之前，提议不生效：新的技能不会被使用，对已有技能的修改也不会生效，芝士仍按原来那一版执行。

- 对你点过「不保存」的技能，芝士不再提议同名的技能。
- 一段对话同时只有一份提议等你决定。
- 项目里的技能超过 20 项后，芝士不再提议新的，改为提议合并或修改已有的。

提议里写着「保存后删除以下记忆：…」时，列出的是芝士之前记下的几条规则。保存后这几条随之删除，由这项技能取代，同一条规则不留两份。

## 修改、恢复与删除 {#manage}

点列表中的一项，右侧打开它的详情：「内容」页签是正文和配套文件，「历史版本」页签列出每一版，例如「第 2 版 · 修改 · @lin · 10月10日」，正在用的那一版标着「正在用」。

- 「修改」：改完点「保存」，成为新的一版。
- 「恢复到这一版」：在「历史版本」中把一个旧版恢复为正在用的版本，恢复也记作新的一版。
- 「放弃改动」：放弃芝士提议的修改，回到正在用的那一版。
- 「删除」：删除后，之后的频道不再使用这项技能，历史版本也一起删除。

项目成员都能新建、修改、保存和删除技能；导入只有项目管理员能做。每次保存、恢复或删除之后，新开始的工作用的就是最新的那一版。
