# 提交 {#submit}

提交是把一道题的作品交给发布者评审，例如把「B 树的插入与删除」的源代码和实验报告打成压缩包上传。每提交一次产生一个新版本，发布者逐版评审。

## 提交表单 {#how}

开始做题目之后（申请制的题要经发布者批准），题目页的主按钮旁边出现文字按钮「提交作业」，点它打开「提交表单」。表单的每一项由发布者设定。文件项上传一个文件，文本项直接填写；必填项没填时提示「此项为必填项」。

需要交几份文件时，按题目描述的要求打成一个压缩包。

表单顶部的「提交剩余时间」是离你自己截止时间的倒计时。直接开始的题，截止时间是题目的截止日期，题目没设就没有倒计时；申请制的题，截止时间在发布者批准你的申请时确定。见[申请与批准](/challenges#claim)。

个人身份和团队身份都申请过同一道题时，表单上方显示「请选择你要使用的提交身份：」。选定身份后再填写。

完整的提交做法见[完成一道题目](/solve-a-challenge#submit)。

## 分阶段的题目 {#stages}

发布者可以把一道题分成几个阶段，例如「需求分析」和「实现」，每个阶段有自己的提交内容和截止日期。题目页的「说明」中有一条阶段时间轴，每个阶段下面写着你在这个阶段的状态：「未提交」「待批改」「已通过」或「被退回」；过了截止还一版没交的阶段写「未通过」。右侧「我的进度」也逐个阶段列出这些状态。

提交表单上方是同一条时间轴，默认选中第一个还没通过、也还没过截止日期的阶段。点另一个阶段切换过去，表单换成那个阶段的提交内容。每个阶段单独评审：这个阶段有一版被判通过，阶段就完成，之后再交的版本不会让它变回未通过；所有阶段都完成，这道题才算通过。阶段过了截止日期，表单显示「已过截止时间，不能再提交」，需要延期时联系发布者。

「我的提交」上方也有这条时间轴，点一个阶段查看这个阶段的各个版本。

## 提交次数 {#times}

题目页「题目信息」中的「提交次数」有两种：

- 「可多次提交」：反复提交，每一版都保留。提交过第一版后，题目页的按钮变为「提交新版本」。
- 「仅可提交一次」：提交过一版后不能再提交，题目页不再有提交按钮。

## 提交记录 {#records}

题目页的「我的提交」列出你的每一版。最上面是最新一版，带版本号（如 `#2`）、提交时间和评审状态。更早的版本在「历史提交」中，点开查看当时的文件和评审结果。

评审状态和发布者的评语显示在每一版下方：

- 「未评审」：下方显示「等待评审中」。
- 「驳回」：下方显示「已驳回」和发布者的评语。题目可多次提交时，修改后提交新版本，见[改完再交一版](/resubmit#resubmit)。
- 「通过」：下方显示「已通过 N 分」和评语。

## 不能提交时 {#blocked}

题目页上没有「提交作业」时，有以下三种情况：

- 「我的进度」显示「已申请，等待通过」：申请还没通过。等发布者在「参与者」中批准，之后出现提交按钮。
- 按钮显示「申请未通过」：发布者拒绝了这次申请，这道题不能再以这个身份提交。需要时联系发布者。
- 「题目信息」中的「提交次数」是「仅可提交一次」，你已经提交过一版。

直接打开提交页的链接时，页面显示以下提示之一：

- 「当前不可提交，请联系题目发布者获取提交权限。」：你还没有开始做这道题，或申请还没通过。先在题目页开始做或申请做这道题，或等发布者批准。
- 「已达到提交次数上限」：这道题仅可提交一次，你已经提交过。点「查看我的提交记录」查看那一版。

## 评审提交 {#review}

题目的发布者和空间管理员在题目页的「参与者」页签中评审。有新提交的一行状态为「待评审」，点这一行的「评审」。其他提交过的一行点「查看提交」。分阶段的题目在评审窗口上方先点要评审的阶段，评审的是这个阶段最新的一版；题目页「数据」页签的「各阶段进度」列出每个阶段上各状态的人数，过了截止还一版没交的人算在「未通过」下。

弹窗最上面是「最新提交」，下面的「历史提交」列出更早的版本。在「评审」中选择「是否通过」：

- 选「通过」时要填「评分」，0 到 100 的整数。没填时提示「通过时要给分：填 0–100 的整数」。
- 选「驳回」时没有「评分」，在「评论」中写明要修改的地方。

点「提交」后提示「评审成功」。这一行的状态变为「已通过」或「未通过」，提交者在「我的提交」中看到结果和评论。

评审过的一版，表单标题变为「修改评审」：改选结果后再点「提交」，或点「撤销评审」撤回。
