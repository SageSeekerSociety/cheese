# 把网页发布成网站 {#publish-a-site}

这一页带你让芝士做一个网页，验收之后发布成项目网站，发一个链接给组员和老师看。比如你们的课程项目要交一个展示页：介绍项目、放几张截图、写清分工。

开始前要有一个项目，并且你是项目负责人或团队管理员，只有他们能发布。

## 让芝士做一个网页 {#build}

在项目里新建一个任务（入口见[任务如何产生](/tasks#task)），在任务页左边的对话里说清网页要什么。任务对话里的话直接给芝士，不用点名。讨论清楚后负责人点「开始」，芝士才动手做。

```prompt
给我们的「校园活动报名小程序」做一个展示页：一句话介绍、三张截图的位置、四个人的分工。只用 HTML 和 CSS，放在 site/ 目录，入口是 site/index.html。
```

```prompt
用 Vite 做的话，把构建好的静态文件放进 site/ 一起交，不要只交源代码。
```

```prompt
页面在手机上也要能看，标题不超过一行。做好后在预览里给我看。
```

> [!NOTE]
> 网站只托管静态文件：一个包含 `index.html` 的目录和它引用的文件，不运行构建脚本，也不运行后端程序。所以要让芝士把构建好的文件一起交上来。限制见[发布网站 · 能发布什么](/sites#what)。

做的过程中，任务页右边的「预览」显示它最后摆出来的那一样，先在这里看效果，有要改的直接在任务对话里说。

## 验收网页 {#accept}

网站只发布已经采纳的版本，所以芝士交上来后先验收。

在任务页点「审阅」看改动，满意就点「采纳」。验收的完整步骤见[验收芝士交回来的改动](/review-changes#review)。

## 发布 {#publish}

采纳之后，从项目看板发布。

:::steps

### 打开「做出了什么」 {#open}

点项目侧栏的「看板」，看板上方「做出了什么」一栏的第一行是网站那一行。

还没发布过时，这一行写着「暂无已发布的网站」，右边是「发布」。

![看板「做出了什么」一栏：最上面一行写着「暂无已发布的网站」，右边是「发布」](/images/site-row.jpg)

> [!NOTE]
> 项目已采纳的版本里还没有能发布的网页时，这一行不出现。

### 确认入口并发布 {#confirm}

点「发布」，弹出「发布网站」，写着「发布项目已采纳的版本」和版本号。

项目里有几个网页目录时，在「网站入口」里选一个；只有一个时直接写着「网站入口：」和那个文件。点弹窗里的「发布」。

完成后：这一行显示网站地址，下面写着版本、谁发布的、什么时候。

### 发给别人看 {#share}

把这一行的地址发给组员和老师。

网站只对这个项目和所属团队的成员开放，打开时要先登录；发布不会让网站变成公开的。

:::

## 改完再发布 {#update}

采纳新的改动不会自动更新网站。先在一个新任务里让芝士改，验收采纳后，回到同一行点「发布更新」。

```prompt
展示页的截图换成最新版，分工那一节加上每个人负责的模块。改完放在原来的 site/ 目录。
```

- 线上已经是最新采纳的那一版时，弹窗里写着「线上的就是已采纳的这一版」。
- 发布时提示「项目已采纳的版本变了，确认之后再发布」，说明刚才又有新的改动被采纳，确认后再发一次。
- 发布失败时，线上仍是上一版。

已经打开网站的人，刷新后才看到新版。
