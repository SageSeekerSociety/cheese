# 任务 {#tasks}

这一页讲任务，以及在项目里从哪里看到任务。任务是频道里一段单独的对话，用来把一件事从讨论做到交付；「全部任务」按「下一步在谁手上」把项目里的任务分组列出。

## 查看任务的入口 {#open-board}

项目里的任务在下面几处列出：

- 「总览」：在电脑上进项目先到这一页，也可以点侧栏项目名下面的「总览」；手机上点频道列表最上面的「总览」。「谁在做什么」按负责人列出还在进行的任务，点标题旁的「全部任务」打开全部任务。
- 「全部任务」：点项目名，在弹出的菜单里选「全部任务」，列出整个项目的任务。每个频道下面那一行「全部任务」打开同一页，只看这个频道。
- 频道右侧「概览」：「进行中 · N」和「最近完成」只列当前频道的任务，见[频道概览](/rooms#channel-overview)。

## 任务如何产生 {#task}

任务由人创建，或者由芝士在支线里创建。有五个入口：

- 在侧栏的频道上点右键，点「新建任务」。
- 在「全部任务」页右上点「新建任务」。选了某个频道时建在那个频道里，没选时建在「综合」里。
- 在一条消息上点「转为任务」，芝士会带着这条消息、前面的讨论和它的[支线](/rooms#threads)开始写任务文档。
- 在支线顶部点「转为任务」，效果和在支线挂着的那条消息上点一样。
- 在支线里让芝士去做一件事，它直接创建任务并开始；是芝士自己想到的事，它创建任务后停在「讨论中」，在支线里问一次负责人要不要开始。

人创建的任务，创建的人是负责人；芝士创建的任务，负责人是让它做这件事的人。一条消息和它的支线可以转出好几件任务。任务的状态由平台按进度更新，不能手动改。

私聊里不能创建任务：新建、把消息转为任务都会提示「私聊里不能创建任务，请到频道里创建」。

## 频道里的任务卡 {#task-cards}

每件任务在频道主线上有一张任务卡，写着任务名、负责人、此刻的状态和最后一次变化的时间。卡在原处变化，主线底部不会为任务追加新的一行。点卡打开[任务页](#task-page)。

- 从一条消息或它的支线转出的任务，卡挂在那条消息下面。消息有支线时，支线那一行在上，几张卡在下面合成一块。
- 单独新建的任务，卡是新建它的人发出的一条，写着「新建了任务」。同一个人接连新建的几件归在同一个名字下面。

卡上的状态和[全部任务](#board)用同一套写法，在等某个人时写出他的名字，比如「待 林晓 审阅」「待 陈默 开始」；在等你时写成「待你审阅」，卡的边框也会变成暖色。采纳后写「已采纳 · PR #45」。还没完成、已经采纳过几步的任务，卡上另写「已采纳 N 次」。

任务每次交付被采纳，或者带着结论关闭，结果会以芝士的回复发回原来那条支线，参与讨论的人都能看到。

## 任务名称 {#task-name}

任务的名字按创建方式来定：

- 创建时填了名字，就用你填的，平台不会再改它。
- 芝士创建的任务，沿用芝士起的标题。
- 没填名字的任务先叫「新任务」。负责人发出第一条有内容的消息后，平台给它起名；只说「在吗」这类话时会等下一条。芝士第一次回复后，平台再结合对话核对一次。

平台起的名字和芝士起的标题，只在任务方向明显变了时才会改，改名不在任务里发消息。

负责人和协作者可以在任务页右上的 ⋯ 里点「重命名」改名。人改过的名字，平台之后不再改。

项目管理员可以在「项目设置 → 任务命名」中选择「手动命名」。之后没填名字的任务保持「新任务」，平台不再给任何任务起名或改名。

## 任务页 {#task-page}

点「总览」「全部任务」、侧栏、频道概览或「待办」里的任务，打开任务页。左边是负责人、协作者和芝士的对话，右边是「概览」「现场」「改动」「预览」四个页签。「现场」是芝士在这个任务里执行的每一步，「预览」是它在这个任务里最后摆出来的那一样。页头的「概览」打开或收起右侧，规则和频道页一样，见[频道页面的区域](/rooms#topic-layout)。

- 负责人和协作者能在任务对话里和芝士说话，其他人能看，有话去频道里说。
- 「概览」里是任务文档：要做什么、做到哪、定了什么。负责人、协作者和芝士都能改，其他人只能看。
- 讨论清楚后，负责人点「开始」。开始之前芝士能看代码、跑命令试做法、写文档，但改动留不下，不改项目；开始之后才动手改。项目没有默认审阅人时，点「开始」后会提示选一位「审阅人」。
- 点页头的负责人可以看到这个任务由谁负责、谁在协作、哪位 AI 队友在做、在哪个环境里做。任务第一次需要环境时用频道当时那一个，之后频道再换也不跟着变；负责人可以在这里单独更换。只加进了这个项目、没有共享给团队的电脑算登记人自己的，只做登记人负责的任务。
- 负责人在任务信息的「协作者」一栏选人后点「添加协作者」，把频道里的人拉进任务，点「移除」请出去；协作者可以自己点「退出协作」。协作者和负责人一样能说话、改文档，开始、转交和关闭只有负责人能做。
- 负责人在任务页右上的 ⋯ 里可以「转交」给频道里的另一个人，或「关闭任务」；芝士也可以关闭任务。关闭时留了结论算「已完成」，没留算「已关闭」，任务的对话里会出现一条说明。
- 一件任务可以分几步交付。芝士每次交付时说明这是不是最后一步：最后一步被采纳后任务结束；不是最后一步，采纳后任务继续，芝士从项目最新的代码接着做下一步，见[验收与采纳](/accept#accept)。
- 任务关闭后，负责人可以在 ⋯ 里点「重新打开任务」。交付过的任务重新打开后，芝士从项目最新的代码接着做。

「概览」是一整列，往下滚动依次是：

- 开始信息和结论：开始后写着谁在什么时候开始的，点「与开始时相比」对照开始那一刻和现在的任务文档；任务关闭时留了结论，下面写着「结论」。
- 任务文档：滚动时文档的工具栏停在顶上。芝士正在这个任务里执行时，工具栏下面是它这一轮的清单。
- 「产出」：芝士在这个任务里做出来的文件。点「保存到资料库」把一个文件存进项目的[资料库](/files#library)，点「从模板新建」用模板新建一份文件。
- 「相关」：这件任务的原讨论（一条支线，或频道主线），以及原讨论里用到的文档和文件。

从一条消息或一条支线创建的任务，由芝士先把原讨论整理成任务文档。文档还空着时，「概览」写着「芝士正在整理…」；环境还没连上时写着「还没能开始，环境连上后会继续」。整理失败时写着「芝士没能整理出文档」，负责人和协作者可以点「重试」；点「自己写」则直接写文档。

侧栏在每个频道下面先列你负责的任务，再列你协作的，各自按最近有动静的排在前面，一共最多 5 个；14 天没有动静的任务不在这里列。你负责或协作的任务里有人说了你还没读的话，那一行加粗，后面是条数；芝士在任务里说的话不算。任务在等你处理时，那一行带一个橙色圆点，只有被等的那个人看得到。最后一行「全部任务」后面是这个频道里还在进行的任务数，点开是只看这个频道的[全部任务](#board)。

## 全部任务 {#board}

「全部任务」把还没结束的任务按「下一步在谁手上」分成四组，从上到下：

| 分组 | 意思 | 行上可能出现的状态 |
|---|---|---|
| 待处理 | 下一步在人手上 | 待审阅、检查未通过、已退回、待回答 |
| 检查中 | 已经交付，平台和芝士在处理，你不需要操作 | 检查运行中、等待检查、修复检查、解决冲突、平台更新分支 |
| 进行中 | 已经开始，还没交付 | 运行中、已开始 |
| 未开始 | 还在讨论，负责人还没点「开始」 | 讨论中 |

每一行写着任务名、所在频道、负责人、状态和最后一次动静的时间。在等你的那几件，状态写成「待你开始」「待你审阅」「待你回答」。点一行打开[任务页](#task-page)。待审阅的任务从这里进入[验收与采纳](/accept#accept)。

页面上方的几个筛选：

- 「全部」「我负责的」「我协作的」「其他人的」：按负责人筛选，后面是各自的任务数。
- 「所有频道」：点开选一个频道，只看这个频道的任务。
- 「已关闭」：看已采纳、已完成和已关闭的任务。

14 天以上没有进展的任务收进最下面的「已停滞」，点开才列出来。在等人审阅或等人回答的任务不算停滞。任务 3 天没有动静时，平台提醒负责人一次。

## 需要你处理的事 {#needs-attention}

需要你处理的事集中在「待办」（手机在底栏，电脑在左侧栏）的「等你处理」里，按项目分组。每条先写要你做什么，再写是哪件任务，最后一行是所在频道和时间：

- 「待你审阅」：任务交付了，等你采纳或退回。
- 「待你回答」：芝士在问你问题。
- 「待你开始」：你负责的任务文档写好了，等你点「开始」。
- 「检查未通过」：你负责的任务检查没过，芝士也解决不了。
- 「已退回」：你负责的任务被退回了，现在没有人在改。
- 「待你决定」：芝士请你在几个选项里选一个。选项就在这一条下面，直接点。
- 「你提的需求已有交付」：你提出的事有了交付。
- 「变更提醒」：芝士告诉你项目里改了什么。看过之后点「标为已读」。

点一条打开那件任务；不属于某件任务的，打开它所在的频道；不指向哪个频道的变更提醒，打开项目的「总览」。处理完、标为已读的事从这里消失。一个项目里有两条以上变更提醒时，项目名右边有「全部标为已读」，点一下全部标掉；要你决定的事不受影响。

频道和任务里的平台提示如果标着「需要手动处理」，说明这一步平台不会自己继续，比如额度用完。它不代表有任务在等验收，处理方法见[额度](/quota#quota)和[常见问题与排障](/troubleshooting#troubleshooting)。

## 一轮结束时看什么 {#turn-summary}

一轮工作结束，对话里会出现本轮摘要：改动了几个文件、增减多少行，点「查看改动」直接打开右侧「改动」页签。
