# 任务 {#tasks}

「组会报名说明」是项目「组会资料」里的一件任务。芝士在任务里写好这份说明，交给一位成员查看；这位成员同意后，说明才加入项目文件。

任务是一件要交付结果的事，有自己的页面和对话。芝士只在任务里修改项目文件。在频道和[支线](/rooms#threads)里，芝士可以查资料、尝试不同做法，但所做的修改不会保留。

## 任务从哪里来 {#task}

大多数任务由芝士创建。把一件需要修改项目文件的事[交给芝士](/agents#summon)，芝士在这条消息下方创建任务，负责人是提出这件事的人。

- 项目设置了默认审阅人（默认查看交付的人）时，任务创建后随即开始。
- 没有设置时，任务停在「讨论中」，等负责人点「开始」。
- 没有人提出、而是芝士在对话中判断需要做的事，芝士也会创建任务。这样的任务不论项目设置如何，都停在「讨论中」，芝士在支线里问负责人要不要开始。

芝士没有创建任务时，用下面的方式自己创建：

- 在消息上点「转为任务」，或在支线顶部点「转为任务」。芝士根据这条消息、前面的讨论和整条支线写出任务文档。
- 在左侧栏频道的「更多操作」里点「新建任务」，或在「全部任务」页右上角点「新建任务」。

自己创建的任务，创建的人是负责人。一条消息可以多次转为任务。与 AI 队友的私聊里不能创建任务。

## 负责人、协作者和审阅人 {#roles}

负责人决定任务什么时候开始。只有负责人能在任务页上转交、关闭和重新打开任务。

协作者和负责人一样能在任务对话里说话、修改任务文档。点任务页页头的负责人，打开任务信息。负责人在「协作者」一栏选人，点「添加协作者」；点「移除」让协作者离开。协作者自己可以点「退出协作」。

审阅人负责查看芝士交付的结果，决定采纳还是退回，见[审阅人](/accept#reviewer)。频道里的其他人能打开任务、阅读对话；他们要说话，在频道里发消息。

## 开始之前和之后 {#start}

开始之前，任务处于「讨论中」。芝士阅读讨论和项目文件，写出任务文档：要做什么、现状如何、需要谁做什么、已确定的事。这时芝士可以运行命令尝试做法，但不修改项目文件。

负责人确认任务文档后，点任务页右上角的「开始」。项目没有默认审阅人时，页头下方提示「需要指定由谁审阅，或在项目设置中设置默认审阅的人」。在「审阅人」中选一位，再点一次「开始」。

芝士在开始之前提出、还没人回答的问题，不影响「开始」。负责人点「开始」后，芝士按最合理的判断定下答案，写进任务文档的「已确定」，再开始修改。

开始之后，芝士修改项目文件，完成后提交审阅。一件任务可以分几次交付。最后一次交付被采纳后，任务关闭。之前的每次交付被采纳后，任务继续，芝士在项目最新的文件上接着修改。

任务结束时显示下面三种状态之一：

- 「已采纳」：最后一次交付被采纳。
- 「已完成」：负责人在任务页右上角的「⋯」里点「关闭任务」并写下结论。芝士也可以关闭任务。
- 「已关闭」：关闭时没有写结论。

任务关闭后，负责人可以在「⋯」里点「重新打开任务」。

## 频道里的任务卡 {#task-cards}

每件任务在频道主线上有一张任务卡，写着任务名、负责人、状态和最后一次变化的时间。任务卡在原处更新，点任务卡打开任务页。

head: 综合

由消息或支线转为的任务，任务卡挂在那条消息下面：支线那一行在上，几张任务卡在下面。单独新建的任务，任务卡是新建它的人发出的一条「新建了任务」。

任务卡上的状态在等某个人时写出他的名字，例如「待 林晓 审阅」「待 陈默 开始」；在等你时写成「待你审阅」。PR 是合并请求，「PR #12」是这次合并的编号。分几次交付、还没结束的任务，任务卡上另写「已采纳 N 次」。

任务每次被采纳或关闭，结果都以芝士回复的形式发回原来那条支线。

## 任务页 {#task-page}

芝士从收到消息到停下的一次执行称为一轮。任务页左边是任务对话，右边是四个页签：

- 「概览」：任务文档，以及「产出」和「相关」。「产出」是任务里做出的文件，「相关」是原来的讨论和用到的文件。芝士为这一轮列了清单时，清单也显示在这里。
- 「现场」：芝士在这个任务里执行的每一步。
- 「改动」：这个任务对项目文件做的修改，审阅也在这里进行。
- 「预览」：芝士在任务里最后展示的网页或文件。

负责人和协作者在任务对话里发的每条消息都交给芝士，不需要 `@`。芝士执行期间补充的要求，并入当前这一轮。

每一轮结束，对话里出现本轮摘要「改动了 N 个文件」。点「查看改动」，打开「改动」页签。

点页头的负责人，查看任务的负责人、协作者、执行这件任务的 AI 队友和环境。环境是芝士读写文件、运行命令的地方，见[设备与环境](/devices#devices)。

任务第一次需要环境时，使用频道当时的环境；之后频道更换环境，任务不随之更换。负责人可以在任务信息里为任务单独更换。

由消息或支线创建的任务，芝士先把原来的讨论整理成任务文档，这时「概览」写着「芝士正在整理…」。整理失败时写着「芝士没能整理出文档」。负责人和协作者点「重试」，或点「自己写」直接写文档。

## 任务名称 {#task-name}

创建任务时填写的名称，平台不会再修改。芝士创建的任务，使用芝士起的名称。没填名称的任务先叫「新任务」；有人发出第一条有内容的消息后，平台为这件任务命名。

平台自己起的名称，只在任务方向明显变化时才修改。负责人和协作者可以在任务页右上角的「⋯」里点「重命名」；人改过的名称，平台不再修改。

[项目管理员](/rooms#rooms)在「项目设置 → 任务命名」中选「手动命名」后，平台不再命名。之后没填名称的任务一直叫「新任务」，直到有人重命名。

## 全部任务 {#board}

「全部任务」页列出项目里的任务：点项目名，在菜单里选「全部任务」。还没结束的任务按「下一步在谁手上」分成四组：

- 「待处理」：下一步在人手上。状态是待审阅、检查未通过、已退回或待回答。
- 「检查中」：已经交付，平台和芝士在处理[平台检查](/accept#open-acceptance)。状态是检查运行中、等待检查、修复检查、解决冲突或平台更新分支。
- 「进行中」：已经开始，还没交付。状态是运行中（芝士正在执行一轮）或已开始（此刻没有在执行的一轮）。
- 「未开始」：负责人还没点「开始」，状态是讨论中。

在等你的任务，状态写成「待你开始」「待你审阅」「待你回答」。

页面上方有三种筛选：

- 「全部」「我负责的」「我协作的」「其他人的」：按负责人筛选。
- 「所有频道」：只看一个频道的任务。
- 「已关闭」：查看已经结束的任务，包括已采纳、已完成和已关闭的，列在「已完成」下。

14 天以上没有进展的任务不在四组里，收在页面最下面的「已停滞」中。在等人审阅或回答的任务不算停滞。任务 3 天没有进展时，平台提醒负责人一次。

任务还列在这几个地方：

- 「总览」页（左侧栏项目名下的第一项）的「谁在做什么」，按负责人列出进行中的任务。
- 左侧栏每个频道下面，列出你负责和协作的最多 5 件任务。有未读消息的任务加粗，等你处理的任务带一个橙色圆点。
- 左侧栏频道下面的最后一行「全部任务」，打开只显示这个频道的「全部任务」页。频道里有进行中的任务时才有这一行。
- 频道右侧「概览」的「进行中 · N」和「最近完成」，见[频道概览](/rooms#channel-overview)。

## 需要你处理的事 {#needs-attention}

需要你处理的事集中在「待办」的「等你处理」里，按项目分组。「待办」在电脑上位于左侧栏，在手机上位于底栏。每一条写着要你做什么、哪件任务、所在频道和时间：

- 「待你审阅」：任务交付了，等你采纳或退回。
- 「待你回答」：芝士在问你问题。
- 「待你开始」：你负责的任务文档写好了，等你点「开始」。
- 「待你决定」：芝士请你在几个选项里选一个，选项列在这一条下面。
- 「检查未通过」：你负责的任务没有通过平台检查，芝士无法自行解决。
- 「已退回」：你负责的任务被退回，目前没有人在修改。
- 「你提的需求已有交付」：你提出的事有了交付，点开查看。
- 「变更提醒」：芝士告诉你项目里改了什么。看过后点「标为已读」；一个项目里有两条以上时，项目名右边有「全部标为已读」。

点一条，打开对应的任务；处理完的事从这里消失。

频道和任务里的平台提示标着「需要手动处理」时，表示下一步要由人操作，例如采纳一次交付，或处理用完的额度。各种提示的处理方法见[常见问题与排障](/troubleshooting#troubleshooting)。
