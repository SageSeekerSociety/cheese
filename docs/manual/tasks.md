# 任务 {#tasks}

「组会报名说明」是项目「组会资料」里的一件任务。芝士在任务里写好这份说明，交给一位成员查看；这位成员同意后，说明才加入项目文件。

任务是一件要交付结果的事，有自己的页面和对话。芝士只在任务里修改项目文件。在频道和[讨论串](/rooms#threads)里，芝士可以查资料、尝试不同做法，但所做的修改不会保留。

## 任务从哪里来 {#task}

大多数任务由芝士建。在频道里把一件需要修改项目文件的事[交给芝士](/agents#summon)，芝士在频道里回复；有人说要做，芝士就建一个任务，挂在它的回复下面，负责人是说要做的人。建任务不会把你带离频道：点芝士回复下方的那一行任务，或者左侧栏的任务，才进入任务页。审阅人默认就是负责人，见[审阅人](/accept#reviewer)。芝士自己看出一件事该做时，先问一句要不要转为任务，点「转为任务」的人是负责人。

在[讨论串](/rooms#threads)里，有人说要做时，芝士把这条讨论串转为任务。转成任务后还是这段对话、还是这位芝士，从这时起它可以修改项目文件。

也可以自己转：点讨论串右上角或频道里的消息上的「转为任务」，点的人是负责人。一段讨论拆出几件各自要做的事时，芝士把每件另开成一个任务，都挂在那条消息下面；在讨论串里的一条回复上点「转为任务」，也是另开一件。还可以在左侧栏频道的「更多操作」或「全部任务」页右上角点「新建任务」，创建的人是负责人。与 AI 队友的私聊里不能创建任务。

## 负责人、协作者和审阅人 {#roles}

项目里的人都能在任务对话里说话。负责人和协作者说的话是给芝士的指令；其他人说的话芝士当作参考，和负责人的意思不一样时按负责人的来。只有负责人能在任务页上转交任务；负责人和协作者能关闭任务，在任务里工作的芝士也能关闭它；芝士在频道里开的任务，由频道里的芝士关闭。关了的任务，角色有「新建任务和审阅」权限的项目成员（默认是管理员和成员，不含导师）都能重新打开，在任务里工作的芝士也能；重新打开会在任务对话里写明是谁打开的。关闭比重新打开收得紧，因为关闭撤不回：还在等审阅的提交跟着作废、PR 被关掉，重新打开也不会恢复。协作者和负责人一样能修改任务文档。点任务页页头的负责人打开任务信息，负责人在「协作者」一栏选人后点「添加协作者」，点「移除」请出；协作者自己可以点「退出协作」。

审阅人负责查看芝士交付的结果，决定采纳还是退回，见[审阅人](/accept#reviewer)。

## 任务的进展 {#start}

任务建好芝士就动手：修改项目文件，任务文档边做边写，完成后提交审阅。讨论串原地转成的任务，芝士先把这段讨论整理进任务文档；负责人还没说要做什么时，它整理完就停下来等。一件任务可以分几次交付，每次采纳后任务继续开着，芝士判断做完了再关闭，显示「已完成」，见[采纳](/accept#is-merge)。负责人、协作者也可以在「⋯」里点「关闭任务」，芝士也能自己关闭（芝士在频道里开的任务，由频道里的芝士判断做没做完并关闭）：写了结论的显示「已完成」，没写的显示「已关闭」。结论跟在对话里那条关闭消息后面。关闭后任务对话里仍然可以说话，交给芝士时它回答关于这件任务的问题，但不再修改项目；要接着做，在「⋯」里点「重新打开任务」，或者在任务对话里让芝士接着做，它会自己重新打开。

## 频道里的任务卡 {#task-cards}

每件任务在频道里有一张任务卡，写着任务名、负责人、状态和最后一次变化的时间，在原处更新。讨论串转成任务后，消息下方还是这条讨论串，顶上多出一行任务卡，下面照旧是回复数和最新一条回复。从这条消息或它的讨论串里另开的任务，在同一块里一件一行。点任何任务都进入它的任务页，和侧栏里点任务进入的是同一页；从讨论串里的回复另开的任务，对话最上面是它出自的那条回复。

```demo-panel
title: 任务卡随任务更新
caption: 讨论串转成任务后，消息下方是这件任务的卡，状态依次显示「进行中」「待审阅」，采纳后显示「已完成」。
head: 综合
parts:
  - kind: msg
    who: 你
    to: 芝士
    say: 帮我把下周组会的报名说明整理成一页，给新同学看。
  - kind: task
    title: 组会报名说明
    owner: 你 负责
    status: 进行中
    until: 2
  - kind: task
    title: 组会报名说明
    owner: 你 负责
    status: 待审阅
    at: 2
    until: 3
  - kind: task
    title: 组会报名说明
    owner: 你 负责
    status: 已完成
    at: 3
```

讨论串转成的和从讨论串另开的任务都挂在那条消息下面；在讨论串里，从某条回复另开的任务也列在那条回复下面。芝士在频道里建的任务，是它回复下方的一行，只写任务名和负责人，之后也不在原处变化。单独新建的任务则是一条「新建了任务」。状态在等某个人时，状态下面一行写出他的名字，例如「待审阅」下面写「等林晓」，等你时写「等你」；最后一次交付被采纳后，「已完成」下面写采纳的人和合进去的「PR #12」；分几次交付、还没结束的任务另写「已采纳 N 次」。PR 是合并请求，「PR #12」是这次合并的编号。任务每次被采纳或关闭，开出它的那段对话里都记一行：在频道里开的记在频道，从讨论串另开的记在那条讨论串。芝士在频道里建的任务，由芝士在频道里说结果。

## 任务页 {#task-page}

任务页左边是任务对话，右边默认是「概览」。页头右边一组按钮打开「概览」「改动」「文件」「终端」，「现场」和「预览」在这组按钮最后的「⋯」里；按钮按下表示那一块开着，再点一下关掉。打开别的任何一块，「概览」就让开，点「概览」它回来；几块可以同时开着，例如「文件」下面是「终端」，旁边是「改动」。「文件」一次显示一份文件，点标题栏上的路径换成同一目录下或最近打开过的文件；「终端」有几个时在标题栏上切换。要看文件树、同时开几份文件、新开或关掉终端，点这两块标题栏上的「在编辑器里打开」，或页头的「编辑器」。讨论串转成的任务，对话最上面是它挂着的那条消息，前面写着它来自哪个频道；另开的任务，「概览」顶上一行引着它是从哪句话来的，点它回到说这句话的地方。「概览」里是任务文档、「产出」（任务里做出的文件）和「相关」（讨论里用到的文档和文件），芝士列了清单时也显示在这里；「现场」是芝士工作记录的原文；「改动」是对项目文件的修改，审阅也在这里进行；「预览」是芝士最后展示的网页或文件。

在「编辑器」里，左边一栏顶上的三颗按钮切换「文件」「搜索」和「改动」。「文件」这一行右边是「新建文件」和「⋯」，「⋯」里有「新建文件夹」「按名称找文件」和「全部收起」；改名和删除在每个文件右边的「⋯」里，或在文件上点右键。

「搜索」按内容查找这件任务的文件：在「搜内容」里输入文字，下面按文件列出含有这段文字的行，点一行在中间打开那份文件并停在这一行。查找不区分大小写，包括还没提交的文件，不包括仓库设定忽略的文件和图片等非文本文件。任务的文件不在环境里时（例如环境空闲后释放），能修改文件的成员搜索时先准备环境，准备好后自动列出结果；只能查看的成员不能搜索。在任务页任何地方按 `Ctrl/Cmd+Shift+F`，页面换到「编辑器」并打开「搜索」。

打开文件和查看「改动」不会准备环境。环境不在时，显示的是已提交的版本，文件路径旁标着「已提交版本」。在文件里输入、打开「终端」或搜索时才准备环境，准备期间这几处显示「正在准备环境」，等得久时显示已等待多久；准备好后改为显示环境里的文件。准备失败时显示「环境未能准备好」和「重试」。

负责人和协作者在任务对话里发的每条消息都交给芝士，不需要 `@`；`@` 了别人、没有 `@` AI 队友的消息只给被 `@` 的人。其他人的消息 `@` 了芝士才交给它，不 `@` 的话芝士下次处理消息时读到。芝士执行期间补充的要求，芝士在执行中读到。芝士对项目文件的修改都在「改动」里；成员也能在「改动」里修改文件，改好后自己提交审阅，见[自己改好后提交审阅](/accept#hand-in)。

「现场」顶部有「概览」和「原始记录」两种看法，默认是「概览」，浏览器记住上次选的那一种。「原始记录」在「概览」之外还列出芝士的思考过程和每条记录的信息，展开「查看 JSON 原文」看记录原文；记录里不超过 10 MB 的图片点「查看图片」打开。工作记录不随时间删除（平台改为长期保留之前的部分旧记录，30 天后不能再查看）；频道删除后，这个频道和其中任务、讨论串的记录立即无法查看。

任务信息里还列出执行这件任务的 AI 队友和[环境](/environment#environment)。任务第一次需要环境时使用频道当时的环境，之后频道更换环境，任务不随之更换；负责人可以在任务信息里单独更换。

从讨论串另开的任务，芝士还在做、任务文档还空着时，「概览」写着「芝士正在做这件任务」；芝士没能开始时写着「芝士没能开始做这件任务」，负责人和协作者点「重试」，或点「自己写」。

## 任务名称 {#task-name}

创建任务时填写的名称，平台不会修改；芝士创建的任务使用芝士起的名称。没填名称的任务先叫「新任务」，有人发出第一条有内容的消息后，平台为它命名，之后只在任务方向明显变化时才改。负责人和协作者可以在「⋯」里点「重命名」，人改过的名称平台不再修改。在「项目设置 → 任务命名」中选「手动命名」后，平台不再命名。

## 全部任务 {#board}

点项目名，在菜单里选「全部任务」。还没结束的任务按状态分组，从上到下是：

- 「待协助」：AI 队友说没有人帮忙就做不下去，下面一行是它的原话。
- 「待回答」：芝士提了问题，在等人回答，下面一行写等谁。
- 「待审阅」：已经提交审阅，下面一行写等谁审阅。平台和芝士还在处理[平台检查](/accept#open-acceptance)时，下面一行写到了哪一步，例如「检查运行中」「检查未通过，芝士修复中」「与主线冲突，芝士处理中」「分支更新中」；芝士修不了的写「检查未通过」和等谁处理，例如「检查未通过，等你」。
- 「进行中」：芝士正在执行，或者在等构建、检查的结果；交付被退回后也是进行中，下面一行写「林晓已退回，修改中」；芝士没有接着改时只写「林晓已退回」。芝士报了在做什么时，下面一行是它的原话和已经做了多久；报了在等结果时，是它在等什么和已经等了多久。它报过在等或需要协助、之后又开始执行的（用 Claude Code 时，平台看得到它在哪一次执行里），不再写那句话。任务页顶部还写着它的原话；它停下一段时间后，旁边写「芝士已离开」，它再次开始执行时这几个字消失。
- 「未开始」：任务建好了，还没有人动手。

芝士提交审阅后，任务的状态跟着审阅走；审阅被退回或作废后，任务回到「进行中」。

在等你的任务，状态下面那一行写「等你」。页面上方按负责人筛选（「全部」「我负责的」「我协作的」「其他人的」），「所有频道」只看一个频道，「已结束」列出已经结束的任务：显示「已完成」或「已关闭」。14 天以上没有进展的任务收在最下面的「已停滞」，在等人审阅或回答的不算；任务 3 天没有进展时，平台提醒负责人一次。

任务还列在「总览」页的「谁在做什么」、频道右侧的[概览](/rooms#topic-layout)，以及左侧栏每个频道下面：那里先列出你负责和协作的最多 5 件任务，有未读消息的带数字（AI 队友说的也算），等你处理的带橙色圆点。频道里还有别的未结束的任务时，最后一行「展开其余 N 个」把它们就地列在下面，点「收起」收回。这个频道的全部任务（包括已结束的）在频道的「更多操作」里点「全部任务」。

## 需要你处理的事 {#needs-attention}

在等你的任务列在「待办」的「等你处理」里，标着「待审阅」「待回答」「待协助」「检查未通过」「已退回」等，每一种的意思见[等你处理](/inbox#waiting)。

芝士停下、需要人来处理时，频道和任务里有一行平台提示，写明出了什么事，并带着要做的那一步，例如「重试」「去环境设置」，见[常见问题与排障](/troubleshooting#troubleshooting)。
