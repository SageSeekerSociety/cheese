# 任务与看板 {#tasks}

芝士接到一件事后，会把它拆成一条或几条「任务」并行推进。项目看板把所有任务按「下一步在谁手上」分成几列，一眼能看出哪些在做、哪些在等你。

## 打开看板 {#open-board}

点击侧栏顶部的项目名，进入项目首页，看板就在这里。话题右侧「总览」里也有一格「看板」，只列当前话题的任务。

## 任务如何产生 {#task}

任务由芝士根据话题里的要求创建：一条任务可以包含多个文件的改动。想分开验收的几件事，在要求里说明「分成几条任务」即可。

看板上没有手动新建任务的入口，也不能拖拽卡片或手动改状态。

## 看板显示什么 {#board}

![项目看板：「施工中」「交付中」「待处理」「做出了什么」四列，每张卡片写着任务名、所在话题和负责人](/images/board.jpg)

| 列 | 意思 | 卡片上可能出现的状态 |
|---|---|---|
| 施工中 | 还没交付，在做或在等人开工 | 运行中、待开工、已交回、失联 |
| 交付中 | 已经交付，平台和芝士在处理，你不用动 | 检查运行中、等待检查、修复检查、解决冲突、平台更新分支 |
| 待处理 | 下一步在人手上 | 待审阅、检查未通过、已退回、待回答 |
| 做出了什么 | 项目里已经采纳的成果，以及发布的网站 | |

采纳后的任务收进底部可展开的「已完成」。「待处理」列头右侧有「只看我的」，只显示在等你的那几条。

每张卡片写着任务名、所在话题、负责人和状态；已开合并请求的还显示 PR 编号。点开卡片可以看标题、状态、负责人、「简报」（交代给它的要求）、「结论」（它交回来的说明）和相关 PR。待审阅的任务从这里进入[验收与采纳](/accept#accept)。

## 需要你处理的事 {#needs-attention}

需要你处理的事集中在「待办」（手机在底栏，电脑在顶栏），每条写着理由：待你审阅、待你回答，或你提的需求已有交付。

话题里的平台提示如果标着「需要手动处理」，说明这一步平台不会自己继续，比如额度用完。它不代表有任务在等验收，处理方法见[额度与算力](/quota#quota)和[常见问题与排障](/troubleshooting#troubleshooting)。

## 一轮结束时看什么 {#turn-summary}

一轮工作结束，对话里会出现本轮摘要：改动了几个文件、增减多少行，点「查看改动」直接打开右侧「改动」页签。右侧「总览」的「进度」列出这一轮做了哪几步。
