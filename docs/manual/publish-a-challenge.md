# 发布一道题目并收作业 {#publish-a-challenge}

以数据结构课的作业「B 树的插入与删除」为例，新建一个空间并发布这道题。之后批准学生的申请，评审学生提交的作业。

:::before
新空间经平台管理员审核通过后才能使用。通过之前，学生无法加入。
:::

## 新建空间 {#create-space}

空间是老师发布题目、学生申请做题和提交作业的地方，一门课开一个。

:::walk
1. 在首页左侧栏的「空间」下点「新建空间」。
2. 填写「空间名称」，在「简介（选填）」中写一句课程介绍。
3. 点「提交审核」。页面转到这份申请，显示「待平台管理员审核」。

审核期间，这个空间在首页左侧栏的「空间」下标为「待审核」。审核通过后标记消失，点它进入空间，左侧栏新增一个分类「默认分类」。

申请被驳回时，标记变为「已驳回」。点这一行查看「驳回原因」，修改名称或简介后点「重新提交」。

## 邀请学生加入空间 {#invite}

学生用邀请码加入空间。新建空间时生成的邀请码可供 50 人使用，永不过期；审核通过后，在空间左侧栏点「设置 → 邀请码」查看。把邀请码发到课程群里，学生加入的步骤见[完成一道题目](/solve-a-challenge#join)。

人数超过 50，或需要为另一个班单独生成邀请码时，在空间左侧栏点「设置 → 邀请码」，再点「新建」。填写「可用人数」和有效期，点「生成」。

## 发布题目 {#publish}

题目的「描述」要写清背景和要求：学生读它，学生项目里的芝士也读它。交什么、怎么评分写在「提交与评分」一节，见[空间](/spaces#publish)。

:::walk
1. 在空间左侧栏点「全部题目」，再点右上角的「发布题目」。
2. 在「题目内容」中填写「名称」和「描述」。随题发出的材料，在「附件」中添加。
3. 在「参与」中把「参与方式」选为「个人」，并选择「难度」。
4. 在「时间」中把「开始方式」改为「申请制」，把「完成期限」改为限时 14 天，并选择「分类」。
5. 点右上角的「发布」。页面回到题目列表的「我发布的」，这道题标着「待审核」。

「开始方式」决定学生怎么开始做这道题：

- 「直接开始」：学生点「开始做这道题」就当场开始，平台立即用这道题为他建项目，不用你批准。新题默认是这一种。「时间」里是「开放日期」（留空就是立即开放）和「截止日期」，没有「完成期限」这一行。「截止日期」可以不填：填了，所有人在这天之前提交；不填，就没有截止。
- 「申请制」：学生点「申请做这道题」，你批准之后，学生再点「开始做这道题」，平台这时才为他建项目。限时从批准那天算起。

设了「人数上限」时，名额满了就不能再开始，申请制的题也不再收新的申请。有人申请或开始做之后，「开始方式」就不能再改，表单上这一项灰着，并写明原因。

「参与方式」发布后不能修改。有必填项未填写时，点「发布」后页头显示「4 项未填写或填写有误」这样的提示，对应的项下面写明原因。

新题默认「可多次提交 · 可编辑提交内容」，学生提交时上传一个文件。需要提交多份文件时，在「描述」中要求学生打成一个压缩包。

要看学生的项目，在「参与」里勾选「把导师加入参与者的项目」，再在「导师」中选人，默认是你自己，也可以选空间的其他管理员。学生点「开始做」之前会看到导师是谁、能看到什么，同意后才能开始；申请制的题在申请时不问，在申请通过后开始做时问。项目建好时，学生开始做时同意的那几位导师自动加入；学生开始做之后才加到题目上的导师不会加入他的项目。导师能看到项目里的公开频道、文档和文件，能发言和评论，看不到私聊。不勾选时，出题人只看得到申请情况和提交的作业，看不到学生的项目。

「AI 的设置」在「题目内容」下面，设置从这道题建出的项目里 AI 队友怎么帮学生，见[给单道题加设置](/guide-the-teammate#per-challenge)。表单末尾的「更多设置」用于限定谁能参与、是否要求实名信息。

发布页边写边保存为草稿，页头显示「草稿已保存」。页头的「草稿」列出你在这个空间的全部草稿，点一份接着写，点「新建草稿」另起一道。有草稿时，空间左侧栏「题目」下面还有一格「我的草稿」，列出每份草稿的名称、来源和修改时间，在这里接着写或删除。

## 和芝士一起出题 {#with-cheese}

发布页右侧是芝士，收起后点页头的「芝士」再打开；手机上点页头的芝士头像，从屏幕底部打开。它能读你上传的文件、查看空间里已有的题目和资料库，把题目直接填进左边的表单。表单上的每一格它都能填，包括导师、附件、起始代码和「AI 的设置」里的默认队友、要求、私有指导、学习目标、资料和技能。

1. 在右侧输入框里写出要出一道什么题。要交给芝士实验指导、讲义等文件时，点输入框左下角的「+」，选「添加文件」，或者把文件拖到右侧面板上。
2. 发送。芝士读文件、查看空间题目，再逐格填写表单；正在填的那一格描着边，旁边是带「芝士」名字的光标。
3. 核对填好的内容。对话里的「表单改动」列出这一次改了哪几格，点一格旁的撤销按钮恢复原样；芝士推断出来、需要你核对的地方列在「待你确认」里。
4. 点「发布」。也可以在对话里说「发布」，由芝士发布这份草稿。

芝士填写过的格子右上角标着「芝士已填写」，你改过这一格后标记消失。芝士改一格里原有的内容时，先把要换掉的那段选中，再写进新的内容。

只想从文件导入时，点「题目内容」右侧的「从文件导入」选文件，或者把文件拖到右侧面板上直接发送，不用写话。芝士把文件里的题目填进表单。

一份文件里有几道题时，第一道填进眼前这份草稿（它还空着的话），其余每道各建一份草稿，排在表单上方，开头一行写着来自哪个文件。点一道切换过去，右侧的对话不变；对话里眼前这道的改动逐格列出，其余几道各占一行。末尾的「全部发布」把填齐的几道一起发布；还缺必填项的那道标出「缺 N 项」，切过去能看到缺的格子。

空间有题目模板时，可以先点「题目内容」右侧的「使用模板」，再让芝士填写，芝士会在模板的小标题下面填内容。也可以直接告诉芝士用哪个模板，比如「用『标准实验』模板，按这份文件出题」。

> [!TIP]
> 要求写得越具体，填出来越接近你要的：写明课程、知识点、交付物和评分方式，比如「按 Lab 1 的格式出一道缓存模拟器实验，自动评测占 60 分，报告 20 分」。

改已发布的题目时，修改同样先存为草稿，点「保存更改」后才落到题目上，在那之前学生看到的仍是原来的题目。改题页右侧的芝士接着这道题「问芝士」里的对话；不想要这些修改时，点「放弃修改」。

改题页「附件」里的添加、替换和删除当场生效，不等「保存更改」。替换后旧的一份留作历史。

题目的描述、阶段、提交内容、评分要点和附件每变一次，题目记一个新版本，例如「第 3 版」。在做这道题的学生在项目总览的「最近进展」里看到「题目更新」和这一版改了什么，项目里的芝士也会读到同样的说明。学生每次提交时记下当时是第几版。

### 起始代码 {#starter-code}

起始代码是学生开始做题时项目代码仓库里已有的代码。在「题目内容」的「起始代码」中选择一个 `.zip` 压缩包；学生的项目建好后，压缩包解开，作为项目代码仓库的第一个提交。放进仓库要一点时间，这期间项目总览显示「代码仓库正在放入题目第 N 版的起始代码」，放好后显示它来自题目第几版。

- 压缩包只有一个顶层文件夹时，这一层去掉，里面的文件放在仓库根目录。`__MACOSX`、`.DS_Store` 和 `.git` 文件夹不放进仓库。
- 压缩包里的 `.gitignore` 照常生效，顶层和各个文件夹里的都算：它忽略的文件（例如 `.env`、`node_modules/`、构建产物）不放进仓库，和你自己提交这个文件夹时一样。
- 上传时就检查压缩包：解不开的、设了密码的、含符号链接或指向压缩包以外路径的、文件名太长或代码仓库不接受的、用了不支持的压缩方式的，以及文件超过 20000 个、解开后超过 2048 MB 的，当场拒绝并说明原因。
- 项目建好后、起始代码放进去之前，如果代码仓库的 main 分支已经有了别的提交，起始代码不会覆盖它，项目总览写明没放进去和原因。
- 发布页上选好压缩包就上传、检查，不合格的当场说明原因，不会随题目发布。
- 改题页替换或移除起始代码当场生效，题目记一个新版本。已经建好的项目仓库不变，之后建的项目拿到新的那一份。移除之前会先确认一次。

## 审核通过题目 {#audit}

发布的题目先进入「待审核」。空间的所有者或管理员审核通过后，学生才能看到和申请。空间所有者发布的题目，也由所有者自己审核。

:::walk
1. 在空间左侧栏的「管理」下点「待审核」。
2. 点这道题展开，核对「题目描述」和「提交要求」。
3. 点「通过」。题目出现在「全部题目」中，标着「可申请」。

## 批准申请 {#approve}

「开始方式」是「申请制」的题，要你批准，学生才能开始做。学生点「申请做这道题」后处于「申请中」，还没有项目；批准之后，学生点「开始做这道题」，平台才为他建项目。限时的天数从批准那天开始算。直接开始的题不用批准。

在题目页点「参与者」页签，再点筛选中的「申请中」。在学生所在行点「批准」，这一行的「截止」列随即显示这名学生的截止日期。

不同意时点「拒绝」，并在「拒绝原因（选填）」中说明原因。被拒的学生又申请了一次时，处理新的那一份；旧的那一份不能再批准或撤回拒绝。要调整某名学生的截止日期，点这一行的「⋯」，再点「设置截止时间」。

## 评审作业 {#review}

学生提交后，「参与者」页签中该学生所在行的状态变为「待评审」。

:::walk
1. 在「参与者」页签中，点该学生所在行的「评审」。弹窗最上面是最新的一版。
2. 在「是否通过」中选「驳回」，在「评论」中写明要修改的地方。选「通过」时还要填「评分」。
3. 点「提交」。页面提示「评审成功」，这一行的状态变为「已通过」或「未通过」。
