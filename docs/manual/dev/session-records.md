# 原始记录 {#session-records}

每个会话的 runner 给 harness 写出的每一条记录编号，后端把这份 journal 镜像下来（`agent.harness.driven`）。原始记录把这些行全部留下：Claude Code 的 stream-json 行、Codex 的 app-server 通知、pi 的 entry，连同平台盖的 `cheese` 戳。

现场的概览和原始记录都从这份记录派生，设计见 #4398。概览默认打开，浏览器记住上次选择。房间成员可以展开阅读思考内容，工具参数和输出保留全文。原始记录显示原有内容，并提供 JSON；概览将工具结果和分身归到对应调用下。

## 存什么 {#what}

镜像里的每一行，不管房间读没读：放了太久没落进房间的、房间一直拒收的、第一条输入之前的，都在。存储前做以下处理：

- 凭据按 `core.obs.scrub_secrets` 的规则替换成 `***`，在写入之前做；字段名像凭据的（`{"password": ...}`），整个值换成 `***`，不管值是字符串、数字还是列表（几个词的字段名按最后一个词判断，“Admin password”算，“Basic usage”不算）；空值和 null 照旧。
- JSONB 存不下的 NUL（二进制输出里会有）换成 U+FFFD。
- Claude Code 的图片独立存入私有桶，记录里保留 SHA-256、MIME 和字节数。单张最多 10 MiB（界面标作 10 MB）；超过上限只保留大小说明。镜像必须先交付图片，才能推进原始记录游标。图片按需鉴权读取，点击缩略图可以打开原图。

一行的身份是它在 journal 里的位置：runner 的序号加 runner 写下它的时刻。同一页读两遍、换一个新镜像从头再读，都只落一次。

## 怎么存 {#storage}

`session_records` 一行是一个会话 journal 里、同一轮的一段连续记录。

- 新记录一条一行，记录本身在 `records` 里。
- `SEAL_AFTER`（5 分钟）之后，巡检 `session record seal` 每分钟把一轮的一段（最多 2000 条、8 MiB）打成一个 gzip JSONL，放进私有桶 `session-records/<对话>/` 下。对象名带起止时间和来源身份；上传并回读校验后，在 `session-record-index/<对话>/` 发布同名的空索引对象，最后在一个事务里删掉短段、写一行指向封存对象的。读取只发现已经发布的索引；上传失败或校验失败不会让未验证对象进入视图。
- 没配私有桶的部署（本地开发）不封存，记录一直留在行里。
- 表上有触发器，拒绝任何 UPDATE。封存是删短段、写长段，记录内容不变。

镜像的保留（`RETENTION_S`）只删原始记录已经留下的行：镜像在 `state` 里记着 `recorded` 游标，第一次记录时从落地游标起步，平台开始记录之前房间已经读过的那些不补。

## 留多久 {#retention}

桶里封存的对象永久保留，没有任何代码删它：过了 30 天不删，对话删掉也不删（#4398 定下转写永久保留）。

会过期的是行。巡检 `session record retention` 每十分钟看一次，删掉最后一条记录已超过 30 天（`retention.RETENTION`）的封存段的行。读取合并数据库和永久桶索引，按原始身份去重，因此行过期后仍能翻页和搜索封存记录。这一点只对发布过索引的封存段成立：索引出现之前封存的段用的是旧的对象名，在 `session-record-index/` 下也没有索引，它们照样留在桶里，但行过期之后应用里读不到。这些旧段不补索引。还在行里、没封存的记录（没配私有桶的部署）不过期，因为行是它唯一的一份。

对话删掉了（频道一删除就算，不等清理做完；连同它的任务和支线），它的行同一个巡检删掉，桶里的对象照样留着。有私有桶时只删已封存的段：还没封存的（最后几分钟，或者删除之后会话还写下的）先等封存进桶，下一轮再删行。`session_records` 不设到 `conversations` 的外键：频道删除后它在 `topics` 里的那一行要留到清理做完，级联赶不上，所以删行只走这一处。

原始记录从不挡住房间：每次拉取在房间读之前最多交 4 页（`RECORD_PAGES`），写不进去的那一页记一条错误日志、留在镜像里，房间照常往下读，下一次拉取再交。

## 怎么读 {#reading}

`GET /topics/{topic_id}/session-records`：按写下的先后排，`turn_id` 只看一轮，`after` / `before` 使用接口给出的不透明游标，`newest` 从最新一页开始，`author` 选择来源，`q` 搜索完整 JSON，`channel=true` 包括房间内任务和支线；`limit` 最多 500。和 `/transcript` 同一道门：能看这段对话现场的人就能读，频道删除立即禁止读取。精确记录和图片接口使用同样的权限检查。

`/transcript` 将原始记录、平台状态和上线前轮次说明合并翻页。平台状态每次变化追加一行，概览显示同一状态的最新变化，原始视图显示全部变化。上线前没有原始记录的轮次只显示一行说明。现场不再写入或读取隐藏的 `blocks.kind=event`。
