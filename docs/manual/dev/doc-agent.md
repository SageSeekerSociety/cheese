# 文档里的芝士 {#doc-agent}

在房间实况文档里找 AI 队友有两条路，答的都是一个只属于这件事的会话，房间那一轮不动：不领工作电脑，不打断房间里正在进行的对话。

- 在评论里 @ 它：这个评论串的会话回答，答案是队友在评论串里的回复。
- 选中文字（或者不选，从顶栏对整篇）打开输入框：这个输入框的会话回答，答案回到输入框旁边的卡上，见[输入框](#box)。

> 讲：一条评论从发出到得到回答。不讲：房间里的一轮（见[一轮对话](/dev/turn)），文档协同本身（见[架构总览](/dev/overview)）。

## 输入框 {#box}

选中文字后浮条上的队友、顶栏上的队友，打开的是同一个输入框：上面输入，下面是常用的说法，分「修改」「提问」两组，打字时跟着筛。

| 在哪打开 | 修改 | 提问 |
|---|---|---|
| 选中能改的文字 | 润色、精简、改成列表（选中的是列表时为改成表格）、翻译成英文 / 中文 | 检查 |
| 选中不能改的文字（归档的房间） | 无 | 解释、检查、翻译 |
| 顶栏，对整篇 | 无 | 总结要点、检查全文、提出结构建议 |

- **说法按编号发**（`polish`、`check`……），每个说法要它做什么写在后端（`doc_agent_box.PRESETS`），按钮上的字只是名字。自己写的一句原样发，改还是答由队友判断。
- 一次提问是 `POST /topics/{id}/doc/agent`，以 server-sent events 返回：`conversation`（会话 id，第一条）、`queued`（排队）、`working`、`delta`（回答的字）、`tool`，最后 `done`（回答、改了的几处、是否被停下）或 `error`。回答在后台任务里跑，读的人离开也照样答完。
- **一个输入框一个会话**：接着说（「再短一点」）带上同一个会话 id，进同一个会话；关掉输入框再开就是新的会话。会话 id 记在 Valkey 里，写着是谁、在哪个房间，只有这个人在这个房间能接着问、停下它、把回答转成评论。
- **改不改由服务端定**：「提问」那组的说法、归档的房间里，这一问不许改文档，会话调改文档的工具也会被拒。
- **改了的几处**：会话改文档时，每一处记在这一问的工作 id 下，回答结束时随 `done` 返回。输入框在正文里把它们标出来（删掉的字划掉、新字高亮），卡上写「已修改 N 处」，撤销是以提问人的名义把每一处换回去。
- **停下**：`POST /topics/{id}/doc/agent/{会话}/stop`，排队中的不再等，正在答的让会话停下；已经改了的照样返回，可以撤销。
- **转成评论**：提问人先在选中的地方发一条评论（写着问了什么），再 `POST /topics/{id}/doc/agent/{会话}/reply/{评论串}`，把这次的回答作为队友的回复放进去；只能放进自己开的评论串。

## 什么评论会被回答 {#trigger}

人发的评论或评论串里的回复，正文 @ 了这个房间里坐着的 AI 队友（`<@handle>`），才会被回答；其他评论什么也不触发。队友自己写的评论不会叫醒自己。评论先存下、提交，然后在后台回答（`doc_agent.hand_to_agent`）。

## 会话 {#session}

和[个人芝士](/dev/assistant#session)是同一套底座（`harness/pi/handless.py`）：中心会话机上钉住版本的 pi，没有手，只开平台给它的工具。

- **一个评论串一个 pi 会话**，会话 id 就是评论串第一条评论的 id；输入框的会话 id 是第一次提问时生成的。都放在会话机的 `~/.cheese/docs/<项目 id>/<会话 id>`。同一串里的追问接着上文，不同的会话互不相干。
- **空闲 60 秒退出**，对话留在磁盘上，下一个问题在同一个对话上重新起来。
- 一个项目最多留 4 个会话在跑，起第 5 个时关掉这个项目最久没用的空闲会话。
- 每个会话内存上限 512 MB；会话机剩余内存不够时不起新会话，这一问按「正忙」回复。
- 用的是这个队友的模型（和它在房间里的一轮同一个绑定），只支持网关模型。

## 轮到谁 {#turns}

- 同一个会话同一时间只答一个问题，后来的等前一个答完。
- 一个项目同一时间最多答 4 个会话（评论串和输入框一起算，`ANSWERING_PER_PROJECT`），多出来的排队，前面的答完一个就接上。输入框排队时卡上写「正忙，空闲后自动回复」，可以取消。评论串排队和回答时，评论卡上同样实时写着走到了哪一步（正忙、正在读文档、正在修改文档、正在回答）：后端往房间推 `comment_activity`，评论串列表的 `answering` 再告诉一遍刚打开的页面。
- 最多等 10 分钟，等不到评论串回复「正忙，稍后重试」，输入框说同样的话。

这两把锁放在 Valkey 里，带过期时间，后端进程中途退出也不会永远占着。评论串那把锁同时记着是谁问的，改文档时用它。

## 带什么上下文 {#context}

会话启动时的系统提示词：规则、项目章程（项目总览的实况文档）、项目共享记忆的索引。会话活着期间不变，每次提问共用缓存。

每次提问现场组装：

- 这个评论串到目前为止的每一条；
- 评论指着的文字，和它所在的那一节（从上面最近的标题到下一个同级或更高级的标题）；
- 文档全文；
- 话题里最近 20 条消息；
- 最后说明要回答谁的哪一条。

## 工具与凭据 {#tools}

会话拿的是房间的凭据：写着项目、房间、这个队友，外加这个评论串（`mint_scoped_token` 的 `resource_id`）。它只开 `/doc-agent/tools/{name}` 和 `/llm/v1/*`。

| 工具 | 做什么 |
|---|---|
| `read_document` | 读实况文档最新全文 |
| `edit_document` | 改文档里的几处文字，和 `cheese_doc_edit` 同一套规则（原文只出现一次，有一处用不上就一处都不改） |

工具只在这个会话正有问题在回答时才开，而且只认这个会话、这个房间、这个队友；没带会话的房间凭据打不开。改动以队友的名义直接改，记成「某某让队友改」，某某是问的那个人；这一问不许改时，改文档的工具只回一句「这次只回答」。

## 回答 {#answer}

会话最后写的文字就是队友在评论串里的回复。准入被拒（模型档位、项目额度）时，拒绝的原因就是回复；会话起不来或中途失败，回复「暂时无法回复，稍后重试」。评论串在这期间被解决或删掉了，就不回复。

## 计费 {#billing}

模型调用经 `/llm/v1` 换上项目的网关 key，和这个队友在房间里的调用一样记在项目上。每次回答结束（答上或没答上）读一次项目 key 上新增的花费，记到这个房间。
