# 验收芝士交回来的改动 {#review-changes}

这一页带你验收芝士做完的一件任务：找到等你审阅的那一件，看清改了什么，再决定采纳、退回还是作废。比如芝士刚把你们的报名表单从 9 项必填改成 4 项，卡上写着「待你审阅」，你要确认它改对了再让改动进项目。

开始前，你得是卡上点名的审阅人。不是你的话，卡上的「更换」可以改由别人审阅。

## 找到等你审阅的任务 {#find}

等你审阅的任务会出现在三个地方，从哪一处进都是同一件任务。

- 待办：「等你处理」下面一行写着任务名和「待你审阅」，点它打开任务。
- 看板：项目侧栏「看板」→「待处理」一列，卡片上标着「待审阅」。
- 任务页：输入框上面有一行「改动 待你审阅」，右边是「审阅」。

![任务页里的验收卡：写着待谁审阅、推荐理由和合并后的提交标题，下面是主按钮和「退回」「作废」；最下面一行「改动 待你审阅」旁边是「审阅」](/images/review-card.jpg)

点「改动 待你审阅」那一行会展开验收卡：上面写着由谁审阅、推荐理由、合并后的提交标题，下面是操作按钮。

## 审阅一件任务 {#review}

先看改动，再问清楚，最后做决定。

:::steps

### 看它改了什么 {#diff}

点「审阅」，右边切到「改动」页签，列出这件任务改了哪些文件；选中一个文件看它的差异。

一件任务里的几个文件是一起交、一起采纳的，看完全部再决定。

> [!NOTE]
> 页签上方的来源写着这件任务的名字。切回「频道改动」看到的是整个频道的改动，不只这一件。

### 问清楚再决定 {#ask}

看不懂的地方，直接问芝士。任务的负责人和协作者在任务页左边的对话里问；你只是审阅人时，到这个任务所在的频道里 `@芝士` 问。

```prompt
@芝士 这次改了哪几个文件？每个文件用一句话说改了什么，有没有动到我没要求改的地方。
```

```prompt
@芝士 必填项为什么留的是姓名、学号、手机号、场次这四个？去掉的那几项以后从哪里来？
```

```prompt
@芝士 你是怎么确认手机上一屏能填完的？把检查的方法和结果发给我。
```

### 采纳、退回或作废 {#decide}

看清楚之后，在验收卡上选一个。

- 「采纳」：改动合进项目，任务显示「已采纳」并自动结束，收进看板底部的「已完成」。
- 「退回」：在「退回理由（可选）」里写清哪里要改，点「确认退回」。任务回到看板的「进行中」，芝士改完会再交一张新的验收卡。
- 「作废」：结束这次审阅，不合并也不退回，在「作废理由（可选）」里写一句，点「确认作废」。之后可以重新提交审阅。

退回理由写清改哪里、改成什么，比如：

```prompt
「院系」不能去掉，老师要按院系统计。把它加回必填，其余保持 4 项。
```

> [!TIP]
> 主按钮的名字会变：任务还没有合并请求（PR）时是「创建 PR」，平台检查没过时「采纳」是灰的。每种情况见[验收与采纳](/accept#is-merge)和[采纳按钮是灰的](/accept#accept-blocked)。

:::

## 采纳之后 {#after}

采纳之后，改动已经在项目里，任务页底部写着「任务已关闭」。

做出来的东西列在看板上方「做出了什么」一栏，每一样写着第几版。采纳的是网页时，可以接着发布成网站，见[把网页发布成网站](/publish-a-site#publish-a-site)。
