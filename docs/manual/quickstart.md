# 快速开始 {#quickstart}

知是是你和 AI 队友一起做项目的地方。这一篇带你走完一整趟——从什么都没有，到你的第一个改动被合并进主分支，大概十分钟。

走完之后你会认识四个词：**项目、房间、活、验收卡**。现在不用先记住，走一遍就有了。

## 开始之前 {#prerequisites}

你只需要一个知是账号。GitHub 仓库不是必需的——每个项目自带一个仓库，第一趟可以完全不碰 GitHub。

## 第一步：建一个项目 {#create-project}

界面最左边那条竖栏是你的项目栏，底部的 **➕** 是新建项目。要填的只有两样：

- **项目名称**
- **所属团队**：一个人用就选「个人」；选了团队，队里的人默认就是这个项目的成员，不用再一个个邀请

点「创建」，界面直接进入这个项目。

**一个项目就是一个 git 仓库。** 它自带一个，所以你现在已经有地方放代码了，不需要先准备什么。

## 第二步：连上你已有的仓库（可以跳过） {#connect-repo}

如果你想在自己已有的代码上开工，去 **项目设置 → 上游仓库**：填 git 地址，点「保存」，再点「同步上游」，历史就拉进来了。有冲突时同步会原样中止，不会只合一半。

如果你还想让后面的「采纳」变成 GitHub 上的一次真实合并，在同一页点 **连接 GitHub 仓库**，把 cheesex-app 装到那个仓库上。装完之后，芝士读 CI 状态、开 PR 所需要的临时凭据会按这个连接自动签发——你不用手工配任何 token。

第一趟建议先跳过这一步，用项目自带的仓库走通全程，回头再连。

## 第三步：开一个房间，说一句人话 {#first-room}

打开项目，第一屏是**看板**，不是某个聊天——看板答的是「现在该谁动」，这是你每天的第一眼。

左侧栏顶部的 **➕（新建话题）** 开一个新房间。点下去它会先问你**交给哪个 AI 队友**，默认那个就行。

> 队友是建房间时选定的，之后不能改：换队友等于丢掉这个房间已经积累的全部上下文。所以这个问题问在开头，而不是留一个设置项。

**房间**就是你和芝士谈一件事的地方。在底部输入框里，像跟同事说话那样说你想做什么：

> 首页现在空的时候什么都不显示，补一句说明文字。

不用写规格，不用列步骤。说清楚**你要什么**、以及**做成什么样算好**，就够了。

## 第四步：它干活的时候，你在看什么 {#watch-work}

芝士会先回你一句它理解的目标和第一步，然后开工。这期间房间里有四处可看：

- **对话**：它的判断、发现、遇到的问题、要你拍板的选择。它需要你做决定时会给出可点的选项，你点一下就是答案。
- **施工现场**：它每调用一次工具就多一行，中文动词加上这一步在干什么。这是它当下正在做的事。
- **实况文档**：右侧那份文档是这个房间的**当前全貌**——目标、结论、下一步。它写给没看过聊天记录的人，所以你隔了两天回来先看它，比翻聊天快。
- **看板**：项目级的视角。一件活一行，按状态分列（施工中 / 交付中 / 等你）。

事情大了，芝士会**拆活**：在同一个房间里同时派出去好几件，各干各的。拆出来的每一件在房间总览和看板上都是一行，点进去能看到它自己的进展。

## 第五步：它交活，你采纳 {#accept}

活干完，对话末尾会出现一张**验收卡**。上面写着它做了什么、对着你的要求逐条给了什么证据，以及一个「采纳」按钮。

**采纳就是当场合并。** 你点下去，代码就进主分支了——不是"标记为通过"然后还有谁去合，就是合并本身。所以点之前该看的是卡上的证据，不是之后再补一道检查。

按钮是灰的时，它上方那行字会说清楚是被哪一条拦住的：

- **合并前必须通过的检查**没过——点名的检查全部通过才能合并
- **分支落后 main**——项目开了「合并前必须跟上 main」，平台会先更新再合
- **PR 上有新提交**——默认「新提交作废已有的采纳」，因为你之前看到的版本已经不是现在这个了

这些规则在 **项目设置 → 分支保护** 里，可以按项目调整。检查没过但你确认要合，「人工放行」在一个需要先展开、再填理由的表单后面——它有意不是一个能顺手点到的按钮。

## 走不通的时候 {#troubleshooting}

第一趟最常见的三种卡住，以及它们各自意味着什么。

- **它没反应**：确认你的消息 @ 了芝士。没有 @ 的消息它收不到。
- **打开项目链接是一片空白**：你多半不是这个项目的成员。让项目里的人把你加进成员名单。
- **采纳时冲突了**：卡会留在那儿并说明冲突，芝士会被派去解决，解完你再采纳一次。

## 接下来 {#next-steps}

走完这一趟，剩下的两件事在你需要时再看。

- 想接自己的机器跑任务：命令行运行 `cheese link`，按提示在浏览器里批准这台设备。
- 想让项目产出一个能访问的网站：让芝士准备好静态站并提交验收，采纳之后在「导出与发布」里发布。
