# 和同学一起做一个项目 {#team-project}

这一页带一个三人小组和芝士一起做完一份课程大作业，从讲清要求、中途改方向，到审阅和交出去。比如你们三个人要在两周内交一份数据结构大作业：用 C 实现一棵 B 树，再写一份实验报告。换成你们自己的作业时，把消息里的课程和要求换掉即可。

你和同学各有一个知是账号就够了。芝士在平台的云端写代码、跑测试，不用准备电脑。

## 把同学拉进来 {#setup}

先建一个团队，再在团队下建项目，同学进了团队就自动进了项目。

- 建团队：首页侧栏「团队」→「新建或加入团队」→「创建团队」，填「团队名称」。
- 发链接：团队侧栏「成员」→「团队链接」→「复制链接」，发到你们的群里。同学打开链接，点「申请加入」。
- 批准：「成员」→「加入申请」，在每位同学那一行点「批准」。
- 建项目：团队的「项目」页 →「新建项目」，填「项目名称」，「归属」已经是这个团队。

![团队「成员」页的「团队链接」：链接右边是「复制链接」和「重置链接」，下面的「加入需要审批」默认开着](/images/team-link.jpg)

> [!NOTE]
> 新建或刚加入的团队，侧栏里要刷新一次页面才出现。每一步的完整说明见[团队](/teams#teams)和[项目](/projects#create-project)。

## 和芝士做作业 {#work}

在项目侧栏点「全局」，三个人和芝士都在这个话题里说话。

```demo-steps
title: 三个人和芝士做一份大作业
note: 画面用的是产品里真的消息行和工作面板（右边那几格）
embed: team-project
steps:
  - label: 讲清作业要什么
    desc: 上传作业要求，在一条消息里说清要交什么，交给芝士。它先复述理解，再列出要做的几步。
    link: /team-project#brief
  - label: 芝士问清一个选择
    desc: 要求里没写清的地方，它发一张问题卡，点一个选项就是回答。
    link: /team-project#answer
  - label: 同学在中途补一句
    desc: 芝士跑着的时候，组里任何人都可以在话题里补一句要求。
    link: /team-project#follow-up
  - label: 看结果：说明加改动
    desc: 一轮结束，读它的说明，再点「查看改动」看每个文件改了什么。
    link: /team-project#review
```

:::steps

### 讲清作业要什么 {#brief}

点输入框左边的回形针上传作业要求，再在同一条消息里点名芝士，写清要交什么、做到什么程度。

```prompt
@芝士 这是数据结构大作业的要求（见附件）。用 C 实现一棵 3 阶 B 树，支持插入、删除、查找，再交一份带测试结果的实验报告。先说说你的理解，列出要做的几步，先别写代码。
```

```prompt
@芝士 先帮我们看懂要求里的「3 阶」是什么意思，用一个插入时节点分裂的例子讲一遍。
```

```prompt
@芝士 林晓负责验收代码，王珊负责验收报告。代码先做插入和查找，删除放到下周。
```

消息里点名了芝士，它才会接手；按 `Ctrl/Cmd+Enter` 发送会自动加上点名。芝士先回一条「收到，……」复述它的理解，步骤多时再发一张清单，做完一步勾一步。

计划没问题，就让它开始：

```prompt
@芝士 就按这几步来，先写插入和查找，每写完一个函数跑一次测试。
```

> [!TIP]
> 复述和你想的不一样时，马上回一句纠正。

### 回答问题卡 {#answer}

要求里没写清的地方，芝士会在对话里发一张问题卡，写明由谁回答。

点一个选项，再点「提交答案」，芝士接着做。选项都不合适时，点「自己填写」写你的想法：

```prompt
键用 int 就行，不用支持字符串。
```

问的不是你时，卡上写着在等谁回答，在群里叫那位同学来答。

### 中途改要求 {#follow-up}

芝士在跑时，右侧「现场」里一步步列出它在做什么；这时组里任何人在话题里补的要求，它在这一轮里都会读到。

```prompt
测试里加一组连续删到只剩根节点的例子，老师说会查这个。
```

```prompt
报告里的复杂度分析用表格，不要大段文字。
```

「现场」顶部写着「没有在运行的会话」时，这一轮已经结束。这时要它换个做法，重新点名它：

```prompt
@芝士 删除现在是直接合并节点。改成先向兄弟节点借，借不到再合并，测试也一起改。
```

> [!NOTE]
> 芝士没在跑时，没有点名它的消息只留在话题里，不会让它开工。规则见[让 AI 队友处理消息](/agents#summon)。

### 检查结果并验收 {#review}

一轮结束时，对话里出现一行「改动了 N 个文件」，点「查看改动」看每个文件改了什么。也可以直接问它：

```prompt
@芝士 这一轮改了哪些文件？每个文件用一句话说改了什么，测试有没有失败的。
```

芝士把一件事做完会提交审阅，对话里出现一行「……已提交，待〈名字〉验收」。点右侧「总览」，打开这件任务，验收卡上写着由谁审阅：

- 「审阅」：看这一版改了什么。
- 「采纳」：满意就点它，成果合进项目。
- 「退回」：在「退回理由（可选）」里写清哪里要改，比如：报告第 3 节缺删除操作的复杂度。再点「确认退回」，芝士改完会再提交一次。
- 「作废」：结束这次审阅，不合并也不退回。

每个按钮的完整说明见[验收与采纳](/accept#accept)。

:::

## 交出去 {#hand-in}

老师要的是单个文件时，从话题右侧下载：「改动」→「项目当前代码」→ 选中文件 → 右上角「⋯」→「下载」。

要留一份整个项目，就打包导出：项目名右边的下拉箭头（「项目菜单」）→「项目设置」→「数据」→「导出项目」。浏览器会下载一个 `.tar` 包，团队里每个人都能导出。

> [!WARNING]
> 导出包里的代码在 `repository.bundle` 里，这是给 git 用的打包文件，双击打不开。交单个文件时用上面的「下载」。

要交到老师在空间里发布的题目，见[完成一道题目](/solve-a-challenge#submit)。
