# 和同学一起做一个项目 {#team-project}

这一页带一个三人小组用知是做完一份课程大作业，从商量分工到交出成果。比如你们三个人要在两周内交一份数据结构大作业：用 C 实现一棵 B 树，再写一份实验报告。换成你们自己的作业时，把消息里的课程和要求换掉即可。

你和同学各有一个知是账号就够了。

## 把同学拉进来 {#setup}

先建一个团队，再在团队下建项目，同学进了团队就自动进了项目。

- 建团队：首页侧栏「团队」→「新建或加入团队」→「创建团队」，填「团队名称」。新团队马上出现在侧栏「团队」下面。
- 发链接：团队下面的「成员」→「团队链接」→「复制链接」，发到你们的群里。同学打开链接，点「申请加入」。
- 批准：「待办」里每条「请求加入团队」旁边点「批准」；也可以在团队「成员」→「加入申请」里批准。
- 建项目：团队的「项目」页 →「新建项目」，填「项目名称」，「归属」选这个团队。建好后页面进入项目的频道「综合」。

![团队「成员」页的「团队链接」：链接右边是「复制链接」和「重置链接」，下面的「加入需要审批」默认开着](/images/team-link.jpg)

同学其他的加入方式（搜索、邀请）见[加入别人的团队](/join-a-team#join-a-team)。

## 在频道里商量 {#channel}

「综合」是项目里所有人说话的地方，三个人在这里商量分工。

普通消息只留在频道里，芝士不会开工。要它帮忙就点名它，芝士在那条消息的支线里回答，主线上多出「N 条回复」；在支线里接着问，仍要 `@` 芝士，见[支线](/rooms#threads)。

点名芝士的两种问法：

```prompt
@芝士 我们三个人想这样分工：一个写插入和查找，一个写删除，一个写测试和报告。按这个分工，每部分要做哪些事？
```

```prompt
@芝士 B 树的「3 阶」是什么意思？用一个插入时节点分裂的例子讲一遍。
```

芝士在支线里只回答，不改项目文件。要它动手做，转成任务，见下一节。

## 把作业变成一个任务 {#task}

任务是频道下面一段单独的对话，有负责人、有一份任务文档，芝士在里面把这件事做完。

```demo-steps
title: 三个人和芝士做一份大作业
note: 画面用的是产品里真的消息行和工作面板（右边那几格）
embed: team-project
steps:
  - label: 讲清作业要什么
    desc: 在任务里说清要交什么。芝士先复述理解，再列出要做的几步。
    link: /team-project#scope
  - label: 芝士问清一个选择
    desc: 要求里没写清的地方，它发一张问题卡，点一个选项就是回答。
    link: /team-project#follow-up
  - label: 同学在中途补一句
    desc: 芝士在做的时候，协作者在任务里补的要求它也会读到。
    link: /team-project#follow-up
  - label: 看结果：说明加改动
    desc: 一轮结束，读它的说明，再点「查看改动」看每个文件改了什么。
    link: /team-project#review
```


:::steps

### 把作业要求转成任务 {#brief}

在「综合」里发一条写清作业要求的消息，再把它转成任务。

```prompt
数据结构大作业：用 C 实现一棵 3 阶 B 树，支持插入、删除、查找，再交一份带测试结果的实验报告。两周后交。
```

```prompt
老师的作业说明原文如下，照这个做：（把作业说明整段贴在这里）
```

鼠标停在这条消息上，点右上角的「转为任务」。页面进入新任务：标题旁写着「讨论中」，右上是「〈你的名字〉 负责」和「开始」。频道里这条消息下面多出「已转为任务」。

芝士根据这条消息和频道里之前的讨论写任务文档，文档在右侧「概览」里。写好之前，「概览」写着「芝士正在整理…」；没整理出来时，点「重试」，或点「自己写」。<!-- 待确认：芝士写任务文档的实际过程只在代码与现有文档里看到，本地没有可运行的模型 -->

![任务页：页头是任务名、状态和负责人，中间是和芝士的对话，输入框上方是一条待审阅的改动，右侧「概览」是任务文档](/images/task-page.jpg)

### 拉同学进来一起做 {#collaborators}

只有负责人和协作者能在任务里和芝士说话，所以先把同学加成协作者。

点页头的「〈你的名字〉 负责」打开任务信息，在「协作者」一栏选同学，再点「添加协作者」。

协作者和负责人一样能在任务里和芝士说话、改任务文档。频道里的其他人能看这个任务，页面上写着「只有负责人和协作者可以在这里和芝士对话」，有话回「综合」里说。

### 和芝士把要求写清楚 {#scope}

任务里的输入框写着「给芝士发消息」：在任务里说的话都交给芝士，不用点名。

```prompt
先复述你对作业的理解，把要做的几步写进任务文档。有拿不准的地方列出来问我们。
```

```prompt
删除时节点不够，先向兄弟节点借，借不到再合并。测试里要有连续删到只剩根节点的例子。
```

```prompt
实验报告写三节：实现思路、测试结果、复杂度分析。复杂度用表格。
```

芝士先回一条「收到，……」复述它的理解，再把步骤写进右侧「概览」的任务文档。点「开始」之前，它只讨论、只写文档，不改项目里的文件。任务文档你们也能直接改；文档里的步骤和要求都对了，就可以开始。

### 让芝士动手 {#start}

要求写清楚后，负责人点页头的「开始」，芝士才动手改项目。

项目还没有默认审阅人时，点「开始」会先提示「需要指定由谁审阅，或在项目设置中设置默认审阅的人」。在「审阅人」里选一位同学，比如负责测试的那位，再点一次「开始」。

状态变成「已开始」。芝士每一步在做什么，看右侧「现场」。

> [!TIP]
> 右侧「概览」顶部有「与开始时相比」，点它对照开始那一刻和现在的任务文档。

### 回答问题、中途改要求 {#follow-up}

芝士执行时，你和协作者随时可以在任务里补充要求。

```prompt
测试再加一组：随机插入 1000 个键，再逐个查找，结果写进报告。
```

```prompt
复杂度分析改成和二叉搜索树对比，同样用表格。
```

要求里没写清的地方，芝士会在对话里发一张问题卡，写明由谁回答。点一个选项，再点「提交答案」；都不合适时点「自己填写」写你的想法。<!-- 待确认：问题卡在任务页里的样子只在频道里见过（okcheese 只读） -->

### 审阅并采纳 {#review}

芝士做完会提交审阅，输入框上方出现一条「改动」，写着「待你审阅」或「待 @〈名字〉 审阅」。

点这一条右边的「审阅」，右侧切到「改动」，逐个文件看芝士改了什么。看完展开这一条，选一个：<!-- 待确认：展开后的按钮在任务页里的排布未在本地看到；「采纳」「退回」「作废」三个按钮名在线上旧版右侧面板里核对过 -->

- 满意：点「采纳」，改动合进项目。采纳后任务自动结束。
- 不满意：点「退回」，在「退回理由（可选）」里写清哪里要改。芝士改完会重新提交。

退回理由写成芝士能照着改的样子，比如：

```prompt
报告第 3 节缺删除操作的复杂度，补上再提交。
```

每个按钮的完整说明见[验收与采纳](/accept#accept)。

:::

## 交出去 {#hand-in}

知是里没有把整个文件夹打包下载的按钮，只能一个文件一个文件地下载。要交源代码加报告，先让芝士打一个压缩包：

```prompt
把 src/ 下的源代码和实验报告打成一个 hand-in.zip，放在项目根目录。
```

再在任务页右侧下载它：「改动」→ 选中 `hand-in.zip` →「⋯」→「下载」。<!-- 待确认：「下载」在旧版话题的「改动」里核对过，任务页的「改动」未单独核对；压缩包这类文件选中后是否直接显示「下载原文件」未实测 -->

要给整个项目留一份备份，打包导出：点侧栏顶部的项目名 →「项目设置」→「数据」→「导出项目」，浏览器会下载一个 `.tar` 包。团队里每个人都能导出。

> [!WARNING]
> 导出包里的代码在 `repository.bundle` 里，这是给 git 用的打包文件，双击打不开。交作业用上面的压缩包。

要交到老师在空间里发布的题目，见[完成一道题目](/solve-a-challenge#submit)。
