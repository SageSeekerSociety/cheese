# 知是设计系统

前端视觉与文案的唯一规范。写页面、改样式、审前端 PR 都以它为准。

它分三层，越往前越稳定：

1. **风格**（§0.1）：我们看起来像什么。
2. **原则**（§0.2）：两件事都想要、只能选一件时，按什么排序。
3. **规则**（§1 起）：从原则推出来的具体做法。每条规则都说明它来自哪条原则；遇到规则没写到的情况，回到原则去推。

代码里的落点只有两处，改颜色必须两边一起改（理由见 §5）：

| 文件 | 管什么 |
|---|---|
| [`frontend/src/style.css`](../frontend/src/style.css) | CSS 变量（手写 CSS 用） |
| [`frontend/src/plugins/vuetify.ts`](../frontend/src/plugins/vuetify.ts) | Vuetify 主题（组件用） |

标志（图形标、字标与组合）怎么用，见 [`brand.md`](brand.md)。

## 0. 风格与原则

### 0.1 风格：温暖的精密

知是像一间安静、明亮的工作室：工具摆放整齐，做事的人很专注，屋子是暖的。

| 气质 | 落在界面上 |
|---|---|
| **专注** | 界面退后，项目、讨论、代码是主角 |
| **精确** | 对齐、间距、每一个状态都是有意为之 |
| **温暖** | 琥珀色、圆润的字标；温度克制地放在关键处，不铺满 |
| **好奇** | logo 里那只仰望月亮的老鼠——探索与求知，也是「知是」这个名字的意思 |

**像**：Linear 的精确，Things 的从容，Notion 的温和。

**不像**：传统中后台（Material 卡片堆、满屏彩色标签）；赛博霓虹风的 AI 产品（紫蓝渐变、发光特效）；卡通化的教育产品。

### 0.2 原则

每条原则都是一个取舍：两件事都想要、只能先顾一件时，按它来排。

1. **内容是主角，界面退后。** 边框、底色、图标、标签只用最少的量把结构说清楚。省下来的空间留给空白，不是用来塞更多内容。
2. **留白是结构，不是剩余。** 用间距而不是线和框来分组：越相关的离得越近，层次一眼可见。密度跟着任务走——扫读的列表和表格可以密，阅读和做决定的地方要松；同一类页面用同一种密度。
3. **清晰优先于巧妙。** 一眼能懂比新奇更重要：熟悉的交互、直白的文案、不需要解释的图标。
4. **不打断心流。** 能就地完成的不弹窗；操作立刻有回应，不等服务器；不丢滚动位置、草稿和选中项；内容加载时布局不跳；键盘能走完主流程。新手不迷路，熟手不被拖慢。
5. **动效解释变化。** 动效告诉人东西从哪来、到哪去、变成了什么。它要自然（进来减速停稳，离开加速走开）、连贯（同一种变化全站同一种动作）、可打断（中途改主意从当前位置接着走）。不为动而动。
6. **AI 是队友，不是魔法。** 芝士在界面上与人以同一种方式出现；它在做什么、做到哪一步、为什么这么做，都看得见。不用特效制造「AI 感」。
7. **每个状态都值得认真做。** 空状态、加载、出错、键盘焦点、深色模式，与正常状态同等重要。高级感大多来自这些没人刻意去看的地方。
8. **温度留给关键时刻。** 平时安静克制；在进门、完成、第一次这些时刻，才给出品牌与情感。

## 1. 颜色

### 1.1 永远写变量名，不写色值

原则 7。产品有浅色和深色两套主题，`var(--text)` 在两套下各自解析成合适的值；写死的 `#36383c` 两套下都是深灰，一到深色模式就看不见。

```css
color: var(--text);   /* 对 */
color: #36383c;       /* 错：深色模式下是黑底黑字 */
```

stylelint 会拦下新增的写死颜色（§7）。

### 1.2 不带 `#` 的写死颜色：Vuetify 固定调色板名

模板属性和 class 里还有一类写死的颜色，长得不像颜色：

```vue
<!-- 错：这四种写法等于写死 #FAFAFA / #FFFFFF / 固定灰 -->
<v-navigation-drawer color="grey-lighten-5">
<v-main class="bg-grey-lighten-5">
<v-avatar color="white">
<span class="text-grey-darken-1">

<!-- 对 -->
<v-navigation-drawer color="background">
<v-main class="bg-background">
<v-avatar color="surface-bright">
<span class="text-medium-emphasis">
```

`grey-lighten-5`、`white` 这些名字来自 Material 固定调色板，不是我们主题里的语义色，切换主题时纹丝不动。它们读起来像语义色，又躲开了 stylelint（它只解析 CSS），所以单独有一道闸门（§7）。

| 别写 | 写这个 | 用途 |
|---|---|---|
| `color="grey-lighten-5"` / `bg-grey-lighten-5` | `color="background"` / `bg-background` | 应用底色、外壳底色 |
| `color="white"`（面、底） | `color="surface-bright"` | 浅色下仍是白，深色下比 surface 亮一档 |
| `color="grey-lighten-4"`（填充块） | `color="surface-light"` | 输入框底、选中行底 |
| `text-grey-darken-1` / `text-grey` | `text-medium-emphasis` 或 `text-on-surface-variant` | 次要文字 |
| `color="grey"`（图标） | `color="on-surface-variant"` | 中性图标 |
| `color="amber"` / `color="amber-darken-2"` | `color="primary"` | 主色 |
| `color="red"` | `color="error"` | 状态色走语义名 |

**唯一的例外**：底色本身不随主题变的地方，压在上面的前景色也不该变。例如默认头像的底色由 `avatarColor()` 按固定的 OKLCH 亮度算出，两套主题下是同一个值，上面的白字就该保持写死的 `#fff`；换成 `on-surface` 反而会坏。这种地方**必须在代码里写明为什么**，否则下一个人会「顺手修好」它。

### 1.3 中性色：按信息离读者多远选

原则 1。每屏绝大部分颜色取自这条色阶。选哪一档看信息的重要程度，不看好不好看。

| 变量 | 用在哪 |
|---|---|
| `--ink` | 标题 |
| `--text` | 正文 |
| `--muted` | 次要文本：副标题、说明、辅助按钮文字、轴标签、表头 |
| `--faint` | 元信息：时间戳、ID、计数、占位提示 |

不要跳档（比如正文用 `--faint`）——那不是低调，是让人看不清。

### 1.4 面与线：按层次选

| 变量 | 用在哪 |
|---|---|
| `--canvas` | 外框：一级导航、侧栏、顶栏 |
| `--surface` | 内容区，以及卡片 |
| `--raised` | 浮在页面之上的一层：菜单、下拉、对话框、底部面板 |
| `--fill` | 悬停高亮、内嵌区块（看板的泳道、代码块、引用） |
| `--fill-2` | 比 `--fill` 重一档 |
| `--line` | 发丝分隔线 |
| `--line-2` | 更明显的分隔线，**也是选中行的底色** |

外框和内容区（原则 1）：导航退后，内容在前。外框是 canvas，内容区是一整块 surface，中间一条 `--line`；侧栏左边那条线和顶栏下面那条线在侧栏左上角拐一个 12px 的圆角，没有侧栏的页面，这个角落在内容区自己身上。手机上也一样：顶栏、底栏是 canvas，中间是 surface。写法在 `App.vue` 的 `.app-pane` 上，页面不再给自己的根元素刷底色。

内容区已经是 surface，所以内容里不再用「灰底上放白卡片」分层：按间距和 `--line` 分组；真要一个框，就是 surface 加 `--line` 描边；需要一块沉下去的区域（看板的泳道、代码块），用 `--fill`。

浮着的比它盖住的东西更亮。浅色下 `--raised` 就是 `--surface`，浮层靠投影浮起来；深色下投影看不见，`--raised` 比 `--surface` 亮一档（§3.4）。浮层里的 `--surface` 和 `--fill` 由全局规则跟着上移，写浮层内容时照常按语义选变量。

`--line-2` 兼作底色，而且是离文字色最近的一层底，所以量文字对比度时以它为准（§2.6）。

### 1.5 状态色：三件套，不能混用

每个状态色有三个变量，用途不可互换：

| 后缀 | 是什么 | 用在 |
|---|---|---|
| `--ok` / `--warn` / `--danger` | 记号 | 状态圆点、1px 边框、图标填充 |
| `--ok-ink` / `--warn-ink` / `--danger-ink` | 文字 | 状态文本、链接 |
| `--ok-wash` / `--warn-wash` / `--danger-wash` | 底色 | 状态标签、提示条背景 |

记号色在浅底上对比度不够写字（`--warn` 在白底上只有约 2.3:1），写字用 `-ink`。

```css
.error-message { color: var(--danger); }       /* 错：浅色下看不清 */
.error-message { color: var(--danger-ink); }   /* 对 */
.error-chip { color: var(--danger-ink); background: var(--danger-wash); }  /* 状态标签的标准形态 */
```

状态色**只用于真实状态**。「这个标签好看」不是状态。状态只有这三种；需要第四级时，用明度或形状区分，不造新颜色。

### 1.6 琥珀：只给要紧的东西

原则 1、3。琥珀只出现在四类地方：

1. **主操作按钮**：一块区域里让事情往下走的那一个，例如发送、提交、去验收。一页里可以有几个，只要各在各的区域；**同一组并排的按钮里只有一个**：「保存」「取消」并排时只有「保存」是琥珀。
2. **未读**：未读数、页签上的新内容点、「以下是新消息」那条线。
3. **当前导航位置**（选中态）：图标用 `--accent`，字用 `--accent-ink`，不垫灰底。
4. **品牌标记**本身。

次要按钮、头像、状态标签、普通图标、选中行底色，一律不用琥珀。琥珀的用处是让人不用想就找到该点的地方；一组按钮里出现两个琥珀，或者琥珀被拿去装饰，这个用处就没了。一块区域里没有推动事情的操作（例如只有开关的设置页），就不出现琥珀。

| 变量 | 用在哪 |
|---|---|
| `--accent` | 主操作按钮的填充、当前导航位置的图标与指示条 |
| `--accent-press` | 上面这些的按下态 |
| `--accent-ink` | 琥珀色文字（`--accent` 本身写字对比度不够） |
| `--accent-wash` | 极浅的琥珀底，罕用 |

`--accent-press` 在两套主题下方向相反：浅色下按下变深，深色下按下变亮。按下要有「更靠近你」的感觉，深色背景上更亮才是靠近。

### 1.7 图表：不用颜色区分系列

原则 1、3。给第二条线一个颜色，等于当场造出第二个「重要」的东西。系列靠明度与线型区分，去色打印后仍分得清：

| 系列 | 颜色 | 线型 | 标记 |
|---|---|---|---|
| 主系列 | `--text` | 实线 2px | 实心圆 4px |
| 副系列 | `--muted` | 虚线 2px（`stroke-dasharray: 4 3`） | 空心圆 4px |
| 网格线 | `--line` | 1px | — |
| 悬停竖线 | `--line-2` | 1px | — |

- 轴标签、图例、表头用 `--muted`，不用 `--faint`：刻度是读图必须读的东西。
- 不引入第二个颜色族（蓝、紫）：它会和状态色抢语义。
- **每张图配一份表格孪生体**（原则 7）：`<details>` 里一张默认折叠的表，标题「查看数据表」。它是读屏用户、键盘用户和想抄一个数的人唯一能拿到数值的地方。

### 2.4 品牌光晕

`--logo-primary`（`#F9B233`）与 `--logo-secondary`（`#E85D2C`）两套主题下相同，只以 4–8% 的透明度叠加使用，所以允许比任何实心填充都鲜艳。它们同时定义在 Vuetify 主题里（`logo-primary` / `logo-secondary`）。

### 2.5 反色

和页面反着色调的小块（浮着的悬停提示）用 `--inverse-surface` / `--inverse-ink` / `--inverse-fill`。深色下它不翻回浅色，而是一块比页面亮的灰：浮着的东西要比它下面的底更亮，才看得出是浮着的；翻成近白的一块，则是深色页面上最刺眼的东西。

| 变量 | 浅色 | 深色 |
|---|---|---|
| `--inverse-surface` / `--inverse-ink` / `--inverse-fill` | `#23242A` / `#FFFFFF` / 白 14% | `#3A3D44` / `#F3F4F6` / 白 10% |

### 2.6 界面杂项

`--scrollbar-*`、`--focus-ring`、`--selection-bg`、`--overlay`、`--shadow-1` / `--shadow-2`、`--code-*` 是管道，不是设计语言的一部分。`--focus-ring` 是无障碍底线，不要移除。

### 2.6 对比度

原则 7。WCAG AA：正文 ≥ 4.5:1，大字号与图形 ≥ 3:1。

**每一档都拿它实际落在的最深那层底色去量**，不能只量 `--surface`。中性色阶里最不利的底色是 `--line-2`（它也是选中行的底色）；焦点圈要在五种底色上都达到 3:1。只量一层底色，等于给这一档判了个假达标。

`--accent` 在浅色下只能做填充不能做文字，这是取舍，不是待办；写字用 `--accent-ink`。

### 2.7 AI 队友头像

AI 队友的头像（`CheeseAvatar`）有自己的一组颜色：五档暖色的深底 `--agent-tone-0` … `--agent-tone-4`，眼睛是 `--agent-ink`。每位队友按 handle 固定分到一档，一个项目里的几位队友靠它区分，改名不变色。深色主题下每一档都提亮，道理和反色一样：比页面亮一些，才像浮在页面上的一块。形状和画法见 [`brand.md`](brand.md) §10。

| 变量 | 浅色 | 深色 |
|---|---|---|
| `--agent-ink` | `#FFF7EA` | `#F6EFE4` |
| `--agent-tone-0` … `4` | `#221E1A` `#22324F` `#1E3A33` `#36294A` `#46292A` | `#4A443D` `#34466A` `#2E5047` `#4A3C61` `#5E3A36` |

## 3. 尺度

### 3.1 圆角：三档加胶囊

| 变量 | 值 | 用在哪 |
|---|---|---|
| `--radius-sm` | 6px | 标签、chip、小徽章 |
| `--radius-md` | 8px | 按钮、输入框、列表项 |
| `--radius-lg` | 12px | 卡片、面板、弹窗 |
| `--radius-pill` | 999px | 胶囊、圆形头像、进度条 |

先问「这个元素是什么」，再看它原来写了几像素：一个 10px 的小标签折到 `--radius-sm`，一个 10px 的输入框折到 `--radius-md`；进度条是胶囊，折到 `--radius-pill`。

- 只圆某几个角时写长写法（`border-top-right-radius` 等）；简写 `0 8px 8px 0` 过不了闸门。
- Vuetify 的部分组件自带 `!important` 的圆角（例如 `VCard` 是 24px），scoped 样式压不过它：在组件上显式写 `rounded="lg"`，否则圆角静默失效。

### 3.2 字号与行高

原则 1、3。排版优先用工具类，不手写 `font-size` / `line-height`：

| 工具类 | 字号 / 行高 | 用在哪 |
|---|---|---|
| `.t-page-title` | 23 / 33，650 | 页面大标题 |
| `.t-console-title` | 23 / 33，650，字距 0 | 管理后台页标题、看板 KPI 大数字 |
| `.t-dialog-title` | 18 / 26，600 | 弹窗标题 |
| `.t-title` | 15 / 21，600 | 分区、卡片标题 |
| `.t-body` | 14 / 20 | 正文 |
| `.t-body-readable` | 14 / 22，400 | 连排三行以上的正文：卡片摘要、详情正文 |
| `.t-reading` | 15 / 24，400 | 660px 阅读栏里的连续正文 |
| `.t-dense` | 13 / 19，600 | KPI 卡短读数、表格计数 |
| `.t-eyebrow` / `.t-eyebrow-read` | 12 / 18，600 | 分区上方的引导词、表头 |
| `.t-meta` / `.t-meta-read` | 12 等宽 / 18 | 时间戳、ID、计数 |
| `.t-num` | — | 任何会被纵向比较的数字（等宽数字） |

`-read` 结尾的两个类与原类同尺寸，颜色是 `--muted` 而不是 `--faint`。新写的元信息用 `-read` 版本。

聊天消息流——人说的话、芝士的回复、输入框——是连续阅读，用 `.t-reading` 那一档 15 / 24（`--lh-15-reading`）；输入框和消息同档，打出来的字和发出去的字一样大。侧栏、列表、按钮、表单这些界面文字仍是 13–14。

必须手写时：

- 字号只用 **12 / 13 / 14 / 15 / 18 / 23 px**，正文不低于 13px，不写半像素。
- 行高成对取 token（`--lh-12` 18、`--lh-13` 19、`--lh-14` 20、`--lh-15` 21、`--lh-18` 26、`--lh-23` 33；长文另有 `--lh-14-loose` 22、`--lh-15-reading` 24）。写整数像素的 token，不写比例：比例会被嵌套的小字号再乘一遍，落到像素网格外。
- 老代码的行高往 token 上折时，按这段文字**是什么**（正文、标题、元信息）选 token，不按数值就近选。
- 中文字体没有 430 这一档字重，写 430 会被渲染成 500；长段中文用 400。

超大字号只出现在门口页面（官网、登录、空状态），属于一次性排版，不进这张表。

### 3.3 间距与密度

原则 2。间距只用 **4 / 8 / 12 / 16 / 24 / 32 px**，门口页面需要大留白时可以用 48 / 64；优先用 Vuetify 的间距工具类（`pa-2` = 8px）。

选哪一档，看两样东西之间的关系，不看「这里空不空」：

| 关系 | 间距 |
|---|---|
| 同一个组件内部（图标与文字、标签与输入框） | 4 / 8 |
| 相关的元素之间（同一组表单项、同一张卡片里的几行） | 12 / 16 |
| 组与组之间 | 24 / 32 |
| 页面上的大区块之间 | 48 及以上 |

能用间距分开的，就不加分隔线和外框。组内间距必须明显小于组间间距，否则分组就看不出来。

密度按页面的任务选一档，同一类页面用同一档：

- **标准**：大多数页面。表单、设置、详情、讨论。
- **紧凑**：以扫读为主的地方。长列表、表格、看板、侧栏。行更矮、组件内部间距取小一档，但组与组之间的间距不缩。

### 3.4 层次：卡片描边，浮层投影

原则 1。**卡片只描边，不投影**：内容区和卡片都是 surface，卡片靠 `--line` 描边和内容分开，沉下去的区域用 `--fill`（§1.4）。投影只给浮在页面之上的东西——菜单、弹窗、抽屉——用 `--shadow-1` / `--shadow-2`。深色下投影几乎不可见，浮层靠比下面更亮的底色（`--raised`，§1.4）分开。

浮层的外壳只画在一处：`style.css` 给 Vuetify 的浮层定好了长相。菜单和下拉（`v-select` / `v-autocomplete` 的下拉也是菜单）是 `--raised` 底、`--line-2` 描边、`--radius-lg` 圆角、`--shadow-2`，里面每一行 36px（手机上 44px），悬停 `--fill`，选中 `--line-2` 加粗；悬停提示和提示条是反色（§2.5），提示的成功、警告、失败由图标的记号色说；对话框的遮罩是 `--overlay`，卡片是 `--raised` 底、`--shadow-2`。所以页面里写一个裸的 `<v-menu>`、`<v-select>`、`<v-tooltip>` 就是对的：不要再给菜单里的 `v-list` / `v-card` 另画底色、描边和投影，也不要给 `v-snackbar` 传 `color`，状态由文字和图标说（§1.5）。

### 3.5 页面宽度

宽度是页面的属性，不归每个页面各自写一个数字：骨架里的一整页套 `AppPage`（`src/components/common/AppPage.vue`），宽度由它的 `width` 档给，页面不再写 `max-width`。五档（默认 `read`），一档一个用途：

| `AppPage` `width` | token | 值 | 用在哪 |
|---|---|---|---|
| `read`（默认） | `--page-w` | 920px | 表单、卡片列表、设置行这类一栏里读一样东西的内容 |
| `wide` | `--page-w-wide` | 1100px | 多列的目录 / 卡片网格：卡片按 minmax 排成好几列，宽屏上列数还要跟着长（市场：一块节点看板加两组卡片），920 只放得下两三列 |
| `prose` | `--page-w-read` | 660px | 整页连续正文（周报、记忆、一篇文档），比 `read` 窄 |
| `full` | —— | 铺满内容区 | 多列的工作面：看板那几列、资料库的目录加正文，自己管列和滚动 |
| `admin` | `--page-w-admin` | 1440px | 管理后台的工作台（表格、KPI 网格；断点用容器查询挂在内容列上） |

**怎么选。** 先看这一页的正文是一栏还是一整块工作面。一整块自己管列和滚动（看板、资料库）用 `full`，管理后台用 `admin`。是一栏，再分「读」还是「看」：连着读的正文用 `prose`；表单和卡片列表用 `read`；卡片排成好几列、宽屏上列数还要长的目录用 `wide`。

连续正文要比表单窄：栏太宽时一行六十多个汉字，回行时眼睛找不到下一行的开头。手机外壳里（窄于 960px）一页只有一栏，`--page-w` 和 `--page-w-wide` 都取 720px，见 §10.8。后台页的断点用容器查询（挂在内容列上），不用视口媒体查询——侧栏折叠省出的宽度，视口查询看不见。

一页套 `AppPage`：项目里的页面（看板、成员、项目文档、资料库）和个人页（收件箱、已归档的项目、市场）都是它。它画顶上那条 48px 页头（和侧栏项目名那一条、房间的话题头是同一条线；页头写这一页是什么，项目名不再写一遍）、正文那唯一一栏，以及页头里的命令按钮（页面用 `useCommands` 登记标了 `header` 的命令）。操作靠右，是小号的文字按钮，图标在字前面；这一页的主操作是唯一一颗琥珀色实心按钮。手机上这一条怎么变，见 §10。

**什么时候不套 `AppPage`。** 三种东西有它自己的外观，再套一层就是第二个页头加第二栏，反而叠了：

- **设置页**（个人、资料、项目、空间）：设置是盖在整个窗口上的一层（`SettingsOverlay`），左边目录、右边内容，标题写在内容里，没有这条页头——下面那条 `so__content`（720 居中）就是它的内容列。设置页共用 `settings-card` 外壳（`styles/settings-card.css`）。
- **一整块工作面里的一节**：看板的一列、`ProjectArtifactView` 里的改动清单 / 两版比较 / 版本列表——它们住在那一页的 `full` 栏里，是那一页的一部分，不是一页。
- **独立的门口页**（不进产品骨架的）：404、`views/account/*`、`ConnectView` 这类，自己排自己的版。

判据只有一句：**这东西是不是产品骨架里的一整页。** 是，就套 `AppPage` 并选一档；不是，就在它的容器上写一行英文注释，说清为什么它不套——下一个读代码的人才分得清这是决定，不是漏掉。

设置浮层（`SettingsOverlay`）的几何自成一条，四类设置页（个人、资料、项目、空间）共用：目录灰栏**钉在窗口左缘、定宽 264px**（目录 216px + 两侧内距各 24px），不随窗口变宽；右边是内容区，一条最宽 **720px**、四边内距 24px 的内容列在「窗口减目录」剩下的地方**居中**（`margin-inline: auto`）。于是目录与内容之间的留白 = 内容列右侧留白 = `(窗口 − 984px) / 2`，天然对称——和 app 壳是同一条规则（左轨钉窗口左缘，页面内容在主区居中）。窗口窄到装不下 720 + 两侧各 24（约窄于 1000px）时，内容列先收窄。各页自己不再设宽度和水平内距，只留竖向节奏，同一宽度下四类页的内容列左右缘对齐。内容区带 `scrollbar-gutter: stable`。关闭按钮（`BaseButton`，`ghost` + `sm`，图标 `mdi-arrow-left`——和 app 壳顶栏那颗返回同一款）落在页头那条 48 的线上：灰栏的 `padding-top` 48px 就是那一节页头，按钮在那条线里竖向居中、左缘对着灰栏的内容内距 24px，不压下面的目录。它和 app 壳顶栏那颗返回是同一款按钮，但分属两个框——壳顶栏是 32 高的窗口栏、里面那颗贴着窗口左缘，而两者不会同时出现（设置一打开就整屏盖住壳），所以各自和自己的容器对齐，不追求跨框对齐。它绝对定位在整个浮层上，右边的目录和内容怎么滚它都不动。窄于 960px 的骨架里没有灰栏，内容列 720 居中（见 §10.8）。

### 3.6 按钮：四种角色、三档大小

原则 1、3。按钮一律写 `BaseButton`（`src/components/base/BaseButton.vue`），不直接写 `<v-btn>`。调用处只说两件事：这颗按钮在这块区域里**是什么角色**（`kind`），**多大**（`size`）。颜色、样式变体、字号、图标大小由角色推出，调用处不写 `variant` / `color`。

| `kind` | 长相 | 用在哪 |
|---|---|---|
| `primary` | 琥珀实心 | 让这块区域的事情往下走的那一颗：提交、保存、下一步、发送。同一组并排按钮里只有一颗（§1.6） |
| `secondary` | `--line-2` 描边、`--text` 字 | 单独出现、要被看见、但不是主操作：设置行里的「修改」「添加」「开启」，空状态里的引导，一组下载里第一颗以外的几颗 |
| `ghost` | 无底无框、`--muted` 字 | 弹窗和表单里的「取消」「返回」，工具条、列表行、卡片角落的操作，所有纯图标按钮，以及会先弹确认的移除、停用、解绑入口 |
| `danger` | `--danger-ink` 红字、无底 | 直接生效、不再确认的破坏性操作。破坏性确认弹窗里的那一颗确认键加 `solid`，实心红 |

| `size` | 高度 | 用在哪 |
|---|---|---|
| `sm` | 28px，字 13 | 列表行、工具条、卡片和设置行里 |
| `md`（默认） | 36px，字 14 | 表单、弹窗底部 |
| `lg` | 44px，字 14 | 门口页面的单个大按钮、手机上整行宽的提交 |

- 纯图标按钮传 `icon`，同时给 `aria-label`（或 `title`），否则读屏只念「按钮」。
- 弹窗底部的顺序固定：取消（`ghost`）在左，主操作在右，靠右对齐。
- 会弹确认的入口用 `ghost`，红色留给确认弹窗里那一颗：一列「停用」「移除」全标红，红色就不再是警告。
- 列表里逐行重复出现的删除/移除入口（文件、成员、连接、设备、密钥……）一律用 `ghost`：几行并排的红图标会让红色失去警告作用。不可逆的先补一个 `danger` 确认（§3.7），红只出现在那一颗确认键上；能重做的（删通知、清变量、撤回申请、撤回邀请）直接生效，不弹确认。接受/拒绝成对出现时是例外：拒绝那一颗仍用 `danger`，它是这一行当下唯一的表态，不是重复出现的行内入口。
- 可逆的操作不算破坏性：能重新连上的「断开连接」用 `ghost`。
- 原来是紧凑密度的按钮（尤其是放在输入框里的图标按钮）保留 `density="comfortable"`，它会透传给 v-btn。
- 不能用 BaseButton 的地方（分段切换 `v-btn-toggle` 里的格子、导航栏、手机整页弹窗页头）留着 `<v-btn>`，前面加一行 `eslint-disable-next-line vue/no-restricted-syntax -- 原因`。
- 角色按这颗按钮在这块区域里做什么来选，不按它以前长什么样。同一个「接入这台电脑」，在空状态里是 `secondary`，在「添加设备」弹窗里是 `primary`。
- 手机整页弹窗页头的 ✕ 和页头动作是顶栏写法（44px、文字色），暂不属于这四种角色。

### 3.7 弹窗：表单弹窗三档宽度，确认框只有一种

原则 1、3。弹窗只有两种，写法各一个组件，不直接写 `<v-dialog>`。

| 种类 | 组件 | 长相 | 用在哪 |
|---|---|---|---|
| 表单弹窗 | `AdaptiveDialog` | 桌面居中，标题、正文、底部「取消 + 主操作」靠右；手机（< 960px）是一整页（§10.5） | 要填一项以上的东西：新建、编辑、接入 |
| 确认框 | `ConfirmDialog`，或 `useDialog().confirm(…)` | 桌面和手机都是居中的 420px 小框：标题、一两句话、两颗按钮 | 让人在「做 / 不做」之间选一个：删除、移出、替换、发送 |

表单弹窗的宽度只有三档，用 `size` 选：

| `size` | 宽度 | 用在哪 |
|---|---|---|
| `sm` | 420px | 一两个字段 |
| `md`（默认） | 560px | 一般表单 |
| `lg` | 720px | 并排两列、带预览的表单 |

- 三档从全仓 63 个弹窗的宽度归出来：420/440 最多，其次是 520–600 和 640–720。查看器、编辑器这类本来就要占满大半屏的不是弹窗，不在此列。
- 确认框没有右上角 ✕，点遮罩、按 Esc 也不关：要人在两颗按钮里明确选一颗。
- 确认键写动作本身（「移出」「删除」「替换」），不写「确定」。不可撤销时确认键是实心红（§3.6 `danger` + `solid`），否则是琥珀主操作。
- 标题用问句说清要做什么、对谁做（「把爱丽丝移出项目？」）；正文只写后果，一两句，不重复标题。

### 3.8 层级

原则 1。`z-index` 只从 `style.css` 的 `--z-*` 里取，不写裸数字。裸数字的毛病不在难写，而在**看不出这一层是什么、该压在谁上面**：下一个人要加一层，只能猜，猜到一个跟邻居一样的值，谁在上面就交给 DOM 顺序。整套 token 与主题无关，只在 `:root` 写一次。

| token | 值 | 用在哪 |
|---|---|---|
| `--z-raised` … `--z-raised-8` | 1–8 | 一个组件自己的层叠上下文里，把某一块抬到兄弟之上。这几个数字只是**次序**，不是含义：文档编辑器那套 2–8 的梯子和图表提示的 1 都从这里取。会同时出现的两个兄弟不能取同一个 token |
| `--z-sticky` | 10 | 钉在自己滚动区上沿的条：页头、侧栏头、落地页顶栏 |
| `--z-panel` / `--z-panel-2` | 20 / 22 | 面板内部的浮件：文档表格手柄、文档评论抽屉 |
| `--z-shell` | 30 | 盖在外壳上的浮件：撤销条、面板自己弹的提示条 |
| `--z-overlay-below-vuetify` | 1999 | 整窗的一层，**要让 Vuetify 的菜单/弹窗压得住**（设置浮层）；Vuetify 的浮层从 2000 起 |
| `--z-overlay` | 2400 | 应用自己的固定浮层，落在 Vuetify 弹窗那一层：命令面板、演示放映、文档键盘条、文档里的弹出块 |
| `--z-overlay-2` | 2450 | 在弹窗之上：全屏的富文本编辑器 |
| `--z-menu` | 2500 | 要盖住上面这些浮层的菜单（编辑器工具栏） |
| `--z-banner` | 3000 | 离线横幅、版本角标：应用自身最高的一层（sonner 的 toast 故意排在整个应用之上） |

- **不动 Vuetify 自己的 z-index。** 它的浮层会自己往上叠：第一个按基值（菜单 2000、弹窗 2400），此后每开一层 +10。所以我们的 token 要么落在 2000 以下（设置浮层），要么跟它同层或更高（应用浮层）。
- `--z-overlay` 与 Vuetify 弹窗基值同为 2400：两者同时在场时由 DOM 顺序决出。当前没有一处会同时出现（应用浮层各自独占屏幕），所以保持原值不动；真要叠在一起，把那一处抬到 `--z-overlay-2` 与 `--z-menu` 之间的空档。
- `z-index` 写在 CSS 里用 token；Vuetify 组件的 `:z-index` 属性只收数字，读不到 CSS 变量，这时在 JS 里留一份带注释的常量（目前只有 `--z-menu` 一份，见 `RichTextToolbar.vue` 的 `MENU_Z`、`CommandPalette.vue` 的 `SHEET_Z`）。

### 3.9 表单与设置行

原则 1、4。表单里**一个字段**写成一个 `BaseField`（`src/components/base/BaseField.vue`），设置页里**一行**写成一个 `SettingsRow`（`src/components/base/SettingsRow.vue`）。两件都只摆位置、挂 aria，控件还是调用处自己的 `v-text-field` / `v-select` / 原生 `<input>`。

**字段：标签在框外。** 不吃控件的浮动标签：outlined 控件的浮动标签骑在边框上，半个字高在框外，两栏叠起来时下面那一栏的标签会压在上面那一栏的边框上（`.claude/rules/frontend.md`）。标签在框外就没有这件事。字号 13px / 500 / `--text`，和 `components/account/AccountField` 一致。

`BaseField` 只做控件做不了的那几件，其余都从插槽属性交给控件：

| 做什么 | 怎么用 |
|---|---|
| 标签与控件关联 | 不给 `id` 就生成一个；控件的 `id` 从 `v-slot="{ id }"` 拿 |
| `aria-describedby` | 提示、报错、字数三行的 id 都拼在里面，`v-bind` 给控件 |
| `aria-invalid` | 有 `error` 时为 true。Vuetify 自己只挂 `aria-describedby`，不挂这个 |
| `aria-required` | `required` 时 true。Vuetify 自己也不挂它 |
| 必填标记 | 标签后一个 `aria-hidden` 的 `*`，加一句只有读屏念的「必填」 |
| 选填下标 | `optional` 时标签后跟「（选填）」 |
| 报错那一行 | `error`，`--danger-ink` 写字（`--danger` 只配当标记色） |
| 字数 | `counter="{ current, max }"`，画成「12/200」 |

```vue
<BaseField :label="t('…')" required :counter="{ current: n, max: 200 }">
  <template #default="{ id, describedby, invalid, required }">
    <v-text-field
      :id="id"
      :aria-describedby="describedby"
      :aria-invalid="invalid"
      :aria-required="required"
    />
  </template>
</BaseField>
```

- **有 `maxlength` 就要有字数**。没有字数，粘进来的长文本被悄悄截断，人不知道少了什么。Vuetify 控件给 `counter` 加 `persistent-counter`（常驻，不只在聚焦时出现）；原生 `<input>` 这种控件由 `BaseField` 的 `counter` 画。
- **必填要有看得见的标记**，不能只靠校验时弹一句报错。`BaseField` 的 `required` 给的是 `*` 加读屏文字「必填」。改用旧栏时当心：Vuetify 控件用的是自己的标签槽（`v-text-field` 的 `#label`），往槽里补文字会改掉标签的可读文字，按标签文字找控件的代码和测试会一起失准。那种地方在槽里放一个空的 `aria-hidden` 标记，用 CSS `::after` 画星号，必填语义交给控件的 `aria-required="true"`（Vuetify 自己不挂它）—— `TaskFormBasicCard` 就是这么做的。
- 标签、必填 / 选填、报错都只说一遍（§8.5）：已经有 `label` 的控件不要再在外面写一遍同义的标题。

**设置行：一种写法。** 同一种设置行现在有三种写法：`.srow` 的 180px 标签列、`.srow--field` 的 120px，以及各组件自己拿 flex 排的没有固定列的行。新写的一律用 `SettingsRow`：标签和一句说明在左，控件在右。`width` 是控件那一栏的宽：

| `width` | 控件那一栏 | 用在哪 |
|---|---|---|
| `text`（默认） | 340px | 一行文本输入 |
| `select-wide` | 280px | 带说明的下拉 |
| `select` | 192px | 普通下拉 |
| `code` | 160px | 短值：数量、标识符 |
| `list` | 自由宽 | 一列名单、一段多行文本 |
| `none` | 满宽 | 不留右边的栏，标签在上、控件占满整行 |

- 标签列 180px，和 `styles/settings-card.css` 的 `.srow` 对齐。
- **容器窄于 672px 时标签换到控件上面**，控件占满整行。判据是这一行有多宽，不是窗口有多宽（设置浮层的内容列、拖动的侧栏都会让窗口宽度答错），所以用容器查询：根元素声明 `container-type: inline-size`，并按 AppPage 的注释补 `width: 100%`——行内尺寸包含之后宽度推不出来。
- 控件不是表单字段（一串读数加一颗按钮）时不传 `for`，标签就是一行字；是表单字段就传控件的 `id`，标签变成 `<label for>`。

### 3.10 加载失败：错误留在它读的那块地方

原则 7。**读一整块内容失败时，不要让失败退化成一个空状态。** 空状态说的是「这里本来就没有」（§8.1「暂无 X」），读失败说的是「这里本该有、没读到」；两者用同一种样子，人错过那一条几秒的红条，就再也分不出「没有」和「坏了」。失败要**替换掉它读的那块内容**，就地给出服务端那句真实原因和一条重试的路。

一个组件：`BaseLoadError`（`src/components/base/BaseLoadError.vue`）。给三样：这一块读失败的那句话（`title`，如「加载总览失败」）、服务端的原因（`error`，取 `ApiError.message`，没有就不显示那一行）、以及 `@retry` 上重新调那个取数函数的入口。`title` 不给就用全局的「加载失败」。

```vue
<BaseLoadError
  v-else-if="failed"
  :title="t('spaces.analytics.overview.loadFailed')"
  :error="errorDetail"
  @retry="load"
/>
```

- 写法照 `views/spaces/detail/analytics/*`：`load` 开头清掉 `failed` 与 `errorDetail`，`catch` 里 `failed = true`、`errorDetail = error instanceof Error ? error.message : null`，**不再** `toast.error`——同一件事不说两遍。
- 只有「一整块内容没读到」才替换内容。列表里某一行、某一次操作（保存、删除）失败仍用 toast：那一行的内容没有消失，也没有整块可替。

### 3.11 保存反馈：设置就地留痕，临时动作弹条

原则 7。保存有两种，反馈也就两种，别混：**改的是一块留得住的设置，就地把结果留在那一块**；**做的是一次过去就没了的动作，结果用全局 toast 说一声**。判据是「保存完以后，这页还立着同一块东西等下一次改吗」——是，就地留；不是，弹条。

- **持久设置区块**（设置页里的一栏、一张表单）：改了没存要能看见，存好了也要能看见「刚存好的是这块」。用 `SaveBar`（`src/components/base/SaveBar.vue`）——脏了才浮出来的那条栏，右边「还原 / 保存」，左端跟一个 `SaveStatus` 和一句「未保存」；`SaveBar` 自己会推 `revert` / `save`。只有一颗按钮、没有脏状态的行（拨一下开关就提交那种），把 `SaveStatus`（`src/components/base/SaveStatus.vue`）摆在按钮旁边。
- **一次性动作**（复制到剪贴板、设了个提醒、立刻生效的一次调用）：没有「这一块」可留痕，成功和失败都走全局 toast（`vuetify-sonner` 的 `toast`）。别再各写 `v-snackbar`。

状态只从 `useSaveState`（`src/composables/useSaveState.ts`）来，一次写用 `run(async () => …)` 包住：

```ts
const { saving, saved, dirty, error, run } = useSaveState({
  feedback: 'inline',            // 持久设置；一次性动作写 'toast'
  dirty: () => dirty.value,      // 有脏状态才传
  messages: { saved: t('…saved'), failed: t('…saveFailed') },
})
```

- `feedback: 'inline'`：失败时 `error` 有值，交给 `SaveStatus` 就地显示，几秒后淡掉；成功同理。`feedback: 'toast'`：成功失败都由 `useSaveState` 弹 toast，不再需要额外的提示状态。
- 一次保存只出现一种样子，且都**在原地淡入淡出**（§9.3 的时长 token），不弹窗、不挤动布局：保存中 `保存中…`（`--muted`）；已保存 `已保存`（`--ok-ink`，`role=status`）；失败 `保存失败`（`--danger-ink`，`role=alert`，按 §8.9 用冒号接服务端原因）。
- **不要再自己写 `saving = ref(false)`**，也不要给一次性动作硬套 `SaveStatus`：那会把「保存失败」的前缀安到「发送失败」上面。一个说法只配一种动作。

### 3.12 空状态：一个组件、三档大小

「这里本来就没有」只用 `BaseEmptyState`（`src/components/base/BaseEmptyState.vue`），不再手写 `<p class="xxx__empty">`、不用 Vuetify 的 `v-empty-state`。文案照 §8.1。

| `size` | 用在哪 | 长相 |
|---|---|---|
| `page` | 整页或整块区域就是空的 | 40px 图标 + 标题 + 说明 + 动作，居中，上下 64px |
| `compact` | 卡片、表格、抽屉里 | 同上，图标 28px，上下 32px |
| `inline` | 设置卡片里、列表下面、筛选后的一句话 | 一行 13px `--muted` 灰字，无图标，默认靠左 |

- 属性：`title`、`desc`、`icon`（给空字符串不画图标）、`action`（一颗 `secondary` 小按钮，点了发 `@action`）、`tone`（`error` 只换图标色）、`align`（`center` / `start`）。动作要别的角色或带图标，放默认插槽。
- `inline` 不带外边距，由所在那块决定：设置卡片里加 `class="settings-empty"`（只管 16px 24px 内距）。
- 读失败不是空状态，用 §3.10 的 `BaseLoadError`。
- `AdminEmptyState` 是它的别名（`compact` 布尔值映射成 `size="compact"`），新代码直接用 `BaseEmptyState`。

### 3.13 数据表格：BaseTable

一张有表头、多列的数据表只用 `BaseTable`（`src/components/base/BaseTable.vue`，原来叫 `AdminGrid`，旧名字仍是它的别名），不再用 `v-data-table`，也不再手写 `<table>`。

- 列宽写在 `cols` 上（每列一个宽度，只给吃剩下宽度的那一列传 `null`）；`minWidth` 是窄屏横滚的下限，默认 1080px，列少的表传小一点。
- 表头写进 `#head` 槽，格子用 `BaseTableTh`。给了 `sortKey` 就是可排序的一列：表发 `@sort(key, dir)`，页面自己排；当前列带箭头和 `aria-sort`。
- 整张表都在手上时用 `useClientTable`（`src/components/base/tableSort.ts`）做排序和分页：每页 10 条，换排序回第一页，空值永远排在最后。
- 分页条 `TablePager` 放进 `#foot` 槽，只有一页时不画。
- 加载、空、读失败三态由表壳保证互斥：`loading`（只在一条都没有时）、`busy`（有旧内容时重取）、`empty` / `#empty`、`state="error"` / `#error`。

## 4. 深色模式

原则 7。只要遵守 §1（永远写变量名），深色模式自动就对；需要专门为深色写代码的情况极少。真的需要时写 `:root[data-theme='dark'] .my-thing { … }`，但先想想是不是选错了变量——十次里有九次是。

三层由 [`frontend/src/theme.ts`](../frontend/src/theme.ts) 统一驱动，必须同时切换：`<html data-theme>`（CSS 变量）、Vuetify 主题（组件）、`<meta name="theme-color">`（手机浏览器地址栏）。

- **存偏好，不存结果**：用户的选择是 `system` / `light` / `dark`，存进 `localStorage` 的 `cheesex.theme`。存成解析后的 `dark`，会把从没碰过设置的用户永远钉在第一次访问时的系统主题上。
- **首屏不闪**：[`frontend/index.html`](../frontend/index.html) 的 `<head>` 里有一段内联同步脚本，在第一帧之前打上 `data-theme`。它故意重复了 `theme.ts` 的几行逻辑（改成 import 就是一个阻塞渲染的请求）；改存储键或颜色常量时两边一起改。
- **切换入口**在用户菜单里（[`ThemeToggle.vue`](../frontend/src/components/common/ThemeToggle.vue)），`跟随系统` 必须始终可以重新选中。

## 5. 两套 token 的关系

| 场景 | 用哪个 | 写法 |
|---|---|---|
| 手写 CSS | 自研 token | `color: var(--text)` |
| Vuetify 组件属性 | Vuetify 主题色名 | `<v-btn color="primary">` |
| 给 Vuetify 颜色加透明度 | Vuetify 变量 | `rgba(var(--v-theme-primary), 0.12)` |

两套的值是镜像关系（`primary` 就是 `--accent`，`surface` 就是 `--surface`），混用不会视觉打架。**唯一的硬规矩：改一个颜色必须两边都改。**只改一边，症状是「有些地方变了有些没变」，很难查。

## 6. 常见错误

| 错误 | 为什么错 | 改成 |
|---|---|---|
| `color: #757575` | 深色下不变 | `var(--muted)` |
| `color: var(--danger)` 写正文 | 记号色对比度不够 | `var(--danger-ink)` |
| `background: #fff` | 深色下是一块白 | `var(--surface)` |
| `color="grey-lighten-5"` / `bg-white` / `text-grey` | 固定调色板名，等于写死 | 见 §1.2 |
| prop 默认值 `color: 'grey-lighten-5'` | 一处写死，所有用它的页面一起坏 | 默认值也用语义色名 |
| 卡片加 `box-shadow` | 违反 §3.4 | `border: 1px solid var(--line)` |
| `border-radius: 10px` | 不在档位里 | `var(--radius-*)`，见 §3.1 |
| `font-size: 10px` | 低于可读下限 | 至少 13px |
| `line-height: 1.6` | 不在档位里 | 配对的 `--lh-*` |
| 用琥珀做普通图标、头像 | 稀释了主操作 | `--muted` 或 `--faint` |
| 引用一个没定义的变量 | 静默失效；在 `background` 这类简写里会让整条声明作废 | 先确认变量在 `style.css` 里存在 |

## 7. 规范怎么被强制执行

能交给机器的交给机器：

| 闸门 | 拦什么 | 在哪 |
|---|---|---|
| stylelint 颜色规则 | 新增的写死颜色（hex / rgb / hsl / 颜色名） | `frontend/stylelint.config.cjs` |
| stylelint 圆角规则 | 不在档位里的 `border-radius` | 同上 |
| 固定调色板闸门 | 模板和 script 里的 `color="grey-*"` / `bg-white` / `text-grey-*` | `.claude/scripts/check-repo-rules.sh` |
| 存量棘轮 | 以上只拦**新增**；存量冻结在基线里，只能减少 | `frontend/stylelint-baseline.json`、`frontend/palette-baseline.json` |

```bash
cd frontend
pnpm run lint:style          # 检查（CI 跑的就是它，只读）
pnpm run lint:style:fix      # 自动修可修的部分
pnpm run lint:style:update   # 修好一批后把基线降下来并提交

cd ..
bash .claude/scripts/check-repo-rules.sh                            # 检查固定调色板
bash .claude/scripts/check-repo-rules.sh --update-palette-baseline  # 修好一批后降基线
bash .claude/scripts/check-repo-rules.sh --self-test                # 证明闸门本身没坏
```

基线只能降不能升。`--self-test` 不是摆设：一个悄悄失效的闸门和一棵干净的树，输出一模一样。

排版（§3.2）、文案（§8）、动效（§9）没有闸门，靠 review。[`frontend-design`](../.claude/skills/frontend-design/SKILL.md) skill 把能人工逐条过的部分做成了一次体检。

## 8. 文案

界面上的字也是设计的一部分。本节管**所有会被用户看见的中文**：按钮、标签、空状态、提示、占位符、`title` / `label` / `placeholder` 属性、前端拼出来的错误文案。代码注释不算。

字符串存在哪、叫什么键、缺英文怎么办，归 [`i18n.md`](i18n.md)，那份有机器闸门；本节只管中文怎么写，没有闸门。

### 8.0 语言风格

原则 3。

> **在表意清楚、读得顺、意思不变的前提下，越短越好。正式、中性、平实；不写废话，不口语，不用黑话。**

- 每个字都要有用。不影响意思的主语和「你」「它」省掉。
- 先说结果或现状，再说用户接下来能做什么。不解释程序内部为什么这样（「磁盘上的版本」「按编辑器的理解重写」）。
- 短不是删信息。用户需要的原因、下一步、打的字还在不在，一样都不能省：「发送失败」不如「留言未发送，稍后重试」。

两个方向都要防：

| ❌ 太口语 | ❌ 文绉绉 / 公文腔 | ✅ 正式、自然、简明 |
|---|---|---|
| 平台检查没跑成 | 平台检查未能顺利完成执行 | 平台检查未能执行 |
| 还没有连接的设备。 | 您当前暂未连接任何设备，敬请添加 | 暂无已连接的设备 |
| 空空如也... | 此处内容为空 | 暂无内容 |
| 知道了（按钮） | 本人已知悉 | 确定 |
| 给这台算力节点起个名字 | 请您于下方输入设备之名称 | 设备名称 |
| 干活（跑沙箱）用哪台机器 | 用于承载任务执行之机器 | 运行任务的机器 |
| 把你自己的 GitHub 账号和这个平台身份关联起来 | 敬请将您的 GitHub 账号与本平台身份进行关联 | 关联 GitHub 账号 |

**人称用「你」，不用「您」。**「您」正是文绉绉的那一边。**也不用「请」**：状态直接说状态（「待你审阅」，不是「请你审阅」），报错直接说怎么办（「稍后重试」）。

### 8.1 空状态

一律写成 **「暂无 X」**，不带句末标点：`暂无请求`、`暂无已连接的设备`、`暂无关联仓库`、`暂无待处理的事`。

到此为止。不再接一句告诉人怎么让这里出现东西：那是在说明产品怎么运转，见 §8.7。

### 8.2 不用黑话

用户看到的字里不能有只有开发者才懂的自造词。判据：**一个第一次用这个产品的人，看到这个词能不能懂？**

| 黑话 | 换成 |
|---|---|
| 跑沙箱 / 干活 / 派活 | 运行任务 |
| system prompt / 注入 / Persona 正文 | 角色设定 |
| 知是基座 | 按它实际是什么写（如「默认镜像」） |
| 小队 | 团队 |
| 题目板 / 题目版 | 空间 |
| 算力节点 / 连接器 / 客户机 | 设备 |
| 根文档 / 根话题 | 按上下文写成「文档」，或不提这个概念 |
| 门禁 / 盒子 | 检查环境 / 工作电脑 |
| 铸造（token） | 签发 |
| CheeseX / cheesex（对用户自称时） | 知是 |
| 新一轮 / 本轮 / 这一轮（指 agent 的一次运行） | 按上下文写，如「继续运行」「这次运行」 |
| 活 / 这条活 | 任务 |
| 子 Agent / 子代理 / Claude Code（指做任务的那个 AI） | 分身 |
| 验收卡 / 任务卡 / 递卡 / 旧卡 | 界面上不说「卡」：按它是什么写（任务、审阅），见 §8.11 |
| handle | 用户名 |
| 磁盘上的版本 | 已保存的版本 |

这张表不是穷举，发现新的就往里加。`agent`、`token` 这类行业通用词不算黑话，但要看读者：给学生看的表单里换成中文说法。产品自己的名词（话题、验收卡、现场、章程、周报集）不是黑话，它们处处出现、含义一致，是可学习的词汇。

### 8.3 括号里不解释产品内部机制

`理由（会留在卡上）` → `理由`；`描述（一句话，显示在下拉里）` → `描述`。

括号只装**一个短限定词**：`名称（英文）`、`退回说明（可选）`。装的是一个句子，就删掉。

### 8.4 操作提示不常驻界面

`拖动调整宽度（双击复位）`、`Enter 发送，Shift+Enter 换行` 这类，移进 `title` / tooltip，或者删掉。占位符也算常驻：输入框空着的时候它一直在那。

例外是命令面板（⌘K）的底栏。面板本来就靠键盘用，按键就是它的操作方式，底栏写的是选中这一条时回车、Tab、Ctrl+回车各做什么；Tab 看不见，不写出来没人会发现。只在桌面显示，手机上没有这一栏。别处的提示不能拿它当先例。

### 8.5 一个控件只说一次

标题和帮助文本说同一件事的，删掉一个。**旁边有按钮时，文字说「现在是什么状态」，不重复按钮要做什么**：按钮是「连接 GitHub 账号」，旁边那句就写 `暂无关联账号`。

### 8.6 短句不加句号

标签、按钮、空状态、单句提示不加句末句号。两句以上的说明正常断句。

也不用破折号和感叹号。省略号只用在正在进行的状态上（`加载中…`、`保存中…`）。

### 8.7 只说明产品自己怎么工作的元素，删掉

判据：这个元素是在说明产品自己怎么工作，而不是在帮用户完成事情——就删。例如 `敬请期待 / 按需开通`、`（默认不 @）`。

**删元素比改文字风险高。**拿不准（它可能是个可点的入口，或者是页面上唯一在说明状态的东西）就保留并提出来问。反例：`敬请期待 / 按需开通` 是废话，但它所在的位置是「这个资源不可用」的唯一信号，正确做法是换成 `暂未开通`，不是删空。

### 8.8 文案开头不放 emoji 当轻重标记

判据：这个 emoji 在说的事，界面上有没有别的东西已经在说？有就删。轻重应该住在结构化字段里（如 `meta.severity`），由前端按字段画点和底色；再在句首放 `⚠️` / `❌`，是同一件事说两遍，屏幕阅读器还会逐字念出来。

例外：符号本身就是内容（表情回应、用户自己打的字）；或者那个表面根本没有轻重字段——那时先给它加字段，再删符号，不要反过来。

### 8.9 状态、报错和按钮

- **状态用「待」**：`待审阅`、`待你审阅`、`待 alice 审阅`、`待回答`。它只说下一步卡在谁那里，不预设结果。「待采纳」就预设了结果。
- **报错只有两种说法**：做了没成，写「X 失败」（`保存失败`）；做不到，写「无法 X」（`无法读取这个文件`）。需要原因时用冒号接在后面，需要用户动手时再加一句，比如「稍后重试」。
- **按钮用动词，说清点了会发生什么**：`设为只读`，不是 `只读`。确认框的按钮复述那个动作（`移出`、`删除`），不用 `确定`。

### 8.10 一个概念全产品只用一个词

同一件事换一个词，读的人会以为是两件事。下面这些已经定了，别处出现同义说法按这张表改：

| 概念 | 用这个词 | 不用 |
|---|---|---|
| 房间里拆出来、交给分身去做的一件事 | 任务 | 活、支线、线程 |
| 做任务的那个 AI | 分身 | 子 Agent、队友、线程 |
| 房间里的 AI 队友 | 项目里给它起的名字（默认「芝士」） | 在代码里写死「芝士」 |
| 芝士把做好的东西交给人看 | 提交审阅 | 递卡、提交验收 |
| 等人看、等人决定 | 待审阅 / 待你审阅 / 待 alice 审阅 | 待验收、待采纳、请你审阅 |
| 看过之后收下 / 打回 | 采纳 / 退回 | 通过、驳回、验收通过 |
| 项目要求几个人同意时，每个人的那一票 | 批准 | 同意、核准 |
| 换一个人来看 | 改由 X 审阅 | 改派验收人 |
| 芝士提问等人回答 | 待回答 / 等你回答 | 待确认、等你决定 |
| AI 队友干活的那台机器 | 工作电脑；选项写「云端 · 规格」或设备名，自有设备后面跟「能访问整台机器」 | 算力、运行资源、运行环境、工作机器、算力池、资源池、云算力、Cloud、Hosted Machine、自托管设备 |
| 项目的初始化脚本、启动脚本和环境变量 | 脚本与环境变量（统称时写运行环境） | 用「运行环境」指机器 |

### 8.11 审阅流程怎么说

这件事对应代码托管平台上的 pull request 评审，但交上来的不一定是代码，也可能是一份文件或一个网站，所以不用「合并请求」「评审」这类程序员的词。

- 状态：`《原型》第 3 版 · 待你审阅`、`待 alice 审阅`；徽章和看板用短的 `待审阅`。
- 动作：`采纳`、`退回` 并排放，由人选；结果写 `alice 已采纳`、`alice 已退回`。
- 被审阅的东西按它实际是什么说：代码写这次改动自己的标题（合并后的提交标题；没有标题时写「改动」），文件写文件名和版本（`《原型》第 3 版`）。代码仓库每次合并都是同一项产物的新一版，「《仓库名》第 N 版」一行里说不出这次改了什么。不另造一个统称，「成果」「交付物」口气都太大。
- 不出现角色名词「审阅人」：句子里说「待 alice 审阅」「改由 bob 审阅」，设置里写「默认审阅」再选人。

### 8.12 这一节没有闸门

写新页面时，把 §8.0 那张表当检查清单过一遍。字符串的**结构**（两边键对齐、占位符一致、英文里混进中文）有闸门，见 [`i18n.md` §5](i18n.md#5-机器闸门)；「英文读起来像机器翻的」仍然只能靠人看。

## 9. 动效

### 9.0 动效做什么

原则 5。动效只做两件事：

- **解释变化**：东西从哪来、到哪去、变成了什么。展开的面板从按钮下长出来，删掉的一条先淡出再让位，切换标签时指示条滑过去。
- **回应操作**：按下的一瞬间就有回应，不等松手，也不等服务器。

在工作区里，**会动的只有两种东西：人刚做了一件事，或者机器正在做一件事。**一屏里动的东西越少，那个动着的东西就越说得出话。门口页面的品牌画面是例外（§9.9）。

动效的性格是**自然、连贯、利落**：像有重量的东西，进来时减速停稳，离开时加速走开；不回弹、不晃动（直接拖拽除外）。

### 9.1 hover 只改颜色，不改位置

指针扫过一个东西，它可以变底色、边框色、文字色，**不可以移动**。高密度列表里每一行都抬 2px，人看到的是整列在跳，而不是「我指到了哪一行」。

```css
.card:hover { background: var(--fill); border-color: var(--line-2); }          /* 对 */
.card:hover { transform: translateY(-2px); box-shadow: var(--shadow-1); }      /* 错 */
```

同一个产品的两半用两套动作语言，人感觉得到，所以一屏只有几个大卡片的页面也不例外。

### 9.2 位置的变化，留给真的变了的时刻，并且保持连续

| 可以动位置 | 因为 |
|---|---|
| 开关的拨柄滑到另一头 | 状态真的翻了 |
| 抽屉、弹层进出 | 一个东西真的出现或消失了 |
| 列表插入、删除、重排 | 列表真的变了 |
| 展开、收起 | 高度真的变了 |

动的时候保持空间上的连续：

- **从哪来，回哪去。**从一张卡片打开的详情，从这张卡片的位置展开，关闭时收回原处；不要凭空出现、凭空消失。
- **高度和位置平滑过渡，不跳。**展开收起过渡高度（`grid-template-rows: 0fr → 1fr`），插入删除先让出或收拢位置，重排时每一项滑到新位置（FLIP）。
- **加载不跳。**骨架屏、占位与真实内容同一尺寸；图片和异步内容提前占好位置。

### 9.3 时长与曲线

四个时长、三条曲线，定义在 `style.css` 的 `:root`，全站共用：

| token | 值 | 用在哪 |
|---|---|---|
| `--dur-press` | 100ms | 按下的回应 |
| `--dur-quick` | 150ms | hover 的颜色变化；离场、收起 |
| `--dur-base` | 220ms | 进场、展开；指示条与重排的移动 |
| `--dur-slow` | 320ms | 抽屉、侧栏、整块面板；从卡片展开成详情 |

| token | 曲线 | 用在哪 |
|---|---|---|
| `--ease-out` | 减速 `cubic-bezier(0.2, 0.8, 0.2, 1)` | 进场、展开：快速出现、缓缓停稳 |
| `--ease-in` | 加速 `cubic-bezier(0.4, 0, 1, 1)` | 离场、收起：慢慢起步、快速离开 |
| `--ease-standard` | 标准 `cubic-bezier(0.4, 0, 0.2, 1)` | 原地的变化：颜色、尺寸、指示条移动 |

- **进场与离场不对称**：离场比进场快一档。人已经决定关掉它了，不该让他等。
- 移动距离越长可以越慢，但不超过 `--dur-slow`。
- 匀速（`linear`）只给真的匀速的东西：旋转、进度条、扫光。
- 新写的动效用 token；老代码里的 `ease` 与字面量时长，改到哪折到哪。

### 9.4 不写 `transition: all`

写具体属性：`transition: background-color var(--dur-quick) var(--ease-standard);`。`all` 会把宽高、内边距这些布局属性一起带上，列表里每帧重排；读代码的人也看不出这行想让什么动，没人敢删。

### 9.5 一直在动的东西，必须自己关掉

`style.css` 底部有一条全局兜底，系统开了「减弱动效」时把所有时长压到接近 0。这对无限循环不够用：一个呼吸动画被压成 0.001ms 的无限循环，会变成高频闪烁。所以凡是写了 `infinite` 的地方，自己再写一条：

```css
@media (prefers-reduced-motion: reduce) {
  .running-dot { animation: none; }
}
```

**关掉动画之后，它表达的信息必须还在。**「正在运行」的点关掉动画后仍是一颗实心点，旁边的是空心圈——区别不靠动。

### 9.6 没人碰也在动的东西，删掉

判据：这个动画在说什么？说得出正在发生的事的留下（加载骨架的扫光、运行中的呼吸点、进度条）；说不出的删掉（上下浮动的图形、永远流动的渐变、纯装饰的入场淡入）。装饰性动画把「有东西在动」这个信号用掉了。

门口页面的品牌画面不适用这一条，见 §9.9。

### 9.7 编排与可打断

- **一次只有一个焦点在动。**同时进场的一组元素依次出现，间隔 20–40ms，整组不超过 300ms；先动容器，再动内容。
- **可打断。**状态之间的切换用 `transition`，不用一次性的 `@keyframes`：中途改主意时，从当前位置反向走回去，而不是跳回起点再播一遍。快速连点不排队。
- **不挡路。**动效进行中，界面照样能点、能输入；不要为了等动画播完而禁用操作。

### 9.8 这一节没有闸门

写页面时过一遍 §9.1、§9.3、§9.4、§9.5。老社区那一侧（`views/spaces`、`views/tasks`、`views/projects`）大量使用 hover 抬升与 `transition: all`，方向是往这一节收，而不是让工作台去学它。

### 9.9 门口页面的品牌画面

原则 8。官网与登录页可以有一块品牌画面：持续、缓慢地动，并回应鼠标。它必须：

- 在「减弱动效」下停在静止的一帧；
- 移出视野或切到后台标签页时暂停；
- 只在门口页面出现，不进工作区；
- 与表单的底色是同一套颜色里相邻的两档，不做黑白对撞；
- 表单一侧的琥珀只有主按钮。
- 已登录的人被打断时（操作前的身份验证）不放画面：那一页是要做完就走的。

登录页的画面每次打开页面从一组里随机取一张，不与这台浏览器上一次看到的相同；在几个账号页之间切换时不换（`components/account/brandScene/`）。账号页的标题在每一页都落在同一高度，页面长短只改变标题下面的内容。往这一组里加画面时，让它和现有的几张一样「重」：有居中主体的，以 logo 画面的大小为准；实心的、自带光晕的要比 logo 小一些，看上去才一样大。

## 10. 手机

宽度小于 960px 时是手机外壳：顶上一条顶栏，从不卸载，页面往里填内容；一级目的地底下有底栏，页面栈里的那几层没有。下面几条从原则 1、3、4、5 推出来，写的是手机上和桌面不同的地方。

### 10.1 手指点得中

触屏上每个控件能点的范围至少 **44×44**。画出来的样子不必变大：小图标、小药丸按钮用 `.tap-target`（`style.css`）把能点的那块往四周撑开，控件自己要有定位。两个控件挨得太近、撑开的范围互相盖住，就是间距不够，拉开间距，不要只撑其中一个。`e2e/tests/layout-invariants.spec.ts` 在 390px 宽下量顶栏和底栏上的每一颗。

### 10.2 标题只写一次，写在顶栏

一页的名字写在顶栏里（路由的标题，或者这一页填进顶栏的内容），页面里不再画同一个名字的大标题和眉题。标题是动态的（一项产物、一个任务的名字），就让它进顶栏，而不是在页面里再写一遍。

### 10.3 一页的操作在顶栏右边

一页的主操作是顶栏右边一颗图标按钮，其余操作收进它旁边的 ⋯。页面不为几颗按钮单占一行。写法是在页面里用 `useCommands` 登记标了 `header` 的命令：桌面上 `AppPage` 把它们画在页头里，手机上顶栏画同一批；一页只标一个 `primary`（顶栏上那一颗），`accent` 是桌面上的琥珀色主按钮。页头这一行在手机上只剩状态（「已保存」这类）；没有状态就不画。

一级目的地的顶栏右边是帮助与反馈和头像；页面栈里的那几层右边只放这一页自己的操作。

### 10.4 操作菜单从底部升起

一组操作在手机上是底部动作面板（`MobileActionSheet`），不是贴着按钮弹出的小菜单：手指够得着，字也放得下。页面里写 `AdaptiveMenu`，同一份操作清单桌面上是下拉菜单、手机上是面板。面板点遮罩、按 Esc、往下拖都能关上。删除这类不可撤销的操作用 `--danger-ink`。

### 10.5 长表单是一整页

要填好几项的表单在手机上是一整页（`AdaptiveDialog`）：左边 ✕，中间标题，右边主操作。页头钉住、正文自己滚，键盘弹起来时主操作不会被压到键盘底下。一两句话的确认框不在此列，仍是居中的对话框。

### 10.6 长按打开一项的操作

列表里的一行、对话里的一条消息，长按（约 500ms）打开它的操作面板，相当于桌面上的右键或悬停出来的按钮。轻点仍是打开它，手指一动就是滚动，都不算长按；长按之后松手的那一下不再触发点开。写法是 `useLongPress`。长按只是快捷方式：同样的操作在页面上要另有入口。

### 10.7 换页的动效

- 往里走一层（话题列表进话题、项目页进它的子页），新页从右边挪进来 24px 并淡入；退回一层，新页从左边进来。平级切换（底栏换一格、同一层换一页）只淡入。
- 「一层」按路由声明的上一层（`meta.backTo`，顶栏的 ← 读的也是它）算，不按浏览器历史：点 ← 回去在历史里是一次前进，人看到的是退回。
- 只有进来的那一页动，旧页随渲染直接换掉：两页同时在场，传进顶栏的内容会叠成两份。动的是装页面的那一层，顶栏和底栏是框，不动；底栏出现、消失和内容区的让位都在换页的同一帧完成，不单独滑。
- 用 `--dur-base` 与 `--ease-standard`，不回弹。减弱动效时直接换页。桌面上换页没有动效。
- 只改 query 或 hash（页内切页签）不算换页。

### 10.8 平板上栏宽有上限

手机外壳一直用到 959px，平板竖屏和横过来的大手机也在里面。宽度一大，单栏铺满整屏就是一行六十多个字，底栏三格之间隔着半个屏幕。所以：

- 页面的那一栏最宽 720px，居中。写法不变，照旧用 `--page-w` / `--page-w-wide`（`AppPage` 的 `read` / `wide` 分别读这两个），这两个 token 在手机外壳里取 720。
- 房间的时间线、输入框和贴在输入框上的那一条收成同一栏，也是 720 居中；滚动的仍是整块。
- 底栏的底色铺满，那几格收在 480px 以内居中。
- 390 宽的手机上这几条都不起作用。

### 10.9 平板上列表和房间并排

768–959px 之间，项目里的话题列表和房间并排成两栏（`useWorkspaceLayout` 返回 `split`）。仍是手机外壳：底栏、房间的页签、从底部升起的面板都不变，变的只有这一处。

- 左栏是手机上整页的那份话题列表，320px，从顶到底一整条，自己滚；项目名那一行留在它顶上。顶栏只盖右边：话题头、←、房间的操作说的都是房间。
- 在列表里点一个话题，只换右边的房间；地址照样变成这个话题的地址，Back 和链接都照旧。列表不重新挂载，滚动位置和展开的分组都还在。
- 换房间只淡入右边那一栏（§10.7 的「往里走」在这里不成立：人还站在同一屏上）。
- 没打开房间时右边只写一行「选择一个话题」。
- 房间顶栏的 ← 仍回到列表那一层：列表不动，右边回到没打开房间的样子，底栏回来。话题页没有底栏，这颗 ← 是离开房间回到一级导航的唯一入口，所以留着。
- 看板、项目文档、设置、成员这些仍是一整页，没有左栏。


### 10.10 平板横放：侧栏可收、房间里只画对话

960–1180px 之间（960 是 Vuetify 的 `mdAndUp`，1180 是 `useWorkspaceLayout` 的 `COMPACT_DESKTOP_MAX_WIDTH`）仍是桌面外壳：常驻的 rail、页头那条线都不变。但再加一条常驻的二级侧栏（280px）之后，正文只剩很窄一条，所以两件事变了：

- **二级侧栏默认收起**，是一只从左边临时拉出的浮层（`SecondaryNavigation`）。开关是 rail 顶上那一颗（`[data-sidebar-toggle]`，`aria-expanded` 说状态、`aria-controls="secondary-sidebar"`）；点遮罩或按 Esc 收起，焦点回到这颗开关。人的选择记在 `localStorage`（只有这颗开关按下的那一下才记——点遮罩、换路由收起的不算）。
- **房间里只画对话**，占满整宽（`TopicView`）。工作面板从右边按需拉出，是一只浮层（`.panel-host--sheet`，`id="topic-panel"`，收起时 `visibility: hidden`，不进 tab 序也不进读屏的树）。默认收着——地址里有 `?tab=` 或 `?card=` 就是「这一格开着」，所以对话里点「查看改动」、点开一张卡、别人发来的链接走的都是同一条路。页头那一颗开关（`[data-panel-toggle]`）开合它，Esc 或点遮罩收起，焦点回到开关。专注模式在这一档里不成立（对话本来就是整宽），入口不出现。

这条线是**视口**断点，`@media` 里用不了 CSS 变量，所以它只以常量存在，由 `useCompactDesktop()` 读出来——不要在样式里另写一个 1180。

比 1180 宽就是今天的样子：侧栏常驻、对话和工作面板可拖 25–80% 分栏（§9）。窄于 960 是手机外壳（§10.9），两栏只在列表和房间之间。
