# Cheese 2.0 · 场景与验收清单（Eval 集）

> v0.1 — 2026-06-13。配套《Cheese 2.0 产品与实现 Spec》。
> **用途**：这是 Fable 开发的靶子 + 验证集。每条场景 = 一句"用户做什么" + "对长什么样"（验收标准）。
> **怎么用**：开发时朝这些场景建；验证时让 agent 拿着场景去操作真实系统（Playwright 当手眼），对照"对长什么样"判断对没对——不写死断言，判断的是"系统行为对不对、符不符合产品语义"。
> **会长大**：今天的能力测试（capability），明天沉淀成回归测试（regression）——验证过的不许退化。
> **分级**：🟢 核心链路（必过，否则产品不成立）/ 🟡 重要 / ⚪ 边角。

---

## 实现方式 × 验证方式（一一对应）

> 每条场景标了**怎么造**：🔧 平台代码 / 🤖 Agent 能力 / 🔧🤖 两者咬合。**实现方式决定验证方式**——这正好解决"怎么 verify"的难题。

| 标注 | 怎么造 | 怎么验 |
|---|---|---|
| 🔧 **平台代码** | Fable 写常规确定性代码（block 表/渲染/状态机/聚合/websocket/PVE 起停），走标准 PR。 | **传统测试**：pytest 单测/集成/契约 + Playwright 断言。确定、快、进 CI 回归。 |
| 🤖 **Agent 能力** | 不写死逻辑，而是编排 Claude Code session + 工具 + prompt/skill（@芝士答、派活、摘要、心跳判断、消化 event）。 | **场景 eval**：真芝士端到端跑，judge agent 读"现场"transcript 对照"对长什么样"判断，不 assert 文本。 |
| 🔧🤖 **咬合** | agent 干活 + 平台壳承接（芝士沙箱跑代码=🤖，采纳卡/diff/PR 集成=🔧）。 | 两套都要：壳走传统测试，agent 行为走场景 eval。 |

**一句话判断**：**界面层（D 全部）几乎纯 🔧 ——确定性、传统测试管够；AI 能力（C 全部）几乎纯 🤖 ——靠 agent eval；其余是咬合。** 这跟模型本身同构：平台是确定的壳，芝士是不确定的灵魂，壳和灵魂用不同方式 verify。

## A. 话题生命周期（核心）

### A1 🟢 🔧🤖 开话题（线上升格）
- **做什么**：在讨论里聊一个点，越聊越大，点"升格"。
- **对长什么样**：左栏出现新话题（带状态徽章）；新话题第一条是芝士的开场白（复述任务+下一步）；原讨论块在父级变成可点的活引用；新话题自带文档（简报）、对话、（按需）沙箱。

### A2 🟢 🔧🤖 自上而下拆解
- **做什么**：大话题简报「拆解」节里有 todo 块，点"单独实现"。
- **对长什么样**：房间时间线上多一条「已派出」标记，点开就是那条支线；房间文档里该块原位变活引用、实时显示这件活的状态；房间「进展」自动聚合。

### A3 🟢 🔧 采纳即交付完成（不归档）
- **做什么**：话题主产物（代码 PR / 报告 / 周报）被指定的人点"采纳"。
- **对长什么样**：产物合入/发布；话题**保持活跃**、打上交付标记（合并只说明这一次交付完成，#442 decision 1）；沙箱不回收；**不能再递第二张验收卡**（分支已在 main 上，再开 PR 是空的）；归档是人另点一次的动作，**归档后对话仍可追评**（再发消息不报错）。

### A4 🟢 🔧🤖 归档后续作
- **做什么**：归档话题的结论块下，冒出后续需求，点升格。
- **对长什么样**：开出新话题；新话题 branch 从当前 main 切（不是复活旧 branch）；前作↔续作双向可跳；前作的结论/记忆在新话题里可被芝士引用。

### A5 🟡 🔧🤖 微话题（顺手小活）
- **做什么**：在 #总览 说"把 README 价格改一下"。
- **对长什么样**：芝士判断这是一句话的活，不开左栏频道；就地一张任务卡（执行→PR→采纳）；完事即归档，不留频道。

## B. 对话 ↔ 文档（一池块两棵树，核心）

### B1 🟢 🔧🤖 双视图同源（对话=历史，文档=状态，不对称）
- **做什么**：对话里芝士回了一段有价值的话。
- **对长什么样**：这段在对话流（时间序，**append-only 历史，不可回改**）出现；芝士把其中结论整理进文档（结构序，如「约束」节，**当前状态，可改**）；点对话里这个块 → 文档高亮同一处（只读跳转）。
- **关键**：对话→文档是"整理"，文档→对话**不是反向同步**（违反物理规则 H1）——改文档不回改对话历史，而是产生一条新对话事件 + 注入 session（见 B2）。B1/B2 是同一机制的两面。

### B2 🟢 🔧🤖 改文档即指令
- **做什么**：直接编辑文档「约束」一节的文字。
- **对长什么样**：文档版本+1；对话流出现"你改了文档"事件；芝士按新文档继续干（后续行为反映改动）。

### B3 🟢 🔧 收拢/展平
- **做什么**：一个块下有多条回复，点"💬 回复 N"。
- **对长什么样**：收拢态 = 主流只见根块 + 回流结论 + 前几条 + "⋯还有 N 条"；展平态 = 回复回到主流带引用条；计数沿 reply_to 链锚定到根块，不管展平收拢都一致。

### B4 🟡 🔧 段落评论
- **做什么**：在文档里划选一段文字，发评论。
- **对长什么样**：命令栏自动挂"段落评论"芯片；评论锚定在那段下方；通知该块作者+维护者；评论本身是块（可回复、可升格）。

## C. AI 队友干活（核心）

### C1 🟢 🤖 @芝士带记忆回答
- **做什么**：新成员进一个进行中的项目，问"现在什么状态、我能干什么"。
- **对长什么样**：芝士的回答准确反映项目当前状态（引用真实的话题/进展/决策），且标注依据来源；答得比翻聊天记录快。

### C2 🟢 🔧🤖 派活→沙箱→PR
- **做什么**：在代码话题里 @芝士"把时间线深翻页退化修了"。
- **对长什么样**：芝士复述确认→在沙箱真的改代码、跑测试→**机器闸门绿（测试/lint 过）才发采纳卡**；采纳卡含变更卡（一句话总结+diffstat+值得看的点）；点"看 diff"能看完整改动。

### C3 🟢 🤖 默认不接话（注意力分离）
- **做什么**：群里两人闲聊，不 @ 芝士。
- **对长什么样**：芝士不插话（只记忆）；只有被 @ 或"回答了它的开放问题"时才发言。

### C4 🟡 🔧🤖 一件活=subagent，可下钻
- **做什么**：芝士干重活时派了并行子任务。
- **对长什么样**：用户始终看到"一个芝士"在汇报；现场里能展开子 agent，各有独立 transcript 和一句话摘要；摘要回流父话题文档。

### C5 🟡 🔧🤖 谁来采纳=点名路由
- **做什么**：话题完事，芝士发采纳卡。
- **对长什么样**：卡递给一个具体的人（"等 XX 采纳"），不是广播；芝士不采纳自己派的活；采纳记名、可撤回。

## D. 界面（核心：对话+文档常驻，工具召唤）

### D1 🟢 🔧 两面常驻
- **做什么**：打开任意话题。
- **对长什么样**：对话 + 文档两列常驻并排；没有一排平级 tab；文科生视角就是"聊天+一页文档"。

### D2 🟢 🔧 工具召唤抽屉
- **做什么**：点文档右上角的工具图标（现场/预览/Git…）。
- **对长什么样**：工具从右侧滑出抽屉，盖住文档右半（文档左半仍在）；✕/Esc 关闭，文档恢复原宽；可"钉住"变常驻列。

### D3 🟢 🔧 全局命令栏唯一入口
- **做什么**：在任何视图（文档/现场/预览）发消息。
- **对长什么样**：只有一个发送栏（横跨全宽）；锚点芯片决定路由（支线/现场/对文档/段落评论）；默认不带 @，@芝士 是召唤按钮。

### D4 🟡 🔧 实时推送
- **做什么**：芝士在干活，另一个成员的屏幕。
- **对长什么样**：消息、文档版本、任务状态实时出现，无需刷新；自己发言滚动到底，翻历史时切话题回来位置记住。

### D5 ⚪ 🔧 专注模式
- **做什么**：点文档的 ⤢。
- **对长什么样**：对话退场，文档变全幅居中页；再点恢复。

## E. 线下接入（event 入口，核心差异化）

### E1 🟢 🔧🤖 建 event
- **做什么**：点"记一笔"，说"今天做了用户访谈，15 人，发现 XX"。
- **对长什么样**：生成一个活动话题；芝士打上时间、类型（访谈）、钉成里程碑、排进日历；可继续在里面聊、可升格。

### E2 🟢 🔧🤖 自建会议记录（Notion 形态，不接外部）
- **做什么**：点"开始记录会议"，录一段，结束。
- **对长什么样**：浏览器录音→自建 ASR 转写→芝士出摘要+待办；落成活动话题；transcript 存档可下钻；待办派给人；**全程不调用飞书/腾讯任何 API**。

### E3 🟡 🔧🤖 导聊天记录
- **做什么**：粘贴一段微信群讨论。
- **对长什么样**：芝士消化成活动话题，抽出做了什么/定了什么/谁负责/下一步。

## F. 机构观测（书院场景，核心商业）

### F1 🟢 🔧🤖 随手记里程碑→自动冒泡
- **做什么**：团队在话题里说"今天立项评审过了"。
- **对长什么样**：芝士钉成里程碑、排日历、冒泡到 Space Dashboard；老师侧无需学生填表就看见进度。

### F2 🟢 🤖 一页纸总结
- **做什么**：老师点开一个团队。
- **对长什么样**：30 秒读懂这个团队在干嘛、到哪了；内容是芝士持续维护的当下真相（不是死快照）；团队自己看和老师看是同一页。

### F3 🟢 🔧 Space Dashboard（老师跨团队）
- **做什么**：书院管理员打开 Dashboard。
- **对长什么样**：所有入驻团队一张表（状态/进度/活跃度/里程碑临近）；一眼看出谁活跃、谁 stale、谁快结项、该催谁；数据是各项目纵览的自动聚合。

## G. 主动性与纵览（核心）

### G1 🟢 🔧🤖 心跳催办（分级、可审计）
- **做什么**：某话题多天没进展且挡着里程碑，等心跳。
- **对长什么样**：芝士发 L2 提示（带 actionable 按钮），不是骚扰式 @全员；L2 受节流（每话题每天≤2）；**根话题的现场能查到"它为什么催"**（心跳决策日志）。

### G2 🟢 🔧🤖 纵览=等你的事
- **做什么**：打开 #总览。
- **对长什么样**：纵览 Canvas 显示里程碑、话题×状态、**等你的事**（按人分派的待办）、风险；收件箱只装需要人决策的，不灌 AI 过程噪音。

### G3 🟡 🔧 主动消息反馈喂度量
- **做什么**：对一条主动消息点"👎打扰了"。
- **对长什么样**：记录反馈；该类触发器降级（频率下降）。

## H. 横切验收（贯穿所有场景的不变量）

> 这些不是单独场景，是每个 eval 都要顺带检查的"系统底线"。

- **H1 🟢 三条物理规则**：事件只追加（流/现场历史不可改）；状态可编辑且改了即指令（文档）；产物经人采纳才生效（闸门）。
- **H2 🟢 人格唯一**：不管多少条支线、多少 session，用户始终面对"一个芝士"。
- **H3 🟢 注意力分离**：任何界面默认不向人灌 AI 过程；过程可下钻、不强推。
- **H4 🟢 不崩**：芝士 API 故障/额度耗尽时，系统降级为可用的"聊天+文档"，不变砖。
- **H5 🟢 溯源闭环**：芝士说的每个结论可点到依据（决策记录/PR/现场片段）。

## 验证怎么跑（操作约定）

1. **手眼 = Playwright**：agent 通过它打开真实应用、点、填、发消息、截图、读 DOM、等异步。
2. **判断 = agent**：拿着上面每条的"对长什么样"，看真实结果判断对没对——判断的是产品语义对不对，不是文本相等。
3. **真 agent 跑核心链路**：🟢 场景用真芝士端到端跑（充分信任 agent，不 mock 掉灵魂）；判断 agent 读"现场"transcript 作为 ground truth。
4. **回归**：🟢 全部纳入回归，改 prompt/换模型后必须仍过；🟡 选择性回归。
5. **失败即信号**：某条不过 → 不是改测试，是改系统（或确认是 spec 没说清→回去补 spec）。
