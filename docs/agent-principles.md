# 平台上的 agent：定下来的原则

这份文档记的是**已经拍板、不再重新讨论**的判断。写下来是因为它们此前只存在于对话里——
每个新会话、每个新来的人、以及平台上的芝士自己，都会从同样的错误直觉重新出发一遍，
然后被同样地纠正一遍。

每条的形式是：**结论 → 为什么 → 它具体否掉了什么做法**。最后一栏最重要：
原则脱离了它否掉的东西就会退化成口号。

---

## 一、agent 是独立的参与者，不是谁的分身

它有自己的上下文、自己的判断、自己会犯的错。把这些记在某个人名下是记错账。
块上就该显示是它说的，不是某个人说的。

**否掉的做法**：给每个人签发一张"他自己的 agent 的凭证"，让 agent 以那个人的身份说话。
也否掉靠偷用户浏览器会话上平台的一切方案——那必然导致人和 agent 在平台眼里是同一个。

## 二、agent 的权限和人一样大

房间里的 agent 就是这个房间的正式成员，能力和人类成员相同。凭证是**认证**的机械需要
（总得知道是谁在连），不是**授权**的分级——凭证不携带任何缩水。

**为什么**：这个平台一路卡住的全部是"权限太小"，没有一次是"权限太大"。App 是 private
导致新人 404、App 缺 workflows scope 导致一整类卡推不上去、外部没有任何申领凭证的入口——
每一条都是闸门造成的停摆。

**否掉的做法**：任何"权限是某人的子集"的委托模型。以及"先给最小权限，需要时再放开"这种
默认收紧的设计姿态。

## 三、"权限来自谁"这个问题问不出来

委托模型的前提是一个 agent 属于一个人。这里不是——一个房间里五个人对着同一个芝士说话。
按说话的人算，它的能力会随谁开口而闪烁；按建房间的人算，它凭什么比房间里另一个人强或弱；
按交集算，它什么都干不了。

**结论**：agent 的权限不从任何人身上流下来，它的作用域是**房间/项目**。

## 四、安全靠可见，不靠限制

它做了什么、说了什么、改了什么，全在房间里留痕，人随时能看、能回滚。用限制换安全，
代价是它什么活都干不成；用可见换安全，它能干活而你看得见。

## 五、采纳 = 合并那个 PR

不是"启动一个稍后会合并的流程"。验收卡是这个 PR 在平台里的视图（diff + checks + 讨论），
人看到一个 CI 已经绿的 PR，点一下，它就合了。

**否掉的做法**：点采纳之后才去开 PR。那样人是在给一份没有任何检查结果的改动点头，
真正的合并发生在之后某个无人参与的时刻。

## 六、平台不跑检查

仓库在自己的 CI 配置里声明检查，forge 跑，平台**读结论**。可合并性由 forge 回答——
分支保护、required reviews、draft 状态都喂这个答案，自己重算必然漂移。

**否掉的做法**：平台自己维护一个 `check_command` 再跑一遍。那是"检查"的第三套私有定义，
而且它跑在一台没有数据库的机器上，只能 `--no-tests`——发出的绿卡意味着 lint 过了，
一条测试都没跑。

## 七、人签字不是产品定律

免审核 / human-out-of-the-loop 是要支持的一档模式。谁来闭合这个环是可配的，
"必须有人点一下"只是当前的默认值。

**否掉的说法**："人工签字是平台唯一的安全支点，替掉它平台就不成立。"

## 八、平台只说两类话：能力，和事件

- **能力**：你能做什么、不能做什么。「这台机器上没有可用的数据库」「你的 git 凭证推不了
  CI 配置文件」「这台机器闲置 N 小时会被回收」。
- **事件**：发生了什么。「上一轮在 X 被中断了」「你上次推送被拒绝了，原因是 Y」。

它**永远不解释某个项目的配置是什么意思**。平台服务所有项目，把某个项目的配置名写进
提示词就是把一家的实现焊进通用产品。

**推论**：项目自己的配置不靠平台念出来，靠 agent 够得着那台机器自己去看。
平台提供的是**通路，不是知识**。意义住在项目自己的仓库里。

## 九、该修的限制不要拿去广播

绝大多数"需要告诉 agent 的限制"其实是"应该被修掉的东西"。沙箱没有数据库 → 给它一个
数据库；凭证读不了 issue → 放宽凭证；App 缺权限 → 去补上。

真正既查不到又修不掉的，只剩物理事实。这一栏应该很短，不该长成一个体系。

## 十、渐进式披露是默认

system prompt 只留**它自己发现不了、且不查就会白干**的东西，其余全部是指针：
项目知识在仓库的 CLAUDE.md，平台工具在 `cheese --help`，流程在 skill 里。

**否掉的做法**：因为"弱模型不会主动去读"就把几 KB 的规则内联进 system prompt。
那是在用体积补偿指针不清晰，而补偿从来不是修。指针不清晰就去修指针。

## 十一、记忆和 CLAUDE.md 是两种东西，不是两个筐

|  | CLAUDE.md | 记忆 |
|---|---|---|
| 是什么 | **我们定的规矩**——事情**应该**怎样 | **实际遇到的事**——当时**发现**是怎样 |
| 时效 | 跟代码一起改，天然是当下的 | 带日期的观察，会过期 |
| 加载 | 每次必加载，所以有体积预算 | 按相关性召回 |

分界不是"这仓库 vs 跨项目"，是**规矩 vs 观察**。记忆可以反过来纠正 CLAUDE.md——
库里就有一条记忆记着「CLAUDE.md 第 3 行把仓库描述成三件套，但实际还有 cli/ 和 evals/」。

晋升（观察 → 规矩）的门槛要高，因为 CLAUDE.md 每个会话都要付钱。库里另有一条记忆记着
「只写在文档里的规则会被静默突破」——搬进去不等于被遵守。

## 十二、不要把一段对话升格成机械

**如果一件事在"你开口让 agent 干"时它本来就会干，那它不该被做成平台的一个功能、
一种轮次、一个状态机。**

这是这个代码库里最贵的一类错误，已知的四个实例：

| 实例 | 平台替它干了什么 | 代价 |
|---|---|---|
| pre-PR 质量闸门 | 替它跑检查 | `pending_gate` 死锁（连带整个话题再也递不出卡）、孤儿扫底、两个超时常量、一个状态背两个相反含义 |
| 定期巡检（心跳） | 替它想起来该催人 | 按闹钟而非按事件推送；要发现的事平台在状态变化那一刻就已经知道 |
| 项目摘要 | 替它总结 | 与话题实况文档形成两份互不知情的"项目状态" |
| 活动接入 | 替它整理线下内容 | 独立会话覆盖了话题的会话指针，导致主对话再也 resume 不回去 |

四个都不是实现没写好，是**位置错了**。

## 十三、从第一性原理解决，不给症状写说明书

发现"两代路由撞车"时，正确的问题不是"怎么绕开撞车"，是"为什么两个不同的东西叫同一个
名字"。发现"卡片卡死"时，正确的问题不是"怎么给死锁加个出口"，是"这个状态为什么存在"。

给症状写一份权威说明，会让下一个人以为问题解决了。

## 十四、续跑就是把 transcript 接回来，平台自己不续

会话里什么都有：原任务、干到哪、它自己说过的话。所以不需要重建任何"断点简报"：一个话题的
下一轮接着同一个会话（`resume_session_id`），人在房间里重新 @ 就是续跑，芝士看到的是同一份
transcript 里多了一句话。

平台自己不续：一轮失败、超时、被判卡住，各发一次事件（`who=human`）然后停下，不重跑——重跑
要么把同一个缺陷再触发一遍，要么再撞上同一台刚死的机器。什么会结束一轮、之后房间看到什么，
见 `agent-liveness.md`。

**否掉的做法**：断了就开一个全新的空会话，然后发一句"接着完成原任务"。新会话什么都没见过，
这等于对一个刚推门进来的人说"接着干"。

## 十五、只 care device，本地容器是过渡形态

围绕"后端能直接看到工作区"建立的便利不能作为设计依据。见 #282。

## 十六、平台的水管不许弄脏机器：不是 docker，也要有 docker 的行为

平台落到一台机器上的一切——代理设置、CA、令牌、脚本、文件——必须**关在
screen 的进程树和它自己的目录里**，像 docker 把容器关在自己的命名空间里那样。
HTTPS_PROXY 是进程级 env（只活在那个 tmux 会话里），CA 是 per-topic 目录下的
文件，凭证随会话生灭。机器是用户的；平台只是借一块进程空间，走的时候不留痕。

**否掉的做法**：写 `/etc/hosts`、装系统 CA、改全局 shell profile、注入机器级
环境变量——哪怕它"只是一行"、哪怕更省事。2026-08-13 给 device 接订阅时，
`/etc/hosts` 按名重定向本是最直接的方案，正是被这条否掉的（进程级
HTTPS_PROXY 替代）。

**与 Hosted Machine 不矛盾**：`visibility=host` 让 agent **看得见并操作**整台
机器，那是用户显式授权的能力；平台自己的管线**污染**整台机器则永远不行。
一个是给 agent 的权力，一个是平台的自律，两码事。

## 附：这份文档是怎么来的

2026-08-12 的一次长对话。当时的工程侧判断（agent 是分身、人签字是产品根基、权限要收紧、
平台该自己跑检查、限制该广播、规则内联进 prompt）被逐条纠正，上面每一条的"否掉的做法"
都是当时真实提过的方案。

同一天还查到一件事，是这些原则为什么必须写下来的直接证据：平台组装的 system prompt
在生产路径上**从未送达过模型**（`HooksTurnProvider.run_turn` 收下 `system_prompt` 形参后
从不使用，两个子类都受影响），所以那 1600 多轮里，芝士既不知道自己是谁，也不知道
自己在什么产品里。写下来的东西没送出去，和没写过是一样的——**这份文档要被真正送达，
才算数**。
