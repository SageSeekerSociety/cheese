## 0. 范围

**谈**：全站外壳（底栏 / 顶栏 / 二级导航）、2.0 话题页、工作面板在手机上的形态。
**不谈**：任何具体的视觉稿、任何 1.0 页面内部的重排。
**不谈桌面**：#47 自己规定了桌面的三面 IA（机构面 / 工作区面 / 团队页），那是 #47 的
范围。桌面**会**因为 #47 变，但不在这份文档里定——这里只谈同一个模型在手机上的样子。

## 1. 现状证据

先摆今天在手机上真实发生的事，全部来自代码，不是推测。

### 1.1 底栏会随项目数量无限长

`BottomAppBar.vue:30` 的过滤条件是 `visibleOnMobile !== false`。而 `App.vue:186-226`
的 `navItems` 里，项目条目（`cxProjects.value.map(...)`）**没有这个字段**，于是每一个
项目都变成底栏的一格：

```
底栏 = 空间 + 小队 + 项目1 + 项目2 + … + 项目N
```

`v-bottom-navigation` 加 `grow`，五个项目就是七格，每格约 53px。这不是"移动端还没做"，
是移动端做了但没有约束。

### 1.2 手机上建不了项目

`App.vue:225` 的 `cx-add`（＋新建项目）是 `visibleOnMobile: false`，而**没有任何
其他地方接住这个动作**。这是今天唯一一处真正的可达性缺失。

### 1.3 话题页那一处断点是坏的

`views/workspace/TopicView.vue:331`：

```css
@media (max-width: 960px) {
  .panes { flex-direction: column; }
}
```

改成纵向之后：
- `:style="{ flex: '0 0 ' + store.chatPct + '%' }"`（`:241`）从"宽度占比"变成"高度占比"，
  而 `chatPct` 的语义和默认值都是按宽度定的；
- `.pane-resizer` 仍然是 `cursor: col-resize`（`:323`）；
- `startPaneDrag` 仍然从 `ev.clientX` 算（`:75`）——纵向布局下横向拖动改的还是那个
  现在当高度用的数。

三处互相矛盾。**这一段应该删掉，不是修好**：手机上根本不存在"可拖动的分栏"这件事。

### 1.4 话题列表的行操作是 hover 才出现的

`TopicSidebar.vue:1305-1307`：`.row-actions` 默认 `opacity: 0`，靠
`.topic-row:hover` / `:focus-within` / `.is-menu-open` 才显形。触摸屏没有 hover，
`:focus-within` 要先聚焦——**⋯ 菜单在手机上摸不到**。这是全站唯一一处真正在触摸下
失效的交互。

### 1.5 输入框回车即发送

`components/ChatPanel.vue:966`：`onComposerKey` 在 `Enter` 且非 `Shift` 且非 IME
组合态时 `sendDraft()`。软键盘上没有 Shift 这一层，回车就是换行键——手机上照这个规则，
用户打不出第二行。

（`isImeKey`（`:962`）那一圈 IME 防护是对的，不要动，手机上更需要它。）

### 1.6 全站没有一处 dvh / safe-area / visualViewport

`grep` 全仓：`dvh` 0 处，`env(safe-area-inset-*)` 0 处，`visualViewport` 只出现在
两个测试的 happy-dom 补丁里（`TopicComputePicker.spec.ts`、`TopicSidebar.rail.spec.ts`）。
唯一的视口高度写法是 `views/teams/Detail.vue` 的两处 `100vh`（`:76`、`:98`）。
也就是说，键盘弹起、地址栏收缩、底部安全区这三件事，目前一件都没处理。

### 1.7 手机顶栏的标题是祖先的标题

`MobileAppBar.vue:183-192`：`updateTitle` 沿路由层级找**第一个 `isFullPage` 的祖先**，
拿它的 `meta.title`。而 `workspaceRoutes.ts:32` 上写的是
`{ title: '项目工作台', isFullPage: true }`。所以在手机上打开任何一个话题，
顶栏都写着「项目工作台」——不是话题标题，也不是项目名。

### 1.8 手机上已经有两层导航 chrome

`App.vue:15-27` 的移动端分支同时挂了三样东西：`router-view name="sidebar"`
（经 `SecondaryNavigation` 变成 temporary 抽屉）、`MobileAppBar`（左上角汉堡
→ `navigationStore.toggleSecondaryDrawer()`）、`BottomAppBar`。
**抽屉和底栏是两套并列的一级导航**，用户要记住"有些地方在下面、有些地方在汉堡里"。

### 1.9 已有的正面先例

`components/chat/ChatDialog.vue` 用 `useDisplay()` 的 `mdAndUp` 让同一个组件在两端
呈两种形态（桌面右侧滑入 + 会话侧栏，手机全屏 + 会话下拉菜单）。这是仓里已经在用的
写法，下面的设计沿用它，不发明新机制。

## 2. 结构诊断

### 2.1 模型以 #47 为准

导航排不出来，根子不在格子不够，在于仓里同时躺着三份互相打架的产品模型。按时间：

| 出处 | 时间 | 说的模型 |
|---|---|---|
| `docs/spec.md` §4 | 2026-06-14，之后未改 | Space → Task Template → Task → **Project**；没有「团队」这个实体，Project 自己持有成员和策略 |
| `docs/unification-plan.md` P4 | 2026-07-11，未勾 | 记下 cheesex 的 Project(uuid) 和知是的 Team(int) **之间没有任何关联**，列了三个选项，结论是"需要产品拍板" |
| **issue #47** | 2026-07-13，**最新** | 拍了：deployment = 机构/租户，Space 降级为部署配置；**归属主体是团队，项目归属到团队** |

**2026-08-18 拍板：以 #47 为准。** 于是这份文档只依赖三条：

1. **一套部署 = 一个机构。** Space 不是可导航的 in-app 实体，是一份部署配置（品牌、
   赛题模板、看板）。机构面（首页 feed / 领题板 / 看板）是一个 config 开关，
   消费版关掉。
2. **归属主体是团队**，团队持有成员和算力；**个人 = 单人团队**（同构，不做第二套）；
   **项目归属到团队**。
3. 桌面 IA 是三面：机构面 / 工作区面（大 box = 团队，小 box = 项目）/ 团队页。

算力那份 spec（`docs/superpowers/specs/2026-07-01-execution-architecture-design.md`
的 v4 修订）已经踩在这上面了——「归属 = 团队 context」「团队池 → 项目 sticky →
会话选择」「团队页（成员 + 算力）」——所以这不是一条孤立的想法。

**代码里 #47 一步没落**，这对落地顺序有直接后果，见 §8。

### 2.2 两端顶层不同不是病

桌面 rail 是 64px × N 的竖列，**装得下实例**——项目一个一个平铺，Discord 就是这么做的。
底栏只有三五格，**装不下会随数据增长的东西**。所以两端的顶层清单本来就该不一样，
这是形态差异，不是漂移。

真正需要守住的不变量窄得多：

> **每个目的地两端都到得着；顶层展开到哪一层，两端可以不同。**

按这条扫一遍，今天的违例只有 §1.2 一处。

### 2.3 但表达方式该换

今天的机制是「一份清单 + 两个否定式可见性过滤器」。问题不在它存在，在于它
**看起来像一份清单，实际是两份**：

- 首页在手机上被过滤掉之后，没有任何东西提示"它的两个子页必须有人接住"——
  接住了是巧合，不是机制；
- `＋新建项目` 被过滤掉之后，同样没有东西提示它无家可归，于是它就真的无家可归了（§1.2）。

**改为两份显式清单（`railItems` / `tabItems`），共享同一批目的地定义。**
只有几个条目，"一棵树 + 投影规则"是过度设计；共享的目的地定义负责保证不会再有
目的地只活在一端。

## 3. 目标形态

### 3.1 外壳：底栏三格

| 格 | 落到 | 说明 |
|---|---|---|
| 空间 | 赛题 / 公告 / 看板 / 讨论 | #47 的机构面，**config 可关**。这几块是页内分段，落在哪一段看角色：学生落赛题，老师落看板 |
| 工作区 | 上次待的那个项目的话题列表 | 日常主场。项目和团队在这一格**里面**展开，不占底栏 |
| 待办 | 跨项目「等你的事」 | 新目的地，桌面同样缺（见 §6） |

**第一格就叫「空间」，从今天到 #47 之后都叫这个。** 它是仓里已有的词，
`SpaceSidebar.vue` 底下那一串（公告 / 全部赛题 / 分类 / 我发布的赛题 / 我参与的赛题 /
讨论 / 审核 / 模板 / 数据分析）就是这一格要装的东西。#47 之后这个词依然成立——
#47 拆掉的是"在多个空间之间切换"，不是空间本身；那一格的内容从"空间列表"收敛成
"这一个空间"，词不用换，格子也不用挪。**这样底栏从第一天就是三格，形状不改两次。**

「赛题」是这一格里最重要的一段，但它只是一段——公告和看板不是赛题，用它命名整格
以偏概全。

不进底栏的：

- **「我」不占格。** 个人项（状态、设备、设置、个人主页）留在顶栏头像菜单里，
  也就是今天的样子。依据是 Slack 走过这条路又退回来了：2023 年底那版底栏是
  Home / DMs / Activity / **You** 四格，设计团队后来收敛成 Home / DMs / Activity
  三格，You 回到头像。个人项是低频的，常驻格按高频付费。
- **「＋新建项目」** 落在工作区那一格的切换器里（在当前团队下建项目），底栏不占格。
- **「私聊」**：按 2026-08-18 的决定留在项目内，不占底栏格。
  （这条是暂定的：#47 让团队持有成员之后，私聊的自然作用域可能从项目变成团队，
  那时候它才够格上底栏。别把它写成规则。）

**消费版只有两格。** 空间那一格 config 关掉之后，底栏是 工作区 / 待办。就这样，不补格：
格数由**部署配置**决定，对同一套部署里的同一个用户永远是稳定的——这和"底栏随用户状态
变形"是两回事，后者才是要避免的。（如果两格实在太空，补的应该是「我」而不是别的，
但按上面 Slack 那条证据，先不补。）

### 3.2 工作区那一格：落在上下文，目录在切换器里

这一格**落地在你上次待的地方**——当前项目的话题列表，一跳就能进话题。这一点抄 Slack：
它的 Home 是**当前工作区的频道列表**，不是一个工作区目录；把目录当落地页，等于给
每天的主路径加一跳。

**顶部的切换器就是 #47 的目录**：

```
大 box = 团队（个人 = 单人团队）
  └── 小 box = 这个团队的项目
        齿轮 → 团队页（成员 + 算力）
```

也就是把桌面上「rail + 二级侧栏」两层，在手机上压成这一格里的一个列表。
没有项目的新用户（还没领题的学生），这一格没有落地上下文，空缺态直接就是这个目录。

**不需要单独的「项目列表页」。** 目录是这一格里的切换器，不是一个新路由——
仓里今天也确实没有 `/projects` 这一层（`workspaceRoutes.ts` 从 `/projects/:projectId`
开始）。

#### 团队没有自己的格子，它按"你在干什么"分到三处

今天 `/teams` 底下是四件不同的事，它们的节奏差得很远，捆在一个顶层区域里才显得需要
一格。拆开之后各有各的家：

| 今天在 `/teams` 的 | 去哪 | 为什么 |
|---|---|---|
| 我的团队（`/teams/mine`） | **工作区**的切换器（大 box） | 这是归属，是你每天回来的地方 |
| 团队详情：成员 / 知识库 / 算力（`/teams/:id/*`） | 大 box 上的齿轮 → 团队页 | 管理动作，从归属处进去 |
| 发现团队（`/teams/explore`） | **空间**那一格 | 找队友是领赛题这条流程的一部分，和赛题放一起才连得上；它是公共的、有意图才去的，不是每天回来的 |
| 入队申请、待处理（`/teams/pending`） | **待办** | 这是"有人在等你点头"，正是那一格的定义 |

### 3.3 手机上不存在常驻的二级侧栏

这是本文最主要的一条结构规则，它同时解掉 §1.8 的两层 chrome 和 §1.4 的 hover 菜单。

二级侧栏的内容，按它和当前页的关系二选一：

- **层级关系**（团队 → 项目 → 话题）→ 提升成**页面栈的一层**。返回靠顶栏的 ←，
  不靠抽屉。
- **并列关系**（机构面的 feed / 领题板 / 看板）→ 压成**页内分段**，留在页面上。

抽屉一个都不留。理由：底栏已经是一层常驻 chrome，再叠一个抽屉就要求用户
记住"哪些东西在下面、哪些在汉堡里"，而这个划分没有任何语义依据（§1.8）。

**代价是可数的，而且不碰桌面。** `SecondaryNavigation.vue` 里
`permanent = mdAndUp`、`temporary = !mdAndUp`——抽屉本来就只是这个组件在窄屏下的
另一种形态，桌面走 `permanent` 分支，一个字都不用改。要改的是四个侧栏
**在手机上**的呈现：`HomeSidebar.vue`、`spaces/SpaceSidebar.vue`、
`teams/DetailSidebar.vue`、`TopicSidebar.vue`。四个，不是"所有 1.0 页面"。

顶栏收成 ← / 标题 / ⋯（页面级操作），标题必须是**当前页**的标题，
不是 `isFullPage` 祖先的标题（§1.7）。右侧保留头像（个人项的家，见 §3.1），
铃铛被底栏「待办」取代（§6）。

### 3.4 话题页

全屏，底栏隐藏（它是栈的末端，不是一级目的地）。

**只有一个窗格。** 对话和工作面板在手机上是同一层的分段，不是左右分栏：

```
[← ] 话题标题 #a3f  [待验收]                    [⋯]
─────────────────────────────────────────────────
 对话 │ 文档 │ 现场 ● │ 改动 ③
─────────────────────────────────────────────────

              （当前分段的内容）

─────────────────────────────────────────────────
 [输入…                                  ] [发送]
```

也就是 **WorkPanel 现有的 Tab 前面加一格「对话」**。P2 的模型原样搬过来，
一条都不用改，而且在手机上更值钱：

- `tabIsOffered`（`WorkPanel.vue:230`）继续按**工作状态**门控，所以实际大多数
  时候是 2–3 格，不是 5 格；
- `tabForPhase`（`WorkPanel.vue:109`）继续决定进来时停在哪一格；
- Tab 上的三种信号（`tabbar__pulse` / `tabbar__dot` / `tabbar__count`，`:342`/`:345`/`:351`）
  在手机上**是唯一的感知通道**——桌面上你还能瞥见旁边那一栏，手机上瞥不见；
- `?tab=` 继续拿在 `TopicView` 手里，多一个 `?tab=chat`。

在手机上不存在、直接不渲染的东西：

- **专注模式**（`TopicHeader.vue:162-168`）——手机上永远是专注的；
- **两处拖拽把手**（`.pane-resizer`、侧栏 `.rail-resizer`）——没有可拖的宽度。
  这一条同时作废 P3 里"给拖拽把手补 pointer 事件"那一项：不是补，是不存在；
- **`@media (max-width: 960px)`**（§1.3）——删掉。

`TopicHeader` 那一行在手机上收成：← / 标题 + #id / 阶段徽标 / ⋯（用量、成员、归档）。
成员头像列和用量按钮进 ⋯，不占那一行。

### 3.5 输入区

- **回车换行，发送靠按钮**（§1.5）。`isImeKey` 那一圈原样保留。
- 键盘弹起用 `visualViewport` 定容器底，容器高度用 `dvh` 不用 `vh`；
  底部内边距吃 `env(safe-area-inset-bottom)`（§1.6）。
- **评审文档的规则 5（评论输入脱离共享输入框）必须排在手机评论之前。** 桌面上共享输入框
  被评论劫持只是别扭；手机上软键盘一弹，用户看不见自己在往哪条评论里打字。

### 3.6 面板在手机上只读优先

- Monaco 编辑、文档源码模式在手机上不提供——软键盘 + 代码编辑器不是能救的组合，
  给一个"在电脑上编辑"的明确说法，不要给一个难用的编辑器。
- 采纳 / 验收动作条吸底，吃安全区。是否给它做手机专属形态见 §7。

## 4. 规则

可检查的不变量，按它们能挡住哪个已发生的错误排：

1. **每个目的地两端都到得着。** 顶层展开到哪一层可以不同（§2.2）。
   ——挡 §1.2。
2. **底栏只装固定的、数量不随数据增长的东西。** 实例（项目、团队）一律在容器格里展开。
   ——挡 §1.1。
3. **底栏的格数由部署配置决定，不由用户状态决定。** 机构面开或关是部署级的；
   不做"有项目时四格、没项目时三格"这种随状态变形的底栏。
4. **手机上没有常驻二级侧栏。** 层级关系进页面栈，并列关系压成页内分段（§3.3）。
   ——挡 §1.8。
5. **任何靠 hover 显形的操作，在触摸下必须有第二条路。** 长按、常驻、或者进 ⋯。
   ——挡 §1.4。
6. **视口高度一律 `dvh`，底部一律吃安全区，键盘一律走 `visualViewport`。**
   ——挡 §1.6。
7. **触摸屏上回车是换行。**
   ——挡 §1.5。
8. **不要"给桌面布局加断点"。** 手机上不成立的交互（拖拽分栏、专注模式、
   代码编辑）应当不存在，而不是缩到一列里继续挂着。
   ——挡 §1.3。

## 5. 路由清单 → 移动端入口

规则 1 只有对着完整路由表才检查得动。以下是 `router/index.ts` 里的全部顶层区域，
以及它们在 #47 之后该去哪。**标 †的行依赖 #47 落地**，在那之前维持现状。

## 6. 「待办」这一格

它是三格里唯一的新目的地，也是唯一需要后端的一项。

今天离它最近的东西是顶栏那颗铃铛（`AppBar.vue` / `MobileAppBar.vue` 的
`NotificationPanel` 下拉），**没有路由、没有页面**。桌面同样缺。

待办落地即取代那颗铃铛——手机上顶栏不再有它（§3.3），桌面上是否同步废掉见拍板 1。

#521 已经给 `TopicOut` 落了 `i_participate` 和 `awaits_me` 两个字段
（`backend/app/domain/topic/schemas.py:55-64`），话题树也已经在用 `awaits_me` 画标记。
但它们只在**单个项目**的话题列表里拿得到——跨项目聚合需要一个新端点。

机构面产生的信号（新赛题、截止临近）也走这一格：这样空间在手机上有两条路——
日常靠信号找上门，主动进入靠底栏「机构」。

聚合哪些来源是拍板项（§7）。

## 7. 需要拍板

1. **「待办」这个词，聚合哪些来源，以及它是否吃掉桌面的铃铛。** 词本身按既有的起名
   流程走（品类词 + 差异属性，可引译名先例），本文用它只是占位。候选来源：`awaits_me`
   的话题、@ 我的消息、待验收的交付卡、机构面的赛题截止——范围直接决定那个新端点的
   形状。另一半是：待办落地后桌面顶栏那颗铃铛是留还是废。按仓库约定「不留被替代的
   形状」应该是废，但那会连带 `NotificationPanel` 现有的全部通知类型，
   所以取决于上面那个来源清单圈到哪里。

2. **问答 / 市场 / 搜索去哪。** 两端都缺入口。选项：(a) 塞进头像菜单；(b) 顶栏放
   搜索入口，问答/市场进搜索结果的分类；(c) 明确它们不在主导航里，只从内容页进。
   Slack 的先例是 (b)：他们把 canvases / lists / automations 收进了搜索，
   而不是往底栏加格。

3. **手机上的采纳/验收动作条。** 是复用桌面那套按钮吸底，还是做一个手机专属形态
   （比如主操作全宽 + 次操作收进 ⋯）。

已经不用拍的（记在这里免得再问一遍）：

- ~~空间在底栏占不占格~~ → 占第一格，就叫「空间」，从今天到 #47 之后都是（§3.1）。
- ~~团队占不占格~~ → 不占，按"你在干什么"分到工作区 / 空间 / 待办三处（§3.2）。
- ~~私聊是否跨项目聚合~~ → 暂定留在项目内，不占格（§3.1）。
- ~~废掉抽屉的范围~~ → 四个侧栏的手机形态，桌面零改动（§3.3）。
- ~~屏幕上「小队」还是「团队」~~ → #47 的模型词是团队，`.claude/rules/frontend.md:84`
  也写着屏幕上用「团队」。跟着改，不单独拍。

## 8. 落地顺序

依赖序，不是排期。什么时候做由 backlog 决定。

### 8.1 已落地（2026-08-18）

1. **两份显式清单**（`railItems` / `tabItems`，共享目的地定义，`Navigation/destinations.ts`）+
   底栏收成 **空间 / 工作区 / 待办** 三格 + ＋新建项目落进工作区那一格。
   §1.1 和 §1.2 到此修完。切换器在 #47 之前是**扁平的项目清单**（rail 上那份），
   团队分组等 §8.2。
2. **话题进页面栈**：工作区 → 话题列表 → 话题页；话题页和私聊页隐藏底栏、顶栏给
   ←（去哪由路由的 `backTo` 说，不用 `history.back()`）；顶栏标题改成当前页标题
   （§1.7）；话题行的 ⋯ 在 `(hover: none)` 下常驻（§1.4）。
3. **话题页单窗格**：删掉 `@media (max-width: 960px)`、手机上不渲染两处拖拽把手和
   专注模式（§1.3）；「对话」成为 WorkPanel tab 栏的第一格，`?tab=chat`；
   对话那一栏抽成 `TopicChatColumn.vue`，因为两端挂在不同位置。
4. **输入区**：触摸屏上回车换行（判据是 `(hover: none)`，不是视口宽度）；
   `--keyboard-inset`（`lib/keyboardInset.ts` 读 visualViewport）+ `dvh` +
   `env(safe-area-inset-bottom)`（§1.6）。
5. **面板只读态**：改动里的 Monaco 在手机上只读；源码模式不提供；因此**可视化编辑
   会丢格式的文档在手机上只读**——源码模式是它唯一存得下去的路，不能让人编辑完
   才发现存不了。

桌面端的形状一点没动。

### 8.2 卡在 #47 上

- **切换器里的团队分组（大 box / 小 box）**——**项目和团队之间的关联今天不存在**。
  `unification-plan.md` P4 写得很直白：cheesex 的 Project（uuid，`owner_handle` +
  成员 handle）和知是的 Team（int）之间没有任何链接。这个外键是 #47 范围第 2 步
  （"工作区/团队一等公民，项目归属收敛到团队"）建的。在它之前，切换器只能是扁平的
  项目列表——**不要在一个还不存在的外键上先把目录做出来**。
- **团队页（成员 + 算力）** ——同上，外加算力那份 spec 的 v4 团队池。
- **「空间」那一格从列表收敛成单一机构面** ——依赖 #47 范围第 1 步（Space 降级为
  部署配置 + config 开关）。在它之前这一格照常落到今天的 `/spaces` 列表，格子的
  位置和名字都不变，所以这一步不改底栏形状。
- **发现团队并进空间那一格** ——同上，#47 之前它还是 `/teams/explore`。
