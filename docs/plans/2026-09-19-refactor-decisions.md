# 2026-09-19 与 Zhifei 逐条聊定的架构结论（重写 ARCHITECTURE 的依据）

「他」= Zhifei。每条都是他今天在对话里拍的板，标 [已定]；带「倾向」字样的是我提、他未反对但也未明确点头的，标 [默认]。

## 一、参与者与身份
1. [已定] 人和 agent 是同一种参与者：唯一身份 + 席位。不同的只是谁拥有它：人拥有自己，被邀请到哪就去哪；agent 实例由建它的项目拥有，只在那个项目有席位，别的项目不能邀请它。
2. [已定] agent 分「类型」和「实例」。类型 = 出厂设置（人设提示词、技能），不属于任何项目，像岗位说明书，可跨项目复用；实例 = 某个项目从某个类型建出来的参与者，唯一身份、自己的记忆、只在该项目有席位。今天 `agent_types` + `agent_instances` 已是这个形状；差别是类型里要拿掉 model 和 harness（见 3、28）。
3. [已定] agent 只按 role 分，模型不是 agent 的属性，也不是分参与者的理由（用第二个 agent 换模型是错放）。模型是**工作的资源绑定**，与机器（地点）同形，卡上并排显示「在哪台机器、用哪个模型、现在在做什么、花了多少」。
   - 聊天（房间主线程）用一个稳定的模型：项目默认，普通成员不碰；主线程不换模型，缓存一直热。
   - 做事按活配脑子：agent 派一条活时自己选（难的强、粗活便宜），在项目策略允许的档位内；超档要人点头就提议（投递规则，下一步在人手上）。人可以在卡上改或打断。「解不了」永远是交给一条活去解，不在聊天里换脑子。
   - 一个 role 最多声明对脑子的要求（如需要看图），解析时满足，不钉型号。
   - 部署决定可选列表（按 harness 筛）；项目定默认和档位策略；供给降级只能拒绝或可见等待，不悄悄换模型（否掉网关按可用性换模型那种 fallback）。
   - 每一轮实际用的模型随用量记在卡上，显示从记录算，不是被 set 的状态。改绑定下一轮生效、同一份 transcript、一条事件；换脑子的一次性预填代价在改的地方亮出来。
   - 用户接触模型的地方只有卡，看多于设；类型和实例里不再有 model/harness 字段。
4. [已定] 没有跨项目的「平台芝士」参与者：每个项目自动有一个芝士类型的实例（今天的默认 `cheese`），是完整参与者，记忆全部关在项目里。
5. [已定] 判据（搬自 8 月多 agent 设计文档）：两个 agent 的区别只是 system prompt 就不该是两个 agent；区别必须是能力/凭据、记忆/专长、责任之一。记录里没有「一个房间两个 agent」的真实需求，只有用第二个 agent 换模型这种错放；一房多队友是 #1180 之后的能力，不是要求。
6. [已定] 将来「人带自己的助理进各项目」= 人拥有实例、席位跟着人，模型里不加新概念，本轮不做。

## 二、记忆与文档
7. [已定] 没有项目记忆池。人和 agent 共同看的只能是文档：实况文档、进度层、仓库里的 docs 和 CLAUDE.md（第十一条：文档是规矩，记忆是观察）。agent 观察到值得所有人知道的事，动作是写进文档（留痕），不是写进共享池。今天 `MemoryScope.project`（7 处，dream 把它当 shared 池写）改成文档。
8. [已定] 记忆全是某个 agent 实例自己的，三种池：在这个项目里学到的（今天 `agent_project`）、对某个人的（今天 `user`）、自己的手艺。全部随实例关在项目里。
9. [已定] 回忆规则：一个池被读出来，当且仅当它「关于」的那个东西在现场；人在房间里才读对这个人的记忆，今天只在私聊读是缺口。写入分错池是唯一真风险，由整理的分类规则守；agent 对人记了什么，人要能看见、能删。
10. [已定] 一个人的偏好要跨项目跟着他，走文档：一份关于他、他自己能改的资料，任何项目的芝士都读得到。

## 三、同一 handle 的线程
11. [已定] 同一个 handle 在一个项目里是一个参与者，会话是它在各地点的线程；线程之间走内部便条：读是投递（同 `notify_running_turn` 那条通道，不进时间线），写是平台 MCP 上的一个工具，形状像 Claude Code 的 SendMessage。
12. [已定] 不同 handle 之间只走 chat，agent 对 agent 也是。

## 四、投递、事件、总览
13. [已定] 平台从不发起一轮，只投递。今天 5 处平台自召唤（分身开局、定时、冲突、重发×2）全部改写成事件加收件人；`SELF_STARTED_AUTHOR="session"` 那种轮次也退场。
14. [已定] 事件落在它「关于」的那个东西上：卡的事落在卡上（PR 绿了、检查红了、上游冲突），房间的事落在房间时间线（机器离线、成员加入），项目的事落在项目总览（房间创生、房间归档、主干新提交、名册变化、巡检到点）。PR 绿了不是消息，是卡的状态变了，通知验收人。
15. [已定] 收件人对每一种事件都是同一条规则：从「下一步在平台手上」转入「下一步在某个参与者手上」那一刻，通知那个参与者一次。不再「一律告诉人」（收紧 agent-principles 十四的「谁被告知」，不动「不重跑」）。
16. [已定] 总览 = 每个项目自带的根房间（`TopicKind.root`，「项目总览」，今天已存在）。没有 scheduler 部件：总览里的芝士就是调度者。`domain/scheduler/` 解散：巡检由芝士自己决定何时看（第十二条第二行）；PR/上游轮询是托管方实现在没有 webhook 时的内部物理事实，产出落各自的卡和房间；记忆整理归 agent 自己的线程或由归档事件触发；孤儿轮次清扫留在轮次活性层；闸门扫底随闸门消失。
17. [已定] 平台提供一个原语：定时投递（任何参与者可请求「某时刻把这条投递给我」）。
18. [已定] 没有跨项目的全局房间，也不需要跨项目的芝士。

## 五、私聊
19. [已定] 私聊是项目内名册两席的房间；一轮不租地点（`needs_place` 假）；今天的 64 MiB 草稿容器不是地点，是会话自己的草稿区，归 L1；agent 权限不缩；用 chat_send，自动发布（`chat.py:2476`）和私聊专用提示词（`prompt.py:191`，#954 残留）删除。
20. [已定] 私聊读项目池加两个参与者各自的池（按第 6 条规则）。

## 六、地点、工具、机器
21. [已定] 平台的 MCP 永远在 claude 进程所在的机器上（会话侧）：chat_send、cheese ask、反馈、要一台机器、同 handle 便条、定时投递。
22. [已定] 其他一切工具一定在开出来的手上：Read/Edit/Write/Bash、项目 `.mcp.json` 的 MCP、项目 CLI。地点没了它们就是不可用，如实标出来，不在会话侧做替身，也不把项目工具搬到中心机。
23. [已定] 机器离线：agent 收到的是一条事件（「这台机器现在够不着：文件、命令、项目 MCP 不可用；对话、记忆、平台工具可用」），那一轮的工具表里项目工具直接标不可用，不让它们各自超时。机主按第 12 条被通知。agent 换机器是通过平台工具向平台提请求：Cloud 平台自己开；另一台自托管要那台机器主人点头；换成功后告知丢了什么（收据）。
24. [已定] 机器随时可回收：地点是有期限、可归还的租约；回收前三张收据（transcript 落库、记忆整理跑过、未提交工作已推）。#442 第 3 条是旧模型的决定，不再是设计约束。
25. [已定] hosted machine 没有独立用途；三档只差物理事实。
26. [已定] 源仓库永远在平台（每个项目恰好一个），资料库和引用型产物在它之外；办公文件走资料库进、产物出；「本地文件」只是连接器的输入输出通道，agent 不在用户文件系统里就地改。
27. [已定] 平台是唯一副本时，导出和备份是架构义务。

## 七、骨架（harness）
28. [已定] harness 不是产品概念，是开发者选项；不在类型上，不在实例上，是部署/项目级的开发者设置；普通用户看不到。
29. [已定] 骨架契约对所有实现、所有语言一样：会话身份和 transcript 的权威副本在平台，每轮结束前增量交上来；恢复从平台副本恢复。pi 满足它的路径倾向和 Claude Code 同一条（进程在中心机、工具走执行器）。契约测试要盖到 pi 的 TypeScript 侧。
30. [已定] 骨架契约加一项能力「后台分身」（应当支持）：能起后台线程做一条活、线程事件带可归到卡的标识、做完给主线程一条便条、主线程能改指令或停掉它。没有的骨架仍可接入，矩阵那一格填差异码：「这种房间做活期间不可答话」。

## 八、活
31. [已定] `cheese split` 的形状干掉：无第二身份（`cheese-<hex8>` 席位）、无第二会话/屏幕/地点、无 kickoff、无 `cheese_bind`。留下「开一条活」= 分支 + 卡 + 负责人；谁来做是负责人的事。分身做完是给父线程的内部便条。
32. [已定] 负责人是卡上的参与者（一个 handle），说的是问责不是进程数；分身是芝士的线程，在卡上都是「芝士」。
33. [已定] 活在房间里是平的，没有子卡；谁能开活不受限。`MAX_SUBAGENT_SPAWN_DEPTH` 是骨架设置，不是设计。
34. [已定] skill 里的默认（不是规则，不进 system prompt）：活默认交给后台分身，主线程留在房间保持可对话，分身做完给便条由主线程决定发什么到房间；改仓库文件只能在一条活的工作区里。

## 九、反馈
35. [已定] 反馈是一个东西一个入口两种写法：人走界面，agent 走平台工具；agent 遇到平台限制或 bug 提反馈而不是绕。

## 十、写作口径
36. 只讨论设计（该不该），不讨论什么时候做、先做哪个。迁移顺序一节改成「与今天的映射和完成判据」，不排期。
37. 非设计题不进文档：self-hosted 还是 Hosted 这个字、文档放哪。

## 十一、与 Cursor 对照后补定（2026-09-19 晚）
38. [已定] 活永远用房间的机器；子 agent 不声明独立环境。要另一台机器就是另一个房间。
39. [已定] 租约有第三态「休眠」（只对 Cloud）：闲置快照后停机，reconnect window 内恢复同一台、工作区原样；归还前收据规则不变。
40. [已定] 机器离线由 agent 处理：平台把机器状态作为事件送到它面前，「开一台机器 / 换到 Cloud」是平台 MCP 上的工具；策略闸门（自托管要机主同意、超费用档位要人点头）让这个工具调用自动变成给人的提议。平台不设等待超时器。
41. [已定] 验证过程的截图/录像走 skill：验证型的活由 skill 要求 agent 录下验证过程，作为引用型产物挂在卡上；平台不为它造机制。
42. [已定] agent 的私有记忆是**文件**：一个事实一个文件（带「关于谁、何时观察到」的元数据）加自动索引，每个实例一个目录，按关于谁分三个子目录（这个项目 / 某个人 / 自己）。存在平台侧，不进项目 git 仓库，平台给版本；通过平台工具在任何地点可读；整理 = agent 重写自己的文件；回忆规则不变（关于的东西在场才读）。可见性：在该 agent 的 profile 里一个「记忆」页，项目成员可看、可翻历史、可删、可标记；**关于某个人的只对当事人可见**；不进房间、不进时间线、改了不通知、搜索不默认覆盖。写入分类规则：任何提到某个人的判断只能进那个人的池。备选（未选）：项目/自己两池仅管理员可见。与「关于你的资料」（人写的、关于自己、跨项目、给同项目所有 agent 读）是两样东西。
43. [已定] 派活是 agent 对骨架原生 subagent 的工具调用，不走平台；骨架契约硬性要求：能起子 agent并指定模型、子 agent 事件带可归到卡的线程标识、父线程能改指令和停止。平台只认卡：agent 先开卡再起子 agent；hook 按线程标识归卡；结束写结论；人对卡的操作投递给父线程执行。子 agent 与父进程同生同死，恢复靠从分支重派，「边干边 commit」是 skill 硬要求。（本条取代第 30 条里「后台分身应当支持」的措辞。）
44. [已定] 模型不是分参与者的理由，判据是 role；模型作为工作的资源绑定见第 3 条；项目级只有默认模型和启用列表。

## 十二、2026-09-19 深夜补定
45. [已定] 功能层不为师生分档。存在的是按席位角色开的看板：出题者看自己题目下的项目、空间管理员看空间，属于按授权范围的视图（#945 那种），不是第二套流程。
46. [已定] 模型供给收成后端一个入口（#218 的方向）；「不悄悄换模型」在这个入口上拒绝。
47. [已定] 反馈的隐私部分：开发者可见、提出它的那个房间的成员可见、反馈中心里其他人不可见。agent 提的内容在它的房间里全部留痕，第四条不破。
48. [已定] 「关掉骨架自带的实现」取 (a)，并带版本：每个骨架的适配层带一份**行为声明**——它自带哪些产品概念（提问、待办、提醒、自动同步……）、每一项平台怎么关掉、这份声明对着哪个钉住的版本验证过。钉住的版本号只写一处，声明引用它，升级 pin 而未重验声明则 CI 红；真正的验证是契约测试对着钉住的二进制跑（harness-contract），@latest 的夜跑 canary 提前预告变化。提供不了关闭动作的项，功能矩阵那一格标「暂缺」。他 2026-09-19：「a 吧，我们写个不同 harness 的行为说明，表上版本，因为和 pin 的版本也有关系，每次 upgrade 都要改」。
