# PR-created CI-head baseline, 2026-10-14

The two-week cohort averages **2.327 distinct CI heads per PR**. The first reduction moves the repository's local quick-check instruction before commit, because committing can already publish a head and start CI. Its effect has not yet been measured.

## Definition and population

`distinct_head_rounds` counts distinct PR head SHAs with a `pull_request` run of `required-ci.yml`, from PR creation to closure or the observation cutoff. Draft and full runs on the same SHA count once; reruns, returning to a previously observed SHA, and merge-group runs add no heads. Only the check named exactly `CI required` is a full judgement. Existing `orchestrator_metrics.py` behaviour and output are unchanged.

The half-open PR-created cohort is 2026-09-30 08:00 UTC through 2026-10-14 08:00 UTC. The run/check snapshot was observed at 2026-10-14 08:56:02 UTC.

| State at cutoff | PRs | Distinct heads | Mean |
| --- | ---: | ---: | ---: |
| All | 1,462 | 3,402 | 2.327 |
| Merged | 1,366 | 3,173 | 2.323 |
| Open | 55 | 162 | 2.945 |
| Closed unmerged | 41 | 67 | 1.634 |

The median is one; 707 PRs have at least two heads. Eight PRs have no observed run and remain in the denominator. The 55 open PRs are right-censored: their counts are lower bounds, so the all-PR mean is not a completed-lifetime mean.

## Observed extra work

There are 1,948 extra heads beyond the first observed head of each of the 1,454 PRs with runs: `3,402 − 1,454`.

| Mutually exclusive evidence label | Extra heads |
| --- | ---: |
| New head after unresolved red checks | 857 |
| Canonical main-sync commit subject | 279 |
| Formal change-request review before new head | 0 observed |
| Unattributed | 812 |

These labels identify evidence, not author intention. Main-sync subjects take precedence over reviews, then failures. Overlapping evidence remains in each report row. Review attribution covers formal GitHub change requests, not informal comments or platform acceptance feedback.

Among preceding failures, `frontend / check` occurs 281 times, `backend / pure (0/1)` 185 times, and `guards / guards` 130 times. Aggregator failures overlap with their component jobs; these frequencies cannot be added.

There are 3,503 in-lifetime workflow executions and 101 executions beyond one per head (`3,503 − 3,402`). Draft/full judgements coexist on 33 heads; 25 have a matching promotion event. Six heads have observed full red-to-green judgements. The snapshot shows 179 rerun attempts beyond the first, and 710 cohort-associated cancelled runs completed before cutoff. Cancellation is not proof of supersession or an extra head.

## What the unattributed heads show

The 812 unattributed extra heads split by the previous head's observed evidence:

| Previous-head evidence | Extra heads |
| --- | ---: |
| Full `CI required` succeeded | 411 |
| Workflow ended without a full judgement (`CI required` skipped) | 17 |
| Cancellation only, with no full success | 384 |

The 411 full-gate successes are not all known to precede the next head: 407 completed before the next run was created, while four completed at or after it. Twenty-four reached success on a rerun attempt. These timestamps bound transitions; they do not establish the exact push time or author intent.

The archive contains 198 `head_ref_force_pushed` events across 141 PRs whose commit IDs match an unattributed transition. Thirty-five PRs contribute at least five unattributed heads, totaling 287; PR #3552 contributes 35 within 4.8 hours. These are indicators of iterative history changes, not proof of why a head was published.

This evidence does not justify another head-reduction rule yet. Timeline coverage is limited to 708 PRs, historical check attempts are incomplete, and the 55 open PRs are right-censored with only 56 minutes between the observation cutoff and the snapshot. Measure a later, settled cohort before changing the required-CI workflow or adding another publication gate.

## First reduction and supporting evidence

The largest attributable class is new heads following red checks: 857, compared with 279 main-sync heads. A deterministic stratified diagnostic sample inspected 12 frontend/check jobs and 12 backend/pure jobs. It is not a random sample and does not estimate population failure proportions.

- Frontend sample: four type-ratchet failures, four lint/format failures, two DOM-environment failures, one router-mock failure, and one scene-ratchet failure.
- Backend sample: eight scan/guard, three signature-drift, and three timing-rooted job-category incidences. PR #2297 and PR #2516 each span guard and drift categories, giving 14 incidences across 12 jobs.
- The implicated checks already enter the local quick plan. No missing-selection fix survived inspection. For example, [PR #2222's type failure](https://github.com/SageSeekerSociety/cheese/actions/runs/36806082761/job/110190806663), [PR #2473's formatting failure](https://github.com/SageSeekerSociety/cheese/actions/runs/37078073575/job/111072341306), and [PR #2214's import guard](https://github.com/SageSeekerSociety/cheese/actions/runs/36688933473/job/109801797895) have locally runnable counterparts.
- Two sampled jobs also show six context-service socket cases each fail with address-in-use and pass on retry. [PR #3311](https://github.com/SageSeekerSociety/cheese/pull/3311) already fixed socket cleanup. This change does not duplicate that fix or extrapolate those cases to the cohort.

`AGENTS.md` previously instructed quick checks before push. It now instructs them on the pending change before commit and gives the direct Python fallback when Task is absent. This timing correction can catch locally detectable failures before automatic publication creates a CI head. Unknown checks remain unverified; the platform's advisory pre-push behaviour remains unchanged so unavailable checks do not prevent preserving work.

No required check is weakened, skipped, or removed. The production deploy chain is untouched. A later PR-created cohort is needed to measure whether the rule changes the mean; this baseline does not claim a reduction already achieved.

## Reproduction and limitations

Collect with a fresh cache:

```sh
python3 .claude/scripts/ci_rounds_collect.py \
  --since 2026-09-30T08:00:00Z --until 2026-10-14T08:00:00Z \
  --cache /tmp/ci-rounds-fresh-cache --output /tmp/ci-rounds-evidence.json \
  --only-multi-head
python3 .claude/scripts/ci_rounds.py /tmp/ci-rounds-evidence.json \
  --output /tmp/ci-rounds-report.json
python3 -m unittest discover -s .claude/scripts -p 'test_ci_rounds.py'
```

The delivered evidence archive contains the observed snapshot, complete per-PR report, deterministic sample selection, sampled job metadata/logs, and a checksum manifest. Re-fetching later can change current-attempt evidence; use the archived observation to reproduce these numbers.

- PR listing is paginated without the search API's 1,000-result cap. Run intervals split at that cap. Page-boundary PR repeats are deduplicated.
- Explicit GitHub association is preferred. A unique repository/branch/lifetime fallback is used when GitHub omits association; ambiguous fallback fails loudly rather than guessing.
- Timelines were fetched for 708 raw multi-head PRs. One loses its second head after lifetime filtering. Promotion and review counts are lower bounds because single-head timelines were not fetched.
- Check suites contain the current attempt as observed, not every historical attempt. Rerun counters can include attempts after cutoff; failure attribution and red-to-green history may be incomplete.
- Workflow creation time bounds transitions; it is not the exact push timestamp. Cancelled status uses the observed run's update time. Same-head red-to-green alone is not evidence of a flaky test.
