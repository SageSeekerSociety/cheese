# 房间侧栏、消息失败与远端等待

本轮按用户确认的顺序处理四条路径。

1. 新建房间返回创建者的真实参与和管理权限；前端立即插入列表首位，后台刷新，并定位选中行。列表刷新挂起时，新房间仍可见。
2. 聊天接收错误携带 `client_id`、稳定错误类型和用户原因，同时覆盖 BaseError 与 AppError。前端立即结束对应消息的发送等待，在消息下显示原因与手动操作。失败消息在连接恢复后保持手动处理；重试沿用同一 ID，后端已有的幂等记录负责去重。未知失败明确说明发送结果待确认，避免声称一定未保存。
3. 工作区文件、差异和摘要请求在等待机器或代码托管服务前释放只读数据库 session；加载的对象保留标量快照。通过显式选项限定调用方，其他业务事务保持其原有生命周期。存在待写入对象时拒绝释放，避免丢失修改。
4. GET 总等待预算 20 秒，覆盖令牌等待、响应体与重试；令牌刷新独立预算 10 秒；工作摘要的远端比较总预算 15 秒。已知应用错误返回 `retryable: false`，前端立即呈现原因，边缘临时故障仍在总预算内重试。HTTP 错误保留类型、请求 ID 和重试标记，展示服务端用户说明。代码托管连接失败及超时转换为可解释的业务错误。

## 验证

本地 72 项后端、60 项前端目标回归通过。TypeScript、Pyright、Ruff、ESLint（零错误）、样式预算及仓库规则检查通过。

- 真实 PostgreSQL：连接池仅允许一条连接，机器调用和代码托管 HTTP 等待期间，另一 session 成功执行查询。
- 后端覆盖新建房间相关性、聊天权限与错误归属、工作区读取/写入权限和异常格式。
- 前端覆盖即时侧栏、选中行定位、消息失败与手动重试、读取/令牌超时、网关重试、响应体挂起和既有登录恢复。
- 浏览器真实组件与模拟 API/连接：列表刷新保持挂起时新房间已可见；发送失败显示在对应消息下；手动重试使用相同消息 ID。
- 中文 PDF 为本地预览，项目和消息为示例数据。

## 部署验收及范围

按顺序验收新建房间、侧栏位置、首条消息、被拒绝消息的提示和重试、文件读取/保存、断线恢复。关注数据库连接占用、文件/摘要响应耗时与错误请求 ID。

这轮没有生产并发压测数据。摘要比较仍逐个执行，新增整体预算保证等待有界。连接释放覆盖显式启用的工作区接口，其他领域的长事务需要按各自写入语义继续审查。普通写请求保持原有超时与重试语义；这轮仅为刷新令牌和 GET 增加总等待预算。
