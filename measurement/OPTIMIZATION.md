# 审查准备去重：前后对照

本地审查准备的中位耗时从 4.406 秒降至 2.891 秒。10 组配对测量的节省中位数为 1.530 秒；每组输出一致。这是一次局部优化，不证明历史任务的总交付时间缩短，也不证明它是最大的可控耗时。

## 改了什么

`pr-review.sh prepare` 原先用同一个提交范围调用两次分类器：一次取档位字母，一次取说明。现在只取说明，从说明首行读取档位。分类器、档位标准和审查流程不变。

`post` 仍独立重算档位，防止修改准备目录里的元数据或分类器副本来降低审查要求。分类失败时，仍保留可用的审查说明，不把部分输出当作免审结论。

这是首提交之后、递卡之前使用的审查准备步骤。任务 #1549 已在这一阶段运行过准备命令，尚未递卡。历史 90 条样本没有可靠的逐次准备命令边界，不能将本次收益乘以历史任务数。

## 复跑

在包含本次改动的仓库根目录执行：

```bash
python3 -I .claude/scripts/benchmark_review_prepare.py \
  --base f5eb87afe372332d644bbe817ce9cf1385b82bb8 \
  --head f99da6ed57f5f4e92a510b133a062d99a89e799c \
  --before f99da6ed57f5f4e92a510b133a062d99a89e799c \
  --pairs 10 --out /tmp/prepare-before-after-rerun.json
```

脚本不访问 GitHub、不修改源仓库。临时仓库与 GitHub 元数据替身仅用于隔离网络变量，没有插入延迟。其他机器的秒数会不同。

## 行为验证与剩余目标

新增回归测试通过真实分类器计数：A、B、G 三档的字母和说明保持一致，准备阶段只分类一次。该测试在旧实现上三档均失败（`2 != 1`），新实现通过。部分输出后失败的分类器不会生成免审结果。原有防篡改、全 PR 档位与增量审查测试继续通过，共 21 项。

本改动不改 CI required、部署链、合并队列或测量口径。历史报告仍有 47.41% 的墙钟无法归因；最大的可控部分仍未证实，整条首提交至首卡的改善量仍拿不到。完整 CI 与本次改动的独立审查需另行完成。
