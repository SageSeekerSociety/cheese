FB-105 临时验收入口 · 目录里第三个模型的分身能力标记

临时页面，只为 PR #5205 验收用，不进产品。每点一次都是新的一轮：现场实算启动环境，再真起一个 Claude Code 进程。

范围与判定

  • 改前 = main 树（本页启动时为 …）；改后 = PR #5205 分支树（…）。两边各自现场跑一次 _model_kwargs，算出这一轮的启动环境。
  • 模拟条件：网关目录里有两个模型，keeps-it 不带标记，third-model 标了 mid_conversation_system=False；主模型和默认子模型都是 keeps-it。主模型第一步把活派给 subagent_type=third-model 的分身。
  • 模型名说明：third-model 只是本地模拟上游用的模型名，不是真实模型。FB-105 原报告里被拒的是 gpt-6-sol / gpt-6-astra；它们当时那次 400 的根因尚未证实，本页不能证明它。
  • 上游是本地模拟的：third-model 收到对话中间的 system 角色消息就回 400「System messages are not allowed」，其余请求都回 200。真实网关、真实 gpt-6-sol/astra 都没碰。
  • 请求 ID：每一轮有自己的 ID，Claude Code 在每个上游请求的 x-fb105-run 头里带上它；下面的上游日志只列带这个 ID 的请求。
  • 成功：这一轮发给 third-model 的请求全是 200（消息角色里没有 system），Claude Code 输出里有 OK from third-model。失败：有 third-model 请求回 400，输出里是 System messages are not allowed。
  • 所有写入都在 /tmp/fb105app/runs/<请求 ID>（Claude Code 的家目录和配置目录也在里面）；不连真网关、不写产品数据库。
一轮大约 15–40 秒；同一时刻只跑一轮。
