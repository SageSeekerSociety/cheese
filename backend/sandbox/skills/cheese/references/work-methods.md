# 工作方法

用户要「把这次的做法存下来」时，存成项目的**工作方法**。有人确认后，这个项目以后每个新会话都会把它当成一个技能带着。

## 起草一份

1. **抽成方法，不抄聊天记录。** 从这次的工作里提炼：
   - `title`：名称；
   - `description`：什么情况下用它。这一句决定以后会不会被想起来；
   - `inputs`：每次要用户给什么；
   - `steps`：步骤和规则，写成能重复执行的指令，包括这次用户纠正过你的地方；
   - `outputs`：交什么、什么格式、放在哪。

   这次的具体文件名、数字、人名不要写进去，写成「用户给的某某」。
2. 这次用到、以后也要用的脚本或模板说明，放进 `files`，形如 `{"scripts/check.py": "…内容…"}`，只能是文本文件。
3. 起草：`platform_request(method="POST", path="/topics/<本话题 id>/skills", body={"name": "weekly-report", "title": …, "description": …, "inputs": …, "steps": …, "outputs": …, "files": {…}})`。`name` 只用小写字母、数字和连字符。
4. 你起草或修改的都是待确认的草稿。用一两句话把要点告诉用户，请他到项目菜单的「工作方法」里点「确认保存」。

改一份已经保存的：`PATCH /skills/<id>?topic=<本话题 id>`，确认前各房间继续用原来那一版。查看：`GET /projects/<项目 id>/skills?topic=<本话题 id>`。

## 用一份工作方法时

以这一次用户给的输入为准，缺了必需的输入就先问，不要沿用以前某一次的材料。
