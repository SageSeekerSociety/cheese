# 评测：这台 server 到底好不好用

工具写完能跑通，不等于模型用得对。评测只回答一件事：**换成一个没见过你代码的模型，拿着这台 server，能不能把真实的问题做出来。**

评测文件跟 server 一起提交，放 `evals/evaluation.xml`。

## 怎么造这 10 道题

1. **先看工具**：`tools/list` 列一遍，写清楚每个工具能干什么、要什么入参。
2. **只读地摸数据**：用只读操作把数据翻一遍，找到真实、有意思的东西——不是编出来的样例。
3. **出题**：10 道，每道都要满足下面六条。
4. **自己解一遍**：用这台 server 把答案做出来，做出来的才算数。

## 每道题都要满足

| 要求 | 意思 |
|---|---|
| **独立** | 一道题的答案不依赖另一道。 |
| **只读** | 解题过程不改变任何东西，重复跑结果一样。 |
| **够复杂** | 要连着调好几个工具、翻几层数据，一次调用就出答案的不算。 |
| **真实** | 是真会有人问的问题，不是「列出所有字段」。 |
| **可判** | 答案唯一、明确，能拿字符串直接比出来（一个数、一个 id、一个短名字更好）。 |
| **稳定** | 答案不会随时间变质。要取决于「今天有几条」的，别出。 |

答案要藏在题目背后：题面里出现答案本身、或两道题同一个答案，都算坏题。

## 格式

```xml
<evaluation>
  <qa_pair>
    <question>找出那些标题里带动物代号的模型发布讨论。其中有个模型要一个形如 ASL-X 的安全等级，X 是多少？</question>
    <answer>3</answer>
  </qa_pair>
  <!-- 再来 9 对 -->
</evaluation>
```

（上面这对是官方仓库里的例子，照它的粒度写。）

## 怎么算过

- 每题独立跑，模型自己决定用哪几个工具，**不许把答案喂给它**。
- 判分只比 `answer`：模型给的最终答案里出现这个字符串就算过。
- 一行一条记录结果（题号、对不对、用了几次调用）。**明显低于七成**就是把工具设计坏了——先回去改说明和入参，别改题。
- 说明书（`instructions`）里能讲清的用法就写进去：工具没被用对时，先怀疑说明，再怀疑模型。
