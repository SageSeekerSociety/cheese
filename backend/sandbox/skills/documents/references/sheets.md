# 表格

## 读和写都用 openpyxl

```bash
uv run --with openpyxl python3 -c "
from openpyxl import load_workbook
wb = load_workbook('预算表.xlsx')          # data_only=True 读缓存的结果值
ws = wb['Sheet1']
print(ws['B7'].value)
ws['B7'] = 1200
wb.save('预算表-改后.xlsx')
"
```

`office.py` **不能**用来改表格，它会拒绝并把这句话告诉你：Excel 的文字不在 Word 那种正文
部件里。表格要改就用 openpyxl，它本来就是为 `.xlsx` 设计的，改单元格不会破坏别的东西。

### 定位单元格

用户指着表格提要求时，消息里给的是单元格地址：

```
在 output/预算表.xlsx 的 Sheet1!B7（「1200」）：这个数字应该按季度摊
```

`ws['B7']` 直接取。**改之前先读一下那个格现在是什么**，和用户看到的括号里的内容对一下：
对不上说明你看的不是同一个文件或同一个工作表，停下来问清楚，不要照着改。

### 改完公式要重算

openpyxl 写下 `=SUM(B2:B7)` 时，写进去的是这串公式本身，不是结果。改一个格也一样：依赖
它的那些公式里存的还是改动之前算出来的数。两种情况文件都能正常打开，公式栏也对，只有
数是旧的，而且没有任何地方会报错——用户看到的就是一个错数字。

重算要在会算公式的程序里加载这份文件，这台机器上没有那种程序。平台那边有，`cheese recalc`
就是去那边算完写回来：

```bash
cheese recalc 预算表.xlsx
```

```
已重算 预算表.xlsx，写出 预算表.xlsx。
有 2 个格算不出来，交付前要处理掉：
  预算!B12  #DIV/0!
  明细!C7   #REF!
```

**这张单子不空就不能交付。** `#DIV/0!` 或 `#REF!` 落在一份预算里，用户会以为是格式问题，
而它其实是「这个数没人算得出来」。算不出来通常是分母是空格、或者引用指向了被删掉的行——
先把原因弄清楚再改，不要把公式改成常数把错误藏起来。

写完就重算，然后再摆出来（`cheese show`）：芝士的预览面板读的是文件里存着的值，没重算
过的表格在预览里公式格是空的。

同理，用 `data_only=True` 读一份**从没被 Excel 打开过、也没重算过**的文件时，公式格读出来
是 `None`。这不是文件坏了，是里面还没存过计算结果——先 `cheese recalc` 再读。

### 重算说「算得出来」，不等于「算对了」

重算只回答一个问题：每个公式算得出来吗。它答不了另一个——公式读的是不是那一行。

这已经发生过一次。把一列公式搬到另一张表上，引用跟着搬过去没变，每一行于是读的是别行的
数：文件能打开，公式栏对，合计也偏偏是对的，只有每一行是错的，而重算照样报「没有算不出来
的格」。抓出它靠的是另外两件事：

```bash
SKILL=skills/documents
[ -d "$SKILL" ] || SKILL="$CLAUDE_CONFIG_DIR/skills/documents"
python3 "$SKILL/scripts/sheets.py" refs 汇总.xlsx
```

它逐个公式格打印读到哪些格，跨表的那格写成 `明细!C2`：

```
统计!B2  =明细!C2*1.1
    读到：明细!C2
```

**读到哪些格不等于读对。** 把这张表对着旁边的标签看一遍——`统计!A2` 写着「预览」，而它读的
`明细!C2` 那一行类别是「消息流」，错位就在这里。它还会点出读到空格的引用，那多半是行号多
错了一位、指到了没数据的那一行。

能从文件本身证明的那一种它会直接报出来并**退出 1**：这一行的标签在被读的那张表里出现在
**另一行**——

```
统计!B2  =明细!C2*1.1
    读到：明细!C2
    标签对不上：这一行是「预览」，读的 明细!C2 不在那一行；「预览」在那张表的第 3 行
```

两张表用的标签体系不同（这边写「第一季度」、那边没有这个词）时它不下判断，这时候只能靠你
对着看。所以退出 0 不等于没有错位，退出 1 一定有。

```bash
python3 "$SKILL/scripts/sheets.py" check 汇总.xlsx --expect '统计!B5=110880'
```

`--expect` 填的是你**独立算出来**的关键结果（自己加一遍、或者从原始数据另算一次）。它拿
文件里存着的值来比，对不上就报出来、退出码非 0；顺带报出没重算过的公式格和算不出来的格。

两个命令都不需要装东西。**先重算再核对**：`check` 读的是文件里存着的值，没重算过就没有值
可比。关键结果要挑那种「一行错就必然对不上」的——一个跨全表的合计可能每行都错而它自己是对
的，那种数抓不住错位。

### 老格式 `.xls` 要先升级

openpyxl 只认 `.xlsx` / `.xlsm`。用户传来 `.xls`（2007 以前的老格式）时先
`cheese convert 报表.xls --to xlsx`，再读转出来那份——不要用别的办法猜里面的数字。
升级完要告诉用户转出来的不是同一份文件，细节见 `reading.md`。

## 交付前

每一份你**生成或改过**的表格，交付（`cheese show`、递卡、告诉用户「做好了」）之前按顺序跑
下面三步。**任何一步退出码非 0 就不算做完**：要么修好再从第一步重跑，要么在交付时把没通过
的那一条原样告诉用户（哪个格、报了什么），说清这一份没有通过核对。不许一声不响地交出去。

- **先 `cheese recalc`**，确认算不出来的格一个都没有。
- **再 `sheets.py refs`**，退出 1 就是有一行读错了标签；退出 0 也要把公式读到哪些格对着
  标签看一遍——尤其是一整列／一整块公式，错位就是在这里发生的。
- **拿独立算出来的关键结果 `sheets.py check`**。从原始数据另算一遍，不要从这份表格里读一个
  数再去比它自己。
- 读回来对一遍：`load_workbook(产出, data_only=True)` 把改动的那几格和相邻几格打印出来，
  确认数对得上、没有改串行。
- 表格的坑是**相邻格**：用户说 B7，你要写的是不是 B7，隔一列就是另一个数字。改完把改动
  的单元格地址和前后值一起报给用户。
