# 表格

## 读和写都用 openpyxl

```bash
uv run --with openpyxl python3 -c "
from openpyxl import load_workbook
wb = load_workbook('预算表.xlsx')          # data_only=True 读缓存的结果值
ws = wb['Sheet1']
print(ws['B7'].value)
ws['B7'] = 1200
wb.save('预算表-改后.xlsx')
"
```

`office.py` **不能**用来改表格，它会拒绝并把这句话告诉你：Excel 的文字不在 Word 那种正文
部件里。表格要改就用 openpyxl，它本来就是为 `.xlsx` 设计的，改单元格不会破坏别的东西。

### 定位单元格

用户指着表格提要求时，消息里给的是单元格地址：

```
在 output/预算表.xlsx 的 Sheet1!B7（「1200」）：这个数字应该按季度摊
```

`ws['B7']` 直接取。**改之前先读一下那个格现在是什么**，和用户看到的括号里的内容对一下：
对不上说明你看的不是同一个文件或同一个工作表，停下来问清楚，不要照着改。

### 公式不计算

openpyxl 写下 `=SUM(B2:B7)` 时，写进去的是这串公式本身，不是结果。结果要等 Excel 或
LibreOffice 打开这个文件的时候才算出来。芝士的预览面板读的是文件里已经存着的值，所以刚由
程序生成的表格里，公式格在预览里可能没有数字。交付这种文件时，把「哪些格是公式、它应该
等于多少」一起告诉用户，别让他打开发现是一片空白。

同理，用 `data_only=True` 读一份**从没被 Excel 打开过**的文件时，公式格读出来是 `None`。
这不是文件坏了，是里面还没存过计算结果。

### 老格式 `.xls` 读不了

openpyxl 只认 `.xlsx` / `.xlsm`。用户传来 `.xls`（2007 以前的老格式）时，如实说读不了，
请他在 Excel 里另存为 `.xlsx` 再发一次——不要用别的办法猜里面的数字。

## 交付前

- 读回来对一遍：`load_workbook(产出)` 把改动的那几格和相邻几格打印出来，确认没有改串行。
- 表格的坑是**相邻格**：用户说 B7，你要写的是不是 B7，隔一列就是另一个数字。改完把改动
  的单元格地址和前后值一起报给用户。
