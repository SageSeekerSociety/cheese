# 表格

## 读和写都用 openpyxl

```bash
uv run --with openpyxl python3 -c "
from openpyxl import load_workbook
wb = load_workbook('预算表.xlsx')          # data_only=True 读缓存的结果值
ws = wb['Sheet1']
print(ws['B7'].value)
ws['B7'] = 1200
wb.save('预算表-改后.xlsx')
"
```

`office.py` **不能**用来改表格，它会拒绝并把这句话告诉你：Excel 的文字不在 Word 那种正文
部件里。表格要改就用 openpyxl，它本来就是为 `.xlsx` 设计的，改单元格不会破坏别的东西。

### 定位单元格

用户指着表格提要求时，消息里给的是单元格地址：

```
在 output/预算表.xlsx 的 Sheet1!B7（「1200」）：这个数字应该按季度摊
```

`ws['B7']` 直接取。**改之前先读一下那个格现在是什么**，和用户看到的括号里的内容对一下：
对不上说明你看的不是同一个文件或同一个工作表，停下来问清楚，不要照着改。

### 改完公式要重算

openpyxl 写下 `=SUM(B2:B7)` 时，写进去的是这串公式本身，不是结果。改一个格也一样：依赖
它的那些公式里存的还是改动之前算出来的数。两种情况文件都能正常打开，公式栏也对，只有
数是旧的，而且没有任何地方会报错——用户看到的就是一个错数字。

重算要在会算公式的程序里加载这份文件，这台机器上没有那种程序。平台那边有，`cheese recalc`
就是去那边算完写回来：

```bash
cheese recalc 预算表.xlsx
```

```
已重算 预算表.xlsx，写出 预算表.xlsx。
有 2 个格算不出来，交付前要处理掉：
  预算!B12  #DIV/0!
  明细!C7   #REF!
```

**这张单子不空就不能交付。** `#DIV/0!` 或 `#REF!` 落在一份预算里，用户会以为是格式问题，
而它其实是「这个数没人算得出来」。算不出来通常是分母是空格、或者引用指向了被删掉的行——
先把原因弄清楚再改，不要把公式改成常数把错误藏起来。

写完就重算，然后再点名（`cheese artifact`）：芝士的预览面板读的是文件里存着的值，没重算
过的表格在预览里公式格是空的。

同理，用 `data_only=True` 读一份**从没被 Excel 打开过、也没重算过**的文件时，公式格读出来
是 `None`。这不是文件坏了，是里面还没存过计算结果——先 `cheese recalc` 再读。

### 老格式 `.xls` 要先升级

openpyxl 只认 `.xlsx` / `.xlsm`。用户传来 `.xls`（2007 以前的老格式）时先
`cheese convert 报表.xls --to xlsx`，再读转出来那份——不要用别的办法猜里面的数字。
升级完要告诉用户转出来的不是同一份文件，细节见 `reading.md`。

## 交付前

- **先 `cheese recalc`**，确认算不出来的格一个都没有。
- 读回来对一遍：`load_workbook(产出, data_only=True)` 把改动的那几格和相邻几格打印出来，
  确认数对得上、没有改串行。
- 表格的坑是**相邻格**：用户说 B7，你要写的是不是 B7，隔一列就是另一个数字。改完把改动
  的单元格地址和前后值一起报给用户。
