# 读材料、查资料、标来源

办公类的活（报告、周报、调研、汇报）几乎都是「读几份材料 → 补一些信息 → 写出结论」。
这三步各有一条最容易出事的地方：读漏了却说读完了、没打开的网页被当成事实、数字写出来
没人找得到它从哪来。下面三节各管一条。

## 一、读材料：先用 read.py，让每一段都带着位置

```bash
SKILL=skills/documents
[ -d "$SKILL" ] || SKILL="$CLAUDE_CONFIG_DIR/skills/documents"
uv run --with pdfplumber --with python-docx --with python-pptx --with openpyxl \
    python3 "$SKILL/scripts/read.py" 材料一.pdf 方案.docx 汇报.pptx 预算.xlsx --media 图片
```

它把每份文件读成带位置的文字：PDF 标「第 N 页」、表格标「表 页-序号」；Word 标段号 `¶12`
和所在章节；演示文稿标「幻灯片 N」，图表把类别和数值列出来；表格按 `工作表!单元格` 列，
**公式和算出来的值分开写**（`B3 = 2.625 ← 公式 =B2/B1`）。

每份文件最后一节是**「没有读到的部分」**：扫描页、图片里的内容、SmartArt、批注、没有计算
结果的公式、因为太长被截掉的后半部分。这一节决定了你能说什么：

- 那里列出的内容，**不能写成「已读」或「文件里说」**。要么补读（`--pages` 读后面的页；
  `--media` 导出的图片用 Read 打开看；公式先 `cheese recalc`），要么在答复里明确说「这部分
  没读到」。
- 扫描件抽不出文字就是抽不出，不要按上下文猜内容。这一版平台没有 OCR；图片你可以打开看，
  看到什么说什么，并说明是看图得来的。
- 脚本报「打不开」「找不到」的文件，就是没读——告诉用户是哪一份、为什么。

`.doc/.ppt/.xls` 先 `cheese convert` 升级再读。要改文件时，定位原文仍然用 `office.py text`
（见 `word.md`），read.py 只负责读。

### 多份材料：一致、冲突、缺失

几份材料说同一件事时，不要挑一份信。先列一张核对表，再写结论：

| 事项 | 材料 A（位置） | 材料 B（位置） | 判断 |
|---|---|---|---|
| 预算使用 | 31.5 万（《进展报告.docx》¶5） | 33 万（《外部评估.pdf》第 1 页） | **冲突** |
| 完成任务数 | 12（¶3） | 12（第 1 页） | 一致 |
| 延期原因 | 未提及 | 未提及 | **缺失** |

冲突要把两边原话和位置都摆出来，能判断哪份更新、更权威就说依据（日期、出处），判断不了就
交给用户；缺失的就说缺失，不要补一个听起来合理的数。表格里的数和文字里的数对不上时，以
能重算的那份为准（`cheese recalc` 后读值），并说明。

## 二、查资料：什么时候搜、搜到的算什么

有 WebSearch、WebFetch 和 `cheese_fetch`（平台代读网页，读不到时会说在哪一步失败）。

- **用户限定了材料（「只用我给的这几份」「不要上网查」），就一次都不搜。** 材料不够时说
  缺什么，不要自己补。
- 没有限定、而任务确实需要外部信息（政策、市场数据、别家的做法）时才搜。先想清楚要核实的
  是哪几件事，每件事找**直接来源**：官方网站、原始公告、论文原文、统计局数据，而不是转述它
  的新闻或博客。
- **搜索结果的摘要不是事实**。要引用，就打开那一页（WebFetch/`cheese_fetch`）读到那句话；
  打不开的页只能写「据搜索摘要，未能打开原文核实」。
- 读不到（付费墙、要登录、反爬）就如实说读不到，不要换一个说法把没读到的内容写进去。

写的时候把三种东西分开，读的人一眼能区分：

- **项目资料**：用户给的文件、项目里的任务和讨论。
- **外部资料**：网页、公开数据，带链接。
- **分析判断**：你据此得出的推断，写明是推断，以及依据哪几条。

## 三、标来源：关键的数字、事实和结论都要找得到出处

格式统一用书名号加位置，写在那句话的后面：

- 文件：《进展报告.docx》¶5、《外部评估.pdf》第 1 页、《季度汇报.pptx》幻灯片 3、
  《预算表.xlsx》汇总!B2、《进展报告.docx》表 1 R3C3
- 项目里的讨论和任务：房间用 `<#房间id>`，一条消息写房间和时间（「周报房间，9 月 25 日
  张三的消息」），任务写任务标题和 id，决策写决策原文
- 网页：`[标题](实际打开的链接)`，外加访问日期

规矩只有一条：**位置必须是你真读到的那个位置**。read.py 给出了段号、页码、单元格，就照抄；
拿不到精确位置时写能拿到的（「第 3 章」「附件二」），不要编页码、单元格或链接。一句话综合
了几处来源，就把几处都写上。

没有来源的数字，要么删掉，要么写明「估算」和估算方法。

## 四、项目里已经有的信息

用户不必把项目里已经存在的东西再粘贴一遍。当前房间信息不够时，按需往外找，找到什么就引用
什么，找不到就说找不到：

```
platform_request(method="GET",
  path="/projects/<项目 id>/context/search?q=<关键词>&topic=<本话题 id>")
```

它在你有权访问的房间里找：房间名、消息与实况文档、任务（标题、简报、结论）、决策、资料库
文件名、产物名。每条命中带着它在哪个房间、什么时候、谁说的——引用时照着写。

- 按任务需要搜几个关键词，读命中的那几处（`cheese_chat_get`、`cheese_library_ls` +
  `cheese library get`），**不要把整个项目的记录都拉下来**。
- 同一件事有新旧两个说法时，以时间更晚、或者被记成决策的为准，并说明你取了哪一个、为什么。
- 返回里 `skipped_rooms` 是你没有权限看的房间数：不要试图绕过去，需要的话请用户把内容
  给你。搜不到就说「项目里没有找到关于 X 的记录」，不要当作不存在而自己补。
