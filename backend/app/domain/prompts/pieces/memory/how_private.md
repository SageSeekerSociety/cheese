### 怎么写

写一条记忆是两步：

**第一步** —— 在他的 `private/<他的 handle>/` 里新建它自己的文件：

```
---
name: <短-kebab-case-slug>
description: <一行摘要——召回时靠它判断相关性>
type: communication | user | feedback | project | reference
---
<事实本身，写明是谁、哪天说的；feedback 接着写 **Why:** 和 **How to apply:**>
```

**第二步** —— 在那个目录的 `MEMORY.md` 里加一行指针，写成
`- [标题](文件.md) — 一句钩子`。`MEMORY.md` 没有 frontmatter，**记忆正文一个字
都不要写进它**。

- **索引这一行就是记忆本身**：以后每次读到的只有它，正文很少有人去翻。所以标题
  加钩子要合成一句照着就能做的主张，不是一个题目：「集成测试连真库，不 mock」是
  主张，「测试约定」是题目。检验办法是在后面接「，对吗」，读得通就是主张。
- **两条硬上限，超了不写入**：索引里新写的一行不超过 150 字符，一条记忆的正文不
  超过 1000 字，communication 记录的正文不超过 300 字。没写进去的那一版会留在同目录的 `<名字>.rejected.md`，改短再写。
  正文写不短，多半是把排查经过当成了结论，或者一条里装了几件事。
- 索引是注入到上下文里的那段，**超出总长上限的部分读不到**，所以保持它短。
- 一条记忆一个文件，**语义切分，不按时间切**：「重试次数」和「发版冻结」是两条，
  「这周三做了什么」不是一条。
- `name`、`description`、`type` 跟着正文一起更新；**写之前先查重**——已经有同一
  件事的那个文件就改它，别新建一个近似的副本。
- 发现哪条已经不成立（错了、被取代了、文件都不在了）就**改它或者删掉它**，不要
  在旁边补一条「更正：」——留一串互相矛盾的版本比删掉难用得多。**删一条就用
  Write 把它写成空内容**，再用 Edit 删掉索引里指向它的那一行；`rm` 碰不到这棵树。
- 写完整句子，像一篇短的小条目：说了为什么就把为什么写上，没说就写「原因未说明」；不要用只有
  当时在场的人才懂的简称（「那个修法」「上面查到的东西」）。
