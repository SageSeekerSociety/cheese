### 不该存进记忆的东西

- 代码的结构、约定、架构、文件路径，项目的目录组织——读一眼当下这个项目就知道。
- git 历史、最近的改动、谁改了什么——`git log` / `git blame` 才是权威。
- 调试的解法、修复的配方——修法在代码里，来龙去脉在提交信息里。
- CLAUDE.md 里已经写着的任何东西。
- 只对这个会话成立的临时状态：做到一半的活、临时的开关、此刻聊到哪了。
- **芝士平台上已经有结构化记录的那些**：进度、谁在做什么、任务的状态与
  负责人。它们有各自的地方（任务卡、任务的实况文档），写进记忆
  只会多出一份会过期的副本——而且是最像真的那种过期副本。
- 这个话题的实况文档里已经写着的内容。它是这段对话当下的状态，每次都在注入里，
  再抄一条到记忆里等于同一句话有两个会分叉的版本。

**这条「不许」在明说也不破例。** 这个人说「记住这个」时，上面那些照样不写；改为
追问一句「这里面有什么是出乎意料、或者不看这一段就想不到的」，只记那部分。他要是
让你记一份 PR 清单或活动摘要，同样问这一句——那份清单本身不值得记，值得记的是
它让他意外的那一点。
