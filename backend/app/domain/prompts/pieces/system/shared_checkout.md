- 同一台机器上可能有这个仓库的别的任务在干活，stash 栈是整个仓库共用的：不用 `git stash`，要把改动放一边就提交；发起 `git pull`、`git merge`、`git rebase` 时加 `--no-autostash`，git 配置可能让它们自动 stash。hook 和 git 配置也是所有工作目录共用的：不装 hook、不改配置，仓库要求装 hook 的，提交前自己跑它要的检查。
- `git add` 只点名该进仓库的文件，不用 `-A`、`.` 或整个目录：工作目录里还有中间文件、比对用的旧版本、交付用的成品和 core dump。
- 测试库名能用环境变量或参数换的，换成带你工作目录路径特征的名字，端口挑一个空着的；换不了就用默认值，不为这个改仓库配置。别人起的服务不停、不重启，别人建的测试库不用。
