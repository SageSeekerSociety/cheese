# 文档形态（知是的文档怎么写）

知是的话题文档是一份持续更新的概览。读者可能刚加入、没有看过任何聊天；他读完应知道这件事为什么做、现在是什么情况、接下来需要做什么。

## 一句话

**文档是状态，不是过程。** 聊天、命令输出、任务卡记过程；文档只留此刻成立的东西。写进去的每一句，都要在「现在」为真，而不是「某天曾经为真」。

## 五块

按这个顺序写，标题用 `##`：

1. **目标** —— 这个话题要解决什么，≤3 句。
2. **当前结论** —— 现在成立的事实、定下来的方案、验证过的结果。每条都是「现在是这样」。
3. **进行中与下一步** —— 接下来要做什么，每条带负责人（`@名字`）。
4. **待决** —— 需要人拍板的问题。
5. **相关** —— 平台自动挂（任务卡、PR、决策卡、子话题）；**不用手写**，写了也不显示。

标题可以按话题类型调整，但**「当前结论」这一块必须有**：项目总览里每个活跃话题后面跟的那句话，就是从它取的。

## 几条硬规矩

- **变了就替换，不追加。** 一条结论不成立了，改掉它本身。不要在旁边加「更正：」「补充：」——读者不该自己推断哪一版有效。
- **不写流水账。** 没有「进展日志」「时间线」这种小节，不按日期一天一行。今天做了什么属于聊天；沉淀下来的状态才属于文档。
- **不粘贴原文。** 命令输出、聊天记录、长代码块不进来。留结论，再给一个指回证据的引用（聊天消息、`<&路径>`、任务卡）。
- **引用要能点开**：话题用 `@话题标题`，工作区文件用 `<&路径>`，成员姓名写准确，要通知本人才用 `@名字`。

示例（一段合格的「当前结论」）：

> 分页已定：改 <&backend/app/api/routes/topics.py> 加 cursor 参数（决策见 @列表接口分页调研）。
> 待办：@张衡 本周过一遍接口设计。

## 维护方式

- **有持久变化时更新**：目标、关键结论、验证结果或下一步变了才改，不照搬对话。简短问答、开工告知和没有新结论的等待消息留在聊天，不为每一轮机械改文档。
- 更新前先用 `cheese_doc_get` 读当前版本，保留仍成立的内容，替换已失效的结论。写入整块覆盖，按你读到的那一版（读到的是旧版会被拒）。
- **写入时的检查只提醒，不拦。** 超过 6000 字、出现流水账小节或连续多行以日期开头、出现「更正：」这类追加段、大段粘贴聊天或命令输出，`cheese_doc_set` 的返回里会带警告——那不是建议，是要求你当场改。
- 重要结论确定后及时更新文档，供并行工作的其他话题和分身查阅。
- 文档是你（AI）的记忆基础，也是人看的界面，**是同一份东西**。
