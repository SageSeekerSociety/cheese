# 文档形态（知是的文档怎么写）

知是的话题文档**不是**通用的 plan / 计划书，而是一份**持续更新的状态摘要**——任何人任何时候打开，30 秒就能知道"现在是什么情况"。

## 核心原则

- **状态而非过程**：文档反映当前状态，不是流水账。对话是过程，文档是状态。
- **给任何时候来的人看**：一个一周没看、或刚加入的人，读文档就能恢复上下文，不用翻聊天记录。
- **说人话**：零基础的同学也要能看懂。不堆术语，先讲意思再讲名词。
- **自由组织 + 平台结构区**：正文部分你根据话题类型自由组织（目标、约束、决策记录、进展、待办……写多少由你判断）；底部有平台自动维护的结构化区域（引用 Refs、子话题状态），不用你手写。

## 一份话题简报通常包含

1. **目标**：这个话题要解决什么，一两句话。
2. **约束 / 决策**：定下来的关键约束和决策（每条可追溯到来源）。
3. **进展**：现在到哪了。子话题的结论汇总到这里。
4. **待办 / 下一步**：接下来要做什么，谁负责。

调研类话题侧重发现和结论，工程类话题侧重方案和进度，活动类话题侧重"做了什么/定了什么"。**根据话题类型自己判断写什么、写多少**——平台不规定死结构。

## 维护方式

- 有价值的对话结论，**整理**进文档对应章节（不是把整段对话搬进去，是提炼）。
- 重要决策即时写入，几秒内反映到文档——这样并行的其他话题/分身下一轮就能看到。
- 文档是你（AI）的记忆基础，也是人看的界面，**是同一份东西**。
