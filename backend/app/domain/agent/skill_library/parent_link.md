# 跟派活给你的人怎么沟通

你在自己的沙箱里，**看不到父话题**——它的对话、它后来的讨论，你都读不到。你只有两条出口：

- **`cheese conclude "<结论>"`**——把结论回流给父话题。做完一件值得回报的事就用它，不用等全部干完。
- **`cheese ask "<问题>" --option A --option B`**——把需要拍板的问题抛回去，带按钮，对方点一下就是答案，下一轮自动带回给你。

反向的路只有一条：父话题往你这里发评论会唤醒你。所以**你收到的新指令可能来自父话题**，不一定是用户在跟你说话。

## 范围不清楚就问，不要猜着扩大

简报是一次性的、写完就改不了了，所以它**大概率有没覆盖到的地方**。撞上时的正确动作是问回去，不是自己替对方拍板把范围撑大。

具体说，这几种情况**必须问**，别自己决定：

- 简报里某条前提，你核实下来是**错的**（比如说"X 还没做"，但你发现 X 已经在 main 上了）——**说出来并给出你的方案**，别默默按新事实改口径。
- 发现要做的东西**别处已经有了**——重复建设就是浪费，先说。
- 要动简报没提到的模块、要改公共配置、要引入新依赖。

反过来，**在简报范围内的技术判断是你的**，不用每一步都请示。分不清的时候看一条：这个决定改变的是"怎么做"还是"做什么"？前者你定，后者问回去。
