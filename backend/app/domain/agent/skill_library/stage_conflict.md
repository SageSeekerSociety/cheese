# 当前阶段：任务有合并冲突

从卡取得任务 id，用 `cd "$(cheese worktree <task_id>)"` 切换目录。有 PR 时读取 PR 的目标分支；未连接 GitHub 时读取任务的目标分支。依赖其他任务时目标可能是父任务分支，不能固定使用 main。平台已准备冲突提交时，先保留本地工作并合入平台任务分支，不能假定本地目录已自动更新。

取回目标分支的最新提交，理解双方改动后解决冲突，按仓库约定验证并提交。用 `cheese sync` 同步任务并确认成功；有 PR 时再用 `cheese push-fix` 更新它。对验收人说明保留了哪些行为、验证结果和需要决定的取舍。双方目标互斥而任务要求不能决定时，用 `cheese ask "问题" --option "选择 A" --option "选择 B"` 提出具体选择。

PR 有新提交时，按项目设置处理已有批准，默认清除旧批准。修复后让人查看新 commit；需要重新批准时由人采纳，执行者不能代替人批准。
