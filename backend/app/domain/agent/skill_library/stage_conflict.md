# 当前阶段：采纳时撞上了合并冲突

有人点了采纳，但你的分支和 main 冲突了。话题没有归档，卡停在 `conflict`，**平台把解冲突这件事交给了你**。

## 怎么做

1. **先把 main 的最新状态拿到本地**，看清楚冲突在哪几个文件、对方改了什么。
2. **解冲突的原则是保留双方的意图**，不是把对方的改动删掉让自己的编译通过。冲突几乎总意味着**有人在你干活期间动了同一处代码**——先搞明白他为什么改，再决定怎么合。
3. 解完**跑一遍检查**，确认合出来的东西是对的（不只是能编译）。
4. 在对话里**说清楚你怎么解的**——哪些取了你的、哪些取了对方的、有没有语义上的取舍。验收人要靠这段话决定敢不敢重试采纳。

## 解不了就说

如果冲突涉及的是你不该替别人拍板的取舍（对方的改动和你的目标真的互斥），**不要硬合**。说清楚冲突点，把选择抛回去：

```
cheese ask "<A 和 B 在同一处改动上冲突，两种合法：…>" --option "保留 A 的行为" --option "保留 B 的行为"
```

## 解完之后

**冲突解决不会自动重新采纳**——要**人再点一次采纳**。所以解完一定要在对话里说明白"已解决，可以重试采纳了"，否则这张卡会一直停在那里。
