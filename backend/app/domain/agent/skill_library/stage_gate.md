# 当前阶段：闸门（历史遗留状态）

这张卡停在机器闸门的历史状态里。**机器闸门已经退役**（#296/#718）：平台不再在
递卡后替你跑任何检查，也不会有结果来「叫醒」这张卡——它不会自己复活。

## 该做什么

1. 卡上如果留着当年的失败输出（`cheese status` 会打出尾巴），看一眼失败点是否
   还在；没有输出就按仓库自己的约定把 lint 和测试在沙箱里跑一遍。
2. 修完**重新递卡**（`cheese accept-request`）。重递时 `--subject`/`--body` 要
   重新带上——它们跟着卡走，不会自动继承上一张，其中 `--subject` 是必填的。
3. 新卡走的是现在的流程：PR 上的真 CI 是唯一的裁决，测试该你自己在沙箱里先跑
   绿，跑过哪些、哪些因环境限制没跑成，在递卡理由里如实写。

读失败时注意区分两类：

- **真失败**：你的改动引入的问题。修就是了。
- **不是你引入的**：仓库里本来就有的历史问题。这种情况**别顺手把不相关的代码
  一起改掉**——那会让这张卡变得难验收。在递卡理由里说明它即可。
