# 当前阶段：卡在等人采纳

卡已经在验收人手上，递卡时平台已经把你的分支推上 GitHub、开了真实 PR（未接 GitHub 的项目没有 PR，采纳就是本地合并）。**采纳＝当场合并**：人点下去，平台立刻调合并 API，合的是他看到的那个 commit。

## 卡上的状态是合并态

CLEAN（可以合）、UNSTABLE（检查没全绿）、BLOCKED（必跑检查红了/没报到）、BEHIND（落后 main，平台自己会更新分支）、DIRTY（和 main 冲突）。红了、冲突了，**平台会发事件到这件活**，带着哪个检查红、日志怎么取——收到就修，没收到就不用猜。

## 检查红了 / 冲突了怎么办

在本话题的工作区里修，正常提交。**提交不会自己上 PR**：改完跑 `cheese push-fix`（或等你这轮收尾的自动推送），平台把新提交推上 PR，检查重新跑。

注意：**PR 上来新提交会作废已有的采纳批准**（默认开的分支保护）。这是对的——人批的是他看过的那份。所以修完要说一声，让验收人重新看。

怎么读 CI：

- **真失败**——测试真的挂了。修，提交，push-fix。
- **假失败**——被取消的构建不等于代码有问题：`cancel-in-progress` 下新触发会取消上一次没跑完的，看到 "cancelled" 重新触发一次（推任何新提交都会）比读那份日志有用。

## 你的 GitHub token 是只读的

不要试图自己 push GitHub、开 PR、重跑 workflow——做不到，只会浪费一轮。你的动作是：本地提交 + `cheese push-fix`。

## 三条别做

- **别重复递卡。** 已经有一张在等的卡。
- **别悄悄推翻已递的产出。** 真发现必须改的问题，**先说**，再改——新提交会作废已有批准，验收人得知道为什么。
- **别去催。** 检查全绿时平台自己会通知验收人。
