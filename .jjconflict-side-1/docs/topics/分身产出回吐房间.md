## 目标

让房间**看得见**两件以前只存在于容器里的事：

1. 派出去的**分身查出了什么**（以前只看得到「派了一个分身去查 X」，看不到答案）；
2. **这一轮改了哪些文件**（以前每个「改文件」都有一行，但没有「这一轮净效果」）。

## 做了什么

三个文件，都在后端：

| 文件 | 改了什么 |
|---|---|
| <&backend/app/domain/agent/chat.py> | 落两种新的现场事件；抽了一个共用的 `_persist_room_event` |
| <&backend/app/domain/agent/hook_events.py> | `PostToolUse` 不再被丢掉——分身那两个工具名会翻成结论事件 |
| <&backend/app/domain/agent/service.py> | 新的事件类型 `AgentToolResult` + 它的 wire 编解码 |

### 1. 分身结论

链路：容器里的 `PostToolUse` hook（**本来就在往后端发**，只是 `translate_hook`
把它 `return None` 了）→ `AgentToolResult` → 房间时间线里一条 `kind=event` 的 block。

- 只认 `Task` / `Agent` 两个工具名。别的工具的返回值不吐——`Read` 的返回值是整个文件，
  `Bash` 的返回值本来就在屏幕上，全吐等于把时间线翻一倍。
- `tool_response` 的形状随 CLI 版本变过（纯字符串 / content 块数组 / dict 包着数组），
  所以解析是**容错**的：读不出来就当没有，而不是崩掉或落一条空事件。
- 房间里那行长这样：`分身查完了：<问题>` + 换行 + 结论摘要（折成一行）。
- **上限 500 字符**（`_SUBAGENT_RESULT_MAX`），超了截断加省略号，`meta` 里带
  `truncated: true`。全文在 transcript 里，房间只要够判断「答到点上了」还是「跑偏了」。
- spool 回补（后端当时没在听）这条路也认它，否则时间线会留着问题、丢掉答案。

### 2. 这一轮的改动汇总

一轮结束时（**在 `provider.checkpoint()` 之后**——那一步才把这轮的编辑变成提交）落一条：

```
这一轮改了 3 个文件（+128 -7）
backend/app/x.py · backend/tests/y.py · README.md
```

- 怎么知道哪些提交是「这一轮的」：轮次开始前读一次分支的提交列表当基线，轮末读第二次，
  差集就是这轮的。读不到基线（没有工作区、git 报错）就**不落汇总**，而不是把整条分支的
  历史当成这一轮。
- 增删量是从 diff 正文数出来的（现成的 workspace 读函数只给 diff 正文，没有 `--numstat`）。
  只在 hunk 内部计数——按 `+++`/`---` 前缀跳过的写法会把一条内容以 `--` 开头的删除行漏掉。
- **不刷屏**：正文只列 12 个路径（`_CHANGE_FILES_LISTED`），多的写成「…另 N 个」；
  diff 正文一个字都不进消息。
- 代价实测：每轮两次 `git log`，热态约 10ms/次，可忽略。

## 前端要什么字段（下一棒接这里）

两种 block 都是 `kind=event`，而且**故意不带 `meta.tool`**——前端 `eventVerb()` 见到
`meta.tool` 就去自己的动词表翻译，表里没有就渲染原始英文名。不带这个键就走
`content` 文本那条路，**今天的前端已经能正确显示**，不需要改前端就能上。

想做专门的卡片时，结构化字段在这里：

```jsonc
// 分身结论
{ "platform": false,
  "subagent": { "tool": "Task", "description": "查分页接口现状",
                "summary": "结论…", "truncated": false } }

// 这一轮的改动
{ "platform": true,
  "changeset": { "commit": "abc1234", "commits": ["abc1234"],
                 "files_total": 3, "added": 128, "removed": 7,
                 "files": [{"path": "backend/app/x.py", "added": 120, "removed": 5}],
                 "files_omitted": 0 } }
```

「点开看 diff」不需要新接口：`GET /api/projects/{project_id}/git/diff?ref=<commit>`
现在就返回那一个提交的 diff。`commits` 是新到旧，`commit` 是其中最新的那个。
