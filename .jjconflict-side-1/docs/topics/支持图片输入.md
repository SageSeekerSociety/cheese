# 支持图片输入

## 目标

聊天输入框支持发图片：粘贴或选文件 → 图片出现在现场消息流里 → 芝士能"看到"这张图。

## 现状：已完成，待验收

两个输入框（工作话题的跨栏输入框、私聊输入框）都支持：**直接粘贴截图**或点图片按钮选图 → 输入框上方出现缩略图（可删）→ 随消息发出 → 消息流里直接显示图片（点击看原图）。纯图片不带文字也能发。@芝士 时它能真正"看到"图片内容并回应。

## 方案（已实现）

1. **存储**：图片上传后落到话题工作区的 `uploads/` 目录（自动进版本库，文件面板可见）。
2. **块表示**：每张图是一个 `attachment` 块（复用块模型预留类型），`content` = 工作区相对路径，`mime_type` = 图片类型；和文字消息同轮发出、可被回复串联。
3. **AI 侧**：不改 AI 调用层。拼消息时告诉芝士"某某发来图片，在工作目录 uploads/xxx.png，用读文件工具打开可见"——芝士在沙箱里读图（其读文件能力原生支持图片），真正看到图。
4. **接口**：`POST /api/topics/{id}/attachments`（multipart 上传）+ `GET .../attachments/raw?path=`（二进制返回，仅限图片扩展名，防止借道输出可执行内容）；WebSocket 消息带 `attachments: [{path, mime}]` 结构化字段。

## 约束 / 决策

- 只支持图片（png/jpeg/gif/webp），单张 ≤10MB，单条消息最多 9 张；其他文件类型以后再说。
- 图片存工作区而非独立对象存储——与"所有产出都是 git"的平台设计一致。
- 附件是结构化字段（块 + mime），不从消息文字里解析。
- raw 读取接口按扩展名白名单限定图片，杜绝从工作区外带 HTML/脚本。

## 验证

- 后端：新增 5 个集成测试（上传/raw 回读、拒非图片、防路径穿越、消息带图建块并进提示词、纯图消息）；全套 218 通过。`test_market_api` 有 1 个与本次无关的失败（本机环境没配可用模型，改动不涉及该模块）。
- 前端：`vue-tsc` 类型检查 + 构建 + vitest 全过。

## 已知边界

- 远程算力模式（compute_provider=remote）下文件在远端节点，上传/读取暂未做代理转发——目前本地部署不受影响，等远程模式启用时再补。
