## 目标

`_converse_impl` 构造 prompt 的 pending 窗口，从"最后一条 AI 消息的位置"改成按块归属划界。修掉三条同根症状：轮次运行中到达的人类消息**永久丢失**、带 @ 的插话被标成**平台指令**、两人同时 @ 时**白跑一轮**并重投已答过的消息。

## 根因

`backend/app/domain/agent/chat.py::_converse_impl`，pending 窗口从 `last_ai`（history 里最后一条 AI 消息的**下标**）起算。`history` 按 `created_at` 升序，而一条轮次进行中到达的人类消息，时间戳排在那轮 AI 回复**之前** → 被下一轮的窗口切掉，且 `last_ai` 只会往前走，所以永久丢失。

关键认识：**"这条消息有没有被读进 prompt"是运行时事实，从时间戳位置反推不出来**。两人同时 @ 的场景可以证明这一点：turn1 在锁上把 u1+u2 合并进了 prompt，但库里没有任何痕迹能让 turn2 知道 u2 已经被答过了。所以必须持久化这个事实。

## 方案

1. **盖戳**：轮次成功跑完后，给它读进 prompt 的人类块盖一个 consumed 戳（`meta.consumed_turn = <turn_id>`，走 `BlockRepository.mark_consumed`）。
2. **划界**：pending = 最后一个带戳的人类块之后、且本身没戳的 message/attachment 块。
3. **不跑冗余轮**：pending 为空且本轮是真人召唤（`user_block_id is not None`）⇒ 这条已被前一轮合并答过 ⇒ 直接结束本轮，不走 `platform_prompt` 兜底。
4. **老数据兼容**：戳是这次改动才有的。话题里一个戳都没有时，退回旧语义（最后一条 AI 消息之前的算已读），否则上线后第一轮会把整个话题历史重放一遍。盖过一次戳就永远走新逻辑。

两个刻意的取舍：

- **不加列、不加 migration**：用 Block 已有的 `meta` JSON 列。仓库多 agent 并发，alembic 分叉的代价高于收益。
- **盖戳放在轮次成功之后（tx2），不在建 prompt 时（tx1）**：轮次崩了/超时/provider 报错就不盖戳，消息留在 pending 里由续跑轮重发。**宁可重复，不可丢失**——重复看得见，丢失看不见。

## 约束（来自简报）

- 三条症状各有各的回归测试，断言必须不同（消息缺席 / 标签错误 / 多余轮次）。测行为不读实现。
- 不动 turn 调度本身（锁、信号量、`TurnRunner.submit` 的排队逻辑是「tmux 插话」那步的地盘）。
- `platform_prompt` 兜底要保留：resume / kickoff / 结论回流这些真的没人说话的轮次仍然走它。
- 先确认没有别处依赖当前窗口语义。

### 测试怎么证明自己有用

四条测试都跑过「把窗口逻辑退回旧语义」的对照，三条症状各红在**不同**的断言上：

| 测试 | 断言的东西 | 退回旧逻辑时的报错 |
|---|---|---|
| `..._is_not_lost_from_the_next_prompt` | 消息**在不在**下一轮 prompt 里 | `assert '顺手看下登录接口' in '[u3]: 继续'` |
| `..._is_not_relabelled_as_a_platform_instruction` | 内容对了，**抬头**是谁 | 那句被 `【平台】…不是任何人手打的话` 包住 |
| `..._run_one_turn_not_two` | **跑了几轮**（不看内容） | `3 == 2`，多出白跑的第三轮 |
| `..._still_speaks_as_the_platform` | 反向守卫：没人说话的轮次仍走兜底 | —（防的是这次改动本身跑过头） |

最后一条是这次改动的**边界**：修的是「有人说话却被当成平台指令」，不是把
`platform_prompt` 拆了。resume / kickoff / 结论回流本来就没有人类块，pending 空是
它们的正常状态 —— 既不能被症状三的早退当成冗余轮吞掉，也仍旧要顶着平台抬头。
