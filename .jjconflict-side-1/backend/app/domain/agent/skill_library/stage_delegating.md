# 当前阶段：拆活

本话题是个**房间**，它自己不带分支、不走验收卡。真正的活是 `cheese split` 出去、由子话题的分身在自己的沙箱里做的。

## 最重要的一条：`cheese split` 是单向的

简报（`--brief`）发出去之后**没有任何办法追加或修改**。子话题拿到的就是那一份，它据此开工，中途你改不了。所以：

**简报必须一次写全。** 想到一半就 split，等于把一个理解不完整的任务甩给一个联系不上的人。

## 简报里必须有的五段

1. **目标**——要什么产出，不是"研究一下 X"，而是"产出 X，满足 Y"。
2. **已核实的事实 + 证据**——你已经查清楚的东西全写进去，并注明是**怎么**核实的（读了哪个文件、跑了什么命令）。明确写「别重新调研」。子话题重跑一遍你已经做过的调研，是这个机制最常见的浪费。
3. **禁区**——明确不做什么。子话题看不到房间里的上下文，不写禁区它就会按自己的判断扩大范围。
4. **验收标准**——逐条、可检验。这是子话题递卡时逐条给证据的对象。
5. **传话路**——告诉它发现简报有错、或需要拍板时怎么找回来（见下）。

## 给子话题留一条问回来的路

子话题**不能主动读父话题**，它只有两条出口：`cheese conclude` 回流结论、`cheese ask` 把问题抛回来。简报里要明说：**发现简报的前提是错的、或者需要拍板，就问回来，不要猜着往下做。**

反过来，**你**要中途给已经在跑的子话题追加要求，唯一的路是往它的话题里发评论：

```
cheese api POST /topics/{子话题id}/comments --data '{"author": "...", "content": "..."}'
```

这条会真的唤醒目标话题的芝士，不限于当前话题。

## 一个已知缺口：拒绝验收卡不会通知

验收卡的「退回」只改数据库那一行——**不会 summon、不会发消息**，跟闸门红了自动 summon 的行为不一致。所以**每次退回一张卡之后，必须额外用上面那条评论把理由传过去**，不能假设子话题会自己知道被打回了。
